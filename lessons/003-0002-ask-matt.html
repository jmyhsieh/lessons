Phase 3 · 第 02 課 · 約 20 分鐘 · 路線判斷

用 /ask-matt 判斷該走哪條路

本課成果：一張工作路線判斷，能說明目前需求該走哪一條 Claude Code 流程。

本課只做：判斷下一步該用哪條路。
先不要做：把 /ask-matt 當成會替你完成工作的萬用指令。
必要前置：若目標程式庫尚未完成 第 01 課的 /setup-matt-pocock-skills，先完成設定；追蹤系統與領域文件未設定前，不要啟動工程流程。

它是分流器（router），不是施工隊

/ask-matt 的職責是把情境分到正確流程。它會告訴你該先用哪個工作技能、何時切工作階段、何時改走 triage、wayfinder 或維護線。真正產出規格、工作項目、程式碼或交接的，是後面的專門工作技能。

情境建議路線
單一工作階段能完成的新需求/grill-with-docs → 同一個對話脈絡直接 /implement
需要多個工作階段的開發工作/grill-with-docs → /to-spec → /to-tickets → 每張工作項目開新對話脈絡跑 /implement
必須用可跑成果回答的設計問題/handoff 出主線 → /prototype → /handoff 把答案帶回
外部錯誤或需求回報/triage 先產生可交給 Claude Code 的議題 → 通常交 /implement；若是難解、間歇或回歸錯誤，再改走 /diagnosing-bugs
巨大、模糊、超過一個工作階段的工作/wayfinder 先建立共享地圖，逐張決策工作項目推進到路徑清楚，再回到 /to-spec；只有工作最後縮成單一小任務才直接 /implement
架構維護/improve-codebase-architecture → 選一個改善點 → 回到 /grill-with-docs
對話脈絡太滿或要分支/handoff 開新工作階段；/compact 留在同一個工作階段。
記住主線：/implement 是實作統籌工具；它內部會用 /tdd，做完再用 /code-review。不要把 /tdd 和 /code-review 畫成與 /implement 平行的主流程。
保持對話脈絡乾淨：從需求追問到 /to-tickets 盡量維持同一個工作階段，不要中途使用 /clear 或 /compact；切完工作項目後，每張 /implement 再各自使用乾淨工作階段。若主線脈絡快滿，先 /handoff。
Wayfinder 是選修分支：只有當「通往目的地的路仍看不清楚」，而且一個工作階段放不下時才使用。若你已能列出完整規格與工作項目，就不需要先畫地圖。選到這條路時，前往 第 13 課。

先分清楚：入口與流程內能力

不是每個工作技能名稱都代表同一種入口。初學時先把它們分成兩層，會比較不亂：

類型例子你怎麼用
主要手動入口/ask-matt、/grill-with-docs、/to-spec、/to-tickets、/implement、/triage、/wayfinder、/improve-codebase-architecture、/handoff你通常會主動選它們開始一段工作。
流程內能力/tdd、/code-review、diagnosing-bugs、domain-modeling、codebase-design常由主流程帶出來，或在特定情境下才單獨使用。

實作步驟（做完打勾）

各寫一句：一個新功能想法、一張外部錯誤回報、一個你覺得難維護的模組。

/ask-matt 我現在的情境是：[貼上情境]。我應該從哪個工作技能開始？

只看它選的路線與理由，先不要立刻執行後續指令。

如果它把 /tdd 或 /code-review 當成主流程起點，請它重新對照 /implement 的職責。

挑一個情境，記下下一課要帶進程式庫地圖或 grill 的輸入。

完成條件：三個情境都已分到對應流程，而且每個選擇都有工作規模與風險依據。

觀念檢查（憑記憶作答）

1. 一個新功能還不清楚，最合理的主線入口是？

新需求先對齊，不是先做。/grill-with-docs 會把想法、詞彙、程式碼現況與 ADR 放在同一個脈絡裡問清楚。

2. /implement 和 /tdd 的關係比較接近哪一種？

/implement 負責依規格與工作項目施工；/tdd 是它內部用來保護實作品質的紀律。

3. Grill 後確認需求能在單一工作階段完成，也不需要 prototype，下一步是？

只有需要跨多個工作階段完成的工作，才要先固化成規格與工作項目。小而已對齊的需求可以留在同一個對話脈絡，直接交給 /implement。

下一步

完成後回對話視窗回報。一般路線下一課是 Phase 3 第 03 課 — 不熟 repo 時，先建立地圖；若選到巨大模糊工作，改走 Phase 3 選修第 13 課 — 建立共享決策地圖。

主要閱讀資源：已審查的 ask-matt 版本（66898f6）；選路前再查 目前的 ask-matt 說明。主線實作與巨大模糊工作的邊界另見 implement 與 wayfinder。

路線選擇有疑問時，交出需求摘要、工作規模與可逆性，請 Claude Code 說明選擇該入口的依據。

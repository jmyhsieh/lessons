先用 plan mode 讓它只規劃不修改

任務目標：能判斷什麼時候用預設模式、什麼時候先切 plan mode。這一課只學「模式選擇」，不處理 allow/deny 規則。

本課只做：用 plan mode 讓它先規劃、不修改。
先不要做：在還沒看 plan 前就切到自動批准。

六種模式先分成三類

類型模式正式專案建議
日常基準Desktop Manual／CLI default工作目錄內讀檔與內建唯讀指令通常直接執行；編輯與其他指令會詢問。
先想清楚plan可以探索檔案與執行探索命令，但不編輯 source；不確定或跨檔任務先用。
例外情境acceptEdits、auto、dontAsk、bypassPermissions等你能清楚說出風險再用；隔離環境以外不要用 bypass。

核心節奏：plan → review → 放行

上一課只讓 Claude Code 讀 repo；plan mode 讓你在第一次修改前，多練一次「探索 → 看計劃 → 才放行」。它可以讀檔與執行探索命令，權限提示仍然適用；核心保證是不能編輯 source。

  1. 切到 plan mode，描述任務。
  2. 它讀 codebase、產出計劃。
  3. 你審計劃，修到能接受。
  4. 批准離開 plan mode，回到 Desktop Manual 或 CLI default 實作。
一句話能描述 diff 的小改可以直接做；跨檔、跨模組、不熟悉的區域，一律先 plan。

實作步驟（做完打勾）

挑一個你可能會讓 Claude Code 做、但還不想馬上改檔的任務。

桌面 App 用 mode selector。CLI 互動模式才用 Shift+Tab。確認它顯示在 plan mode。

Explore the codebase and propose a plan.
Do not modify files yet.

檢查它是否列出會動到的檔案、風險、驗證方式。缺任一項就要求補齊。

🎉 完成！你現在知道什麼任務要先進 plan mode。

觀念檢查

1. plan mode 和口頭要求「先給計劃」最大差異是？

口頭要求是指引；plan mode 是模式層級的限制。

2. 哪種任務最適合先用 plan mode？

不確定性越高，越需要先探索與計劃。

Phase 1 · 第 01 課 · 約 10 分鐘

四個 Claude 工作表面，四種交付路線

任務：能依工作環境與成果類型，判斷一項工作該留在 Claude 對話、交給 Cowork、進入 Claude Design，還是開 Claude Code session。

本課只做：判斷同一件事該交給哪個 Claude 工作表面。
先不要做：用「哪個模型最強」或「哪個畫面最新」當唯一判斷標準。

核心觀念：差別不在「聰明程度」，在工作環境

這四種入口會重疊，但主要交付物不同。真正的判斷軸是工作環境與成果類型：你要一段回答、一組完成的知識工作檔案、一個可反覆評論的視覺原型，還是經過測試的 repo 變更？

Claude（claude.ai 網頁 / App）

對話助理 — 你貼內容進去，它回答出來。

適合：問問題、寫草稿、分析你附上的檔案或程式碼片段、使用 connectors 查資料。重點是由你提供 context，不是把一個本機工作區交給它持續操作。

Claude Cowork

知識工作代理 — 遠端任務可跨裝置接續；Desktop 也能直接處理本機檔案。

可從 web、Desktop 或 mobile 委派多步驟任務，遠端 session 會跟著帳號跨裝置接續；Desktop 另支援直接讀寫你授權的本機檔案。適合：整理文件、研究彙整、產出報告與簡報。Dispatch 若判斷任務屬於軟體開發，也可能建立 Code session；不要把分頁名稱當成硬邊界。 （官方上手指南）

Claude Design

視覺協作畫布 — 建立設計、互動原型、簡報與可交接的 design intent。

適合：先比較多個視覺方向、套用 design system、在 canvas 上評論與精修，再把選定方向交給 Claude Code 實作。它仍是 beta，現階段在 web 與 Claude Desktop 使用；prototype 不是 usability、accessibility 或 production readiness 的證明。 （官方入門指南）

Claude Code

軟體工程代理 — 在 git repo 裡讀程式碼、改檔案、跑指令、開 PR。

可在終端機、VS Code/JetBrains、桌面 App、瀏覽器使用。理解整個 codebase，能跨多檔案修改、執行測試驗證、操作 git。這是你要在工作 repo 上用的工具。 後續進入工作 repo 前，會在安裝課確認 Git 是否可用；本課先只練工具選擇。 （官方文件）

📄 已為你整理成一頁速查表，可列印放手邊。

練習：你來判斷

不要回頭看上面 — 先憑記憶作答（提取練習才能建立長期記憶）。

1. 「把專案裡所有過時的 API 呼叫改成新版，並跑測試確認沒壞。」

需要跨檔案修改 repo 程式碼並執行測試 → Claude Code。

2. 「把這個資料夾裡 30 份會議記錄整理成一份季度總結文件。」

多步驟檔案處理、產出文件、非程式碼 → Cowork。

3. 「這段 error message 是什麼意思？大概該往哪個方向查？」

貼上內容、得到解釋即可，不需動到檔案 → Claude 就夠了。若要它直接在 repo 裡追出根因並修掉，才升級到 Claude Code。

4. 「先用品牌元件做三個可互動的 dashboard 方向，選定後再交給工程實作。」

要先在視覺畫布探索、比較與評論原型，再 handoff 給工程 → Claude Design。

Phase 7 · Verify · 007-0004 · Durable test

把同一個 browser claim 寫成最小 Playwright Test

Entry：帶入 007-0001 的單一 claim、007-0003 的 exact baseline identity、originating ticket／Engineering closeout，以及一個可控制、可恢復且不含 production mutation 的 test fixture。先讀 repo instructions 與現有 Playwright conventions；本課只新增保護這個 claim 的一個 test，不擴成 browser matrix、CI 或整條 journey suite。

Verified environment：本例於 2026-07-17 以 @playwright/test@1.61.1、Node 24.16.0、macOS 26.5.2 arm64 與 system Google Chrome 重現。你的 repo 應使用自身 lockfile、config、browser project 與 test command；無法確認版本、browser binary、base URL 或 fixture authority 時，不可把本例結果冒充你的 environment evidence。

1. 固定一個 test identity

Claim ID: checkout-guest-confirmation
Test file: tests/browser/checkout.spec.ts
Test name: guest can complete checkout
Given: controlled guest fixture at the recorded app revision
When: click the accessible button named「送出訂單」
Then: heading named「訂單完成」is visible
Disproving behavior: heading is absent or a different state remains
Out of scope: authenticated roles, payment provider, other browsers, CI

Identity rule：下一課製造 RED 與修正後 GREEN 時，test file、test name、action 與 assertion 都不變。只切換或修正可控制的 faulty fixture／app behavior；若把 expected 改成錯誤畫面、skip、放寬 locator 或刪掉 assertion，就沒有證明 test 能保護原 claim。

2. 寫最小 user-observable assertion

import { test, expect } from '@playwright/test';

test('guest can complete checkout', async ({ page }) => {
  await page.goto('/checkout?fixture=guest');
  await page.getByRole('button', { name: '送出訂單' }).click();
  await expect(
    page.getByRole('heading', { name: '訂單完成', exact: true })
  ).toBeVisible();
});
選擇理由回饋
從 user-visible action 開始測 public browser behavior，不呼叫 private handler 或查內部 state。Test 仍可由 claim card重述。
使用可存取 role／name讓 assertion 對齊使用者能辨識的 outcome；repo 若有更穩定 public locator convention，依 repo 為準。Locator 在 baseline fixture 唯一命中。
只有一個 decisive assertion先證明 bounded claim；不要順便 snapshot 整頁、比每個 style 或加入無關 API checks。失敗訊息直接指出哪個 observable outcome 不成立。
retries: 0 做 RED 校準故障敏感度檢查不能被 retry 掩蓋或只留下最後一次成功。Faulty fixture 必須產生 failing run，而非 flaky／passed。

Test boundary：Screenshot、snapshot、console log、trace 或 exploration transcript 都可以協助理解，但不是這個 assertion。先保存一個 test file／name／claim mapping；不要現在開 trace、推 branch、建立 actual PR、修改 CI，或宣稱一個 browser project 代表所有 viewport、role 與 real users。

Tangible win：一個對應單一 claim、可在 repo command 下執行的最小 Playwright Test，以及固定的 test identity card。
Observable feedback：Reviewer 能從 test 找到 starting state、user action 與 expected outcome，並能指出哪一個 controlled faulty behavior 應使同一 assertion 失敗；若只能靠讀 internal code 判斷，test 尚未對準 browser seam。

哪個改動能在下一課證明 test 真正保護 claim？

敏感度證明要讓同一 assertion 與壞掉的 behavior 發生可觀察衝突；改 expected、skip 或 retry 到綠都會抹掉 RED。

Legal stop／return／continuation：沒有 safe controlled fixture、repo 不允許新增／執行 test、base URL 或 setup 不可重建、locator 只能依賴不穩定 internal detail，或執行會碰 production／真實交易時，保存 test draft 並停止；claim 錯誤回 007-0001，baseline identity 缺口回 007-0003，repo write／fixture 需要另回 originating Engineering route取得 authority。最小 test 可解析後，進 007-0005 先證明 controlled faulty fixture RED，再以同一 identity 修正後 GREEN。此頁不代表 durable evidence、Browser evidence addendum、Phase 或 Migration complete。

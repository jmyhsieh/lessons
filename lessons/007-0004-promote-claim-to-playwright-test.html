Phase 7 · 驗證 · 007-0004 · 持久的test

把同一個瀏覽器主張寫成最小Playwright Test

進入條件：帶入007-0001的單一主張、007-0003的精確基準識別、原始工作票／工程收尾，以及一個可控制、可恢復且不含正式環境變更的測試資料。先讀儲存庫指示與現有 Playwright 慣例；本課只新增保護這個主張的一個test，不擴成瀏覽器矩陣、CI或整條流程測試套件。

已驗證環境：本例於2026-07-17以 @playwright/test@1.61.1、Node 24.16.0、macOS 26.5.2 arm64 與系統 Google Chrome 重現。你的儲存庫應使用自身鎖定檔、設定、瀏覽器專案與測試命令；無法確認版本、瀏覽器執行檔、基準 URL 或 fixture 權限時，不可把本例結果冒充你的環境證據。

1. 固定一個test識別

Claim ID: checkout-guest-confirmation
Test file: tests/browser/checkout.spec.ts
Test name: guest can complete checkout
Given: controlled guest fixture at the recorded app revision
When: click the accessible button named「送出訂單」
Then: heading named「訂單完成」is visible
Disproving behavior: heading is absent or a different state remains
Out of scope: authenticated roles, payment provider, other browsers, CI

識別資訊規則：下一課製造RED與修正後GREEN時，test檔案、test名稱、動作與斷言都不變。只切換或修正可控制的有缺陷的 fixture／應用程式行為；若把預期結果改成錯誤畫面、skip、放寬定位資訊或刪掉斷言，就沒有證明test能保護原主張。

2. 寫最小使用者可觀察的斷言

import { test, expect } from '@playwright/test';

test('guest can complete checkout', async ({ page }) => {
  await page.goto('/checkout?fixture=guest');
  await page.getByRole('button', { name: '送出訂單' }).click();
  await expect(
    page.getByRole('heading', { name: '訂單完成', exact: true })
  ).toBeVisible();
});
選擇理由回饋
從使用者可見的動作開始測公開瀏覽器行為，不呼叫內部處理器或查內部狀態。測試仍可由主張卡重述。
使用可存取角色／名稱讓斷言對齊使用者能辨識的成果；repo若有更穩定公開定位資訊慣例，依repo為準。定位資訊在基準fixture唯一命中。
只有一個關鍵斷言先證明有界主張；不要順便快照整頁、比每個樣式或加入無關API checks。失敗訊息直接指出哪個可觀察結果不成立。
retries: 0 做RED校準故障敏感度檢查不能被retry掩蓋或只留下最後一次成功。有缺陷的 fixture必須產生失敗的執行，而非不穩定／已通過。

測試邊界：Screenshot、快照、主控台記錄、trace或探索逐字紀錄都可以協助理解，但不是這個斷言。先保存一個test檔案／名稱／主張對照；不要現在開trace、推branch、建立實際的PR、修改CI，或宣稱一個瀏覽器專案代表所有viewport、角色與真實使用者。

可見成果：一個對應單一主張、可在repo command下執行的最小Playwright Test，以及固定的test識別卡片。
可觀察回饋：審查者能從test找到起始狀態、使用者動作與預期結果，並能指出哪一個受控的有缺陷的行為應使同一斷言失敗；若只能靠讀內部的code判斷，test尚未對準瀏覽器接縫。

哪個改動能在下一課證明test真正保護主張？

敏感度證明要讓同一斷言與壞掉的行為發生可觀察衝突；改變預期結果、略過或retry到綠都會抹掉RED。

合法停止／返回／續行：沒有安全的受控 fixture、儲存庫不允許新增／執行test、基準 URL 或設定不可重建、定位資訊只能依賴不穩定的內部細節，或執行會碰正式環境／真實交易時，保存test草稿並停止；主張錯誤回007-0001，基準識別缺口回007-0003，儲存庫寫入／fixture需要另回原始的工程路線取得權限。最小test可解析後，進 007-0005 先證明受控的有缺陷的 fixture RED，再以同一識別修正後GREEN。此頁不代表持久證據、瀏覽器證據附錄、Phase或Migration完成。

先審查 planner 產生的 spec

今天只做一件事：讓 planner 把一條需求整理成可讀 spec，先核准範圍，再允許產生 test code。

Spec 是審查關卡：planner 應輸出人在寫 code 前就能評估的步驟與預期結果；如果需求仍模糊，先修 spec，不要把模糊放大成很多 tests。

產生一份 bounded spec

提供使用者目標、開始狀態、必要動作、預期結果、停止線，以及上一課的 seed test；有 PRD 時只附相關段落。

Use the Playwright planner for only this path: ＿＿。
Use the existing seed test and relevant requirement: ＿＿。
Write one Markdown spec under specs/. Do not generate tests or edit product code.

逐項檢查範圍、前置條件、步驟、預期結果與未涵蓋項目；刪除模型自行加的情境，留下 approved spec 與 review note。

完成：你已有一份已核准、可逐項轉成 test 的 specs/*.md。

先核准人可讀 spec，能在低成本階段攔下錯誤範圍與錯誤預期，再交給 generator。

Phase 9 · 標準化 · 009-0009 · 條件式契約分支

把一次已證明的LLM Wiki維護萃取成可重跑契約

進入條件／選修：Mission已選擇標準化LLM Wiki維護，而且能帶入 008-0008 的指定維護證據，以及後續008-0005完成證明與008-0007作業收尾。若只有原始來源、第一次生成的知識庫切片、未審查的操作筆記，或只覺得流程「應該可重用」，不進本分支；回原路補證明。

1. 先固定證明識別，不從記憶重寫流程

Maintenance run / operating closeout IDs:
Existing wiki revision / maintained revision:
Raw source pack / stable source IDs / rights record:
Claim-provenance and review-log locations:
Declared fixture / environment / restore point:
Exact completion oracle / pass result:
Failure / recovery / retry evidence:
Reviewer disposition / unresolved limitations:
External actions: none | separately approved receipt

證明前置條件：契約只能萃取證據已出現且被審查者處置的行為。原始來源包、穩定來源ID與主張層級來源脈絡繼續是來源的唯一權威來源；知識庫頁面、摘要、連結、匯出檔、契約與套件都是衍生的產物，不得互相循環背書。

2. 分開不變條件與每次執行參數

契約欄位保留為不變條件每次重跑明確給定參數
輸入只接受具穩定 ID、權利與定位資訊的原始來源集合。來源版本、變更觸發條件、受影響的主題叢集、基準修訂版。
輸出只修改有界的本機測試資料；每個已變更主張可回到原始定位資訊。輸出路徑、預期頁面／連結／匯出檔、執行識別。
權限最小讀取／寫入範圍、先預覽、代理程式不自我批准外部動作。允許的路徑、操作者、核准收據；共用／遠端目標預設不允許。
判定依據來源追溯、連結／匯出、空白／重複、範圍相等性與審查紀錄檢查。指定的命令／程序、預期結果、測試資料指紋。
恢復失敗可見、部分影響有處置、還原或冪等重試已實測。檢查點、還原識別、重試鍵、升級處理負責人。
判斷不支援、衝突、遺漏、權利與限制留給人處置。審查者問題、決策紀錄、法務停止點。

不得過度概括：若證據只覆蓋一種來源版面、單一本機測試資料或特定失敗，契約就明列限制；不得把一次成功改寫成「任何知識庫都可維護」，也不得把本機復原推論成正式環境就緒。

Positive fixture / disconfirming fixture:
Change / recertification / retirement triggers:
  1. 正例重播：用已證明測試資料重跑契約，結果應對上同一組原始來源差異、有界寫入集合與判定依據。
  2. 反證重播：移除定位資訊、改成未授權路徑、破壞基準或製造重複重試，確認契約在變更或外部影響前停止。
  3. 恢復重播：中斷一次有界執行，確認檢查點、部分影響紀錄與還原／重試能重建預期狀態。
  4. 範圍比較：若重播需要新增輸入、權限、判斷或輸出，先修契約與重新證明，不把缺口藏進套件指示。
契約驗收檢查清單
可見成果：一份由008-0008維護證據萃取，清楚分開不變條件／參數／權限／判定依據／復原／人工判斷的具版本維護契約。
可觀察回饋：另一位操作者只依契約就能在正向測試資料重現有界維護，並在缺來源脈絡、越界寫入、錯誤修訂版或重複重試時，於變更前得到可解釋的安全停止點。

既有維護成功過，但新套件想順便允許同步遠端知識庫。契約應怎麼處理？

封裝不授予新權限；原證明只覆蓋可復原的本機維護，遠端副作用必須另立範圍、核准、收據與復原證據。

返回／合法停止／續行：維護證據、原始來源識別、來源脈絡、權限、判定依據、失敗／復原或審查者處置任一不可重建時，保存草稿，精確回003-0007／003-0005、008-0008、008-0005或008-0007補缺口。契約能在正反例中重跑後，帶著它回 009-0003，依受眾與執行需求 只選一種 套件分支，完成後再銜接009-0008；不要補做所有套件。LLM Wiki總整線索 只供保存跨路線沿革，可選且不是進入、完成或組織採用前提。

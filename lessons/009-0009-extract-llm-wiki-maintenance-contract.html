Phase 9 · Standardize · 009-0009 · Conditional contract branch

把一次已證明的 LLM Wiki maintenance 萃取成可重跑 contract

Entry／elective：Mission 已選擇 standardize LLM Wiki maintenance，而且能帶入 008-0008 的 exact maintenance evidence，以及後續 008-0005 completion proof 與 008-0007 operating closeout。若只有 raw sources、第一次生成的 wiki slice、未 review 的操作筆記，或只覺得流程「應該可重用」，不進本 branch；回原路補 proof。

1. 先固定 proof identity，不從記憶重寫流程

Maintenance run / operating closeout IDs:
Existing wiki revision / maintained revision:
Raw source pack / stable source IDs / rights record:
Claim-provenance and review-log locations:
Declared fixture / environment / restore point:
Exact completion oracle / pass result:
Failure / recovery / retry evidence:
Reviewer disposition / unresolved limitations:
External actions: none | separately approved receipt

Proof prerequisite：Contract 只能萃取 evidence 已出現且被 reviewer disposition 的行為。Raw source pack、stable source IDs 與 claim-level provenance 繼續是 source of truth；wiki pages、summary、links、exports、contract 與 package 都是 derived artifacts，不得互相循環背書。

2. 分開 invariant 與每次執行的 parameters

契約欄位保留為 invariant每次 rerun 明確給 parameter
Inputs只接受具 stable IDs、rights 與 locator 的 raw-source set。Source versions、change trigger、affected topic cluster、baseline revision。
Output只修改 bounded local fixture；每個 changed claim 可回到 raw locator。Output path、expected pages／links／exports、run identity。
AuthorityLeast read／write scope、preview-first、agent 不自我批准 external action。Allowed paths、operator、approval receipt；shared／remote target 預設不允許。
OracleSource trace、link／export、blank／duplicate、scope equality 與 review-log checks。Exact command／procedure、expected result、fixture fingerprints。
RecoveryFailure 可見、partial effects 有 disposition、restore 或 idempotent retry 已實測。Checkpoint、restore identity、retry key、escalation owner。
JudgmentUnsupported、conflict、omission、rights 與 limitations 留給人 disposition。Reviewer question、decision record、legal stop。

Do not generalize：若 evidence 只覆蓋一種 source layout、單一 local fixture 或特定 failure，contract 就明列限制；不得把一次成功改寫成「任何知識庫都可維護」，也不得把 local recovery 推論成 production readiness。

3. 寫出對錯誤輸入會拒絕的 maintenance contract

Contract ID / version / owner:
Originating maintenance evidence / exact revisions:
Promise / audience / explicit non-goals:
Invariant source-of-truth and provenance rules:
Parameters / accepted input schema:
Read authority / write authority / approval boundary:
Preview / deterministic completion oracle:
Expected artifact and evidence outputs:
Known failure classes / safe-stop behavior:
Restore / retry / escalation procedure:
Human judgments that package must not automate:
Positive fixture / disconfirming fixture:
Change / recertification / retirement triggers:
  1. Positive replay：用已證明 fixture 重跑 contract，結果應對上同一組 raw-source delta、bounded write set 與 oracle。
  2. Disconfirming replay：移除 locator、改成未授權 path、破壞 baseline 或製造 duplicate retry，確認 contract 在 mutation 或 external effect 前停止。
  3. Recovery replay：中斷一次 bounded run，確認 checkpoint、partial-effect record 與 restore／retry 能重建預期狀態。
  4. Scope comparison：若 replay 需要新增 inputs、authority、judgment 或 output，先修 contract 與重新證明，不把 gap 藏進 package instructions。
Contract acceptance checklist
Tangible win：一份由 008-0008 maintenance evidence 萃取，清楚分開 invariant／parameters／authority／oracle／recovery／human judgment 的 versioned maintenance contract。
Observable feedback：另一位 operator 只依 contract 能在 positive fixture 重現 bounded maintenance，並在缺 provenance、越界 write、錯誤 revision 或 duplicate retry 時於 mutation 前得到可解釋的 safe stop。

既有 maintenance 成功過，但新 package 想順便允許同步 remote wiki。Contract 應怎麼處理？

Packaging 不授予新 authority；原 proof 只覆蓋 recoverable local maintenance，remote side effect 必須另立 scope、approval、receipt 與 recovery evidence。

Return／legal stop／continuation：Maintenance evidence、raw-source identity、provenance、authority、oracle、failure／recovery 或 reviewer disposition 任一不可重建時，保存 draft，精確回 003-0007／003-0005、008-0008、008-0005 或 008-0007 補缺口。Contract 能在正反例中重跑後，帶著它回 009-0003，依 audience 與 execution need 只選一種 package branch，完成後再 rejoin 009-0008；不要補做所有 package。LLM Wiki capstone thread 只供保存跨 route lineage，可選且不是進入、完成或組織採用前提。

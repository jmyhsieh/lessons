Phase 10 · 驗證 · 010-0003

建立代表性 success case set

進入條件：Claim 與 comparison frame 已在 run 前固定。本課只定義並執行代表正常用途的 success cases，保留 raw observations；failure、越界與 adversarial inputs 留到 010-0004，不把「預期拒絕」混成低分成功案例。

1. 選 cases，不挑展示品

案例角色要代表選擇證據
典型案例目標 audience 最常見的 bounded task shape來源、頻率假設、fixture identity
變化案例仍在 promise 內的 input size、format 或 ambiguity為何 material，不能只換名字
判斷需要人處置 unknown／conflict 的正常情境預期 agent 留下 decision point

  1. 凍結 case set 與 fixture fingerprints，避免看到第一個結果後替換難題。
  2. 依 frame 分別執行 candidate 與 comparator；每個 run 保存 exact identity。
  3. 先寫 raw observation，再套 rubric；unknown 不填成零或平均值。
  4. 只描述 declared cases 支持的範圍，不因三個成功例宣稱普遍有效。
可見成果：一組有 representation rationale、固定 fixtures、candidate／comparator raw observations 與後置 scoring 的 success-case evidence。
可觀察回饋：Reviewer 可重跑同一 case set，查出 case 是否只挑容易展示的例子，並把每個 score 回連到原始 artifact 或 event。

第一個 variation case 失敗，正確做法是？

Case set 在 run 前固定；意外 failure 是 evidence，不能靠重新分類或刪除維持漂亮結果。

合法停止／返回／續行：Case 沒有 representation rationale、fixture 可變、candidate／comparator 條件不同、raw evidence 缺失或 scoring 早於 observation 時停止，回 010-0002 修 frame。Success set 可抽查後，續到 010-0004；此時尚不能做 keep／change／retire judgment。

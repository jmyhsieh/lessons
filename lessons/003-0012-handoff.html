用 /handoff 做跨 session 交接

目標：學會在 pipeline 中途分支、session 收工或 context 變髒時，用 /handoff 產出一份「冷啟動接力文件」，讓同一台機器上的全新 session 不用重講一遍脈絡；跨人或跨機器時，再加上明確、安全的傳送步驟。

本課只做：把下一個人或 session 需要的脈絡打包。
先不要做：把 handoff 當成完整 report 或長期文件庫。

它解決的問題

Phase 1 第 12 課 教過：context 塞滿就砍掉重練、乾淨 session 贏過污染的長對話。但「重練」有個成本 — 脈絡跟著消失。handoff 就是在按下重練之前，先把值錢的脈絡壓縮成文件帶走：

長對話（context 漸髒）→ /handoff 今天到此，明天繼續做 X
                              ↓
                  交接文件（存到 OS temp 目錄）
                              ↓
新 session 開場：「讀這份交接文件，繼續」 → 乾淨 context ＋完整脈絡

四個設計細節（SKILL.md 原文）

設計為什麼
存到 OS temp 目錄，不放 workspace交接文件是消耗品，不該污染 repo（同 Phase 3 第 11 課報告的做法）
不重複既有 artifacts — spec、ADR、tickets、commits 用路徑引用單一事實來源：脈絡的正本在文件制度裡，handoff 只記「正本沒有的東西」（當下的決策過程、卡住的點、下一步）
內建 suggested skills 區塊告訴下一個 agent 該用哪些 skill 繼續（例：「接下來跑 /implement 實作 ticket 3」）
產出時遮蔽敏感資訊（API key、密碼、個資）這是 skill 的必要指令，不是零漏網保證；交接前仍要自己掃一眼
參數很重要：/handoff 下一個 session 要做 X — 它會針對 X 裁剪內容。「為了繼續 debug」和「為了寫文件」需要的脈絡完全不同，有參數的交接文件精準得多。

什麼時候用（四個真實 repo 場景）

  • 中途分支：主線把一個問題交給全新 prototype session，完成後再用另一份 handoff 把答案帶回主線。
  • 收工交接：下班前 /handoff 明天繼續實作 ticket 5，明早新 session 直接接力。
  • 糾正兩次還不對（Phase 1 第 12 課的砍掉重練訊號）：先 handoff 再重開 — 把「學到的教訓」帶進新 session 的第一句 prompt。
  • 跨人交接：你 grill 到一半要請假，同事接手 — 先把交接文件經授權的安全管道送到對方能讀的路徑，再由他的 agent 冷啟動。

與相鄰機制的分工：/compact 是同一個 session 內壓縮歷史；claude -c 是接續同一個對話；handoff 則做一份本機 temp 文件，供新的 session 讀取。它的文體可以服務跨人或跨機器交接，但本機 temp 路徑不會自動同步：必須先經授權管道安全傳送，並在目的端改用實際可讀路徑。

跨機器邊界：不要把 /tmp/... 或 $TMPDIR/... 路徑直接貼給另一台機器。先重查 redaction，再用組織核准的安全管道傳送；確認接手方可讀後，依資料保留政策清理兩端暫存副本。

實作步驟（做完打勾）

最好是有點歷史的（grill 到一半、修 bug 修到一半都行）。

/handoff 下一個 session 要 [具體說明接下來做什麼]

打開 temp 目錄的文件檢查：(a) 有沒有重複貼 spec/ticket 的內容（應該是引用路徑）？(b) suggested skills 給對了嗎？(c) 自己掃一遍有沒有漏網的敏感資訊。

先在同一台機器開全新 session：「讀 [文件路徑]，繼續這個工作」。觀察它需不需要再問你本該在文件裡的事 — 需要的話，那就是交接文件的漏洞，回頭補。跨機器實測時，必須改用安全傳送後的目的端路徑。

給自己立一條規則：長 session 收工或 pipeline 中途換 session，先 handoff。一週後回顧：接力的啟動時間少了多少？

🎉 你的工作脈絡現在可以讓本機新 session 冷啟動；跨人或跨機器則有明確傳送邊界。回對話視窗回報：冷啟動實測有沒有露餡？

Phase 3 驗收 rubric

不要用「12 課都看過」當結業證據。選一條真實路線，交出可冷啟動的 artifact chain：

  • 新需求：對齊結論 → spec／ticket（若需要）→ implementation evidence → code review → handoff。
  • 外部回報：durable issue → triage state → diagnosis evidence → regression verification → handoff。
  • 維護改善：architecture finding → 被選定的 seam → spec／implementation evidence → handoff。
  • 巨大模糊 effort：wayfinder map → linked decisions → spec → tickets → implementation evidence → handoff。

AI 老師能只靠這些 artifacts 說出「做了什麼、怎麼驗證、還剩什麼」，才建立 learning record。

觀念檢查（憑記憶作答）

1. handoff 文件裡發現它把整份 spec 內容貼了進來，該怎麼處理？

skill 原文：不重複既有 artifacts，用路徑引用。複製會製造兩份會分岔的事實；交接文件的價值在「正本沒有的脈絡」（決策過程、卡點、下一步）。

2. /compact 和 /handoff 的本質差異是？

compact 服務「這個對話繼續」；handoff 服務「新對話從文件冷啟動」。handoff 產生的是本機 temp 檔，不會自動傳到另一台機器。

3.（複習 Phase 1 第 12 課）糾正它兩次同一問題仍失敗，加上本課工具後的最佳流程是？

（間隔複習）Phase 1 第 12 課 說砍掉重練；本課補上「怎麼帶走學到的東西」— handoff 把失敗嘗試中值錢的部分（什麼不行、為什麼）變成新 session 的起點。compact 留在原對話，污染還在。

/handoff — 把對話打包給下一個 agent

目標：學會在 session 收工或 context 變髒時，用 /handoff 產出一份「冷啟動接力文件」，讓明天的你（或同事、或全新 session）不用重講一遍脈絡。這是 001-12 context 收尾的延伸。

它解決的問題

001-12 教過：context 塞滿就砍掉重練、乾淨 session 贏過污染的長對話。但「重練」有個成本 — 脈絡跟著消失。handoff 就是在按下重練之前，先把值錢的脈絡壓縮成文件帶走：

長對話（context 漸髒）→ /handoff 今天到此，明天繼續做 X
                              ↓
                  交接文件（存到 OS temp 目錄）
                              ↓
新 session 開場：「讀這份交接文件，繼續」 → 乾淨 context ＋完整脈絡

四個設計細節（SKILL.md 原文）

設計為什麼
存到 OS temp 目錄，不放 workspace交接文件是消耗品，不該污染 repo（同第 21 課報告的做法）
不重複既有 artifacts — PRD、ADR、issues、commits 用路徑引用單一事實來源：脈絡的正本在文件制度裡，handoff 只記「正本沒有的東西」（當下的決策過程、卡住的點、下一步）
內建 suggested skills 區塊告訴下一個 agent 該用哪些 skill 繼續（例：「接下來跑 /tdd 實作 issue #3」）
自動遮蔽敏感資訊（API key、密碼、個資）temp 目錄的檔案可能被其他工具讀到 — 但別全信自動遮蔽，交接前自己掃一眼
參數很重要：/handoff 下一個 session 要做 X — 它會針對 X 裁剪內容。「為了繼續 debug」和「為了寫文件」需要的脈絡完全不同，有參數的交接文件精準得多。

什麼時候用（三個真實 repo 場景）

  • 收工交接：下班前 /handoff 明天繼續實作 issue #5，明早新 session 直接接力。
  • 糾正兩次還不對（001-12 的砍掉重練訊號）：先 handoff 再重開 — 把「學到的教訓」帶進新 session 的第一句 prompt。
  • 跨人交接：你 grill 到一半要請假，同事接手 — 交接文件＋CONTEXT.md 讓他的 agent 冷啟動。

與相鄰機制的分工：/compact 是同一個 session 內壓縮歷史；claude -c 是接續同一個對話；handoff 是做一份可攜帶的文件，跨 session、跨機器、跨人都能用 — 也是第 23 課 agent brief 的近親（都是「讓陌生 agent 冷啟動」的文體）。

實作步驟（做完打勾）

最好是有點歷史的（grill 到一半、修 bug 修到一半都行）。

/handoff 下一個 session 要 [具體說明接下來做什麼]

打開 temp 目錄的文件檢查：(a) 有沒有重複貼 PRD/issue 的內容（應該是引用路徑）？(b) suggested skills 給對了嗎？(c) 自己掃一遍有沒有漏網的敏感資訊。

開全新 session：「讀 [文件路徑]，繼續這個工作」。觀察它需不需要再問你本該在文件裡的事 — 需要的話，那就是交接文件的漏洞，回頭補。

給自己立一條規則：長 session 收工必 handoff。一週後回顧：早上接力的啟動時間少了多少？

🎉 你的工作脈絡現在可以跨 session、跨日、跨人存活了。回對話視窗回報：冷啟動實測有沒有露餡？

觀念檢查（憑記憶作答）

1. handoff 文件裡發現它把整份 PRD 內容貼了進來，該怎麼處理？

skill 原文：不重複既有 artifacts，用路徑引用。複製會製造兩份會分岔的事實；交接文件的價值在「正本沒有的脈絡」（決策過程、卡點、下一步）。

2. /compact 和 /handoff 的本質差異是？

compact 救的是「這個對話還要繼續」；handoff 服務的是「下一個對話（或下一個人）」— 跨 session、跨機器、跨人。

3.（複習 001-12）糾正它兩次同一問題仍失敗，加上本課工具後的最佳流程是？

（間隔複習）001-12 說砍掉重練；本課補上「怎麼帶走學到的東西」— handoff 把失敗嘗試中值錢的部分（什麼不行、為什麼）變成新 session 的起點。compact 留在原對話，污染還在。

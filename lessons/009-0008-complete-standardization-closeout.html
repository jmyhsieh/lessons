Phase 9 · 標準化 · 009-0008 · Route closeout

把一個通過 rerun 的 package 收斂成可維護 closeout

進入條件：帶入 009-0003 的 selection record，以及 009-0004、009-0005、009-0006、009-0007 其中恰好一條 conditional branch 的 exact package、fresh-context evidence 與 owner disposition。Closeout 保留被選中的 package identity、scope、authority、validation 與 reuse judgment；它不要求補做其他三種 package，也不把 selector 變成 package ladder。

單一分支驗收規則：Selection record 的 selected package 必須與唯一 branch evidence 的 package identity／digest 完全一致。若 closeout 收到零條或多於一條 branch、source of truth 分裂，或另一種格式有獨立 consumer requirement，停止並回 009-0003；不要在本頁新 author 第二個 package。

3. 讓證據對錯誤 package 會失敗

  1. 正例：在 fresh context 只提供 exact package 與 declared fixture，確認 promised output、run record 或 check 與 expected evidence 一致。
  2. 反例：使用 near-miss、缺 prerequisite、越界 scope 或無 authority fixture，確認 package 依 branch contract 拒絕、non-zero 或 safe stop。
  3. 恢復：保留 failure identity、partial effects 與 recovery result；重跑不得掩蓋 skipped record、擴大 retry 或產生未批准 external effect。
  4. Repo Review 檢查：若 selected package 產生任何 repository diff，記錄 fixed point 與 final candidate SHA，附 006-0008 的兩軸 Review；finding 修正後必須以新 SHA 全部重跑。

4. 做 learner reuse judgment

處置何時成立Closeout 後動作
reuse同一 digest 的正反例與 recovery 都符合 contract，limitations 可接受。保存 closeout；未來 task 仍重新確認 inputs、authority 與 environment。
reviseFresh context 暴露 instruction、trigger、scope、interface 或 recovery gap。回 contract／selected branch 修訂，產生新 version／digest，重跑受影響 evidence；repo diff 重新 Review。
retire來源、dependency、risk、owner 或 workflow promise 已無法安全維持。保留 retirement reason 與 successor／no-successor，不讓舊 package 繼續被選用。

重新開啟條件：Contract promise、audience、scope、owner、dependency、permission、source of truth、package bytes、completion oracle、failure semantics 或 Review candidate 任一改變，都使既有 closeout 不足以覆蓋新版本。新 consumer 或新組織情境也必須重新選擇，不可用 adoption 假設延伸 proof。

可見成果：一份綁定單一 selected package version／digest、accountable owner、permissions、fresh-context 正反例、recovery、必要 Review 與 learner disposition 的 Standardization closeout。
可觀察回饋：另一位 reviewer 能只靠 closeout 找到 exact package 與證據，對錯誤 digest、超 scope request、缺 authority、negative fixture 或過期 Review 明確拒絕，並重現 learner 為何 reuse、revise 或 retire。

Reusable Skill 的 positive、near-miss 與 recovery 都通過，但 package 改了一行 instruction，digest 已不同。可以沿用原 closeout 嗎？

Closeout 綁定 exact package identity；任何 package mutation 都觸發 reopen。補做其他 branch 不會恢復失效 evidence。

宣稱上限：Closeout 證明的是一個 bounded package 在 declared fixtures 中忠實承載已證明 workflow。它不證明 workflow 本身、授予 authority、宣稱 production readiness、代表 organization adoption，或要求四種 branch 全部完成；後續 evaluation 也必須另立 claim 與 evidence。

合法停止／返回／續行：若 package identity／owner／scope／authority 不完整、branch evidence 不等於一條、正例與反例不是同一 digest、failure 無 recovery、learner 未做 disposition，或 repo diff 缺 final immutable Review，保存 draft 並回 009-0001、009-0002、009-0003、唯一 selected branch，或 006-0008 的精確缺口。只有 checklist 全部可重建且 disposition 已記錄，才在本頁合法停止並回 catalog；需要比較品質或決定是否繼續投資時，可另從 010-0001-set-workflow-evaluation-claim.html 開始，這不是自動 continuation，也不代表 Phase 9、Phase 10、production 或 course complete。

請一個人完成一個任務

今天只做一件事：讓 Claude Code 幫你準備一個中立任務句，再由真人不受提示地試用設計。

不要教他怎麼按：只說目標，例如「請完成活動報名」，然後觀察他在哪裡停住。

做一次五分鐘測試

只測最重要的一條路徑，例如「請完成活動報名」；刪掉任何暗示按鈕位置或操作順序的字。

請他邊做邊說想法；除非完全無法繼續，否則先不要提示。

只提供真人做了什麼與卡在哪裡，請它提出一個最小設計修正；不要讓模型把自己的看法冒充使用者回饋。

完成：你已有一則真實使用觀察，不再只依靠自己或 Claude 的看法。

觀念檢查

測試時最適合對使用者說什麼？

只說任務目標，才能觀察介面本身是否幫助使用者找到路徑。

帶走這個就好

入門先測一個人、一個任務、一個卡點。完整 responsive 與 accessibility audit 留到進階驗證。

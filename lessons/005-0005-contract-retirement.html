Phase 5 · 第 05 課 · 約 25 分鐘 · Contract cleanup

整理、合併與停用 repo 規範

目標：定期清理 repo contract，保留仍有效的規範，合併重複內容，退役過時或造成負擔的規則。這是 Phase 5 的收尾課。

本課只做：產出 contract cleanup note。
先不要做：沒有 evidence 就直接刪掉或保留規範。

規範也有維護成本

Repo contract 的價值在於讓下一個任務更容易交付；如果它不再被使用、已被 template 或 gate 取代、或每次都造成例外，它就會變成維護成本。Contract cleanup 的目的不是刪文件，而是讓規範集合保持可讀、可信、可執行。

清理時要保留 evidence：為什麼 keep、merge、retire，放在哪裡，下一次何時再檢查。這讓後續 agent 不必重新推測歷史決策。

Effort policy 也要清理

如果某條 contract 曾允許 max 或要求 xhigh，cleanup 時要確認它是否仍必要。任務已穩定、template/gate 已補齊、或同類任務在 high 就能完成時，應把例外降回 high，避免高成本設定變成預設習慣。

觀察處理方式
最近三次同類任務都在 high 通過。移除 xhigh/max 例外。
max 沒有產生更好 evidence。降回 high，保留 reason。
xhigh 仍常 blocked。修 input/gate，而不是升到 max。

Cleanup decisions

Decision何時使用處理方式
Keep近期仍被使用，且 evidence 支持有效。保留原位，設定下一次 review 時點。
Merge兩條 contract 重複或互相依賴。合成一條更短規則，移除重複段落。
Move位置錯，導致正確的人看不到。搬到 issue template、PR template、CLAUDE.md、reference 或 gate。
Retire過時、無 evidence、常被跳過，或已被自動化取代。刪除或標註 deprecated，留下 retirement note。
判斷規則：如果一條 contract 不能說明最近一次有效 evidence，也沒有下一次 review 時點，就應該檢查是否合併、移動或退役。

Retirement note 範例

contractCleanup:
  contract: reference/old-handoff-checklist.html
  decision: retire
  reason: replaced by PR template evidence fields and runner gate
  evidence: last 5 handoffs did not reference this checklist
  replacement: .github/PULL_REQUEST_TEMPLATE.md
  rollback: restore if reviewers ask for manual handoff checklist twice in 30 days

實作步驟（做完打勾）

包含 CLAUDE.md、AGENTS.md、reference checklist、issue/PR template、hooks、runner gates。先列，不先改。

找 usage note、effectiveness log、template 使用紀錄或 gate result。若有 effort 例外，也找最近一次使用 xhigh/max 的 reason 與 outcome。找不到 evidence 就標記為 review needed。

一次清理少量 contract。避免把清理任務變成大型重構。

每個決策都要有 reason、evidence、replacement 或 rollback。刪除規範也要能解釋。

如果 contract 被移動或退役，要同步更新 reference index、toc 或 repo guide，避免留下失效連結。

你已完成 contract cleanup note。回對話視窗貼上 inventory 與決策，請 AI 老師檢查是否有誤刪或漏掉替代位置。

觀念檢查（憑記憶作答）

1. Contract cleanup 的主要目的？

清理不是為了刪文件，而是讓 repo contract 保持可讀、可信、可執行。

2. 一條 contract 已被 gate 完全取代，通常應該？

被自動化取代後，舊 checklist 可能只需保留說明或退役，避免多套規則互相衝突。

3. 清理 contract 前，應先？

先找 usage note、effectiveness log 或 gate result，才能知道該 keep、merge、move 還是 retire。

4. 同類任務已能用 high 通過時，應該？

任務穩定後，高 effort 例外應退場，否則成本規則會慢慢變成不必要的預設。

Phase 5 收束

完成 Phase 5 第 05 課後，你有一個完整的 harness operations loop：repo contract → review loop → effectiveness evidence → template promotion → hook/gate promotion → cleanup。下一次遇到新工作流，不必直接平台化；先用這條迴圈逐步證明它值得維護。

用 worktree 隔離一條 parallel edit line

任務：在 disposable Git fixture 開一個 Claude Code worktree，證明兩個工作目錄的檔案改動不互踩，再安全清理。

Worktree 隔離Worktree 不隔離
Working directory、branch、tracked／untracked file changes。Git object database、remote、credentials、network、database、deploy target 與其他 external side effects。
適合兩條可能改檔的獨立 local tasks。不是 permission sandbox，也不會自動解決 branch merge conflict。

建立、觀察、清理

  1. 只在 clean、可丟棄的 Git fixture 執行；先保存 git status --short 與 git worktree list。
  2. 用目前 claude --help 確認 --worktree，再執行 claude --worktree toolbox-isolation。不要重用現有 branch 名稱。
  3. 在新 session 只建立一個 fixture marker；回原工作目錄確認 marker 不存在，再用 git worktree list 比對兩個 path／branch。
  4. 記錄新 worktree 是否缺少 gitignored config 或 dependencies；不要為了方便把 secret 改成 tracked file。
  5. 退出 session。清理前檢查該 worktree 的 status、untracked files 與 commits；只有確認無需保留的工作後才移除，最後再跑 git worktree list。
Tangible win：一張 worktree isolation record，含 before／during／after inventory。
Observable feedback：Marker 只出現在新 worktree；兩個 branch/path 可辨識；清理後 inventory 回到 baseline，沒有遺失未保存工作。

兩個 worktrees 同時指向同一個 staging database，是否已被安全隔離？

Worktree 解決 local filesystem／branch collision；external systems、credentials 與 side effects 仍是共享風險。

Legal stop／return：Fixture 不乾淨、branch/path 已存在、兩條任務會碰同一 external resource、或無法判斷 worktree 是否有未保存工作時，保留現況並停止，不使用 --force 清理。把 isolation evidence 寫回 Return notebook，記為 Lesson practiced，返回 Targeted-remediation return point。

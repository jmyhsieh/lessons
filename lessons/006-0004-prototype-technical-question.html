用可丟棄 prototype 回答一個問題

Conditional entry：alignment record 已經只剩一個需要 runnable evidence 的 UI 或 logic 問題。Prototype 的形狀由問題決定；它不是 production foundation。

Question this prototype must answer:
LOGIC or UI branch:
Minimal states / interactions:
Evidence to observe:
Timebox and throwaway location:
Result: supported / rejected / uncertain
Spec decision changed:
  1. 用 handoff 把問題、constraints 與 evidence criteria 帶到乾淨 throwaway context。
  2. 只做能暴露答案的最小 states 與 interaction，不補 auth、persistence 或 production polish，除非它們正是問題。
  3. 由真實操作者跑邊界案例；模型自評不算 observable feedback。
  4. 把答案、failed cases 與對 spec 的影響帶回主線；prototype code 不 merge。
Tangible win：一個能回答單一問題的 throwaway prototype 與 decision note。
Observable feedback：操作者能重跑指定 scenario，看到 supported、rejected 或 uncertain 結果，並在 spec 中找到對應決策。

Prototype 回答完問題後，下一步是？

Prototype 的產物是答案；production delivery 需要另行 spec、tests 與 review。

Return／legal stop／continuation：問題不是單一可觀察問題、需要真實 production data、或無法隔離權限時停止並回 alignment。答案足夠後，把 decision note 帶回 006-0005；不要留在 prototype branch。

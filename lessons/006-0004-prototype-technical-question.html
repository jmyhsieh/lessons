第 6 階段 · 建置 · 006-0004 · Conditional 原型

用可丟棄原型回答一個問題

條件式進入：對齊紀錄 已經只剩一個需要可執行 evidence 的 UI 或邏輯問題。原型 的形狀由問題決定；它不是正式環境基礎。

Question this prototype must answer:
LOGIC or UI branch:
Minimal states / interactions:
Evidence to observe:
Timebox and throwaway location:
Result: supported / rejected / uncertain
Spec decision changed:
  1. 用交接把問題、限制與 evidence 準則帶到乾淨可拋棄脈絡。
  2. 只做能暴露答案的最小狀態與互動，不補驗證、持久化或正式環境潤飾，除非它們正是問題。
  3. 由真實操作者跑邊界案例；模型自評不算 observable feedback。
  4. 把答案、失敗案例與對規格的影響帶回主線；原型程式碼不合併。
具體成果：一個能回答單一問題的可拋棄原型與決策 筆記。
可觀察回饋：操作者能重跑指定情境，看到 受支援、退回或 不確定 結果，並在規格中找到對應決策。

原型 回答完問題後，下一步是？

原型 的產物是答案；正式環境交付需要另行規格、測試與 review。

返回／合法停止／續行：問題不是單一可觀察問題、需要真實正式環境資料、或無法隔離權限時停止並回對齊。答案足夠後，把決策 筆記 帶回 006-0005；不要留在原型分支。

Lesson 0001 · 約 10 分鐘

三個 Claude，三種工作流

任務：能對任何一項工作，正確判斷該交給 Claude、Cowork 還是 Claude Code — 這是你在正式專案上使用 Claude Code 之前的第一步。

核心觀念：差別不在「聰明程度」，在「能碰到什麼」

三個產品底層是同一系列模型。真正的差異是權限與工作環境：它能讀取什麼、能改動什麼、在哪裡執行。

Claude（claude.ai 網頁 / App）

對話助理 — 你貼內容進去，它回答出來。

碰不到你的檔案。適合：問問題、寫草稿、分析你貼上的程式碼片段、腦力激盪。一問一答的回合制。

Claude Cowork

知識工作代理 — 在你授權的資料夾裡完成多步驟任務。

桌面 App 上執行，能讀、編輯、建立你指定資料夾中的檔案。適合：整理文件、研究彙整、產出報告與簡報。你描述成果，離開，回來收成品。對象是「文件與檔案」，不是程式碼 repo。 （官方產品頁）

Claude Code

軟體工程代理 — 在 git repo 裡讀程式碼、改檔案、跑指令、開 PR。

可在終端機、VS Code/JetBrains、桌面 App、瀏覽器使用。理解整個 codebase，能跨多檔案修改、執行測試驗證、操作 git。這是你要在工作 repo 上用的工具。 （官方文件）

📄 已為你整理成一頁速查表，可列印放手邊。

練習：你來判斷

不要回頭看上面 — 先憑記憶作答（提取練習才能建立長期記憶）。

1. 「把專案裡所有過時的 API 呼叫改成新版，並跑測試確認沒壞。」

需要跨檔案修改 repo 程式碼並執行測試 → Claude Code。

2. 「把這個資料夾裡 30 份會議記錄整理成一份季度總結文件。」

多步驟檔案處理、產出文件、非程式碼 → Cowork。

3. 「這段 error message 是什麼意思？大概該往哪個方向查？」

貼上內容、得到解釋即可，不需動到檔案 → Claude 就夠了。若要它直接在 repo 裡追出根因並修掉，才升級到 Claude Code。

4. 「找出這個 bug 在 codebase 裡的根本原因並修好它。」

要在 repo 內追蹤、修改、驗證 → Claude Code。

讀懂 current specs 與 active changes

本課成果：一張 OpenSpec workspace 地圖，分清目前已成立的行為、正在提議的變更與封存紀錄。

目錄代表不同時間狀態：openspec/specs/ 是目前行為的規格正本；openspec/changes/<name>/ 是尚未封存的提議，不應被當成已上線功能。

畫出目前狀態

位置你在讀什麼
openspec/specs/Current specs：已接受、目前應成立的系統行為。
openspec/changes/<name>/Active change：proposal、delta specs、design 與 tasks；內容仍可能被審查或改寫。
openspec/changes/archive/Archive：已完成變更的時間戳記錄，用來追查當時的意圖與差異。
openspec list
openspec list --specs

第一個命令列出 active changes；第二個列出目前 specs。若清單為空，照實記錄，不要為了讓目錄看起來完整而補文件。

openspec show <spec-or-change-name>

先確認顯示的是 current spec 還是 active change，再摘要它描述的行為、尚未完成的部分與下一個合理動作。

從下一次真的要改的行為著手，例如「登入失敗後顯示剩餘嘗試次數」。不要從「替整個既有系統補齊規格」開始。

觀念檢查

第一次把 OpenSpec 放進既有專案，適合從哪個範圍開始？

OpenSpec 對 brownfield 專案的建議是從正在發生的真實變更開始；全面回填容易寫出過時或無法驗證的規格。

關鍵判斷

Current spec 描述的是現在，active change 描述的是差異。讀者若無法分辨兩者，就還不能安全地進到實作。

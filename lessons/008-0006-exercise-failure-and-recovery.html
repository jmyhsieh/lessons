Phase 8 · 操作 · 008-0006 · Recovery evidence

刻意讓 fixture 失敗一次，證明 workflow 會恢復或安全停住

進入條件：已有一份 008-0005 completion proof、可重建的 fixture 與已實測 restore point。複製成功 fixture成獨立 failure-exercise copy，保留原 evidence 不動；本課只注入一個代表性且可控制的 local fault，不在 production、external service 或真實使用者資料上製造事故。

1. 選一個會考驗 recovery contract 的 fault

故障安全性：不要測真正寄送、push、deploy、刪 production data、付款或其他不可逆 action。若唯一「真實」failure 只能在 production 才出現，就改用 local simulator／fixture、tabletop，或誠實記錄未驗證；不可為了 closeout 增加風險。

3. 不把 rollback 寫成萬靈丹

有些外部 action 無法真正 rollback。對這類 workflow，先以 idempotency／dedupe 防止重複、以 approval stop 阻擋 target 漂移，並預先定義 compensation owner；若 compensation 也有風險，就保留 state 並 safe stop。Agent 不得因「大概可補救」而自行 retry 不可逆 action。

可見成果：一份由 controlled fault、decisive failure、bounded retry／idempotency、restore／rollback或 safe stop，以及 corrected oracle rerun 組成的 recovery record。
可觀察回饋：Observer 能看見 failure 前後 state、證明 retry 沒有 duplicate，並從同一 evidence 判斷 workflow 是恢復完成還是誠實停在可接手 checkpoint。

外部 API timeout，無法確認 action 是否已成功，正確 recovery 是？

Ambiguous outcome 是重複 side effect 高風險情境；必須先用 idempotency 或 authoritative receipt 判定，不能靠 retry 或 agent inference。

合法停止／返回／續行：無法安全注入 fault、failure 不 decisive、retry 造成 duplicate、restore／rollback 失敗、safe-stop state 無 owner、corrected oracle 不綠，或任何 production／external effect 被意外觸發時，保存 evidence 並停止；依問題回 authority、execution 或 completion lesson。Recovery record完整後，進 008-0007 整理 operating workflow closeout；單次恢復成功仍不代表 production reliability。

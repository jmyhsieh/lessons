用工作樹分開平行工作

本課成果：一張平行工作配置，說清楚每個工作樹（worktree）負責的分支與範圍。

本課只做：用工作樹分開平行工作區。
先不要做：在不懂 Git 狀態時同時開多條工作線。

工作樹解決什麼

Git 工作樹（worktree）是同一個程式庫中的另一個工作目錄：有自己的檔案與分支，共用同一份歷史。

機制隔離什麼適合
子代理對話脈絡調查、審查。
工作樹工作階段檔案修改同時做多個獨立任務。
桌面 App 的新工作階段會自動使用隔離工作區；CLI 可用 claude --worktree feature-auth。
工作樹是一份全新的檢出。如果每個工作階段都需要被 Git 忽略的 .env 或本機設定，可在程式庫根目錄建立 .worktreeinclude；它使用 .gitignore 語法，而且只會複製本來就被忽略的檔案。

實作步驟（做完打勾）

把 .claude/worktrees/ 加到 .gitignore。若需要複製本機設定，再審慎建立 .worktreeinclude，不要為了方便，把敏感資訊改成受 Git 追蹤的檔案。

一個做小功能、一個修小錯誤。確認兩邊各自有分支與變更。

兩邊都照既有流程：查看程式差異、驗證、提交、開 PR。

先結束對應工作階段，再用 git worktree list 找出路徑；確認工作樹沒有未提交變更、未追蹤檔案或未保留的提交後，執行 git worktree remove <path>，最後再跑一次 git worktree list 驗證已移除。Claude 建立的互動工作樹在退出時可能自動清理或詢問是否保留；-p --worktree 不會自動清理。不要用 --force 掩蓋不清楚的狀態。

完成條件：工作樹清單能對應分支與負責範圍，各工作樹狀態也已確認。

觀念檢查

1. 同時做功能 A 與錯誤修復 B，適合？

獨立任務需要檔案隔離，不只是對話脈絡隔離。

2. 新工作樹跑不起來，常見原因是？

工作樹是全新檢出，.env、node_modules 這類檔案通常要另外處理。

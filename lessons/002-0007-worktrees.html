用 worktree 分開平行工作

任務目標：理解 worktree 如何讓多個 Claude Code session 同時改不同分支而不互踩。

本課只做：用 worktree 分開平行工作區。
先不要做：在不懂 git 狀態時同時開多條工作線。

worktree 解決什麼

git worktree 是同一個 repo 的另一個工作目錄：自己的檔案、自己的分支、共用同一份歷史。

機制隔離什麼適合
subagentcontext調查、review。
worktree session檔案修改同時做多個獨立任務。
桌面 App 的新 session 會自動使用隔離工作區；CLI 可用 claude --worktree feature-auth。
Worktree 是 fresh checkout。若每個 session 都需要 gitignored 的 .env 或本機設定，可在 repo root 建立 .worktreeinclude；它使用 .gitignore syntax，而且只會複製本來就被忽略的檔案。

實作步驟（做完打勾）

把 .claude/worktrees/ 加到 .gitignore。若需要複製本機設定，再審慎建立 .worktreeinclude，不要把 secrets 改成 tracked files。

一個做小功能、一個修小 bug。確認兩邊各自有分支與變更。

兩邊都照既有流程：看 diff、驗證、commit、PR。

用 git worktree list 確認沒有不需要的 worktree。

🎉 完成！你已經能安全平行開多個 session。

觀念檢查

1. 同時做 feature A 與 bugfix B，適合？

獨立任務需要檔案隔離，不只是 context 隔離。

2. 新 worktree 跑不起來，常見原因是？

worktree 是新 checkout，.env、node_modules 這類通常要另處理。

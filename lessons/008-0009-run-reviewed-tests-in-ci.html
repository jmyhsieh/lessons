Phase 8 · 進階第 09 課 · 約 20 分鐘

讓 reviewed tests 在 CI 執行

今天只做一件事：請 Claude Code 依現有政策提出最小 CI 變更，讓已審查的 tests 成為可信 gate。

不要宣稱全部 UI 都被保護：CI 只證明設定的 projects、環境與 tests 在該次 run 的結果；人工 usability、完整 accessibility 與視覺品質仍需其他證據。

建立一張 CI proof card

請 Claude Code 檢查 CI workflows、支援 browsers、secrets、artifact policy 與既有 test commands，先回報最小方案，不要直接編輯。

只加入產品明確支援的 browser projects；安裝依賴、啟動 app、執行 tests 與失敗行為都要可見。Reports、traces 與 screenshots 可能含 token 或資料，需限制存取與保留期限。

先在本機用同一 command 通過，再確認 CI run 結果與 artifacts。Proof card 寫下 scope、command、projects、結果、artifact policy 與已知限制。

進階完成：你已有一張把 reviewed tests、真實 CI run 與限制連在一起的 CI proof card。

觀念檢查

對外說明 Playwright CI 結果時，可靠的做法是什麼？

可信說法要列出實際 tests、projects、run 與限制，並把可能含敏感資料的 artifacts 放在受控位置。

帶走這個就好

Claude Code 可以接線，Test Agents 可以擴充 tests；真正的交付完成線仍是被人審查過的 scope、run evidence 與誠實限制。

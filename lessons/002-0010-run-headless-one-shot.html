把一次成功的互動改寫成有界限的單次執行

任務：在可信、非敏感練習環境中，用 claude -p 執行一個唯讀任務，固定提示、工具、輸出、預算與完成證明。

非互動模式會跳過工作區信任對話框；因此只能從你已確認可信的目錄執行。它也可能載入專案／使用者脈絡；需要更小的脈絡時，先從目前 claude --help 理解 --bare 的取捨，不能假設無頭等於無設定。

執行一次，再用程式碼判斷

  1. 建立只有 fixture.txt 的可復原目錄，內容放一個可人工核對的非敏感事實。
  2. 先用 claude --help 確認本機旗標；依目前說明組合有界限的命令：
claude -p \
  --tools "Read" \
  --allowedTools "Read" \
  --permission-mode plan \
  --output-format json \
  --max-budget-usd 0.10 \
  --no-session-persistence \
  "Read fixture.txt and return only the recorded project code."
  1. 保存命令、CLI 版本、結束狀態、stdout／stderr、成本／執行時間中繼資料與是否觸發權限錯誤。
  2. 用確定性解析器檢查輸出格式與已知專案程式碼；不要讓另一個模型以「看起來正確」判斷完成。
  3. 再跑一次相同輸入，記錄結果是否穩定；這只證明有界限的練習環境，不代表正式環境自動化就緒。
具體成果：一份可重跑的唯讀無頭命令與執行紀錄。
可觀察回饋：程序在預算內結束、輸出可解析且命中已知事實、沒有寫入工具或工作階段持久性。

claude -p 能輸出 JSON，是否已足以放進 CI？

本機單次執行只證明本機執行契約；CI 是另一個外部執行與權限邊界。

合法停止／返回：目錄不可信、輸入含敏感資料、必要工具超出唯讀、旗標不在目前說明、無法設定成本上限或確定性判定基準時停止，不執行單次執行。把契約與證據寫回續作筆記本，記為 Lesson practiced，返回 Targeted-remediation return point；不要把本課當成 CI 部署。

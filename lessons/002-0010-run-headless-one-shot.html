把一次成功的互動改寫成 bounded one-shot

任務：在可信、非敏感 fixture 中，用 claude -p 執行一個 read-only task，固定 prompt、tools、output、budget 與 completion proof。

Non-interactive mode 會跳過 workspace trust dialog；因此只能從你已確認可信的 directory 執行。它也可能載入 project／user context；需要更小的 context 時，先從目前 claude --help 理解 --bare 的取捨，不能假設 headless 等於無設定。

執行一次，再用 code 判斷

  1. 建立只有 fixture.txt 的 recoverable directory，內容放一個可人工核對的非敏感 fact。
  2. 先用 claude --help 確認本機 flags；依目前 help 組合 bounded command：
claude -p \
  --tools "Read" \
  --allowedTools "Read" \
  --permission-mode plan \
  --output-format json \
  --max-budget-usd 0.10 \
  --no-session-persistence \
  "Read fixture.txt and return only the recorded project code."
  1. 保存 command、CLI version、exit status、stdout／stderr、cost／duration metadata 與是否觸發 permission error。
  2. 用 deterministic parser 檢查輸出格式與已知 project code；不要讓另一個模型以「看起來正確」判斷完成。
  3. 再跑一次相同 input，記錄結果是否穩定；這只證明 bounded fixture，不代表 production automation ready。
具體成果：一份可重跑的 read-only headless command 與 execution record。
可觀察回饋：Process 在 budget 內結束、輸出可解析且命中已知 fact、沒有 write tool 或 session persistence。

claude -p 能輸出 JSON，是否已足以放進 CI？

Local one-shot 只證明本機 execution contract；CI 是另一個外部執行與權限邊界。

合法停止／返回：Directory 不可信、input 含敏感資料、必要 tool 超出 read-only、flag 不在目前 help、無法設定 cost limit 或 deterministic oracle 時停止，不執行 one-shot。把 contract 與 evidence 寫回 Return notebook，記為 Lesson practiced，返回 Targeted-remediation return point；不要把本課當成 CI deployment。

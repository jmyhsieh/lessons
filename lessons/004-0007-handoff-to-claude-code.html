Phase 4 · 第 07 課 · 約 25 分鐘 · Handoff 練習

保留 design intent，handoff 給 Claude Code

目標：把設計來源、優先順序、狀態、responsive 規則、accessibility 與驗證證據一起交給 Claude Code；先 dry inspect，再授權最小範圍的實作。

本課只做：完成可追溯的 handoff bundle 與 read-only repo 對照。
先不要做：只丟一張 screenshot、讓 agent 猜 design intent，或連上工具後立刻盲寫整個 repo。

知識：Handoff 不只交付畫面

Bundle 欄位至少要包含
SourceClaude Design 專案連結、選定 revision、design system 來源
Intent使用者目標、資訊層級、關鍵互動、為何選這個方向
States正常、loading、empty、error、disabled 與完成狀態
Rulesresponsive 行為、元件／token 對應、accessibility 要求
Evidence已驗證內容、未解問題、已知限制與可接受差異
Scope本次最小切片、non-goals、完成條件與驗證方法
Design intent 是取捨的理由。像素描述告訴 Claude Code「長什麼樣」；intent 告訴它在 repo 限制下必須優先保住什麼，以及哪些細節可以調整。

知識：官方同步與連線路徑

依 Anthropic 的 Claude Design get-started 指南（本課核對日期：2026-07-14）：

  • 在 Claude Code 使用 /design-sync，將既有 design system 帶入 Claude Design 工作流。
  • Claude Design 的 Export 可選 handoff 到 local coding agent 或 Claude Code Web。
  • 若要從 Claude Code 連接 Claude Design，先加入官方 Design MCP，再以 /design-login 登入：
claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp

/design-login

這些 beta 指令與 availability 可能變動；若介面或指令不一致，以最新的 官方 get-started 為準。MCP 連線提供 design context，不代表你已授權改 repo。

知識：先 dry inspect，不盲寫

先以 read-only 方式檢查 handoff bundle 與目前 repo，不要改檔，
也不要執行會產生副作用的命令。請回報：
1. design 元件／token 對應到哪些既有檔案
2. 缺少或互相衝突的狀態與規則
3. 最小可實作切片與預計改動檔案
4. 可重跑的驗證命令與人工 browser checks
看到 mapping 才同意寫入。若 Claude Code 想新建 design system、重做相鄰頁面或改超出 bundle 的檔案，先停下來縮小 scope；不要把工具連線當成 blanket approval。

實作 checklist（做完打勾）

在 bundle 寫清楚專案、版本、採用理由、驗證紀錄與尚未解決的問題。不要只寫「照設計稿做」。

逐欄填完上方表格。若某個狀態尚未設計，明確標成 open question，不讓 Claude Code 自行猜成需求。

使用 Claude Design Export handoff；或在 Claude Code 依官方指南設定 Design MCP、登入並執行需要的 sync。不要混用未核對的舊指令。

請 Claude Code 對照 bundle、repo 與既有元件，回報 mapping、衝突、預計檔案及驗證方式。此步驟不改檔。

檢查預計 diff 是否只碰必要檔案、是否沿用 repo 慣例，然後才進入下一課的實作。

你的 handoff 已可被檢查，而不只可被觀看。把 dry-inspect mapping 貼回對話視窗，請 AI 老師找出仍在靠猜測的欄位。

觀念檢查（憑記憶作答）

1. 哪一項最能保住 design intent？

Intent 包含目標、優先級與取捨理由，讓工程限制出現時仍知道該保住什麼。

2. Design MCP 連線成功代表什麼？

連線提供 context 與工具能力，不會自動擴大 repo 寫入權限或任務 scope。

3. Handoff 後第一個安全動作是？

Dry inspect 先揭露 mapping、衝突、預計檔案與驗證方式，再決定是否授權寫入。

Phase 1 · 第 05 課 · 約 20 分鐘 · 實作課（桌面 App 優先）

讓 Claude Code 讀懂團隊規範（CLAUDE.md）

任務目標：在工作 repo 建立一份 CLAUDE.md，讓 Claude Code 每次 session 自動遵守你們的建置指令、程式風格與專案慣例 — 不用每次重講一遍。

本課只做：把團隊工作規範整理進 CLAUDE.md。
先不要做：把領域知識、issue 細節、一次性任務全塞進 CLAUDE.md。

它是什麼

每個 session 都從全新的 context 開始。CLAUDE.md 是放在 repo 根目錄的 markdown 檔，每次 session 開始時自動完整載入，等於團隊給 AI 的 onboarding 文件（官方文件）。判斷該不該寫進去的訊號：

  • 它第二次犯同一個錯
  • code review 抓到它本該知道的本專案慣例
  • 你發現自己每個 session 都在重打同一句說明

放哪裡、給誰看

位置範圍用途
./CLAUDE.md專案（隨 git 共享給全隊）建置/測試指令、架構、命名慣例
./CLAUDE.local.md專案 · 只有你（加進 .gitignore）個人沙箱網址、測試資料
~/.claude/CLAUDE.md你的所有專案個人偏好
正式專案提醒：./CLAUDE.md 會進版控、全隊共用 — 提交前讓同事 review，跟一般程式碼一樣走 PR。

寫得有效的三原則（官方建議）

  • 短：目標 200 行以內，越長遵守度越差。
  • 具體可驗證：「縮排用 2 空格」優於「格式要乾淨」；「commit 前跑 npm test」優於「記得測試」。
  • 不自相矛盾：兩條規則衝突時它會隨機挑一條。

注意：CLAUDE.md 是指引不是強制 — 它是 context，不是程式閘門。必須百分之百擋下的事（例如禁推 main）要用 hooks 或 permission 設定，之後的課會教。

什麼時候用 /init

/init 適合第一次進 repo 時產生 starter CLAUDE.md：它會分析 codebase，整理能推斷出的建置指令、測試方式與專案慣例。如果已經有 CLAUDE.md，它會提出改進建議，而不是直接覆蓋。把它當成「可審稿初稿」，不要當成團隊規範的最終版（官方文件）。

情境建議做法
第一次進 repo，還沒有 CLAUDE.md先用 /init 產生初稿，再人工審稿。
桌面 App 的 slash menu 沒有 /init用自然語言請它讀 repo 高層檔案並草擬。
要補團隊才知道的流程或禁忌手動補上，因為模型通常無法從 codebase 推斷。

實作步驟（做完打勾）

桌面 App：在工作 repo 的 session 裡，用自然語言請它先讀高層檔案，再產生或更新 CLAUDE.md。例如：

Read the repo at a high level and draft a concise CLAUDE.md.
Include build/test commands, code style, and project conventions.
Ask before editing the file.

slash command：在 prompt box 輸入 /，如果清單有 /init，可先用它產生 starter CLAUDE.md。沒有看到就用上面的自然語言做法。

初稿只包含它能從程式碼推斷的內容。加上只有你們團隊知道的：例如「新 API 一律走 src/api/handlers/」「不要動 legacy 目錄」「PR 標題格式」。記得套用三原則。

桌面 App：開新 session，問一個答案寫在 CLAUDE.md 裡的問題，看它答得對不對。若 / 清單有 /memory，也可用它查看或編輯已載入的 memory。

開分支、commit、開 PR 讓同事 review（複習 Phase 1 第 04 課的三道護欄）。

🎉 完成！你們 repo 現在有了 AI 的 onboarding 文件。之後每次它犯「本該知道」的錯，就回來補一條 — CLAUDE.md 是活文件。

觀念檢查（憑記憶作答）

1. 「禁止直接推送 main」這條規定，最可靠的實作方式是？

CLAUDE.md 是指引（context），不保證百分之百遵守；必須強制的規則要用技術閘門（hooks / permissions）。這是官方文件明確的分工。

2. 哪一條最適合寫進團隊共享的 CLAUDE.md？

共享 CLAUDE.md 放全隊通用、每個 session 都需要的事實。個人環境放 CLAUDE.local.md；單次任務內容直接在對話講即可。

3.（複習 Phase 1 第 01 課）「把這個資料夾的 50 份 PDF 報告彙整成一頁摘要」該用？

（間隔複習）多步驟檔案處理、非程式碼 → Cowork。判斷軸永遠是「它需要碰到什麼」。

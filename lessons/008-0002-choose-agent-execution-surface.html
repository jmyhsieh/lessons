比較時固定五個 operating dimensions

  1. 觸發條件：由誰、何時、根據哪個 event 啟動；manual trigger 可接受，不必為了「自動」加 schedule。
  2. 持續性：一次 run、同一 session 多輪，或跨 session goal；state 存在哪裡，誰能重新識別。
  3. 監督方式：誰看得到 progress、能停止、能處理 approval；背景執行不得消除 human stop。
  4. 重疊／重試：前一輪未完時 skip、queue 或 stop；不得默認並行寫同一 fixture。
  5. 成本／時間：最大 rounds、deadline、token／compute／storage boundary 與超限處置。

選擇規則：選最小能保持 mission 與 observable feedback 的 surface。不要把 /goal、/loop、Desktop scheduled task 與 cloud Routine 當成必走工具階梯，也不要同時跑多個 surface 來「比較完整」。

可見成果：一張 execution selection card，固定唯一 surface、trigger、continuity、supervision、overlap、cost 與 stop。
可觀察回饋：Reviewer 能用同一張 card 解釋為何其他 surface 被拒絕，並指出排程／持續執行沒有授予任何新 write 或 external authority。

本機 fixture 每十分鐘要做一次唯讀 freshness check，操作者全程在線且前一輪未完必須 skip。最小合適選擇是？

Surface selection 服務 trigger 與 boundary；單一受監看的 local loop 已足夠，重複 surfaces 只會增加 state、權限與重複執行風險。

合法停止／返回／續行：候選 surface availability、session ownership、overlap、stop control 或 cost ceiling 任一不明，就保存 card 並回 008-0001 縮小 mission；不要用 cloud 假設填補 evidence。唯一 surface 已選且仍保持 read-only 後，進 008-0003 定義 authority envelope。這張 card 不代表 workflow 已執行或 Phase complete。

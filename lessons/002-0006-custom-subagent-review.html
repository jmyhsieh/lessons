Phase 2 · 第 06 課 · 約 20 分鐘 · 審查代理

建立專門負責審查的自訂子代理（custom subagent）

本課成果：一份由唯讀審查代理產生、能對照程式差異的審查結果。

本課只做：建立一個範圍明確、專門審查的代理。
先不要做：讓審查代理同時負責修程式碼與批准自己。

獨立審查的價值

撰寫程式碼的工作階段會受自己的推理歷程影響。審查子代理只看程式差異、需求與標準，立場更乾淨。

請使用審查子代理，依 PLAN.md 審查這份程式差異。
只回報正確性缺口、缺少的測試或範圍擴張。
要求「只回報影響正確性的缺口」，避免審查變成風格偏好清單。

最小審查代理定義

---
name: repo-reviewer
description: Reviews diffs for correctness gaps and missing tests
tools: Read, Grep, Glob
---
Review against the stated task and existing repo conventions.
Report only actionable issues with file references.

審查代理不給 Edit。這是職責分離：它提出問題，主工作階段決定怎麼修。

實作步驟（做完打勾）

CLI 可用 /agents 建立；Desktop App 或手動設定時，在 .claude/agents/ 建檔。工具只給唯讀。

給它任務摘要、程式差異與明確審查標準。

標出哪些是正確性缺口、哪些只是建議。只把前者帶回主工作階段。

完成條件：唯讀審查代理已對照實際差異產生結果，每個問題都有檔案位置與理由。

觀念檢查

1. 審查子代理為什麼不給 Edit？

審查者不該同時有筆，否則角色混在一起。

2. 同一個工作階段寫完後直接叫它審查，主要缺點是？

讓審查代理用新的對話脈絡重看一次，才比較接近獨立審查。

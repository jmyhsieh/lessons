Phase 6 · Build · 006-0003 · Request alignment

把 request 對齊成可驗證的 delivery boundary

任務：以 repo map 與現有 docs 為證據，釐清 outcome、scope、constraints、acceptance evidence 與 stop line；先 shared understanding，再決定是否需要 conditional prototype。

留下 alignment record

Requested outcome:
In scope / out of scope:
Affected user-visible behavior:
Repository constraints:
Acceptance evidence:
Test seam:
Decision still needing a runnable answer:
Shared-understanding confirmation:
  1. 逐項對照 repo map、issue、domain docs 與現有 tests，不從一般慣例補猜測。
  2. 把含糊詞改成可觀察行為，並列出非目標。
  3. 選足以保護 intent 的高層 test seam；deterministic code 能判斷的事不交給模型自評。
  4. 只有存在「必須玩過才知道」的 UI／logic 問題，才走 006-0004；否則直接凝結 spec。
Tangible win：一份可由使用者核准的 alignment record。
Observable feedback：使用者能逐項確認 outcome、scope、evidence 與 unknown，並明確選擇 prototype 或直接 spec。

何時需要 conditional prototype？

缺 acceptance criteria 應繼續對齊；prototype 只回答需要 runnable evidence 的單一問題。

Legal stop／continuation：使用者尚未確認 shared understanding、scope 仍會 materially 改變，或沒有可靠 test seam 時停止。需要 runnable answer 才去 006-0004；不需要則直接到 006-0005。

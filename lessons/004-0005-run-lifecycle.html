Phase 4 Lab · 第 05 課 · 約 45 分鐘 · Run lifecycle

管理 run history、rerun 與 closeout

目標：把 Phase 4 第 04 課的 evidence、gate results 與 report 串成可追查的 run lifecycle，並定義 rerun、final handoff 與 closeout。

本課只做：append-only history、rerun lineage、handoff 與收工決策。
先不要做：dashboard、自動 repair loop、多租戶資料庫或完整 transcript 備份。

Run history 不是 evidence 本身

Claude Code Session Store 用來 mirror session transcripts，讓不同 host 可以 resume；Observability 用 traces、metrics、events 看工具、token、成本與失敗位置。Harness 的 run history 比它們更小：只是一個本地索引，讓 reviewer 找得到 input、evidence、gates、report 與 status。

資料放哪裡用途
Run history.harness/runs.jsonl 或 SQLite。查詢每次 run 的狀態與 artifact 路徑。
Evidence.harness/evidence/<run-id>/保存 stdout、stderr、gate output。
Report.harness/reports/<run-id>.md給 reviewer 判斷結果。
TelemetryOTel backend。看成本、延遲、工具呼叫、失敗位置。
判斷規則：run history 只索引 canonical paths 與狀態，不複製大型 logs、不複製完整 prompt、不取代正式 telemetry。

Run record 範例

{
  "runId": "run-0042",
  "inputId": "issue-0042-login-timeout",
  "startedAt": "2026-06-13T09:30:00Z",
  "endedAt": "2026-06-13T09:38:10Z",
  "status": "needs-review",
  "agentStatus": "needs-review",
  "gateStatus": "pass",
  "evidenceDir": ".harness/evidence/run-0042",
  "gateResultsPath": ".harness/evidence/run-0042/gate-results.json",
  "reportPath": ".harness/reports/run-0042.md",
  "costUSD": 0.42
}

Rerun 不覆蓋舊結果

每次 rerun 都建立新的 runId，並用 parentRunId 指回來源。只有 transient failure、可修正 input 或明確 reviewer 要求適合 rerun；缺憑證、scope 不清或連續同因失敗應交給人處理。

Rerun 規則：舊 evidence 永遠保留；rerun note 必須寫 trigger、變更內容與新的 stop condition。不要把重跑當成無限自動重試。

Final handoff 與 closeout

Final handoff 不是聊天摘要。它要索引 latest run、parent chain、scope、changed files、gate results、evidence、未解風險與建議決策，讓下一個 reviewer 不必追問就能接手。

Closeout意義
ship必要 gates 通過，可交付。
review需要指定 reviewer 做人類判斷。
rerun已定義可修正原因與下一個 run。
blocked缺外部條件，已記錄 owner 與 next action。
downgradeharness 不適合，退回單次 agent session。
Closeout 規則：必須回答「現在可以停止嗎？」若不能，必須指定 owner 與 next action；沒有 owner 的 open item 不算 closeout。

實作步驟（做完打勾）

先用 runs.jsonl：append-only、容易 diff、容易 fixture 測試。等查詢需求變多再換 SQLite。

來源必須是實際 run 產物：input contract、agent evidence、gate results、report path。不要從聊天摘要重建。

list 列出 runId、inputId、status、startedAt 與 reportPath；show 回傳完整 record，artifact 不存在時標示 stale。

列出哪些狀態可重跑，並要求每個 rerun 都產生新 runId、parentRunId 與 rerun note。

Handoff 只索引 canonical artifacts；closeout 只能選五種決策之一。非 ship 必須有 owner 與 next action。成本可以記錄供開發觀察，但不能直接作正式財務決策。

觀念檢查（憑記憶作答）

1. Run history 最應該保存什麼？

Run history 是索引層：保存狀態與 canonical paths。完整 stdout/stderr 留在 evidence。

2. Rerun 應如何保存結果？

每次 rerun 都建立新 runId 並指回 parentRunId，舊 evidence 才能保留供比較與追查。

3. 第一版最適合用什麼格式？

JSONL 最小、append-only、容易測試。查詢需求真的變多後，再升級 SQLite 或資料庫。

4. Cost 欄位可以直接用來做什麼？

官方文件提醒 cost 是 client-side estimate。適合開發觀察與粗略預算，不適合正式財務決策。

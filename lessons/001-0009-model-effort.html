Phase 1 · 第 09 課 · 約 15 分鐘 · 模型與 effort

先用預設，再調模型與 effort

任務目標：先用目前模型的預設 effort；結果不理想時，能分清楚是 context 不足、模型能力不夠，還是 effort 不夠。

本課只做：看懂目前模型與 effort，並練習一次「只調一個旋鈕」。
先不要做：背所有版本、把 max 當預設，或在 context 不完整時靠升級硬跑。
先相信實際 picker：default 會依帳號、組織與 provider 選建議模型；sonnet、opus、fable 等 alias 也會隨 provider 更新。先用 /model 看這個 session 真正可用的選項，不要只照課本上的版本名稱。

先判斷哪裡出了問題

你看到的症狀先做什麼要調的旋鈕
prompt、工具或 repo context 不完整補清楚目標、來源、權限與驗證方式。先不要調模型或 effort。
Claude 已讀關鍵資料、認真嘗試，仍判斷錯誤換能力更高的模型。Model
Claude 跳過檔案、測試、查核，或太早停下要求更徹底地完成工作。Effort

模型決定能力範圍

選項先這樣理解
default回到帳號或組織建議的模型；入門先從這裡開始。
sonnet日常 coding 的 generalist：範圍清楚、能用 tests 驗證的工作。
opus複雜推理的 expert：模糊需求、架構取捨、困難 bug。
fable最困難、最長時間任務的 specialist；不是任何帳號的預設，只有可用時才會出現在 picker。
haiku簡單、明確、重視速度與成本的工作。

Effort 決定做得多徹底

Effort 不只是「想多久」；它也會影響 Claude 讀多少檔案、使用多少工具、跑多少驗證，以及在回來問你之前推進多少步。官方建議多數任務先用模型預設值，再依結果調整。

選項何時使用
auto／模型預設一般起手式；目前多數新模型預設為 high，但不必手動重設。
low／medium任務短而明確，或你更在意速度與成本。
high／xhigh需要更完整探索、工具操作與查核；可用範圍依模型而異。
max最困難且有明確停止條件的 session-only 選項；可能過度思考，不適合長期預設。

實作步驟（做完打勾）

Claude Code：執行 /model；桌面 App 也可使用送出按鈕旁的 model dropdown。先記下目前模型與可用 alias，不要急著切換。

小提醒：新版 CLI 在 picker 按 Enter 會切換並存成未來 session 的預設；按 s 才只切換目前 session。

執行 /effort 查看目前設定；也可在 /model picker 用左右鍵調 slider。若先前手動改過，使用 /effort auto 回到模型預設。

Current model: [picker 顯示的模型]
Current effort: model default

If context is missing: fix the prompt, tools, or scope.
If Claude tried thoroughly but was still wrong: use a stronger model.
If Claude skipped files or verification: raise effort.

若它跳過查核，維持模型只提高 effort；若它已充分查核仍解錯，維持 effort 改用較強模型。比較第二次是否真的補上缺口，完成後用 /effort auto 回到預設。

🎉 完成！你已能分辨 context、model 與 effort 三種不同問題。

觀念檢查

1. Claude 找到正確方向，卻跳過 tests 就說完成，該先調什麼？

它不是不知道怎麼做，而是做得不夠徹底；這是 effort 問題。

2. Context 完整，Claude 也仔細讀過並驗證，仍解錯困難問題，該先調什麼？

它已經充分嘗試，但能力仍不足；這時才升級模型。

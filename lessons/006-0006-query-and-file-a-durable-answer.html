Query 並留下可重用答案

今天只做一件事：問一個需要跨頁整理的問題，再判斷答案值不值得寫回 Wiki。

Query 會讓探索繼續累積：Claude Code 先從索引找到相關頁面，再帶著來源回答；只有未來還會再用的結果才寫回 Wiki。

讓答案不只留在聊天裡

例如比較兩個方案、找出一段時間的變化，或整理不同來源共同支持與互相衝突的地方。

請 query 目前的 LLM Wiki 來回答：
[寫下一個需要跨頁整理的問題]

若有 index.md，先用它定位相關頁面。
答案請列出使用的 Wiki 頁面與 raw source；資料不足時說明缺口。
先不要寫入檔案。回答後再建議這份結果是否值得寫回，以及最適合放在哪裡。

若答案形成新的比較、連結或可重用結論，再同意寫回並更新 index／log；臨時答案就留在對話，不增加維護負擔。

完成：你已完成一次有引用的 query，並對寫回 Wiki 做出明確判斷。

觀念檢查

Query 得到答案後，哪個做法最好？

值得重用的新連結與分析才寫回；全存會製造雜訊，全不存則失去累積效果。

帶走這個就好

Query 不只取出答案，也能產生新知識頁。判斷標準不是答案漂不漂亮，而是它未來是否值得重用。

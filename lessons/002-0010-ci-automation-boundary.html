在 CI 中安全使用 Claude Code

任務目標：評估什麼 headless 任務可以放進 CI，並用最小權限、穩定輸出與成本紀錄包住它。

本課只做：界定 CI 中能安全交給 Claude Code 的任務。
先不要做：讓 CI 自動產生未經人工 review 的 production 改動。
沒有人在場 = 權限設計取代你的眼睛。CI 裡先做唯讀摘要、diff review、文件檢查；會寫檔、會 push、會修改環境的任務不要直接無人值守。

CI 任務的四個條件

  • 明確認證：--bare 不讀 OAuth/keychain；使用 ANTHROPIC_API_KEY、傳入的 apiKeyHelper 或 provider credentials，不依賴開發者電腦的登入狀態。
  • 最小工具面：--allowedTools 只會預先批准工具，不是 allowlist；用 --tools 限制 built-in tools。能從 stdin 餵資料就用 --tools ""。
  • 穩定輸出：--output-format json 固定 result envelope；回答內容需要固定欄位時用 --json-schema。
  • 可營運：記錄成本、時間、失敗率與誤報率。

安全 diff review 範例

git diff main |
claude --bare -p "Review this diff for risky production config changes.
Return only filename:line and reason. Return empty output if none." --tools ""

這個設計沒有給 Claude built-in tools；diff 已經從管線餵進去。CI 還必須依上面的規則提供 bare mode 可用的明確認證。

實作步驟（做完打勾）

例如 typo linter、dangerous config review、release note 摘要。

能不用工具就用 --tools ""；真的需要才列最小 built-in tool 集合。不要把 --allowedTools 誤當成限制工具可見性的 allowlist。

正常 diff、有問題 diff、空 diff。輸出都要穩定。

CI log、PR comment、artifact 或 JSON 檔。要讓人能判斷是否採納。

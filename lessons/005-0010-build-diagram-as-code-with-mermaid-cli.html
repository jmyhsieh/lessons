用 Mermaid CLI 建立可審查的 diagram-as-code

進入條件／Code readiness：第 07 課的 core closeout 已通過，而且新需求需要可 diff、可重跑的流程圖／關係圖；圖中每個節點與連線都能回到已確認的 source ID。使用 pinned Mermaid CLI 只建立一張 diagram vertical slice，將原始碼、render command 與輸出一起交給 reviewer。

本課只做：一個 bounded .mmd source、一次 SVG render、一次事實／可及性／slide-fit review。
先不要做：把整份 deck 圖表化、把 render 成功當成內容正確，或用圖中的箭頭自行創造因果關係。
完成邊界：這是 optional continuation。完成、跳過或失敗都不會增加或撤銷第 07 課的 Presentation completion；單張 diagram 與成功 render 也不能單獨構成 Presentation closeout。

先把圖的 claim 寫成一句話

欄位例子阻擋條件
受眾問題哪三個 evidence gates 才能進入 delivery？只想讓 slide「更豐富」
圖表主張Source → Claim → Slide 是 traceability 流程，不是時間估算箭頭語意不明或暗示未證實因果
來源 IDs每個 factual node 對應 ledger ID節點文字由模型補齊且無來源
備援（Fallback）同內容的文字清單／表格只能靠顏色、位置或視覺連線理解

用 pinned CLI render 最小 slice

# 應顯示 11.16.0；使用既有本機 Chrome，避免下載另一份 browser
PUPPETEER_SKIP_DOWNLOAD=true npx --yes @mermaid-js/mermaid-cli@11.16.0 --version

cat > diagram.mmd <<'EOF'
flowchart LR
  Source["Source · S01"] --> Claim["Verified claim · C01"]
  Claim --> Slide["Reviewed slide · P03"]
EOF

cat > puppeteer-config.json <<'EOF'
{"executablePath":"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome","args":["--no-sandbox"]}
EOF

PUPPETEER_SKIP_DOWNLOAD=true npx --yes @mermaid-js/mermaid-cli@11.16.0 \
  -p puppeteer-config.json -i diagram.mmd -o diagram.svg
test -s diagram.svg
shasum -a 256 diagram.svg

命令證據邊界：本課釘定 @mermaid-js/mermaid-cli@11.16.0，並假設本機 Google Chrome 路徑存在。版本、browser 或輸出 hash 與紀錄不符時先停下來查明；不要無聲改用 latest。Hash 只能辨識輸出 bytes，不能證明圖中 claims。

實作 checklist

從已通過的 storyboard／claim ledger 取一個流程或關係；列出 source IDs、箭頭語意、需要揭露的 unknown 與文字 fallback。

限制在能回答問題的節點與邊；pending claims 保留 [待確認]，不要為了對稱補資料。

保存 exact version、command、exit status、non-empty output 與 hash；用 browser 打開 SVG，檢查 clipping、font fallback、contrast 與 200% zoom。

在實際尺寸檢查 label 可讀性、投影距離與周邊內容；同時提供等價文字說明。依 005-0006重查 claims／accessibility。

若 .mmd、config 或 SVG 進 repo，建立 immutable candidate SHA，再依 Repo Review contract分開做 Standards Review 與 Spec Review。任何修正都建立新 SHA，重跑 render、checks 與兩軸 Review。

具體成果：一組可由別人重跑的 .mmd、pinned render command、non-empty SVG、hash、文字 fallback 與 exact-SHA Review evidence。
可觀察回饋：請 reviewer 從 source IDs 逐一核對節點與箭頭，再於 target slide 只看圖重述其 claim；記錄錯誤關係、無法理解的連線、被截斷文字與缺少的 fallback，修正後重新 render／review。

觀念檢查

1. Mermaid CLI render 成功後，哪個結論成立？

Renderer 只能證明這次輸入可轉成輸出；它不知道箭頭是否符合來源，也不會替你完成 target-context review。

2. 哪一個需求適合進入本 elective？

Diagram-as-code 的價值是可追蹤、可重跑的關係表達；它不應創造 claims，也不能替代 core closeout。

返回與停止線

返回／續行：diagram、文字 fallback、target-slide check 與 Review bundle 都通過後，直接回 課目表。若新需求改為 version-controlled React deck，另選 005-0009 Open-Slide；兩個 electives 沒有先後依賴。

合法停止點：CLI／browser identity 不符、factual node 或箭頭無 source ID、pending claim 被畫成 confirmed、SVG 為空、文字 fallback 缺少、target slide 不可讀、candidate 未固定，或 Review finding 未解決時，保留 source 與 command evidence 後停止。回 005-0002或本課對應步驟修正；不可發布，也不可改寫 core closeout。

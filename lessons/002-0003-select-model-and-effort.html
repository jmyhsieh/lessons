Phase 2 · Equip · 002-0003 · Conditional toolbox lesson

用任務需求選 model，用不確定性選 effort

任務：替 active route 寫一張 model／effort selection card，用一個低風險 prompt 驗證選擇是否達到事先定義的 feedback rubric。

先分清楚兩個旋鈕

選項主要影響何時才調整
Model可用能力、行為特性、速度與成本邊界目前能力與任務複雜度、風險或 context 需求不匹配。
EffortAgent 嘗試投入多少推理與工作scope 已清楚，但不確定性或取捨需要更多分析。

可用 model、alias 與 effort levels 會依 model、帳號、provider、組織設定及版本改變。先看目前 session 的 picker 或 CLI help，只選介面實際提供的值；若需要的選項沒有出現，記錄 gap 並返回 active route，不要自行猜測名稱。

執行一次 bounded smoke test

  1. 從 picker 或 claude --help 記錄目前環境實際提供的 model／effort controls；不要從課程硬猜可用名稱。
  2. 選一個不修改檔案、不呼叫外部服務的小型 prompt，它必須保留 active route 的主要推理形狀。
  3. 先寫三個可觀察 rubric items，例如「列出兩個風險」「指出未知資訊」「給出 legal stop」。
  4. 用 selection card 指定的設定執行一次，記錄顯示的 model／effort、輸出、延遲或成本訊號，以及 rubric 結果。
  5. 若 rubric 通過就停止；若未通過，只依事先寫好的 escalation signal 調整一次。重複失敗時修 scope、context 或 feedback loop，不用更高 effort 硬跑。
Tangible win：一張 selection card，加上一筆 bounded model／effort smoke-test record。
Observable feedback：介面顯示的設定與 card 一致；三個 rubric items 有逐項結果；你能說明保留、升級、降級或停止的理由。

高 effort 的 smoke test 仍無法指出關鍵未知資訊，下一步應該是什麼？

Model 與 effort 是工作設定，不會補回缺少的 context、模糊 scope 或失效的驗證方式。

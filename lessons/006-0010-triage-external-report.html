Phase 6 · Build · 006-0010 · Conditional branch

先驗證與分流外部回報，再交回 Engineering core

Entry／conditional：只有 issue 或 repo 設定納管的 external PR 以 raw request 進來，且你有讀取 tracker、repo instructions 與相關 code／checks 的權限時才進入。/to-tickets 產出的 agent-ready ticket 已經完成 shaping，不重跑 triage。

1. 先讀完整 report，再核對 repo

讀 body、comments、labels、author、dates；PR 還要讀 diff。保留已回答的 triage notes，並做兩個 codebase checks：以 domain concept 搜尋是否已實作，以及查看是否有相似的既有拒絕決策。接著重現 bug，或驗證 PR diff 是否符合它聲稱的行為。

2. 分開 category 與 workflow state

欄位只選一個判斷證據
Categorybug／enhancement描述既有行為壞掉，或要求新增／改善能力。
Stateneeds-triage／needs-info／ready-for-agent／ready-for-human／wontfix由 claim verification、缺漏資訊、所需 judgment／authority 與 acceptance criteria 決定，不把 category 當狀態。

Human checkpoint：先向 maintainer 提出 category、state、repo 摘要與理由，再等裁決。若要對 tracker 留 comment，依目前 triage contract 加上 AI disclaimer；label、comment、close 都是外部 mutation，沒有授權就只保存 local draft。

Triage 不是 diagnosis：一般已確認且範圍清楚的 report 可以回 core；遇到難解、間歇或回歸 bug，handoff 應保留 exact symptom 與現有 evidence，再改走 006-0011 diagnosis branch。不要在沒有 tight feedback loop 時用原因假說取代 triage verification。

Tangible win：一份 external-report triage handoff，包含 verified claim、恰好一個 category、一個 state、maintainer disposition 與可驗收的下一步。
Observable feedback：Reviewer 能重跑 verification、看見 redundancy／prior-rejection 搜尋範圍，並確認沒有衝突的 state 或未授權 tracker mutation。

一張外部 bug report 描述含糊，而且依提供步驟無法重現；現在最合適的 evidence 與 state 是？

無法驗證且資訊不足是 needs-info 的強訊號；triage 要保存 evidence 與可回答的問題，不能猜原因或越過 maintainer 裁決。

Legal stop／return／continuation：state roles 衝突、tracker mapping 不明、claim 無法驗證、需要 reporter 補件、maintainer 尚未裁決，或下一步要求未授權 external mutation時，保存 local handoff 後停止。若 report 已充分 verified 且 maintainer 接受 disposition，帶著 handoff 回 006-0003 對齊 bounded request；難解 bug 改走 006-0011。完成本頁只代表這一張外部回報已被分流，不代表 Engineering Phase 或 Migration complete。

把 repo contract 放進 review loop

目標：讓第 40 課產出的 repo contract 成為下一輪 review 的檢查依據，而不是寫完就放著。這一課只設計 review loop，不新增自動化。

Contract 要被使用，才算被固化

第 40 課把 verified workflow 放到合適位置；第 41 課要確認 reviewer、下一個 agent 或任務 owner 真的會讀到它。Review loop 的重點不是多一份文件，而是讓每次同類任務都回答四個問題：哪條 contract 適用？它有沒有被遵守？它抓到什麼？它造成什麼負擔？

Claude Code memory 適合保存 repo 規範，但 memory 不是證據。Review loop 需要在 PR、handoff 或 run report 裡留下 contract usage note，讓後續可以判斷 contract 是否仍有價值。

Review loop 四格

欄位要回答例子
Applicable contract這輪任務套用哪一條規範？reference/harness-input-contract.html
Observed compliance有沒有照做？缺哪一塊？brief 已列出 scope-out 與 gate evidence。
Review signal它讓 review 更容易，還是只是增加欄位？reviewer 不需再追問驗收範圍。
Next actionkeep、revise、promote 或 retire？keep，累積到第 42 課 effectiveness log。
判斷規則：一條 contract 如果不會在 review 中被點名，就還不是營運中的 contract，只是參考文件。

Contract usage note 範例

contractUsage:
  contract: reference/harness-input-contract.html
  appliedTo: DOC-142
  observedCompliance: pass
  reviewSignal: scope-out was explicit; no clarification needed
  nextAction: keep
  evidence: reports/DOC-142-review.md

實作步驟（做完打勾）

從第 40 課的 contract note 開始。先選一條最近會再次用到的規範，不要一次檢查整個 repo。

入口可以是 PR checklist、handoff report、run report 或 reviewer note。選下一個人自然會看的地方。

只加四欄：contract、observed compliance、review signal、next action。欄位越少，越容易持續使用。

請 agent 或 reviewer 在交付時填 usage note。不要先把它做成 hook；先確認人類 review 真的需要這條規範。

如果 note 提供了有效 signal，下一課再開始追蹤趨勢。單次結果只代表一次使用，不代表規範一定穩定。

你已完成 review loop 設計。回對話視窗貼上 usage note，請 AI 老師檢查欄位是否足夠少、位置是否自然。

觀念檢查（憑記憶作答）

1. Review loop 最先要確認的是？

Phase 4 的第一步是讓 contract 進入實際 review。沒有被使用，就無法判斷有效性。

2. Contract usage note 應該放在哪裡？

usage note 要讓下一個人可以檢查，因此應放在 PR、handoff 或 run report 等 review 入口。

3. 一次 review loop 最好檢查？

先檢查一條最相關的 contract，才能看出它是否真的改善同類任務。

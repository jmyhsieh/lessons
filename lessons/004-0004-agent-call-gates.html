Phase 4 Lab · 第 04 課 · 約 45 分鐘 · Agent call + gates

呼叫 agent 並執行 deterministic gates

目標：把 Phase 4 第 03 課的 dry-run plan 接上單一 agent call，再由 deterministic code 執行 gates、保存 evidence 並產生 report。

本課只做：單次 agent call、gate execution 與可審查 report。
先不要做：自動修復、batch、scheduler 或開放全部工具。

這一片為什麼要小

Claude Code CLI reference 說明 claude -p 會送出查詢後結束，並提供 --output-format、--max-turns、--max-budget-usd、--tools、--allowedTools 等旗標。Runner 的第一個真 call 應該先把這些限制固定下來。

Agent SDK overview 適合需要程式化 session、tool、permissions 時使用；但若你只是把單一 dry-run plan 接成一個可驗證 call，先用 CLI wrapper 比較容易看見每個 artifact。

Wrapper 只做四件事

段落要留下什麼不做什麼
Invoke實際 argv、cwd、startedAt。不手寫 shell 字串。
Limitmax-turns、budget、tools、allowed tools。不開放全部權限。
Capturestdout、stderr、exit code、duration。不只相信口頭摘要。
Classifypassed、failed、blocked、needs-review。不在這一片自動修復。
判斷規則：agent call 一旦接上，wrapper 的第一責任不是成功完成任務，而是讓 reviewer 能重建「它被要求做什麼、實際回了什麼、為什麼停下」。

把 effort 當成 evidence

真 agent call 必須記錄 model、effort、budget 與 goal condition，否則之後無法判斷結果是因為任務困難、推理不足、還是限制太鬆。第一版預設 high；只有 gate failure 需要跨模組推理時，才切到支援 xhigh 的模型並記錄原因。不要在 unattended runner 預設使用 max。

欄位要記錄
modelalias 或完整 model id。
efforthigh、xhigh、或 auto，並說明升級原因。
goalCondition從 runner contract 來的完成條件。
budgetturns、cost cap、timeout。

Evidence packet 範例

.harness/evidence/run-0042/
  command.json
  prompt.txt
  agent.stdout.json
  agent.stderr.txt
  exit.json
{
  "argv": ["claude", "-p", "<prompt>", "--output-format", "json", "--max-turns", "3"],
  "model": "sonnet",
  "effort": "high",
  "goalCondition": "All declared gates pass and report includes evidence paths.",
  "tools": ["Read", "Edit", "Bash"],
  "allowedTools": ["Bash(npm test -- auth)"],
  "stdoutPath": ".harness/evidence/run-0042/agent.stdout.json",
  "stderrPath": ".harness/evidence/run-0042/agent.stderr.txt",
  "exitCode": 0,
  "status": "needs-review"
}

Gate 與 report 由 deterministic code 負責

模型可以修改內容、摘要結果，但不能自己宣告 tests 或 checks 通過。Wrapper 必須執行 contract 裡的命令，保存 command、exit code、stdout/stderr 與 artifact path，再依固定 precedence 決定狀態。

狀態何時使用
blocked缺權限、憑證或必要環境，無法完成驗證。
failed至少一個必要 gate 明確失敗。
needs-review命令通過，但仍有人工判斷或未驗證項目。
passed所有必要 gates 通過，且沒有未處理風險。
狀態 precedence：blocked > failed > needs-review > passed。Report 至少列出 status、scope、gate table、evidence paths、unverified items 與 next action。

實作步驟（做完打勾）

不要重新組一套規則。Phase 4 第 03 課列出的 prompt、tools、gates、paths，應該是這一片唯一的 input。

避免把 prompt、paths、tool rules 串成一條 shell 字串。Wrapper 應該能把實際 argv、model、effort、goal condition 寫進 command.json。

stdout 與 stderr 寫進 evidence 目錄；report 只引用路徑與摘要，不複製整份 log。

用 deterministic code 執行每個 gate，保存結果並依 precedence 分類。Report 引用 evidence paths，不複製完整 logs。

Agent SDK observability 提醒 telemetry 可記錄工具與成本，但內容型資料需要更謹慎。若 stdout/stderr 可能含 token、客戶資料或祕密，先 redact 再進 report。

觀念檢查（憑記憶作答）

1. 加入真 agent call 後，wrapper 第一責任是什麼？

第一個真 call 的重點是能重建過程：argv、prompt、stdout、stderr、exit code 與分類結果。

2. 為什麼先設定 turns / budget？

限制 turns、budget 與 tools 是 unattended runner 的基本護欄；否則一次 call 可能消耗過大或越權。

3. 哪種內容應放 evidence，不直接塞進 report？

完整 stdout/stderr 屬於 evidence。Report 應該放摘要、狀態、路徑與 reviewer 需要的判斷點。

4. Unattended runner 預設使用哪個 effort 較合理？

第一版 runner 要可控且可重跑，預設 high；只有明確升級條件且模型支援時才用 xhigh，max 不應作為 unattended 預設。

5. 誰應該判定 test gate 是否通過？

可機械判定的 gate 應由 deterministic code 執行並記錄 exit code；模型不能用自述取代證據。

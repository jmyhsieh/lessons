第 6 階段 · 建置 · 006-0008 · 獨立審查

以兩個獨立視角 Review 同一個不可變候選版本

進入條件：006-0007 已留下精確 candidate SHA、fixed point、原始規格與可重跑檢查。先 checkout 或解析精確 SHA；候選版本識別不能是分支、工作樹或移動中的 HEAD。

先固定比較，再分開判斷

git rev-parse <fixed-point>
git rev-parse <candidate-sha>
git diff <fixed-point>...<candidate-sha>
git log <fixed-point>..<candidate-sha> --oneline

兩個審查者必須收到相同差異識別，但彼此不共享結論。工具選擇可依環境調整；輸入與 evidence 邊界 不變。

標準軸

只問差異是否符合儲存庫指引、本機慣例與有文件記錄的標準。逐項引用規則與檔案/區塊；啟發式異味要標成判斷。

Standards findings:
- rule / location / evidence
- severity / suggested repair

規格軸

只問原始 議題／規格是否完整、正確且沒有範圍膨脹。逐項引用 需求，再對照檔案/區塊。

Spec findings:
- requirement / location / gap
- missing, wrong, or unasked behavior

不要合併兩軸：標準通過不代表做對需求；規格 通過也不代表符合儲存庫規則。保留兩份發現與各自結論，不跨軸重排成單一分數。

具體成果：一份綁定固定點與精確候選版本 SHA 的標準／規格 審查套件。
可觀察回饋：讀者能分別計數兩軸發現，並驗證兩份報告 review 的是同一份不可變差異。

Review 後修正一項規格發現，下一步是什麼？

任何候選版本變更都使舊 Review evidence 失效；新 SHA 必須重新通過完整 Review contract。

發現項返回／合法停止：任一軸有發現、審查者看見不同候選版本、規格或標準 source 缺失、檢查被跳過，或 Review 期間候選版本改變時，停止並回 006-0007 做有界限的修補；建立新 SHA 後從本課開頭重跑兩軸。只有兩軸都對最終候選版本 SHA無未解發現，才保存 套件，續到 006-0009 工程交付收尾；本頁不宣稱路線、Phase 或遷移完成。

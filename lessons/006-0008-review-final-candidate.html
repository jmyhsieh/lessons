第 6 階段 · 建置 · 006-0008 · Independent Review

以兩個獨立視角 Review 同一個 immutable candidate

進入條件：006-0007 已留下 exact candidate SHA、fixed point、originating spec 與可重跑 checks。先 checkout 或解析 exact SHA；candidate identity 不能是 branch、working tree 或移動中的 HEAD。

先固定比較，再分開判斷

git rev-parse <fixed-point>
git rev-parse <candidate-sha>
git diff <fixed-point>...<candidate-sha>
git log <fixed-point>..<candidate-sha> --oneline

兩個 reviewer 必須收到相同 diff identity，但彼此不共享結論。工具選擇可依環境調整；輸入與 evidence boundary 不變。

Standards 軸

只問 diff 是否符合 repo instructions、local conventions 與 documented standards。逐項引用規則與 file/hunk；heuristic smell 要標成 judgement call。

Standards findings:
- rule / location / evidence
- severity / suggested repair

Spec 軸

只問 originating issue／spec 是否完整、正確且沒有 scope creep。逐項引用 requirement，再對照 file/hunk。

Spec findings:
- requirement / location / gap
- missing, wrong, or unasked behavior

不要合併兩軸：Standards pass 不代表做對需求；Spec pass 也不代表符合 repo 規則。保留兩份 findings 與各自結論，不跨軸重排成單一分數。

具體成果：一份綁定 fixed point 與 exact candidate SHA 的 Standards／Spec Review bundle。
可觀察回饋：讀者能分別計數兩軸 findings，並驗證兩份報告 review 的是同一份 immutable diff。

Review 後修了一個 Spec finding，下一步是什麼？

任何 candidate mutation 都使舊 Review evidence 失效；新 SHA 必須重新通過完整 Review contract。

發現項返回／合法停止：任一軸有 finding、reviewer 看見不同 candidate、spec 或 standards source 缺失、checks 被跳過，或 Review 期間 candidate 改變時，停止並回 006-0007 做 bounded repair；建立新 SHA 後從本課開頭重跑兩軸。只有兩軸都對最終 candidate SHA無未解 finding，才保存 bundle，續到 006-0009 Engineering closeout；本頁不宣稱 route、Phase 或 Migration complete。

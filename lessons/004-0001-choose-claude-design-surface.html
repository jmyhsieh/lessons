Phase 4 · 第 01 課 · 約 15 分鐘 · Surface choice

判斷 Claude Design 是否是正確工作表面

目標：看到一個設計任務時，先依預期產物選對工作表面，而不是把 Claude Design、Claude Code 的 frontend-design 與 artifacts 混為一談。

本課只做：替一個真實任務選工作表面並寫出理由。
先不要做：還沒釐清產物就開始畫原型或改 repo。

核心知識：名稱相近，產物不同

Claude Design 是 Anthropic Labs 推出的獨立產品，可用來協作建立設計、互動原型、簡報與其他視覺作品。它不是 Claude Code 裡的一個 skill。

工作表面主要產物適合的問題
Claude Design 可比較、可精修的視覺設計與原型 「版面與互動還沒定，我要先看幾個方向。」
Claude Code + frontend-design repo 裡可執行的前端程式碼 「需求與邊界已清楚，請依現有技術棧實作並驗證。」
Claude Code artifacts 從 repo 與 session context 產生可分享的 live page 「我要用真實元件比較 UX 方向，或展示 walkthrough 與執行證據。」

官方 Claude Code repo 的 frontend-design skill 指導 Claude 產出有明確視覺方向、可實際運作的前端介面；它仍在 Claude Code 的 repo 工作流中。相較之下，Claude Code artifacts 把完整 session context 轉成可分享、會隨工作更新的 live page；目前是 Team 與 Enterprise 的 beta 功能，不等於 Claude Design 畫布。

最小決策規則：要在可評論、可直接編輯的 project／canvas 探索設計，就選 Claude Design；要在 repo 裡「實作、測試、提交」就選 Claude Code；要從真實元件與 session context 產生 live page，做 code-grounded UX exploration 或展示執行證據，就考慮 Claude Code artifact。完整流程可以依序使用三者，但不要期待一個表面包辦全部工作。

Beta 邊界要先看

依目前官方說明，Claude Design 仍在 beta，提供 Pro、Max、Team 與 Enterprise 方案使用；Enterprise 預設關閉，由管理員啟用。它目前限 web 與 desktop，且使用量和 Claude chat、Claude Code、Cowork 共用。大型 repo、多人同時編輯與 inline comments 也有已知限制；導入團隊流程前，請先重查 最新 availability 與 known limitations。

實作 checklist

只寫一個名詞：例如「三個 dashboard 方向」、「可合併的 React diff」或「可分享的 PR walkthrough」。

是視覺與互動、程式實作，還是溝通與展示？不確定性的種類比工具名稱更能決定工作表面。

用一句話完成：我選 [surface]，因為現在要先降低 [uncertainty]，產出 [artifact]。

若選 Claude Design 或 Claude Code artifacts，先確認帳號方案、管理員設定與可用裝置；不要把 beta availability 當成永久承諾。

你已選定工作表面。把決策句貼回對話視窗，請 AI 老師挑戰你是否把「探索設計」與「實作程式碼」混在一起。

觀念檢查（憑記憶作答）

1. 版面仍未定，想先比較三個視覺方向，應先用哪個表面？

此時最大的未知是視覺與互動方向，Claude Design 最適合先產生並比較原型。

2. frontend-design skill 的主要產物是什麼？

frontend-design 是 Claude Code plugin 裡的 skill，目標是建立可運作、具設計品質的前端介面程式碼。

3. 導入 Claude Design 前最誠實的做法是什麼？

Beta 的 availability、限制與使用量規則可能變動；導入前應以最新官方說明為準。

Phase 4 · 第 12 課 · 約 25 分鐘 · Closeout decision

判斷任務何時可以收尾（closeout）

目標：替整條 harness 工作流加上收工判斷。這一課只決定何時停止、何時人工 review、何時 rerun、何時降級回單次 agent；不新增 scheduler、不做 dashboard。

本課只做：產出 ship、review、rerun、blocked 或 downgrade 的決策。
先不要做：把 closeout 當成最後一個 command。

Closeout 是決策，不是最後一個 command

Claude Code best practices 把工作流收束到 tests、commit、PR 等可驗證成果；Hooks reference 也把 Stop 定義成 Claude 完成回應時的生命週期事件，甚至可用 Stop hook 要求 Claude 繼續補驗證。但 harness closeout 不能只靠模型說「完成」。

Cost tracking 提醒失敗 conversation 仍會消耗 token 與成本，所以 closeout 要有明確停止條件：證據夠了就收工，缺人類判斷就轉 review，缺環境就 blocked，重跑超過預算就停。

五種收工決策

Decision何時使用下一步
shipGates 通過、evidence 存在、handoff 可接手。交 reviewer 或開 PR。
review技術證據足夠，但產品、安全、風險需要人判斷。指定 owner。
rerun失敗原因明確、已修正、retry budget 還有額度。建立新 run。
blocked缺 credential、資料、環境或權限。記錄 unblock 條件。
downgrade任務不再重複、input 不穩、gate 沒價值。回到單次 agent。
判斷規則：closeout 必須讓下一個人知道「現在可以停止嗎？」以及「如果不能，誰要做什麼」。沒有 owner 的 open item 不算 closeout。

Closeout record 範例

{
  "runId": "run-0043",
  "decision": "review",
  "reason": "all gates passed but auth fixture still depends on staging token",
  "evidenceVerified": true,
  "handoffPath": ".harness/reports/run-0043-handoff.md",
  "retryBudgetRemaining": 0,
  "owner": "backend lead",
  "nextAction": "approve fixture strategy or provide stable test credential"
}

實作步驟（做完打勾）

只允許 ship、review、rerun、blocked、downgrade。不要留下「差不多好了」。

確認 final handoff 的 report、gate results、evidence directory 都存在。若 artifact 缺失，不能 ship。

若已經重跑過或沒有新修正，停止自動 rerun，改成 review 或 blocked。

所有非 ship 決策都要有 owner。下一步要可執行，不能只寫「再看看」。

把 closeout record 放進 final handoff。下一個 agent 或 reviewer 應該不用問你就知道狀態。

你已完成 closeout decision。回對話視窗貼上 closeout record，請 AI 老師檢查決策是否能防止無限重跑。

觀念檢查（憑記憶作答）

1. Gates 都過但仍需產品判斷，該選？

技術證據足夠但仍需要人類判斷時，應該轉 review，而不是假裝模型能替人決策。

2. 缺 credential 時，最適合的決策？

缺 credential、資料、環境或權限時，重跑通常只會重複失敗，應改成 blocked 並寫清 unblock 條件。

3. 任務不再重複時，harness 應該？

Harness 是為重複、穩定、可驗證的工作流服務；任務不再重複時，回到單次 agent 比維護 runner 更划算。

下一步

把 closeout decision 當作 harness 路線的收尾：能 ship 就交付，不能 ship 就明確轉 review、rerun、blocked 或 downgrade。接著進入 Phase 4 第 13 課：把 Phase 4 第 01–12 課串成一次真實 repo 的端到端演練。

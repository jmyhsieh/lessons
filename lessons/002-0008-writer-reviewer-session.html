用兩個 session 分工寫作與審查

任務目標：用兩個乾淨 session 分工：一個寫，一個審。你要練的是把 review 意見帶回 writer，而不是讓同一個對話自我確認。

本課只做：用兩個 session 分開寫作與審查。
先不要做：讓同一個 session 自寫自審後直接合併。

雙 session 流程

Writer sessionReviewer session
在 writer worktree 實作、驗證，建立 checkpoint commit。
在另一個 worktree 以明確 base ref 與 writer branch 讀取同一份 committed diff。
逐項處理 reviewer 意見。
為什麼要 checkpoint commit：不同 worktree 共用 git objects 與 refs，但不共用未提交的工作目錄變更。若 writer 只留下 uncommitted diff，reviewer worktree 看不到那份內容。

實作步驟（做完打勾）

照 Phase 1 第 11 課/Phase 1 第 12 課完成探索、實作、驗證與 diff review，然後在 writer branch 建立 checkpoint commit。先記下 base ref 與 writer branch，例如 main 與 claude/task-name。

在另一個 worktree 的乾淨 session，不必 checkout writer branch；用明確 refs 取得 committed diff，先確認檔案清單正是要審的範圍：

git diff --stat main...claude/task-name
git diff main...claude/task-name
Review the committed diff from main...claude/task-name
against this task brief. Only report correctness gaps,
missing tests, or scope creep.

不要全部照單全收。先分類：must fix / optional / not relevant。

修完 reviewer 意見後，重新跑原本的成功條件，並用新 commit 或 amend 更新 writer branch。若 diff refs 改變，reviewer 必須重新讀取新的 committed diff。

🎉 完成！你完成了一輪雙 session 品質工作流。

觀念檢查

1. 雙 session 比同一對話直接 review 的主要優點是？

乾淨 context 比「自己檢查自己」更接近獨立審查。

2. reviewer 回報很多建議時，第一步是？

review 意見仍要人類判斷，不是新的命令來源。

用 Open-Slide 建立可版本控制的簡報

進入條件／Code readiness：第 07 課的核心收尾已通過；新需求接受靜態 HTML／瀏覽器列印 PDF，且 Git 差異、React 客製或部署價值足以承擔 Node、儲存庫與 Review 成本。重用已驗證的來源包與故事板，只建立 3 頁 React 垂直切片，完成註解 → 編輯 → 建置 → 不可變 Review 的可重現迴圈。

本課只做：在獨立工作區重建封面、evidence、建議三頁並驗證靜態建置。
先不要做：重做整份簡報、把建置成功當成內容正確，或承諾 open-slide 能交付 PPTX。
完成邊界：這是選用 continuation；完成、跳過或失敗都不會增加或撤銷第 07 課的簡報完成。3 頁建置或本課 Review 也不能單獨構成簡報交付收尾。

先選對產製路線

Claude Design

以對話、畫布與註解精修視覺，可輸出 PPTX、PDF、HTML。

選它：需要畫布優先協作、PowerPoint 交接，或不想維護儲存庫。

open-slide

程式代理編寫固定 1920×1080 畫布的 React 頁面，工作區可進 Git，輸出靜態 HTML 或 PDF；瀏覽器檢查器也能直接調整元素並留下註解。

選它：需要版本差異、客製互動、可部署 HTML，而且團隊接受 React／Git 是 source of truth。

這是交錯練習，不是換工具重做內容。沿用同一份已查核主張，只比較編寫、審查、版本與匯出的差異。open-slide 的投影片是任意 React 元件，不是 PowerPoint 替代品。來源：open-slide Introduction。

在獨立工作區啟動

先確認 node --version 與 npm --version 可執行，再到不會形成巢狀儲存庫的父目錄建立工作區：

# 先驗證本課釘定的 CLI identity
npx --yes @open-slide/cli@1.3.2 --version

# 請在教材 repo 之外的獨立父目錄執行
npx --yes @open-slide/cli@1.3.2 init phase5-open-slide --name phase5-open-slide --use-npm --no-git
cd phase5-open-slide
npm audit
npm run dev

初始專案產生器會產生 AGENTS.md、CLAUDE.md、slides/、themes/ 與框架設定。先讓代理讀儲存庫規則，再使用工作區內技能；不要略過這個契約。來源：Getting started 與 Agent skills overview。

已知安全邊界：Source 操作配方在 2026-07-16 對初始專案跑 npm audit 時觀察到 2 個中等風險、1 個高風險的 Vite／esbuild 發現，且當時無修正版本。使用時必須重跑稽核、把結果留在 evidence；只在隔離本機做靜態建置，不把開發伺服器暴露給不受信任內容或網路。政策要求乾淨稽核時，停止並改選其他路線。

交給代理的有界限提示

Read AGENTS.md and use the local create-slide and slide-authoring skills.

Create a deck named phase5-vertical-slice with exactly 3 pages:
1. Cover — decision and audience
2. Evidence — one confirmed chart or comparison
3. Recommendation — trade-off, owner, and next action

Inputs:
- Storyboard: [貼上第 03 課的三張 cards]
- Confirmed sources: [貼上 source IDs；不要貼 pending items]
- Brand: [approved palette / type / assets]

Constraints:
- Use no new claims, quotes, logos, dependencies, or asset rights.
- Keep source IDs and caveats in the sidecar claim ledger.
- Plan the three pages before editing.
- After editing, run npm run build and report changed files and checks.

實作清單

交付接受 HTML／PDF，而且 Git 差異、React 客製或部署能力帶來實際價值；若必須交可編輯 PPTX，留在 Claude Design 主線。

啟動開發伺服器，確認起始投影片可開啟；不要在目前教材儲存庫裡執行 init。

在瀏覽器檢查器指定元素、問題、保留項與成功條件，再請代理使用 apply-comments；不要用「更好看」當回饋。

執行 npm run build 與 npm run preview，打開 dist/ 版本；依第 06 課重查主張、權利與鍵盤導覽，再依第 07 課檢查目標螢幕與真實彩排。PDF 要從 Export → PDF 或 ?print=1 另行檢查。建置 green 只證明工具能產生輸出。

commit 成不可變候選版本 SHA，依 Repo Review contract分開做 Standards Review 與 Spec Review。任何發現修正都要建立新 SHA，重跑建置／checks 與兩個 Review；不可把舊 evidence 搬到新候選版本。

具體成果：一個精確的 3 頁 Open-Slide 垂直切片、靜態建置、Git 差異與綁定精確候選版本 SHA 的 Review 套件。
可觀察回饋：另一位審查者能由同一 SHA 重建建置、逐一對照三頁與來源 ID，並在目標螢幕只用鍵盤操作；記錄主張不一致、導覽失敗、版面溢出與 Review 發現，而非只評「好不好看」。

觀念檢查

1. 哪種需求最適合 open-slide？

open-slide 的檢查器也能直接調整元素並留下註解；真正的分界是 React／Git 是否能作為 source of truth，以及交付是否必須是可編輯 PPTX。

2. open-slide 建置成功後，下一步是什麼？

建置只證明可產生靜態輸出；內容、權利、可及性、目標環境與聽眾理解仍需要獨立證據。

Phase 5 · 005-0009 · 約 45–60 分鐘 · Conditional Code-first elective

用 Open-Slide 建立可版本控制的 deck

Entry／Code readiness：第 07 課的 core closeout 已通過；新需求接受 static HTML／browser-print PDF，且 Git diff、React 客製或部署價值足以承擔 Node、repo 與 Review 成本。重用已驗證的 source pack 與 storyboard，只建立 3 頁 React vertical slice，完成 comment → edit → build → immutable Review 的可重現迴圈。

本課只做：在獨立 workspace 重建 cover、evidence、recommendation 三頁並驗證 static build。
先不要做：重做整份 deck、把 build 成功當成內容正確，或承諾 open-slide 能交付 PPTX。
Completion boundary：這是 optional continuation；完成、跳過或失敗都不會增加或撤銷第 07 課的 Presentation completion。3 頁 build 或本課 Review 也不能單獨構成 Presentation closeout。

先選對產製路線

Claude Design

以對話、canvas 與 comments 精修視覺，可輸出 PPTX、PDF、HTML。

選它：需要 canvas-first 協作、PowerPoint 交接，或不想維護 repo。

open-slide

Coding agent 編寫固定 1920×1080 canvas 的 React pages，workspace 可進 Git，輸出 static HTML 或 PDF；browser inspector 也能直接調整元素並留下 comments。

選它：需要版本差異、客製互動、可部署 HTML，而且團隊接受 React／Git 是 source of truth。

這是 interleaving 練習，不是換工具重做內容。沿用同一份已查核主張，只比較 authoring、review、版本與 export 的差異。open-slide 的 slides 是任意 React components，不是 PowerPoint replacement。來源：open-slide Introduction。

在獨立 workspace 啟動

先確認 node --version 與 npm --version 可執行，再到不會形成 nested repo 的父目錄建立 workspace：

# 先驗證本課釘定的 CLI identity
npx --yes @open-slide/cli@1.3.2 --version

# 請在教材 repo 之外的獨立父目錄執行
npx --yes @open-slide/cli@1.3.2 init phase5-open-slide --name phase5-open-slide --use-npm --no-git
cd phase5-open-slide
npm audit
npm run dev

Scaffolder 會產生 AGENTS.md、CLAUDE.md、slides/、themes/ 與 framework config。先讓 agent 讀 repo rules，再使用 workspace-local skills；不要略過這個 contract。來源：Getting started 與 Agent skills overview。

已知安全邊界：Source recipe 在 2026-07-16 對 scaffold 跑 npm audit 時觀察到 2 個 moderate、1 個 high 的 Vite／esbuild findings，且當時無修正版本。使用時必須重跑 audit、把結果留在 evidence；只在隔離本機做 static build，不把 dev server 暴露給不受信任內容或網路。政策要求 clean audit 時，停止並改選其他 route。

交給 agent 的 bounded prompt

Read AGENTS.md and use the local create-slide and slide-authoring skills.

Create a deck named phase5-vertical-slice with exactly 3 pages:
1. Cover — decision and audience
2. Evidence — one confirmed chart or comparison
3. Recommendation — trade-off, owner, and next action

Inputs:
- Storyboard: [貼上第 03 課的三張 cards]
- Confirmed sources: [貼上 source IDs；不要貼 pending items]
- Brand: [approved palette / type / assets]

Constraints:
- Use no new claims, quotes, logos, dependencies, or asset rights.
- Keep source IDs and caveats in the sidecar claim ledger.
- Plan the three pages before editing.
- After editing, run npm run build and report changed files and checks.

實作 checklist

交付接受 HTML／PDF，而且 Git diff、React 客製或部署能力帶來實際價值；若必須交可編輯 PPTX，留在 Claude Design 主線。

啟動 dev server，確認 starter slide 可開啟；不要在目前教材 repo 裡執行 init。

在 browser inspector 指定元素、問題、保留項與成功條件，再請 agent 使用 apply-comments；不要用「更好看」當回饋。

執行 npm run build 與 npm run preview，打開 dist/ 版本；依第 06 課重查 claims、rights 與 keyboard navigation，再依第 07 課檢查目標螢幕與真實彩排。PDF 要從 Export → PDF 或 ?print=1 另行檢查。Build green 只證明工具能產生輸出。

commit 成 immutable candidate SHA，依 Repo Review contract分開做 Standards Review 與 Spec Review。任何 finding 修正都要建立新 SHA，重跑 build／checks 與兩個 Review；不可把舊 evidence 搬到新 candidate。

Tangible win：一個 exact 3-page Open-Slide vertical slice、static build、Git diff 與綁定 exact candidate SHA 的 Review bundle。
Observable feedback：另一位 reviewer 能由同一 SHA 重建 build、逐一對照三頁與 source IDs，並在 target screen 只用鍵盤操作；記錄 claim mismatch、navigation failure、layout overflow 與 Review findings，而非只評「好不好看」。

觀念檢查

1. 哪種需求最適合 open-slide？

open-slide 的 inspector 也能直接調整元素並留下 comments；真正的分界是 React／Git 是否能作為 source of truth，以及交付是否必須是可編輯 PPTX。

2. open-slide build 成功後，下一步是什麼？

Build 只證明可產生 static output；內容、權利、可及性、目標環境與聽眾理解仍需要獨立證據。

選修收尾、返回與主要閱讀

把命令、prompt、停止線保存成 open-slide agent deck 速查表。Static HTML／PDF 的正式邊界見 open-slide Export。

Return／continuation：Review bundle 通過後，直接回 課目表。只有新的 diagram-as-code 需求才另選 Mermaid CLI elective；不要把 one-pager 或 diagram 當成本課的必修下一步。

合法停止點：CLI identity 不符、audit 不符合政策、repo rules 未讀、source ID／rights 不可追溯、static build 未驗證、target-screen accessibility／rehearsal 未跑、candidate 未固定，或任一 Review finding 未解決時，保留 workspace 與 evidence 後停止。回本課對應步驟或 005-0002修正；不可擴成完整 deck、發布，也不可改寫 core closeout。

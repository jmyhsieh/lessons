Phase 4 Lab · 第 02 課 · 約 40 分鐘 · Harness contract

定義 input、gate、evidence 與交付契約

目標：把值得 harness 化的任務寫成完整 contract：穩定 input、可執行 gates、可回看的 evidence，以及分工清楚的 report／handoff。這一課先固定契約，不寫 runner。

本課只做：產出一份 runner 可以忠實執行的 harness contract。
先不要做：在 input、gate 或 evidence 還模糊時先自動化。

為什麼 issue / brief 要先 harness-ready

Claude Code best practices 強調兩件事：給 Claude 可執行的驗證方式，並在 prompt 裡提供具體脈絡。這正是 harness-ready issue / brief 的用途：讓每次啟動都拿到同樣清楚的任務，而不是靠你在對話裡臨場補洞。

模糊需求 → harness-ready issue / brief → runner prompt → gate → evidence

如果 input 不穩，後面即使加上 claude -p、Agent SDK 或 CI，也只是把模糊需求自動化。

一份 issue / brief 要有六格

欄位寫在 issue 或 brief 裡的內容例子
ID這次任務可追蹤的名稱。issue-0042-login-timeout
Source任務正本在哪裡，不要把全文複製到每個地方。issues/0042.md
Outcome完成後使用者或團隊能觀察到什麼。逾時後重新登入不會卡在空白頁。
Scope允許碰哪些路徑、系統或資料。src/auth/**、tests/auth/**
Gates哪些檢查失敗就不能收工。npm test -- auth、人工 review
Stop遇到哪些缺口必須停下來問人。需要 production secret、要改 migration、需求互相衝突。
判斷規則：一個陌生 agent 只看這份 issue / brief，就應該能開始探索、知道不能碰哪裡、知道怎麼驗收、知道何時必須停下來問你。

Gate、evidence 與交付物

項目回答什麼最低要求
Scope gate有沒有碰到契約以外的路徑或系統？可判定的 allowed paths／protected files。
Verification gate需求是否真的成立？可重跑 command 與 pass/fail。
Review gate哪些部分仍需人類判斷？明確 reviewer 與 artifact。
Evidence為什麼可以相信 gate 結果？command、result、artifact path、decision。
Report這一輪發生了什麼？status、changes、gates、exceptions、next。
Handoff下一個 agent 如何接手？current state、canonical links、decisions、next action。
單一事實來源：report 與 handoff 只引用 spec、ticket、diff、evidence 的正本，不複製全文。沒有 pass/fail 或明確 reviewer 的項目只是提醒，不是 gate。

實作步驟（做完打勾）

只挑一個。最好是重複、可驗收、常讓你重講背景的任務，例如「每週整理 bug issue」或「修登入回歸」。

打開 Harness-ready issue / brief 速查表，把 ID、Source、Outcome、Scope、Gates、Stop 填完。

圈出「改善、整理、處理、看一下、幫我」這類詞。每個都要改成可觀察結果、允許範圍或明確停止條件。

使用 Gates／evidence 速查表，確認每個 gate 都有 command、result、artifact 或 reviewer decision。

用 Report／handoff 速查表 分開兩種讀者：reviewer 看結果，下一個 agent 看接手方式。最後確認 Source、Scope、Gates、Evidence、Report、Handoff 都有固定位置。

你已完成第一份 harness contract。回對話視窗貼上 input、gates、evidence、report 與 handoff 定義，請 AI 老師找出仍靠口頭保證的地方。

觀念檢查（憑記憶作答）

1. 這一課的主要產物是什麼？

Phase 4 第 02 課只把 issue / brief 的任務來源、範圍、驗收與停止條件寫穩，還不是 runner 或測試報告。

2. contract 裡遇到 production secret 才能繼續，應該怎麼做？

Production secret 屬於 Stop 條件。Agent 應停止並回報缺口，不應自行假設或繞過權限。

3. 為什麼不要太早把流程接進 CI 或 SDK？

如果 issue / brief 的 input contract 不穩，自動化只會放大模糊需求；先穩住 Source、Scope、Gates、Stop。

4. 哪一項才是可重跑的 evidence？

Evidence 必須讓 reviewer 能回看 gate 為何通過；口頭保證與聊天印象不能重跑，也不能追查。

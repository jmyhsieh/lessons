研究 / 資料職能 — 從 paper 到可重跑結果

目標：把 Claude Code 用成研究助理，而不是結論製造機。你要練的是交付能重跑、能質疑、能說明限制的研究包。

研究 / 資料職能的穩定流程

研究問題 → paper / data inventory → Claude Code 重現 → oracle tests → domain review → limitation note

研究案例提醒我們：測試通過不代表理論正確。prompt、資料版本、domain invariant 與失敗原因都要留下。

槽位對照

槽位研究問題下一個 artifact
定義要重現哪個 claim？paper / data inventory
製作如何把方法轉成可跑流程？script / notebook
驗證結果是否對得上？oracle tests / comparison table
校準哪些地方需要專家判斷？domain review 與 limitation note

實作步驟

列 paper、data、環境、版本、預期輸出。缺一項就標成風險，不要假裝完整。

請它先產 script / notebook 與執行方式，再跑測試或輸出比較表。

把已知不變條件、數值範圍、資料筆數、baseline 結果寫成檢查。

記錄失敗、偏誤、prompt framing、資料限制與哪些地方需要 domain reviewer。

完成研究 / 資料職能演練。把你的研究問題貼回對話，請 AI 老師幫你找最脆弱的驗證點。

觀念檢查

1. 研究職能最重要的交付是？

研究要能被重跑與質疑，不能只留下結論。

2. oracle tests 的限制是？

測試抓得到一部分錯誤，但理論假設與 domain invariant 仍要專家判斷。

3. prompt framing 應該怎麼處理？

prompt framing 會影響偏誤，應和資料、程式碼、版本一起留下。

創業 / Founder 職能 — 從洞察到市場回饋

目標：把 Claude Code 用成 founder 的速度槓桿，而不是問題定義的替代品。你要練的是用 AI 加速產品切片，同時保留使用者理解、review 與取捨。

Founder 職能的穩定流程

使用者洞察 → 一頁 spec → Claude Code 做產品切片 → founder review → 真實使用者回饋 → 下一輪假設

Founder 案例的共同訊號是：實作成本下降後，稀缺能力會跑到問題定義、spec quality、review 與市場回饋。

槽位對照

槽位Founder 問題下一個 artifact
洞察哪個痛點真的存在？使用者片段與假設
Spec第一個切片要做什麼？一頁 spec
Build怎樣最快讓人試？demo / internal tool
Review哪些地方不能放給 AI 自行決定？review checklist

實作步驟

不要從功能開始。先寫出你最近聽到的使用者痛點、發生場景與目前替代方案。

把範圍壓到一個切片：輸入、行為、輸出、非目標、不能自動決定的取捨。

要求它交付 demo 或 internal tool，同時附上測試方式、限制與待確認問題。

安排真實使用者或內部 operator 試用，記錄下一輪假設，而不是繼續堆功能。

完成 Founder 職能演練。把你的產品切片貼回對話，請 AI 老師檢查是否缺少使用者證據。

觀念檢查

1. Claude Code 寫 code 變快後，Founder 更該負責什麼？

實作成本下降後，真正稀缺的是判斷哪個問題值得做。

2. 一頁 spec 最該包含什麼？

非目標能防止範圍膨脹，驗收條件讓 demo 可被判斷。

3. Demo 完成後，下一步是？

Founder 的流程要回到市場訊號，否則只是快速製造功能。

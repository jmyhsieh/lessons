Phase 3 · Deliver · 003-0008 · Conditional branch

只把 active source normalize 成可檢查的 working copy

進入條件：Raw source 可合法處理，但其 PDF、Office、image 或 layout 讓 claim extraction 不可靠。Readable source 不需轉換；MarkItDown 與 Docling 是二選一，不是連續必修。

依 source shape 選一個工具

選擇適合必查邊界
MarkItDown需要輕量 Markdown working copy，原檔結構相對直接。Output 服務 text analysis，不代表 human-layout fidelity；process I/O 權限必須受限。
DoclingLayout、table、OCR 或 structured output 需要較細檢查。限制 input／output；remote services 與 external plugins 未明確授權時保持關閉。

  1. 在隔離環境閱讀 current official help，只選一個 converter 與最窄 input scope；raw file 保持不變。
  2. 輸出到獨立 working directory，記錄 tool、time、options 與 normalized file identity。
  3. 抽查開頭、含 table／image 的一段與結尾；比較 headings、reading order、numbers、links、footnotes 與 missing content。
  4. 把錯置、OCR uncertainty 與缺少元素標在 transformation record；不得靜默修成看似合理的文字。
Tangible win：一份不覆蓋 raw source、帶 transformation record 的 normalized working copy。
Observable feedback：Reviewer 能用抽樣位置重做 raw／normalized 對照，辨識工具選擇、remote boundary 與至少一項已檢查的 fidelity risk。

一份可直接閱讀的 Markdown source 已有 stable ID，下一步應該是？

Normalization 只修正 active source 的可用性缺口；沒有缺口就不增加 derived copies。

Return／legal stop：抽樣 fidelity 可接受且 limitations 已記錄後，回 003-0003；工具成功不是 route completion。若 rights、sensitive-data policy、input boundary、remote behavior 或數字／reading order 無法驗證，保存 raw source 與 failure log 後停止，改用 manual extraction 或回 readiness。

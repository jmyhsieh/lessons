Phase 3 · Deliver · 003-0010 · Conditional branch

用 DuckDB 產生一個可重算的 tabular finding

進入條件：Active evidence 是 CSV、Parquet 或其他支援的 tabular source，而且 mission 有一個可用 SQL 回答的 bounded question。若只需閱讀幾列，直接抽查即可。

先定義 query contract

Question / decision supported:
Source ID / file identity / captured at:
Read-only or in-memory boundary:
Expected schema, grain, units, time range:
Null / duplicate / exclusion rules:
Exact SQL and DuckDB version:
Output path:
Sample-row and aggregate reconciliation:
  1. 依 current official DuckDB documentation確認 file reader 與 CLI option；優先 read-only 或 in-memory，不覆寫 source。
  2. 先看 schema、row count、null、duplicate、units 與時間範圍；把 data grain 寫進 query contract。
  3. 保存 exact SQL，再輸出一個 bounded table。Filter、join、denominator 與 aggregation 要能由 reviewer 看懂。
  4. 抽查至少三個 source rows，並以獨立 subtotal 或簡單計算對照 aggregate；將 discrepancy 保留為 limitation。
  5. 把 finding、query、output 與 source locator 一起帶回 claim ledger；query result 不會自動成為 interpretation。
Tangible win：一個帶 exact SQL、schema assumptions、output 與 reconciliation record 的 tabular finding。
Observable feedback：Reviewer 能重跑 query 得到同一結果，追到抽樣 source rows，並說明 filter、denominator 與 limitation 如何影響 finding。

Aggregate 看起來合理，但 denominator 的 null rows 未定義，該怎麼做？

可重跑不代表語意正確；schema、grain、null 與 denominator 都是 claim boundary。

Return／legal stop：Finding 通過 sample-row 與 aggregate reconciliation 後，回 003-0003；不要把 DuckDB 練習升格為 Knowledge completion。若 schema、units、join key、rights 或 discrepancy 無法釐清，保存 SQL 與 failure evidence 後停止，不輸出確定語氣的結論。

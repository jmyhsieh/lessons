第 3 階段 · 交付 · 003-0010 · Conditional 分支

用 DuckDB 產生一個可重算的表格發現

進入條件：目前 evidence 是 CSV、Parquet 或其他支援的表格 source，而且任務有一個可用 SQL 回答的有界限的問題。若只需閱讀幾列，直接抽查即可。

先定義查詢契約

Question / decision supported:
Source ID / file identity / captured at:
Read-only or in-memory boundary:
Expected schema, grain, units, time range:
Null / duplicate / exclusion rules:
Exact SQL and DuckDB version:
Output path:
Sample-row and aggregate reconciliation:
  1. 依目前官方 DuckDB 文件確認檔案讀取器與 CLI 選項；優先唯讀或 in-memory，不覆寫 source。
  2. 先看 schema、列數量、空值、重複值、單位與時間範圍；把資料粒度寫進查詢契約。
  3. 保存精確 SQL，再輸出一個有界限的表格。篩選、關聯、分母與彙總要能由審查者看懂。
  4. 抽查至少三個 source 列，並以獨立小計或簡單計算對照彙總結果；將差異保留為限制。
  5. 把發現、查詢、輸出與 source 定位一起帶回主張台帳；查詢結果不會自動成為詮釋。
具體成果：一個帶精確 SQL、schema 假設、輸出與調節紀錄的表格發現。
可觀察回饋：審查者能重跑查詢得到同一結果，追到抽樣 source 列，並說明篩選、分母與限制如何影響發現。

彙總看起來合理，但分母的空值列未定義，該怎麼做？

可重跑不代表語意正確；schema、粒度、空值與分母都是主張邊界。

返回／合法停止：發現通過樣本列與彙總結果調節後，回 003-0003；不要把 DuckDB 練習升格為知識完成。若 schema、單位、關聯鍵、權利或差異無法釐清，保存 SQL 與失敗 evidence 後停止，不輸出確定語氣的結論。

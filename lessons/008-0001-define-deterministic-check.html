Phase 8 · Operate · 008-0001 · Route entry

先把「做完了」寫成 agent 無法自評通過的 check

Mission／entry：帶入一個已由人手安全完成過、值得重複的 local workflow，以及它的真實 inputs、允許處理的 fixture、預期 output 與已知 failure。你必須具備 Code readiness，能辨識 repo instructions、權限、diff 與 relevant checks；本 route 只在 recoverable local fixture 練習，不要求 production mutation。

Precondition：若 manual success 沒有可識別 inputs、可觀察 output 或 recoverable fixture，先停止並縮小 workflow。不要因為 agent 說「已完成」、沒有 error、status 顯示 green，或檔案存在，就把 completion 當作已證明。

2. 選一個獨立於 agent 敘述的 oracle

工作結果Deterministic predicate不夠可靠的替代品
產生固定格式檔案Parser 成功、必要欄位等於已知 literal、禁止欄位不存在。「檔案已建立」或 agent 摘要。
轉換一組 bounded records輸入 ID 集合與輸出 ID 集合精確對應，錯誤清單為空。只看處理筆數或最後一行 green。
更新 local fixture state由 public read interface 查得預期 state，且 fixture 外 fingerprint 未變。查內部暫存值或相信 write command exit 0。

Oracle boundary：能用 deterministic code 計算的 routing、count、schema、hash、status 與 invariant，就不要交給模型判斷。品質、風險或是否接受殘餘限制仍由 learner 判斷，不能偽裝成機械 pass。

3. 先校準 failure，再保存 baseline

  1. 在 disposable copy 對一個已知不完整或刻意錯誤的 output 跑 check，確認它以預期 predicate 失敗；setup error 不算 decisive failure。
  2. 對已知正確的 manual result 跑同一 check，記錄 command／inspection、exit、關鍵 output、input identity 與時間。
  3. 保存 fixture 外的 read-only fingerprint 或範圍清單，供後續判斷 workflow 是否越界。
  4. 請另一個人只看 contract，指出一個可能誤報成功的情境；補強 predicate，而不是加一句 agent prompt。
Tangible win：一份綁定真實 inputs、反證條件與已校準 failure／success 的 deterministic completion contract。
Observable feedback：Reviewer 能在不讀 agent 對話的情況下，讓同一 check 對錯誤 fixture 失敗、對已知正確 fixture 通過，並指出哪些判斷仍需要人。

哪一項能作為 operating workflow 的 completion oracle？

可靠 oracle 必須針對本次輸入，以可重跑 predicate 產生可反證結果；agent 自評與未綁定 run identity 的綠燈都不是 completion proof。

Legal stop／return／continuation：沒有 safe fixture、input identity、可反證 predicate、已知 failure 校準或 Code readiness 時，保存 contract draft，依缺口回 readiness／originating route；不要啟動任何 write-capable automation。Contract 能由別人重跑後，進 008-0002 選一個 local-first execution surface。此時只完成 oracle，不代表 workflow、Phase 或 Migration complete。

Phase 7 · 驗證 · 007-0006 · Conditional diagnosis

只有 failure 還解釋不了，才保留 trace

條件式進入：只在 007-0005 的 test 仍失敗／flaky，而且 failure output、direct observation、console／request evidence不足以區分假說時進入。若同一 test 已有 decisive RED 與 corrected GREEN，立刻 bypass 本課，直接準備 007-0007 addendum；trace 不是每次必跑的 evidence tier。

操作方式校準：2026-07-17 以 @playwright/test@1.61.1 將 trace 設為 failure-only conditional：faulty run 在 TRACE_MODE=1 產生非空 trace.zip；corrected rerun 在 TRACE_MODE=0 通過且沒有 trace artifact。這證明設定行為，不代表 trace 內容已診斷你的 app。

進入判定準則：如果你不能寫出至少兩個可被 trace 區分的假說，先不要 capture。Trace 是用來回答已命名的診斷問題，不是為 addendum 增加一個漂亮附件；screenshot 或 trace 本身也不會讓 assertion 變成 durable。

2. 將 capture 限定在 failing run

// playwright.config.ts — 只示範 conditional shape
const diagnose = process.env.PW_DIAGNOSE === '1';

export default defineConfig({
  retries: 0,
  use: { trace: diagnose ? 'retain-on-failure' : 'off' }
});

# 只跑 exact failing test；使用 repo command 與已核准 artifact path
PW_DIAGNOSE=1 npx playwright test tests/browser/checkout.spec.ts \
  --grep "guest can complete checkout" --retries=0

# 在可信本機環境查看，不把 artifact 上傳未知服務
npx playwright show-trace path/to/trace.zip
檢查面只記 direct observation另列 inference
操作／DOMClick 前後 locator、visible state、URL 與 timing。「可能等待錯誤 element」仍是 hypothesis。
Console／網路Exact message、request URL／method／status、response timing；敏感 payload 不抄入 notes。「API壞了」要由具體 response 或另一個 check驗證。
原始碼／stackTrace 能顯示的 call與 failure point。Root cause 仍須由修正後同 assertion rerun證明。
Artifact 檔案Local path、SHA／size、capture mode、retention與 cleanup。有 trace 不等於找到原因，也不等於 real-user evidence。

3. 用 trace 導出一個可反證 repair

  1. 將 trace observation 對回已命名 hypotheses；不符合的明確排除，仍未知的保持 unknown。
  2. 只修最小 root cause 或 controlled fixture；若 app／test candidate 有任何 byte 改變，記錄新 candidate identity，稍後重新套用完整 Review contract。
  3. 以 PW_DIAGNOSE=0 重跑同一 test／assertion；GREEN 才是 repair evidence，trace 不是。
  4. 確認正常路徑沒有新 trace artifact；保留必要 artifact identity與精簡 observation，依 retention plan清理原檔。

隱私／成本邊界：Trace 可能包含 DOM、URL、request metadata、console、source與 screenshots。只在 safe fixture或已核准資料範圍 capture；不要用真實 secrets、payment、personal data或未授權 logged-in workflow做教材練習。看見超出 authority 的資料就停止、隔離並依 repo policy清理，不要把 trace attach 到 issue、PR或外部服務。

可見成果：一份只為未解 failure建立的 trace diagnosis record，包含 capture justification、artifact identity、direct observations、分離的 hypotheses、bounded repair與 trace-off GREEN rerun。
可觀察回饋：Reviewer 能指出 trace 中哪一項 observation 排除／支持哪個 hypothesis，並確認正常 rerun 沒有依賴 trace；若拿掉 trace 仍沒有可驗證的 repair decision，本課尚未完成。

007-0005 已有同 identity 的 decisive RED 與 corrected GREEN，沒有未解 failure。下一步是？

Trace 是 conditional diagnosis artifact。Durable claim 的核心是同 assertion能對故障 RED、修正後 GREEN；沒有診斷問題就不應增加 capture。

合法停止／返回／續行：Trace justification 不成立、capture 可能越過資料／site／artifact authority、artifact viewer不可信、trace無法區分 hypotheses、repair 後同 test不綠、結果仍 flaky、cleanup 未完成，或變更後 candidate 尚未重新 Review 時，保存 non-sensitive facts並停止；回 007-0005重新建立可比較 failure，或回 originating Engineering route 修 candidate。只有 trace observation導出可反證 repair且 trace-off rerun GREEN後，才續到 007-0007；完成本 conditional lesson 不代表 Browser evidence route、Phase 或 Migration complete。

Phase 10 · 入門第 04 課 · 約 15 分鐘

把 Markdown 與原始文件逐項對照

本課成果：一份記錄缺頁、OCR 錯字、表格與閱讀順序的人工查核表。

不要只讀順暢段落：轉換錯誤最常藏在換頁處、數字、專有名詞、表格與多欄版面。抽查首頁、中間頁、末頁和一個高風險區塊，才能決定能否往下使用。

做一次最小品質查核

確認首頁標題與末頁內容都在，而且輸出頁數沒有明顯短少。若輸出缺少整頁，先標記為受阻（blocked），不要用模型猜回內容。

抽一段含專有名詞與數字的文字逐字比對，再檢查一張表格和一個多欄或圖說區。記下頁碼、原文、轉換結果與影響。

範圍：首頁／中間頁／末頁／表格 1
結果：通過 3，需修正 1
問題：第 7 頁料號 O 被辨識為 0
決定：修正後可供搜尋；金額仍須回原始 PDF 查核
原檔：docs/vendor-guide.pdf
輸出：converted/vendor-guide.md
入門完成：你有一份已人工抽查的 Markdown 與明確使用限制，不再把「有輸出」當成「可信」。

觀念檢查

哪項最能證明轉換結果可供後續使用？

命令跑完、文章讀起來順，都可能掩蓋缺頁、數字或表格錯誤；原檔對照才是品質證據。

關鍵判斷

轉換完成時，應保留原始內容的來源、查核結果與使用限制，不必把每份文件硬修成完美 Markdown。

主要閱讀：Docling usage 與 MarkItDown README；查核欄位見 文件轉 Markdown 路線卡。

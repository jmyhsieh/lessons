Phase 4 · Design · 004-0005 · Refinement

一次精修一層，讓每個 revision 都能解釋

Entry：已選定一個 direction，並保留 baseline revision 與選擇理由。本課把 feedback 轉成 bounded revisions，不用「再好看一點」覆蓋決策歷史。

用 feedback 類型控制 revision scope

Layer一次可改Feedback oracle
Content／hierarchy標籤、順序、資訊優先級使用者能找到並理解關鍵內容
Interaction／states一條 task path 與其 loading／empty／error指定 task 可完成，狀態變化可理解
Responsive一個 viewport range 的 reflow／control不溢位，核心 action 保持可達
Visual system一組 approved tokens 或 component treatment與 system source 一致，層級仍清楚

Change isolation：先記錄 baseline，選一個 feedback claim，只改一層，重新執行相同 task，再決定 accept／revise／revert。Direct canvas edit、inline comment 與 chat 都可以用；它們不改變 evidence 要求。

建立 revision ledger

Decision: accept / revise / revert
Reason / remaining assumption:
  1. 把一則 feedback 轉成具體 expected improvement；無法觀察就先釐清。
  2. 保存 revision identity，再做最小變更；不要順手重畫其他 sections。
  3. 用相同 task 與資料重跑，記錄 improvement 與 regression。
  4. 由學習者 disposition：accept、revise 或 revert，並保留理由。
Tangible win：一份至少含 baseline 與一輪 accept／revise／revert 判斷的 revision ledger。
Observable feedback：Reviewer 能切回 baseline、重跑同一 task，判斷變更是否真的改善 feedback claim，並指出被同時改動而無法歸因的層。

Reviewer 說找不到主要 action，最可驗證的下一輪是？

隔離單一 layer 才能把 observable change 歸因到這次 revision，也保留 revert 能力。

Legal stop／continuation：Baseline 不可回復、feedback 沒有來源、單一 revision 混改多層，或 task rerun 未記錄時，保留 ledger 並停止擴大。Selected revision 可重現且主要 feedback 已 disposition 後，進 004-0006 prototype assumptions。

Phase 9 · 入門第 03 課 · 約 12 分鐘

決定由你手動啟用，還是讓 Claude 自動啟用

本課成果：一張 repo-checkpoint 啟用方式決策卡。

兩種負擔：Claude 自動啟用（model-invoked）會把 description 列在 Claude 可見的 Skills 清單，增加對話脈絡負擔（context load）；使用者手動啟用（user-invoked）則要由工程師記得何時輸入名稱，增加使用者記憶負擔（cognitive load）。兩者沒有永遠比較好的答案。

先問誰該決定時機

repo-checkpoint 只在你要暫停、交接或盤點時使用，時機由人決定，因此第一版選擇手動啟用。若是 Claude 每次寫 API 端點都必須套用的共同規範，才較可能選擇自動啟用。

請 Claude Code 確認有 disable-model-invocation: true。description 仍保留給人閱讀的一行摘要，但不需要堆滿重複同義詞。

---
name: repo-checkpoint
description: Summarize current work as Changed, Verified, Remaining, and Blocked.
disable-model-invocation: true
---

記錄「使用者手動啟用／由人控制收尾時機／接受記住一個名稱／不讓它在無關對話自動出現」。不要只抄 YAML。

完成：啟用方式、代價與實際檔頭設定已對齊。

觀念檢查

哪個情境最適合由使用者手動啟用？

帶外部影響或需要人選時機的工作流程，通常應由人明確啟用。自動啟用適合 Claude 必須自行發現的知識或流程。

關鍵判斷

啟用方式是設計選擇；只開啟真實工作流程需要的自動啟用。

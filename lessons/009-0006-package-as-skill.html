Phase 9 · 標準化 · 009-0006 · 條件式分支

把跨工作區的有界指示封裝成可重用 Skill

進入條件：009-0003已選 skill，因為同一已證明的工作流需要跨工作區被正確觸發，且契約、受眾、相依項目、負責人與發布邊界都清楚。Skill 是指示套件，不是工作流證明、工具安裝程式、權限授予或通用政策。

1. 先設計觸發條件，再配置漸進式揭露

能力邊界：Skill 可以指示如何使用已可用的能力，但不能創造工具、憑證、沙箱存取或核准。缺相依項目時應輸出缺口與安全停止點，不得偷偷安裝、改全域設定或改用未授權服務。

2. 用觸發條件矩陣驗證選擇性

測試材料預期結果
指定的正向任務觸發 Skill，讀取最少必要資源，依契約產生證據。
近似但不符合的任務不觸發，或先指出缺少的關鍵輸入。
缺少相依項目停止並列出缺口，不安裝、不擴權。
外部寫入要求要求當次權限、目標與承載內容；Skill 文字不算核准。
失敗測試資料判定依據失敗，保留證據並依已宣告的復原／安全停止點處置。

3. 在全新脈絡重跑套件

  1. 建立隔離測試資料，只安裝或掛載指定的 Skill 套件與已宣告的相依項目；不要帶入作者工作階段。
  2. 以一個正例與至少一個近似反例執行；保存輸入、是否觸發、載入資源、步驟、檢查輸出與停止原因。
  3. 由另一位審查者比對 Skill 行為與萃取出的契約，確認套件沒新增承諾、權限或隱藏相依項目。
  4. 任何修訂都增加套件版本／摘要並重跑受影響測試資料。
套件證據
可見成果：一個具備有界觸發條件、漸進式資源、版本／負責人與全新脈絡測試證據的可重用 Skill 套件。
可觀察回饋：正例會選中並完成已宣告的檢查；近似反例不誤觸發，缺相依項目／權限時安全停止，審查者能把行為逐項追到工作流契約。

Skill在全新脈絡發現缺少CLI相依項目，契約未授權安裝。正確行為是？

套件不會擴張能力或權限；缺少的相依項目是可觀察的stop，不是繞過邊界的理由。

合法停止／返回／續行：觸發條件無法區分近似反例、資源重複真實來源、相依項目／發布方式／負責人不明、全新脈絡依賴個人狀態，或 Skill 擴張權限時，保存測試證據並回 009-0003／009-0002。只有精確套件版本通過正例、近似反例、缺少相依項目與失敗檢查，才前往 009-0008-complete-standardization-closeout.html；不要再完成其他套件分支。

權限模式與 plan mode — 省力但同樣安全

任務目標：認識所有權限模式，學會「先 plan mode 看計劃 → 再放行執行」的工作節奏，並設定一條 deny 規則硬擋 git push — 把第 4 課說的「技術閘門」真正裝上。

六種權限模式（官方文件）

模式行為正式專案建議
default每類工具第一次使用時詢問✅ 日常基準
plan只能讀檔與唯讀指令，不能改任何東西✅ 任務開頭先用這個
acceptEdits自動接受工作目錄內的檔案編輯⚠️ 信任度高的小任務再用
auto自動批准＋背景安全檢查（研究預覽）⚠️ 同上
dontAsk未預先允許的工具一律自動拒絕特殊自動化情境
bypassPermissions跳過所有詢問🚫 只能用在容器/VM 等隔離環境

切換方式：桌面 App 用輸入框旁的模式選單；CLI 按 Shift+Tab 循環（第 2 課練過）。

核心工作節奏：plan → review → 放行

第 3 課你是用「嘴巴」要求它先給計劃。plan mode 是同一件事的系統強制版：模式本身保證它只能探索、不能動手。建議的節奏：

  1. 切到 plan mode，描述任務 → 它探索 codebase、產出計劃
  2. 你審計劃，來回修到滿意
  3. 批准計劃離開 plan mode → 它才開始實作（回到逐項詢問）
任務越大、越不確定，plan mode 的價值越高。一行小改可以跳過；跨檔案的修改一律先 plan。

permission 規則：真正的硬閘門

第 4 課的觀念檢查考過你：「禁推 main」要用技術閘門。閘門就是 .claude/settings.json 的規則，由 Claude Code 程式強制執行，不是模型自由心證。評估順序：deny → ask → allow，deny 永遠贏。

{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git commit *)"],
    "deny":  ["Bash(git push *)", "Read(.env)"]
  }
}

常用 pattern：Bash(npm run *) 萬用字元、Read(.env) 擋敏感檔（任意深度）、WebFetch(domain:example.com) 限定網域。專案的 .claude/settings.json 進版控全隊共享；個人的放 settings.local.json。

注意：deny 規則擋得住內建檔案工具與常見指令（cat、sed 等），但擋不住任意子程序（例如它寫一支 Python script 自己開檔）。要 OS 層級的隔離需啟用 sandbox — 進階主題，之後有需要再教。

實作步驟（做完打勾）

在工作 repo 切到 plan mode，丟一個你最近想做的中型任務，只看計劃不實作。觀察它探索了哪些檔案、計劃合不合理。

請它幫你（或自己手動）在 repo 的 .claude/settings.json 加入：

{ "permissions": { "deny": ["Bash(git push *)"] } }

開新 session，故意請它 push this branch — 確認被擋下。這就是「指引 vs 強制」的差別，親眼看一次才會記住。

觀念檢查（憑記憶作答）

1. plan mode 和「在 default 模式下請它先給計劃」的差別是？

口頭要求是指引；plan mode 是模式層級的強制 — 它在 plan mode 下只有讀取與唯讀指令可用。

2. 同一個工具同時命中 allow 和 deny 規則，結果是？

評估順序固定為 deny → ask → allow，任何層級的 deny 都不能被 allow 蓋過（包括指令列參數）。

3.（複習第 4 課）CLAUDE.md 寫了「commit 前要跑 lint」，它有時還是忘了。最可靠的解法是？

（間隔複習）CLAUDE.md 是 context 指引，不保證遵守；「必須在特定時點執行」的事用 hooks — 官方文件對這個分工講得很明確。

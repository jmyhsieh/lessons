第 2 階段 · 裝備 · 002-0002 · Conditional 工具箱課程

先把讀取、寫入與外部副作用分開

任務：替目前路線寫一張權限邊界卡，並在安全練習環境用計畫模式證明探索沒有新增來源 diff。

權限不是提示裡的一句話

真正的權限邊界由 Claude Code 應用程式執行，不由模型自行保證。規則衝突時採 拒絕 → 詢問 → 放行權限順序 的優先順序；把敏感或不可逆行為留在拒絕／詢問，比要求模型「小心一點」可靠。

層次這次工作階段的例子判斷
讀取讀取指定練習環境內的來源、tests 與指引只開放完成 偵察 所需範圍；憑證與無關資料不在範圍。
寫入修改來源、設定或建立檔案本快速驗證測試不需要寫入；保持計畫模式，任何來源編輯都是停止訊號。
外部副作用push、部署、發訊息、修改遠端服務本課全部禁止；需要時回目前路線重新核准，不由工具箱課程擴權。

執行零新增 diff 的快速驗證測試

  1. 在可復原練習環境記錄起始 git status --short 與目前分支；不要假設工作樹原本是乾淨的。
  2. 用介面的模式選擇器切到計畫，或從 CLI 以 claude --permission-mode plan 開始工作階段。
  3. 要求 Claude 讀取一個已核准檔案，說明它的目的，並提出一個可能的來源編輯計畫；不要離開計畫模式。
  4. 再次記錄 git status --short，比較前後輸出；確認沒有因本次快速驗證測試增加或改變任何檔案。
  5. 保存模式、提示、前後狀態、Claude 的偵察摘要與你的學習者判斷。
具體成果：一張權限邊界卡，加上一份規劃模式快速驗證紀錄。
可觀察回饋：核准的 讀取 產生可核對摘要；前後工作樹狀態相同；沒有寫入或外部副作用。

哪一項最能證明這次權限快速驗證符合邊界？

模式限制與外部可觀察證據才能證明邊界；模型的自我陳述不是權限控制或驗證結果。

返回邊界：把卡與快速驗證證據寫回 Return notebook，狀態記為 Lesson practiced，然後回到原本的 Targeted-remediation return point。不要在本課切到略過權限檢查，也不要順便修改真實路線成果。

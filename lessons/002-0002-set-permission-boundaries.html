第 2 階段 · 裝備 · 002-0002 · Conditional toolbox lesson

先把 read、write 與 external side effects 分開

任務：替 active route 寫一張 permission boundary card，並在 safe fixture 用 plan mode 證明探索沒有新增 source diff。

權限不是 prompt 裡的一句話

真正的 permission boundary 由 Claude Code 應用程式執行，不由模型自行保證。規則衝突時採 deny → ask → allow 權限順序 的優先順序；把敏感或不可逆行為留在 deny／ask，比要求模型「小心一點」可靠。

層次這次 session 的例子判斷
讀取（Read）讀取指定 fixture 內的 source、tests 與 instructions只開放完成 reconnaissance 所需範圍；credentials 與無關資料不在 scope。
寫入（Write）修改 source、設定或建立檔案本 smoke test 不需要 write；保持 plan mode，任何 source edit 都是停止訊號。
外部副作用push、deploy、發訊息、修改遠端服務本課全部禁止；需要時回 active route 重新核准，不由 toolbox lesson 擴權。

執行零新增 diff 的 smoke test

  1. 在 recoverable fixture 記錄起始 git status --short 與目前 branch；不要假設工作樹原本是乾淨的。
  2. 用介面的 mode selector 切到 plan，或從 CLI 以 claude --permission-mode plan 開始 session。
  3. 要求 Claude 讀取一個已核准檔案，說明它的目的，並提出一個可能的 source edit plan；不要離開 plan mode。
  4. 再次記錄 git status --short，比較前後輸出；確認沒有因本次 smoke test 增加或改變任何檔案。
  5. 保存 mode、prompt、前後狀態、Claude 的 reconnaissance 摘要與你的 learner judgment。
具體成果：一張 permission boundary card，加上一份 plan-mode smoke-test record。
可觀察回饋：核准的 read 產生可核對摘要；前後 working-tree 狀態相同；沒有 write 或 external side effect。

哪一項最能證明這次 permission smoke test 符合邊界？

模式限制與外部可觀察 evidence 才能證明邊界；模型的自我陳述不是權限控制或驗證結果。

返回邊界：把 card 與 smoke-test evidence 寫回 Return notebook，狀態記為 Lesson practiced，然後回到原本的 Targeted-remediation return point。不要在本課切到 bypass，也不要順便修改真實 route artifact。

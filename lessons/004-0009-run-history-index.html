Phase 4 · 第 09 課 · 約 25 分鐘 · Run history

記錄每次執行結果，方便追查

目標：把第 31、32 課產出的 agent evidence、gate results、report path 串成一筆可查詢 run record。這一課只做 append-only run history，不做 dashboard、不做多租戶資料庫、不存完整 transcript。

本課只做：產出可查詢的 run record 索引。
先不要做：把 run history 當成完整 evidence 或聊天備份。

Run history 不是 evidence 本身

Claude Code Session Store 用來 mirror session transcripts，讓不同 host 可以 resume；Observability 用 traces、metrics、events 看工具、token、成本與失敗位置。Harness 的 run history 比它們更小：只是一個本地索引，讓 reviewer 找得到 input、evidence、gates、report 與 status。

資料放哪裡用途
Run history.harness/runs.jsonl 或 SQLite。查詢每次 run 的狀態與 artifact 路徑。
Evidence.harness/evidence/<run-id>/保存 stdout、stderr、gate output。
Report.harness/reports/<run-id>.md給 reviewer 判斷結果。
TelemetryOTel backend。看成本、延遲、工具呼叫、失敗位置。
判斷規則：run history 只索引 canonical paths 與狀態，不複製大型 logs、不複製完整 prompt、不取代正式 telemetry。

Run record 範例

{
  "runId": "run-0042",
  "inputId": "issue-0042-login-timeout",
  "startedAt": "2026-06-13T09:30:00Z",
  "endedAt": "2026-06-13T09:38:10Z",
  "status": "needs-review",
  "agentStatus": "needs-review",
  "gateStatus": "pass",
  "evidenceDir": ".harness/evidence/run-0042",
  "gateResultsPath": ".harness/evidence/run-0042/gate-results.json",
  "reportPath": ".harness/reports/run-0042.md",
  "costUSD": 0.42
}

實作步驟（做完打勾）

先用 runs.jsonl：append-only、容易 diff、容易 fixture 測試。等查詢需求變多再換 SQLite。

來源必須是實際 run 產物：input contract、agent evidence、gate results、report path。不要從聊天摘要重建。

先列出 runId、inputId、status、startedAt、reportPath。不要先做複雜查詢語法。

show 應該回傳單筆完整 record，並檢查 artifact paths 是否存在；不存在時標示 stale，不要靜默通過。

Cost tracking 說明 SDK 的 cost 欄位是 client-side estimate。可以放進 run record 做開發觀察，但不要用它自動收費或做正式財務決策。

你已完成 run history 的最小索引。回對話視窗貼上兩筆 run record 與 history list/show 摘要，請 AI 老師檢查是否已經足以支援 rerun policy。

觀念檢查（憑記憶作答）

1. Run history 最應該保存什麼？

Run history 是索引層：保存狀態與 canonical paths。完整 stdout/stderr 留在 evidence。

2. 第一版最適合用什麼格式？

JSONL 最小、append-only、容易測試。查詢需求真的變多後，再升級 SQLite 或資料庫。

3. Cost 欄位可以直接用來做什麼？

官方文件提醒 cost 是 client-side estimate。適合開發觀察與粗略預算，不適合正式財務決策。

第 6 階段 · 建置 · 006-0012 · Conditional branch

從 architecture friction 找出一個可交付的 seam

進入條件／條件分支：只有維護摩擦已有 evidence，例如同一知識散落在多個 callers、變更反覆碰到相同 hot spot、缺少可代表真實行為的 test seam，或 diagnosis 留下具體 architecture follow-through 時才進入。Code readiness、安全 workspace、repo instructions、domain glossary 與相關 ADR 都必須可讀。

1. 先圈窄 scope，再做 read-only survey

若 learner 已點名 module、subsystem 或痛點，就只看該範圍；否則由近期 commit history 找反覆變動的 hot spot。閱讀 callers、tests 與 dependencies，尋找理解一個概念卻必須來回跳轉、interface 幾乎和 implementation 一樣複雜，或 test 只能穿透內部才能成立的摩擦。

共同 vocabulary：module 透過一個 interface 提供行為；seam 是 interface 所在位置；adapter 是在 seam 上滿足 interface 的具體角色。深度帶給 caller leverage、帶給 maintainer locality。不要用泛稱掩蓋這些不同決策。

2. 比較候選，但只選一個

每個候選以 before／after visual 說明 files、friction、可能的 deepening、test improvement 與 recommendation strength；報告存到 OS temp directory，不把探索 artifact 混進 repo。先讓 learner 選候選，再用 grilling 釐清 constraints、dependencies、seam、interface、背後 implementation 與應存活的 tests。

判斷Evidence 問題
深度（Depth）一個更小的 interface 能否隱藏更多 caller 必須重複知道的規則？
刪除測試刪掉 module 後，複雜度會消失，還是重新散落到 N 個 callers？只有後者支持 deepening。
Seam 真實性行為真的需要在此變動嗎？只有一個 adapter 時，先視為 hypothetical seam，不製造無用 indirection。
測試介面caller 與 tests 能否跨同一個 interface 驗證 observable outcome，而不讀內部 state？

Discovery 不是 implementation：本 branch 只證明一個 bounded architecture request 值得進 delivery flow。不要先抽 module、搬 callers、刪 tests 或更新 production interface；也不要把所有報告候選變成 backlog。若 learner 拒絕候選，只有難以回頭、缺少背景會令人意外且存在真實 tradeoff 的 load-bearing reason 才是 ADR 候選。

具體成果：一份 learner 選定的 architecture seam discovery brief，附 survey evidence、visual report 位置、deep-module vocabulary、testable interface 與明確 out-of-scope。
可觀察回饋：Reviewer 能由 inspected modules 與 deletion test 重現摩擦，說明 seam 為何真實，並指出哪些 caller behavior 可透過同一 interface 驗證；repo 尚無 implementation diff。

Architecture report 列出四個候選，而其中一個只有 production adapter，沒有真實替代行為；下一步最合適的是？

Survey 先找 deepening opportunity，learner 再選一個；「one adapter = hypothetical seam」避免以未來想像製造淺層 indirection。

合法停止／返回／續行：摩擦沒有 evidence、scope 無法收窄、domain terms／ADR 衝突未釐清、learner 尚未選候選、seam 只是假設、interface 無法成為 test surface，或開始需要 production mutation 時，保存 survey notes 後停止。Brief 完整且 learner 接受後，帶著它回 006-0003 對齊 bounded request，再走 spec／tickets／implementation／Review core；不要由本頁直接修改 code。完成本頁只代表一個 architecture seam 已形成可檢查的 delivery input，不代表 Engineering Phase 或 Migration complete。

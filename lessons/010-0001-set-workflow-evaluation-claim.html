Phase 10 · Prove · 010-0001 · Route entry

先固定要評估的 workflow claim

Entry／readiness：帶入一份可重建的 009-0008 Standardization closeout：exact package version／digest、workflow promise、owner、scope、authority、正反例、recovery 與 learner disposition 都存在。若 package 還在變、只靠人氣或示範成功，先回 Phase 9；本路不替未證明 workflow 補包裝。

Pre-registration rule：在任何 evaluation run 前寫下 candidate、comparator、frame 與 threshold。後面可以因證據修正 claim，但必須保留原版本與理由；不得看完結果才改題目。

2. 設定 claim ceiling

  1. 只評估 declared fixtures 與 audience，不從 local evidence推論 production、real-user 或 organization impact。
  2. Package 的既有 read／write authority 不因 evaluation 擴張；external actions 預設 none。
  3. Agent 可以整理與批判 evidence，不能批准自己的 package，也不能取代 learner disposition。
  4. 成本、速度與分數是 observations，不是自動通過器；安全 stop 與 material failure 可凌駕平均分。
Tangible win：一張在執行前固定 candidate、audience、outcome、comparator、threshold 與 claim ceiling 的 evaluation claim card。
Observable feedback：另一位 reviewer 能指出什麼結果會支持、削弱或直接否定 claim，且無須猜測 package identity 或決策門檻。

哪個 evaluation claim 可以進下一課？

可評估 claim 必須在觀察前固定 candidate、scope、outcome、comparator 與 threshold，並容許 evidence 反駁。

Legal stop／return／continuation：Package identity、originating closeout、audience、observable outcome、comparator 或 threshold 任一不明時，保存 claim draft，回 009-0008 或向 owner 補決策。Claim 可被反駁且 ceiling 清楚後，續到 010-0002；完成本課不代表 workflow 已通過 evaluation。

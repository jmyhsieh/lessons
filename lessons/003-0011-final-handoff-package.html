整理最後交付包（final handoff）

目標：把 latest run、parent chain、evidence、gate results、rerun note 與未解風險整理成下一個 agent 或 reviewer 能接手的交付包。這一課只做交接包，不做新功能、不補跑 gate。

本課只做：產出最後交付包的最小內容。
先不要做：把所有 log 全塞進 handoff。

Final handoff 不是聊天摘要

/handoff skill 的原則是：不要複製已在 PRD、plan、issue、commit、diff 內的內容，而是用路徑或 URL 引用；同時要列出 suggested skills，並移除敏感資訊。Harness final handoff 也採同一個邊界：它不是完整 transcript，而是 artifact index 加上決策摘要。

Session Store 可以保存可 resume 的 transcript；Observability 可以追蹤工具、token、成本與失敗位置。Final handoff 則回答一個更小的問題：下一個人現在要看哪幾個檔案、相信哪些結果、接著做什麼。

交付包只放七件事

區塊內容不要放
Decisionpassed、failed、blocked 或 needs-review。模糊的「應該好了」。
Latest runrunId、inputId、reportPath。整段聊天紀錄。
Parent chainrerun 來源與每次差異。覆蓋舊 run。
Evidence indexgate results、stdout/stderr、截圖路徑。完整 log 複製貼上。
Risk list未驗證項目、owner、下一步。沒有 owner 的待辦。
Suggested skills下一輪該用的 skill 或命令。泛泛的「繼續做」。
Redactions確認 secret、token、PII 未外洩。原始 credential。
判斷規則：final handoff 應該讓 reviewer 不問 agent 也能接手；如果還需要「你剛剛到底做了什麼」的口頭補充，交付包還不夠好。

最小模板

# Final handoff: issue-0042-login-timeout

Decision: needs-review
Latest run: run-0043
Parent chain: run-0042 -> run-0043
Report: .harness/reports/run-0043.md
Gate results: .harness/evidence/run-0043/gate-results.json
Evidence: .harness/evidence/run-0043/

What changed since parent:
- gate timeout 120s -> 240s

Open risks:
- Auth fixture still depends on staging token; owner: backend lead.

Suggested next skills:
- review
- diagnose

Redactions:
- No secrets, tokens, or PII included in this handoff.

實作步驟（做完打勾）

從 history show <run-id> 抓 runId、inputId、status、reportPath。不要手寫第二份真相。

若有 rerun，列出 parentRunId 與 changed since parent。讓 reviewer 知道這輪和上一輪差在哪。

只列 canonical paths：gate results、report、stdout/stderr、截圖。完整內容留在 artifacts，不塞進 handoff。

每個未解風險都要有 owner 與下一步；沒有 owner 的風險就是交接失敗。

確認 handoff 沒有 secret、token、credential、PII。必要時只保留 artifact path 與脫敏摘要。

你已完成 final handoff package。回對話視窗貼上你的 handoff 模板，請 AI 老師檢查 reviewer 是否能不靠聊天紀錄接手。

觀念檢查（憑記憶作答）

1. 交付包最該引用什麼？

Final handoff 應該引用 canonical artifact paths，避免複製大型 log 或依賴 agent 記憶。

2. 哪個內容不該直接放 handoff？

handoff 可以放最新狀態與未解風險，但 secret、token、credential、PII 必須移除或脫敏。

3. 交付包完成的判斷標準？

Final handoff 的目的不是好看或宣傳，而是讓下一個 agent 或 reviewer 能可靠接手。

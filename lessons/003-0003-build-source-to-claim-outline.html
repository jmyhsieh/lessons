第 3 階段 · 交付 · 003-0003 · 主張 規劃

先把來源證據接到主張，再開始生成成果

任務：用穩定 source 識別碼建立一份來源至主張大綱，讓每個重要主張都有定位、狀態與 限制。

主張台帳最小欄位

欄位寫法
主張識別碼／文字C-01 加一個可驗證句，不用模糊主題。
類型Source 陳述、推論、建議或未解問題。
證據Source 識別碼加頁面／章節／列／時間戳記；URL 本身不是定位。
狀態supported、unknown 或 conflict；不要用語氣取代狀態。
邊界受眾、時間範圍、假設、反證 與不能推廣到哪裡。

從問題到大綱

  1. 把任務改寫成受眾要做的決策／用途；只保留直接服務這個目的的章節。
  2. 先從原始來源套件 抽出 evidence 筆記，附 source 識別碼／定位；不要先請模型寫結論再回頭找來源。
  3. 將筆記組成主張，分開 source 陳述與你的推論。沒有 evidence 的句子標 unknown。
  4. 同一主張的來源互相矛盾時標 conflict，保存兩側 evidence；在解析前不選較順耳的一邊。
  5. 把 受支援 主張排入 大綱，並在每個章節下留下 限制 與 review 問題。

衝突是 evidence 狀態，不是寫作障礙；先保留差異並限縮主張，才能避免生成內容掩蓋不確定性。

分支／合法停止：核心 route 下一步是 一般知識切片；任務若明確需要本機知識庫，可選 LLM Wiki 條件式支線，之後同樣回到 003-0005 驗證。重要主張多數為未知／衝突，或 source 定位不完整時，保存大綱後停止，不生成 artifact。

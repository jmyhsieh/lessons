Phase 9 · 入門第 02 課 · 約 15 分鐘

讓 Claude Code 建立第一個專案 Skill

本課成果：一個 repo 內可執行的 /repo-checkpoint。

先放在專案裡：.claude/skills/repo-checkpoint/SKILL.md 只跟著這個 repo，容易 review、版本控制與移除。等多個 repo 都證明需要時，再考慮跨專案共享或包成 plugin。

先審草稿，再執行

貼上下面提示詞。第一版只允許一個 SKILL.md，不加 scripts、hooks、plugin manifest 或額外抽象層。

請先讀這個 repo 的 CLAUDE.md、AGENTS.md 與現有 .claude/skills 慣例。
依這張 brief，草擬 .claude/skills/repo-checkpoint/SKILL.md：
- 人工執行 /repo-checkpoint
- 只讀目前對話、repo 變更與檢查證據
- 輸出 Changed、Verified、Remaining、Blocked
- 未跑、跳過或失敗的檢查必須誠實列出
- 不修改檔案、不 commit、不 push
先顯示完整草稿與唯一預計新增的檔案，等我核准後才寫入。

確認路徑、檔頭設定（frontmatter）、四段輸出與停止線都正確，再核准這個單檔 diff。若 Claude Code 提出超出需求卡的能力，請它刪掉。

直接在目前 repo 執行並保存結果。若這個 Claude Code 對話啟動時連最上層 .claude/skills/ 都不存在，建立後需重開 Claude Code，讓檔案監看功能發現新目錄；既有目錄內的 Skill 變更通常會即時生效。

完成：你已有一個專案 Skill、一份可見輸出，以及第一次執行證據。

觀念檢查

第一次自訂 Skill 為什麼先放在專案裡？

專案 Skill 的適用範圍清楚，也能跟 repo diff 一起審查。它不會繞過權限，也不會自動成為所有 repo 的共同規則。

關鍵判斷

先得到一個能執行的最小 Skill；後續優化都要建立在真實執行證據上。

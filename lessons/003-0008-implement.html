Phase 3 · 第 08 課 · 約 60 分鐘 · 實作交付

用 /implement 完成一張 issue

目標：認領第 07 課切出的第一張 issue，用 /implement 依 PRD 與單張 issue 完成交付。這一課把 /tdd、測試、/review 與 commit 收進同一條實作流程。

本課只做：完成一張小而可驗收的 issue。
先不要做：一次丟整份 PRD、整批 issues 或未切片的大功能。

Pipeline 全景：你在這裡

/to-issues → /implement → tests → /review → commit → /handoff

/implement 是 orchestrator

/implement 的原文職責是「依 PRD 或 issues 實作工作」。它不是單純寫 code，而是把施工流程串起來：

階段你要看什麼
讀 PRD 與單張 issue只做這張 issue，不順手擴 scope。
使用 /tdd在預先同意的接縫上做紅綠燈循環。
規律跑檢查常跑單檔測試與 typecheck，最後跑完整測試。
使用 /review完成後檢查 Standards 與 Spec，再處理發現。
commit 當前分支commit message 要能指回 issue 與驗收結果。
重點：/tdd 與 /review 是 /implement 裡的品質紀律，不是與 /implement 平行的主流程。

實作步驟（做完打勾）

選第 07 課產出的第一張 AFK issue。確認它有 PRD 連結、驗收條件、測試接縫與 blocked-by。

/implement 根據這份 PRD 與這張 issue 實作：[PRD 路徑] [issue 路徑]

如果它試圖一次處理多張 issue，立刻收斂回單張。

確認每個關鍵行為至少有一次 RED → GREEN。沒看見失敗的測試，不要相信它真的保護了需求。

要求它回報 typecheck、單檔測試、完整測試或本 repo 對應的驗證命令。命令、結果與未跑原因都要講清楚。

完成後跑 /review 檢查規範與規格。處理完發現，再 commit 到目前分支。

🎉 你已完成第一張可交付 issue。回對話視窗回報：哪個測試先紅後綠？review 抓到什麼？

觀念檢查（憑記憶作答）

1. /implement 最適合吃什麼輸入？

/implement 適合依 PRD 與單張 issue 施工。整份 PRD 太大，模糊需求太早。

2. /implement 裡的 /review 主要檢查什麼？

/review 看 Standards 與 Spec：是否符合 repo 規範，以及是否忠實完成 issue/PRD。

3. 沒看過測試先失敗就綠了，該怎麼辦？

TDD 的信任來自 RED → GREEN。沒看過 RED，就不知道測試是否真的抓得到問題。

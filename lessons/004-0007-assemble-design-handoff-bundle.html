第 4 階段 · 設計 · 004-0007 · Route stop

把 intent、states、evidence 與 limits 組成可接手的 handoff

結束證據：組裝一個有 version identity、可重新開啟、能讓接手者理解取捨與未驗證範圍的 Design handoff bundle。完成後 Design route 可以合法停止；repo implementation 不是本課的隱含完成條件。

交接資料包欄位

Brief、Claude Design project、selected revision、approved design-system／content sources、owner、日期與 access boundary。

User task、audience、information hierarchy、selected direction、non-goals、可接受 deviations。

包含 Happy path、loading、empty、error、disabled、responsive behavior、keyboard／focus／name／contrast expectations。

包含 Prototype assumption record、tested environment、feedback、disposition、supported／contradicted／untested claims。

Unresolved assumptions、known risks、learner judgment，以及 stop 或進 Phase 6 Build 的明確選擇。

Bundle 欄位齊全。這只表示必要欄位都有可開啟 evidence；仍需由學習者與接手者檢查一致性並寫下 judgment，才是 Design route exit evidence。

可攜式資料包紀錄

Bundle ID / date / owner:
Mission / audience / task:
Brief / selected revision / source links:
Design system / content authority:
Intent / hierarchy / key trade-offs:
Interaction and required states:
Responsive and accessibility rules:
Prototype evidence / environment / feedback:
Supported / contradicted / untested:
Non-goals / acceptable deviations:
Unresolved assumptions / risks:
Learner judgment: accept / revise / stop
Continuation: legal stop / Code readiness / Phase 6 Build

執行 handoff feedback loop

  1. 由一位沒參與生成的人只讀 bundle，重述 user task、selected direction、states、rules 與 three largest risks。
  2. 請對方從 evidence 抽查一個 responsive 或 accessibility claim，並指出哪些只是 prototype observation。
  3. 若選擇 repo implementation，先做 read-only mapping：可能檔案、既有 components、衝突、最小 vertical slice 與 repo checks；這一步不授權寫入。
  4. 由學習者 disposition handoff feedback，更新 bundle ID，選擇 legal stop 或 continuation。
具體成果：一份 versioned Design handoff bundle，整合 source、intent、states、rules、evidence、scope、learner judgment 與 feedback。
可觀察回饋：接手者不靠作者口述，就能重述設計、抽查 evidence、列出 implementation unknowns，並明確說出 prototype 尚未證明什麼。

Bundle 已完成，但目前 mission 不需要 repo implementation，最正確的狀態是？

Design route 的合法 stop 就是 reviewable handoff bundle；implementation 只有 mission 選擇時才跨入 Build。

合法停止／後續路線：Bundle 缺 source identity、material states、evidence、learner judgment 或 feedback disposition 時，保留 Lesson practiced 並回到最小缺口。Bundle 一致後可回 課目表合法停止。若交付物要包含 repo diff，先確認 Code readiness，再進 Phase 6 Build；implementation、checks、Review 與 closeout 全部留在 Build。

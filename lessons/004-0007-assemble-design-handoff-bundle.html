第 4 階段 · 設計 · 004-0007 · Route 停止點

把意圖、狀態、evidence 與限制組成可接手的交接

結束證據：組裝一個有版本識別、可重新開啟、能讓接手者理解取捨與未驗證範圍的 Design handoff bundle。完成後設計路線可以合法停止；儲存庫實作不是本課的隱含完成條件。

交接資料包欄位

簡述、Claude Design 專案、已選修訂、已核准設計系統／內容來源、負責人、日期與存取邊界。

使用者任務、受眾、資訊層級、已選方向、非目標、可接受偏差。

包含順利途徑、載入、空白、錯誤、停用、響應式行為、鍵盤／焦點／名稱／對比預期。

包含原型假設紀錄、已測試環境、回饋、處置、受支援／已反駁／未測試主張。

未解假設、已知風險、learner judgment，以及停止點或進 Phase 6 建置的明確選擇。

套件欄位齊全。這只表示必要欄位都有可開啟 evidence；仍需由學習者與接手者檢查一致性並寫下判斷，才是設計路線 exit evidence。

可攜式資料包紀錄

Bundle ID / date / owner:
Mission / audience / task:
Brief / selected revision / source links:
Design system / content authority:
Intent / hierarchy / key trade-offs:
Interaction and required states:
Responsive and accessibility rules:
Prototype evidence / environment / feedback:
Supported / contradicted / untested:
Non-goals / acceptable deviations:
Unresolved assumptions / risks:
Learner judgment: accept / revise / stop
Continuation: legal stop / Code readiness / Phase 6 Build

執行交接 feedback loop

  1. 由一位沒參與生成的人只讀套件，重述使用者任務、已選方向、狀態、規則與三個最大風險。
  2. 請對方從 evidence 抽查一個響應式或可及性主張，並指出哪些只是原型觀察。
  3. 若選擇儲存庫實作，先做唯讀對照：可能檔案、既有元件、衝突、最小垂直切片與儲存庫檢查；這一步不授權寫入。
  4. 由學習者處置交接回饋，更新套件 ID，選擇 legal stop 或 continuation。
具體成果：一份有版本的設計交接套件，整合 source、意圖、狀態、規則、evidence、範圍、學習者判斷與回饋。
可觀察回饋：接手者不靠作者口述，就能重述設計、抽查 evidence、列出實作未知事項，並明確說出原型尚未證明什麼。

套件已完成，但目前任務不需要儲存庫實作，最正確的狀態是？

設計路線的合法停止點就是可審查交接套件；實作只有任務選擇時才跨入建置。

合法停止／後續路線：套件缺 source 識別、重要狀態、evidence、learner judgment 或回饋處置時，保留 Lesson practiced 並回到最小缺口。套件一致後可回 課目表合法停止。若交付物要包含儲存庫差異，先確認 程式碼就緒狀態，再進 第 6 階段建置；實作、檢查、Review 與收尾全部留在建置。

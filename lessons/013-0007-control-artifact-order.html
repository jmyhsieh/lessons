逐份控制 artifact 產生順序

本課成果：一個用 /opsx:new 建立、再以 /opsx:continue 逐份審查的 change。

Artifact dependencies 決定資訊怎麼往下傳：前一份內容會成為下一份 artifact 的輸入。需求還不穩時，逐份產生能讓你提早修正；變更已很清楚時，才考慮 /opsx:ff。

先啟用需要的 expanded commands

openspec config profile
openspec update
git status --short
git diff

在互動設定裡選擇需要的 expanded workflows，接著更新 Claude Code 的指示。把選項與新增路徑記下來；本課不改 custom schema，也不使用 beta Stores。

/opsx:new improve-session-expiry-message

/opsx:new 只建立 change 骨架；其他 artifacts 要再用 /opsx:continue 或 /opsx:ff 產生。先確認名稱與 schema，再繼續。

/opsx:continue improve-session-expiry-message

每次執行後都閱讀實際生成的檔案，檢查範圍、行為、假設與未決問題。內容正確才再執行一次 /opsx:continue。

觀念檢查

需求仍可能調整時，哪一種做法最容易在早期攔下偏差？

逐份產生可在 proposal 或 specs 階段先修正，避免不正確的假設一路流到 design、tasks 與程式碼。

停止線

Profile 與生成指示更新後，先審 diff。若不確定新增 command 的行為，就回官方 commands 文件核對，不要用猜的。

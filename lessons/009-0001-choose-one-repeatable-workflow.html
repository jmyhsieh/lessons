Phase 6 · 入門第 01 課 · 約 10 分鐘

從一個重複工作流程開始

本課成果：一張來自真實程式庫工作的 Skill 需求卡。

Skills 囤積困境（skill hell）：手上裝了很多 Skills，卻不知道哪個可靠、何時該用，最後也得不到預期結果。先用同一套檢查標準改好一個真實工作流程，再決定是否需要更多 Skills。

判斷值不值得做成 Skill

回想你至少講過兩次的流程，例如「收尾時列出 changed、verified、remaining、blocked」。一次性需求、純事實或一句簡短偏好，先不要做成 Skill。

輸入可以是目前 Claude Code 對話與程式庫狀態；輸出要能被看見與審查，例如四段狀態摘要。避免只寫「做得更好」。

這個 Skill 只整理現況，不替你提交、推送或部署，也不把沒跑過的檢查寫成通過。先把第一版縮到一個低風險結果。

Skill 名稱：repo-checkpoint
何時需要：我要暫停、換工作階段或確認目前狀態時
輸入：目前對話、程式庫變更與已知檢查結果
輸出：Changed / Verified / Remaining / Blocked
停止線：不修改檔案、不執行外部發布、不把未驗證寫成已通過
完成：你已有一張只涵蓋一個重複流程的 Skill 需求卡。

觀念檢查

哪個最適合成為第一個 Skill？

第一個 Skill 應來自真實、重複、低風險且有可見輸出的流程；不是一次性任務，也不是把所有工作一次包完。

關鍵判斷

先找出值得穩定重用的一組指示，再決定是否做成 Skill。

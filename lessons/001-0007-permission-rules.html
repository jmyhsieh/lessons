控制 Claude Code 能做什麼（permission rules）

本課成果：把「不要推送 main」「不要讀取 .env」寫成 Claude Code 會強制執行的權限規則（permission rules）。

本課只做：把 allow / ask / deny 變成清楚的權限規則。
先不要做：用口頭提醒代替必須強制的 deny 規則。

規則比提醒可靠

CLAUDE.md 是上下文指引；permission rules 是程式層的硬閘門。評估順序是 deny → ask → allow，命中 deny 就不會被 allow 蓋過。

{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git commit *)"],
    "deny":  ["Bash(git push *)", "Read(.env)"]
  }
}
注意：這不是作業系統 sandbox。它能擋 Claude Code 內建工具與常見指令，但不要把它當成保護祕密的唯一防線。
桌面 App 路徑：權限模式用畫面上的 mode selector；allow / ask / deny 規則則直接寫進 .claude/settings.json。Desktop Code tab 不支援會開 terminal-dialog 的 /permissions。

實作步驟（做完打勾）

建議先用 Bash(git push *)，因為好驗證、風險也明確。

{ "permissions": { "deny": ["Bash(git push *)"] } }

請它 push 目前分支，確認動作被擋下。驗證硬規則，比相信文件重要。

團隊共用規則放專案設定；個人偏好放 local 設定。

完成條件：權限規則已用測試命令證明會擋下指定操作，並留下實際結果。

觀念檢查

1. 同一個指令同時命中 allow 和 deny，結果是？

規則順序固定為 deny → ask → allow。

2. 「commit 前要跑 lint」最適合放 permission rules 嗎？

permission 管能不能做；hook 管某時點必須發生什麼。

Hooks — 把規則變成保證

任務目標：在工作 repo 設定兩個 hook：一個自動格式化（每次編輯後必跑）、一個阻擋危險操作（PreToolUse 硬擋）。完成「指引 → 閘門 → 自動化」三層安全模型的最後一層。

你已經知道的三層模型，hooks 補完它

層機制性質哪一課
指引CLAUDE.md它「會盡量」遵守第 4 課
閘門permission allow/deny程式強制，擋「能不能做」第 5 課
自動化hooks程式強制，管「某時點必發生什麼」本課

Hooks 是你定義的 shell 指令，在 Claude Code 生命週期的固定時點必定執行 — 不靠模型自覺（官方指南）。常用事件：

  • PreToolUse — 工具執行前：可以擋下它（驗證、阻擋危險指令）
  • PostToolUse — 工具執行後：格式化、lint 剛改過的檔案
  • Stop — 它回完話時：跑最終檢查；可阻擋結束，但不是無限阻擋
  • Notification — 等你輸入時：桌面通知

關鍵語意：exit code

exit 0  → 放行（照常走權限流程）
exit 2  → 擋下！stderr 的訊息會回饋給 Claude 讓它調整
其他    → 視為 hook 自身錯誤，動作照常進行
記這一行就夠：exit 2 = 擋下並告訴它為什麼。Stop hook 連續阻擋太多次時，Claude Code 會結束回合；更細的控制（allow/deny/ask）可用 JSON 輸出，見官方參考。

設定長相

hooks 寫在 .claude/settings.json（專案共享）。官方範例 — 每次編輯後自動跑 Prettier：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command",
          "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }]
      }
    ]
  }
}

matcher 篩選觸發的工具（regex，空字串 = 全部）；hook 從 stdin 收到 JSON（工具名、參數等），此例用 jq 取出被改的檔案路徑。

安全注意：hooks 是以你的權限執行的任意 shell 指令 — 寫進去前先理解每一行，團隊 repo 的 hooks 變更要走 review。另外官方建議：可以直接請 Claude 幫你寫 hook（「Write a hook that runs eslint after every file edit」），但產出一樣要自己讀過。

實作步驟（做完打勾）

在工作 repo 的 session 裡，請它依你們的格式化工具（Prettier／Black／gofmt…）寫一個 PostToolUse hook 並加進 .claude/settings.json。讀懂每一行再接受。

叫它隨便改一個檔案（故意亂縮排），確認儲存後格式自動被修正。

挑一個你們 repo 真正的禁區（例如 migrations 資料夾、production 設定檔），請它寫一個 PreToolUse hook：偵測到對該路徑的寫入就 exit 2 並在 stderr 說明原因。

故意請它修改禁區檔案。觀察兩件事：動作被擋下了嗎？它收到 stderr 的理由後怎麼調整行為？

.claude/settings.json 進版控，全隊共享這兩道保證 — 照常走 PR。

🎉 三層安全模型集滿！回對話視窗回報：阻擋 hook 觸發時 Claude 的反應是什麼？有沒有遇到 jq／路徑相關的坑？

觀念檢查（憑記憶作答）

1. 「每次編輯檔案後都要跑 lint」— 最可靠的實作是？

「某時點必發生」= hooks 的職責。CLAUDE.md 是指引（第 4、5 課考過的同一條主線）；permission 管的是「能不能」，不是「之後做什麼」。

2. PreToolUse hook 想擋下動作並讓 Claude 知道原因，正確做法是？

exit 2 = 擋下，stderr 會回饋給 Claude；exit 0 = 放行；其他 exit code 視為 hook 錯誤、動作照常進行 — 選錯 exit code 等於沒擋。

3.（複習第 5 課）PreToolUse hook 回了 allow，但同一個指令命中 settings.json 的 deny 規則，結果？

（間隔複習）deny 永遠贏 — 不論來源是 allow 規則、指令列參數還是 hook 的 allow 決定。

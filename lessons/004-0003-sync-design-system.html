第 4 階段 · 設計 · 004-0003 · Conditional 系統分支

只用已核准脈絡，同步後逐項校正

進入條件：簡述已指向已核准設計系統、品牌 source、設計檔案或可安全讀取的 codebase 脈絡。沒有這類 source 時跳過本課，直接進 004-0004；不要讓 Claude 發明一套看似正式的權杖。

先分清兩種工作

工作授權範圍完成 evidence
組織設計系統設定／測試／發布具權限的組織負責人，在 Claude Design 設定介面操作來源、review／測試結果、已發布狀態與負責人記錄
專案層級匯入／同步本次專案被允許讀取的 GitHub、設計檔案、上傳或本機 codebase匯入識別、可用元件／權杖、缺漏與校正記錄

邊界：專案匯入不會自動發布組織系統；匯入成功也不代表 source 品質正確。若 source 混亂、過時或權限不清，先停止而不是補猜。

已驗證環境：2026-07-16 依 Anthropic 設計系統設定與入門指南檢查組織設定、已發布狀態與專案匯入介面；實際標籤、可用性與同步行為可能在測試版期間改變，操作前重查官方頁面。

  1. 先記下 source 識別、負責人、修訂與允許存取範圍，再匯入。
  2. 用一個代表性元件比對字體排印、色彩、間距、狀態與響應式規則。
  3. 把不一致分成修正脈絡、修正簡述、保留偏差或停止；不得靜默接受。
  4. 請 source 負責人或審查者抽查一個元件對照，確認另一人能重現同一判斷。
具體成果：一份帶 source 識別、不一致處置與 evidence 的系統對齊紀錄。
可觀察回饋：審查者能從已核准 source 抽查一個元件／權杖，重現預期與觀察到的差異，並判斷是否可進方向探索。

專案匯入完成後，看到間距權杖與已核准系統不同，應怎麼做？

匯入只帶入脈絡，不創造權威；差異必須回到已核准 source 與人類處置。

合法停止／返回：Source 負責人、權限、修訂或代表性對照無法確認時，保存對齊草稿並停止；不要用生成權杖填補。對齊結果可抽查，或已誠實記錄「無已核准系統」後，重新加入主線 004-0004 設計方向探索。

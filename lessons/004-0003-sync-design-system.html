Phase 4 · Design · 004-0003 · Conditional system branch

只用 approved context，同步後逐項校正

Entry condition：brief 已指向 approved design system、brand source、design file 或可安全讀取的 codebase context。沒有這類 source 時跳過本課，直接進 004-0004；不要讓 Claude 發明一套看似正式的 tokens。

先分清兩種工作

工作Authority完成 evidence
組織 design system setup／test／publish具權限的 organization owner，在 Claude Design 設定 surface 操作來源、review／test 結果、Published state 與 owner 記錄
Project-level import／sync本次 project 被允許讀取的 GitHub、design file、upload 或 local codebaseimport identity、可用 components／tokens、缺漏與校正記錄

邊界：Project import 不會自動發布 organization system；匯入成功也不代表 source 品質正確。若 source 混亂、過時或權限不清，先停止而不是補猜。

Verified environment：2026-07-16 依 Anthropic Design system setup 與 Get started guides 檢查 organization setup、Published state 與 project import surfaces；實際 labels、availability 與同步行為可能在 beta 期間改變，操作前重查官方頁面。

  1. 先記下 source identity、owner、revision 與允許存取範圍，再匯入。
  2. 用一個代表性 component 比對 typography、color、spacing、state 與 responsive rule。
  3. 把 mismatch 分成修正 context、修正 brief、保留 deviation 或停止；不得靜默接受。
  4. 請 source owner 或 reviewer 抽查一個 component mapping，確認另一人能重現同一判斷。
Tangible win：一份帶 source identity、mismatch disposition 與 evidence 的 system alignment record。
Observable feedback：Reviewer 能從 approved source 抽查一個 component／token，重現 expected 與 observed 的差異，並判斷是否可進方向探索。

Project import 完成後，看到 spacing token 與 approved system 不同，應怎麼做？

匯入只帶入 context，不創造權威；差異必須回到 approved source 與人類 disposition。

Legal stop／return：Source owner、權限、revision 或代表性 mapping 無法確認時，保存 alignment draft 並停止；不要用生成 token 填補。Alignment 可抽查，或已誠實記錄「無 approved system」後，rejoin 004-0004 direction exploration。

Phase 6 · 進階第 09 課 · 約 20 分鐘

用新對話做前後對照測試

本課成果：一輪有比較基準、只改一個變因的 Skill 改進紀錄。

成功啟用 ≠ Skill 有效：Claude 有啟用它，只證明啟用方式正常；執行是否遵守步驟、完成條件與證據界線，是另一個問題。編寫 Skill 時殘留的對話會幫 Claude 補洞，所以測試要換新對話。

做一張最小測試表

至少包含：程式庫有變更且檢查通過、工作目錄乾淨、存在狀態為 skipped／failed／unrun 的檢查。每個情境先寫預期流程，不以固定句子當答案。

手動啟用的 repo-checkpoint 應在輸入 /repo-checkpoint 時執行，普通聊天不自動套用。若改成 Claude 自動啟用，另測應該啟用與不該啟用的提示詞，記錄漏掉或誤用的情況。

每個情境都新開 Claude Code 對話：一份讓 Skill 可用，一份停用 Skill；比較四段是否完整、證據界線是否正確、是否交代全集。不要在同一段對話先教答案再測。

根據證據，只改 description、按需讀取提示、引導詞、完成條件或一條仍有效的規則。需要更正式的自動比較時，才依官方文件安裝 skill-creator@claude-plugins-official；安裝外掛不是本 Phase 的完成前置。

Phase 6 完成：你有一個可執行 Skill、四段檢查紀錄、新對話比較基準，以及一個經過重跑的最小改進。

觀念檢查

為什麼測試 Skill 要換新的 Claude Code 對話？

若留在寫 Skill 的同一段對話，Claude 已看過意圖與理想答案，可能表現良好，卻不是 Skill 本身造成的。

關鍵判斷

可靠 Skill 需要「比較基準 → 一個修改 → 重跑」的執行證據；作者或 Claude 的自評不能取代實測。

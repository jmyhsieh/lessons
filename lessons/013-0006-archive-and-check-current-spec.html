Phase 13 · 第 06 課 · 約 20 分鐘

封存變更並核對 current spec

本課成果：一筆可追查的 archive 紀錄，以及一份已反映完成行為的 current spec。

Archive 是狀態轉移：它會把 change 的規格差異合併到 current specs，並把 change 移入帶日期的 archive。只有實作與證據都完成時才執行。

封存前後都要查

逐項確認 tasks、產品程式、相關測試、code review 與人工驗收。任何未完成或未驗證內容都要明列；不要靠 archive 把狀態變成「看起來已完成」。

openspec validate add-login-attempt-feedback

Validate 檢查 artifacts 的結構與規則，不會替你執行 repo tests。兩種證據都要保留。

/opsx:archive add-login-attempt-feedback

Core workflow 的 archive 會在需要時提示同步 delta specs。先看完預計變更，再確認封存；若 current specs 的結果不合理，先停下來修 change。

openspec list
openspec list --specs
git status --short
git diff --stat
git diff

確認 active list 不再出現該 change、current spec 已描述新行為、archive 目錄留有日期紀錄，且 diff 沒夾帶其他工作。

完成：你能從 current spec 讀到新行為，也能從 archive 找回這次變更的原始意圖與決策。

觀念檢查

執行 archive 前，最重要的核對組合是什麼？

Archive 應該反映已完成且已驗證的行為；程式、規格與證據不一致時，封存只會把錯誤狀態保存下來。

你已走完「選路 → 初始化 → 讀 workspace → propose → apply → archive」。接下來可直接在真實小變更重複這個閉環；需要控制 artifact 順序、查深層漂移或同時管理多個 changes 時，再進 07–09。

Lesson 001-18 · 約 20 分鐘 · Review agent

Custom subagent 與獨立 review

任務目標：建立一個唯讀 reviewer subagent，讓它用乾淨 context 審查 diff，而不是讓剛寫 code 的同一個對話自我審查。

獨立 review 的價值

寫 code 的 session 會受自己的推理歷程影響。reviewer subagent 只看 diff、需求與標準，立場更乾淨。

Use a reviewer subagent to review this diff against PLAN.md.
Only report correctness gaps, missing tests, or scope creep.
要求「只回報影響正確性的缺口」，避免 review 變成風格偏好清單。

最小 reviewer 定義

---
name: repo-reviewer
description: Reviews diffs for correctness gaps and missing tests
tools: Read, Grep, Glob
---
Review against the stated task and existing repo conventions.
Report only actionable issues with file references.

reviewer 不給 Edit。這是職責分離：它提出問題，主 session 決定怎麼修。

實作步驟（做完打勾）

用 /agents 或在 .claude/agents/ 建檔。工具只給唯讀。

給它任務 brief、diff 與明確審查標準。

標出哪些是正確性缺口、哪些只是建議。只把前者帶回主 session。

🎉 完成！你現在有一個能重用的 reviewer subagent。

觀念檢查

1. reviewer subagent 為什麼不給 Edit？

審查者不該同時有筆，否則角色混在一起。

2. 同一 session 寫完後直接叫它 review，主要缺點是？

乾淨 context 的 reviewer 更像第二雙眼睛。

Phase 9 · 標準化 · 009-0007 · 條件式分支

讓確定性程式碼承擔可可靠判定的流程

進入條件：009-0003已選 command-process，因為契約的路由、驗證、解析、格式化或轉換有穩定的機器介面。品質取捨、風險接受、例外處置與不可逆／外部動作核准仍留給人。

1. 先定義介面與失敗語意

Command / process version / owner:
Inputs / schema / identity / size limits:
Outputs / stable format / evidence location:
Exit 0 means:
Non-zero exits / stderr contract:
Read / write set / dry-run / idempotency:
Timeout / retry ceiling / rollback or safe stop:
Human judgment and approval handoff:
Dependencies / verified fixture / retirement:
交給程式碼保留給人
結構驗證、有界路由、排序、解析、格式化、字面門檻值與可重跑檢查。來源是否可信、結果是否夠好、風險是否可接受、例外怎麼處理、是否執行外部／正式環境寫入。

明確失敗規則：無效輸入、部分輸出、逾時、相依項目不符或略過的紀錄必須產生可辨識非零／已阻擋狀態；不能為了「流程跑完」把未知結果格式化成成功。

2. 建立最小可判別fixture矩陣

  1. 正例固定預期 stdout／產物與結束碼 0。
  2. 無效綱要、缺少識別資訊或越界輸入固定回傳非零，且不產生最終產物。
  3. 重跑同一測試資料，確認輸出可比較，且不重複外部影響。
  4. 若命令產生儲存庫差異，建立不可變候選版本 SHA，回006-0008做標準／規格審查。
# Fresh-context rerun protocol
mkdir a-clean-disposable-fixture
copy exact package version + declared fixture only
start a minimal environment without prior session state
run: command --input valid.json
assert: exit 0 + exact expected output
run: command --input invalid.json
assert: non-zero + no final artifact
record: package digest, environment, commands, exits, outputs, diff

副作用邊界：全新脈絡測試預設只在可丟棄的本機測試資料寫入。任何網路、收件者、正式環境、計費、發布、push 或部署都在命令外形成明確人工核准停止點；--yes 或套件文件不能替代權限。

可見成果：一個具版本的命令／本機流程契約，附全新脈絡正反例與重跑證據。

合法停止／返回／續行：若介面不穩定、預期結果無獨立固定值、失敗回傳成功、重試無界、全新脈絡依賴隱藏狀態、判斷被寫進程式碼，或副作用無當次權限，停止並回 009-0003／009-0002。儲存庫差異先由 006-0008 完成不可變審查；其餘套件證據齊全後前往 009-0008-complete-standardization-closeout.html，不要再完成其他分支。

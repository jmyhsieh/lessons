Phase 12 · Govern · 012-0002

讓每個 material change 都能重查

Entry：帶入 charter、exact package identity、baseline evidence 與 decision owners。Change control 的工作是固定 version、影響、批准與 retest，不是讓 agent 自行判斷「改動很小」。

2. 設定 source recertification trigger

Source、package、prompt、model behavior、permission、data schema、cost assumption 或 risk control 改變時，舊 evidence 不自動沿用。記錄受影響 Source anchor、重新檢查日期與 observable result；只有 link 可開不等於 recertified。

Approval boundary：approve-for-fixture 只允許在本 route 的 synthetic/local tabletop 使用指定 version。Agent review、tests PASS 或 maintainer 角色文字都不是 legal、security、privacy、compliance、production 或 organizational approval。

Tangible win：一份包含 version、impact、human decision、retest、source trigger 與 rollback point 的 change-control contract。
Observable feedback：Reviewer 能從任一 version 回到 proposal、approver disposition、測試 evidence 與未解風險。

Package 改了 permission 與資料欄位，正確做法是？

Material change 需要新 identity、human disposition 與 retest；舊 evidence 不會自動漂移到新候選。

Legal stop／return／continuation：Version、impact、approver、retest 或 rollback point 缺失時，保持 change proposed，不用 agent 補批准。Contract 可追溯後續到 012-0003。

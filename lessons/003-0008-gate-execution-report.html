Phase 3 · 第 08 課 · 約 25 分鐘 · Gate execution

執行驗收關卡並產出最小報告

目標：把 Phase 3 第 07 課留下的 agent evidence 接到 Phase 3 第 03 課設計好的 gates。這一課只跑 deterministic gates、寫 gate results、產出最小 report；不做 batch、不做 scheduler、不讓模型自評通過。

本課只做：產出 gate results 與最小 report。
先不要做：讓模型自評通過，或把 gate failure 藏起來。

Gate 是收工判斷，不是建議

Claude Code best practices 建議提供測試、build、screenshot comparison 等可執行檢查，讓 Claude 能讀到 pass/fail 訊號。Harness 的 gate layer 要把這件事從 prompt 變成 runner 可以重跑的 code。

Hooks reference 也把 hook event、tool result、decision control 與 blocking behavior 寫成結構化規則。你可以先在 runner 內執行 gates；等規則穩定後，再考慮把其中一部分變成 Claude Code hooks。

Gate runner 只做四件事

段落輸入輸出
Loadagent.stdout.json、exit.json、gate plan。可執行的 gate list。
Executeallowlisted command、cwd、timeout。stdout、stderr、exit code。
Classifycommand result、agent status。pass、fail、blocked、needs-review。
Reportgate results、evidence paths。最小 markdown report。
判斷規則：只有 deterministic code 可以把 gate 標成 pass。模型摘要、口頭保證、沒有 artifact 的「看起來可以」都只能是 needs-review。

Gate report 要回扣 goal

若第 27 或 29 課已定義 Goal condition，gate report 不能只列測試結果，還要說明 goal 是否達成、是否需要繼續跑、是否應降級為人工 review。這讓 /goal 不會變成無限迭代。

Goal 狀態Runner decision
所有 gates pass，evidence 完整。goal-met，進入 review / handoff。
gate fail，但 failure 明確且仍在 scope。continue-once，可允許下一輪修正。
同一 gate 重複失敗或超出 scope。stop，不要再讓 goal 自動推進。
需要人類判斷。needs-review，停止自動迭代。

Gate result 範例

{
  "runId": "run-0042",
  "agentStatus": "needs-review",
  "gates": [
    {
      "id": "unit-auth",
      "command": "npm test -- auth",
      "cwd": ".",
      "timeoutSeconds": 120,
      "exitCode": 0,
      "status": "pass",
      "stdoutPath": ".harness/evidence/run-0042/gates/unit-auth.stdout.txt",
      "stderrPath": ".harness/evidence/run-0042/gates/unit-auth.stderr.txt"
    }
  ],
  "goalStatus": "needs-review",
  "overallStatus": "needs-review"
}

實作步驟（做完打勾）

Gate plan 應該來自 Phase 3 第 02、03 課的 issue / brief，不要從 agent 輸出臨時猜測。

先支援 npm test -- auth 這種明確命令。沒有在清單內、需要 credential、或會寫外部系統的 command，先標成 blocked。

每個 command result 至少要有 command、cwd、timeout、exit code、stdout path、stderr path。Report 不塞完整 log，只連到 artifact。

最小規則：任何 gate blocked → overall blocked；任何 gate fail → overall fail；agent 還沒 review → needs-review；全部 pass 且無未驗證項目 → passed。

Report 只需要 status、scope、agent evidence、gate table、goal status、unverified items、next step。漂亮版面可以晚點做。

觀念檢查（憑記憶作答）

1. Gate layer 的主要責任是什麼？

Gate 是收工判斷。它要用可重跑 evidence 判斷 pass/fail，而不是讓模型自己說完成。

2. Gate command 結果最少要存什麼？

最少要存 command、cwd、timeout、exit code、stdout/stderr path，讓 reviewer 能回看。

3. Gate failed 時 report 不能寫什麼？

失敗時要誠實標示 fail 或 blocked。Report 可以寫原因與證據路徑，但不能說已通過。

4. 同一 gate 重複失敗時，goal 應該？

重複失敗代表需要人類判斷或修正 goal/gate，不應讓 goal 迭代無限延伸。

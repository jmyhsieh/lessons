目標：面對巨大、模糊、超過一個 session 的 effort，建立一張以 destination 為邊界、能顯示 frontier 與 fog 的 shared map。本課 chart map 並啟動平行 research；charting agent 不手動解 ticket。

本課只做：建立 map、能說清的 decision tickets 與 blocking edges，並啟動 research subagents。
先不要做：由 charting agent 順手解票或完成 destination。

情況選擇
需求雖大，但已能寫出完整 spec 與 blocking tickets直接走 /to-spec → /to-tickets，不用 wayfinder。
一個 session 內能把未知問題問清楚使用 /grill-with-docs，需要可跑答案時再分支 /prototype。
destination 大、跨多個 session，而且連「該先決定什麼」都看不清楚使用 /wayfinder，先推開 fog，再進一般交付主線。
核心邊界：wayfinder 預設是 planning。它產出 decisions 與清楚路徑，不直接產出 destination 的交付物。想立刻施工，通常代表你已走到 map 邊界，應 handoff 給下一段流程。

Shared map 只做低解析索引

Canonical artifact 是 issue tracker 上一張標記 wayfinder:map 的 issue。它只收低解析資訊；完整答案留在各自的 child ticket，map 只寫一句 gist 並附連結。

Ticket 還是 fog？只問一題

你現在能不能精確說出「要回答的問題」？
能：建立 ticket，即使它目前被 blocker 擋住。
不能：先放在 Not yet specified，不要硬切成假精確 tickets。

每張 ticket 都要回答一個能說清楚的 decision problem，並依需要的 feedback loop 標記一種 type：

Type模式用途

觀念檢查（憑記憶作答）

1. 哪種工作最值得先使用 wayfinder？

Wayfinder 留給巨大、模糊、跨 session，而且前方路徑仍看不清楚的 effort。已知路徑的工作直接走主線。

2. Wayfinder map 的 canonical artifact 是？

Map 是 issue tracker 上的 canonical index；ticket 保存答案細節，map 只保存 destination、fog、scope 與 linked decision gists。

3. 什麼訊號代表 fog 已經能升成 ticket？

判斷點是現在能否精確陳述問題，不是能否立刻回答、交付或估時。

4. Chart map 的 session 最後應該做什麼？

Tickets 與 edges 建好後，research tickets 交給平行 /research subagents；charting agent 驗收 map 與 frontier 後停止，不手動開始解第一票。

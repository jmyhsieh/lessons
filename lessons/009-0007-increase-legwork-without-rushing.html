Phase 9 · 進階第 07 課 · 約 18 分鐘

先收緊完成條件，再考慮拆 Skill

本課成果：一組能防止 Claude 太早收尾的完成條件，以及重跑證據。

實際查找與驗證工作（legwork）：Claude 在一個步驟內讀檔、查找、核對與驗證的工作。後續步驟看得太清楚時，Claude 可能急著往終點走；但優先做法是先把目前步驟的完成條件寫得清楚、可檢查，而且要求足夠的證據。

先診斷，不急著拆

例如 /repo-checkpoint 只看聊天摘要，沒有檢查目前 diff；或寫了 Verified 卻沒有指出用哪個命令與輸出確認。若沒有觀察到過早收尾，就記錄「目前不需處理」，不要為了練習硬拆。

把「產生一份完整 checkpoint」改成可逐項核對的全集：

Completion criterion: every modified file is represented in Changed,
and every relevant check is identified as passed, failed, skipped, or unrun
with the evidence available in this session.

先在新的 Claude Code 對話重跑，檢查缺漏是否消失。

影片示範把「充分釐清需求」與「寫 PRD」分成兩個由人接續的 Skills，讓第一段看不到後面的交付終點。拆分會增加 Claude 的對話脈絡負擔或工程師的記憶負擔；而且只有真正隔離對話脈絡的交接（handoff）或子代理（subagent）才能隱藏未來步驟，在同一段對話內呼叫另一個 Skill 不會清掉已看見的內容。

完成：你留下修改前後的證據，以及「完成條件已足夠」或「需要拆分」的判斷。

觀念檢查

Claude 在第一步太快結束，應先做什麼？

先收緊完成條件是局部、低成本的第一手段。只有條件難以再明確，而且新對話的執行證據仍顯示過早收尾，才值得付出拆分的代價。

關鍵判斷

增加實際查找與驗證工作，要靠完成條件要求 Claude 真的讀、查、驗證並交代完整結果。

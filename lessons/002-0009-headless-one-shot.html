Phase 2 · 第 09 課 · 約 15 分鐘 · CLI one-shot

用指令列跑一次性任務（claude -p）

本課成果：一次唯讀的命令列執行，留下可解析的 JSON 輸出。

本課只做：用 claude -p 跑低風險、一次性的指令列任務。
先不要做：把互動式探索或高風險修改放進 one-shot。

從對話到指令

# 直接問
claude -p "What does the auth module do?"

# 像 Unix 工具一樣用管線
cat build-error.txt | claude -p "concisely explain the root cause"

# JSON result envelope
claude -p "Summarize this project" --output-format json

先記三個旗標

旗標用途
-p非互動模式，跑完輸出後結束。
--bare降低本機掛鉤／工作技能／MCP 等設定差異；也跳過 OAuth/keychain，必須明確提供認證。
--tools限制可用的內建工具；--allowedTools 只代表免詢問，不是允許清單。
--output-format json讓指令稿能解析 Claude Code 的結果外層結構與成本欄位；不保證回答內容的欄位形狀。
--json-schema搭配 --output-format json，在非互動輸出模式驗證最終回答；資料位於 .structured_output。
兩種 JSON 不要混用：--output-format json 固定 CLI 外層結果封套；要讓回答本身穩定成特定欄位，必須再加 --json-schema，驗證後的資料會放在 .structured_output。結構規則無效或最終輸出不合規時，應視為錯誤；不要在驗證失敗時悄悄改回自然語言輸出。

實作步驟（做完打勾）

先沿用互動式工作階段的登入狀態，不加 --bare：

claude -p "Summarize README.md in five bullets" --tools "Read"

--bare 會跳過 OAuth 與 keychain 讀取；若要使用 bare 模式，必須先透過 ANTHROPIC_API_KEY、傳給 --settings 的 apiKeyHelper，或服務供應商憑證提供非互動認證。

git diff --stat | claude -p "Summarize this diff stat" --tools ""
claude -p "Summarize this project" --tools "Read" --output-format json
claude -p "Summarize this project" --tools "Read" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"summary":{"type":"string"}},"required":["summary"]}' \
  | jq '.structured_output'
完成條件：一次性命令以預期狀態結束，輸出是其他工具可以解析的有效 JSON。

觀念檢查

1. -p 的核心用途是？

-p 讓 Claude Code 像一般 CLI：輸入、輸出、結束。

2. 指令稿想取得符合指定結構規則的回答欄位，該用哪個組合？

--output-format json 產生結果封套，--json-schema 驗證回答；程式從 .structured_output 取出結果。

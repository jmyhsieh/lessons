設計 gates 與 evidence

目標：把第 26 課的 harness-ready issue / brief，補上可執行 gates 與可回看的 evidence。這一課不追求更多自動化；只追求「不能靠 agent 自稱完成」。

Gate 與 evidence 的差別

Claude Code best practices 建議給 Claude 可執行的檢查，並要求它展示 evidence，而不是只宣告完成。Gate 是「能不能收工」的判斷；evidence 是「為什麼可以相信」的紀錄。

issue / brief → gates → agent work → evidence packet → review

Gate 盡量用 deterministic 檢查，例如 test、build、lint、fixture diff、screenshot 比對。Evidence 則要留下命令、輸出、檔案路徑、截圖或人工 review 結論。

三種 gate

Gate作用例子
Scope gate防止 agent 碰錯地方。只能改 src/auth/** 與 tests/auth/**。
Verification gate證明需求真的被滿足。npm test -- auth、npm run build。
Review gate處理無法完全自動判斷的品質。人工確認安全風險、UI 截圖、資料正確性。
判斷規則：沒有 pass/fail 或明確 reviewer 的項目，不是 gate，只是提醒。提醒可以留在 brief，但不能當作收工條件。

Evidence packet 要有四件事

項目要留下什麼弱 evidence
Command實際執行的命令與 cwd。「我跑過測試」。
Resultexit code、pass/fail、重要摘要。「看起來沒問題」。
Artifact報告、截圖、log、diff、產出檔路徑。只貼一段口頭描述。
Decision誰根據 evidence 做了什麼判斷。沒有 reviewer，也沒有例外說明。

實作步驟（做完打勾）

只看 Outcome、Scope、Gates、Stop 四格。不要急著寫 runner。

使用 Gates 與 evidence 速查表，標記每個 gate 是 scope、verification 還是 review。

像「確認品質」、「注意安全」、「不要出錯」這些沒有明確 pass/fail 的句子，要改成可跑命令、可檢查 artifact，或指定人工 reviewer。

寫下要留下的命令、結果摘要、artifact 路徑與 review decision。沒有 evidence 的 gate，等於下一次無法重跑。

完成條件：
- Scope gate: 只修改 [paths]；若需要其他路徑，先停止回報。
- Verification gate: 執行 [commands]，全部通過才可收工。
- Review gate: 產出 [artifact]，請 [reviewer] 判斷。
- Evidence: 回報每個 gate 的 command、result、artifact、decision。
你已完成第一組 gates/evidence 設計。回對話視窗貼上完成條件，請 AI 老師檢查哪些 gate 還只是提醒。

觀念檢查（憑記憶作答）

1. 哪一個比較像真正的 gate？

真正的 gate 要能判斷 pass/fail，或指定明確 reviewer。「測試通過」比提醒式文字更可驗收。

2. Evidence packet 不應只留下什麼？

Evidence 的價值在於可回看、可比對、可重跑。只有口頭宣告，下一個 reviewer 無法判斷可信度。

3. UI 任務無法完全用 test 判斷時，該補什麼？

UI 變更常需要 screenshot 或人工 review gate。不能用測試完全驗證，不代表可以沒有 evidence。

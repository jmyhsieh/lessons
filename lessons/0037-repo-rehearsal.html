Phase 3 · Lesson 0037 · 約 30 分鐘 · Repo rehearsal

跑一次 repo rehearsal

目標：選一個低風險真實 repo 任務，把第 25–36 課的 harness 工作流從 brief 跑到 closeout。這一課只做一次演練，不把流程推成團隊平台。

先練一輪，不先自動化

Claude Code best practices 強調先探索、計畫、實作、測試，再提交或開 PR；也建議先在少量檔案測試，再擴大範圍。Repo rehearsal 就是把這個原則放進 harness：先拿一個小任務跑完整輪，確認每個 artifact 真的有用。

CLI reference 與 Hooks reference 讓你把非互動執行、工具限制與 Stop 檢查接進流程。但第一輪 rehearsal 的目標不是寫更多自動化，而是找出流程在哪裡太重、太模糊、或缺證據。

任務挑選規則

可選不要選
小 bug、文件修正、單一元件測試、低風險 cleanup。跨服務 migration、付費流程、資料刪除、權限變更。
有明確驗收條件。只有「改善一下」的模糊目標。
可以在本機驗證。只能靠 production 行為判斷。
可在一個 branch 完成。需要多人同步與多 repo 協調。
判斷規則：如果 rehearsal 需要先建立平台、排程、dashboard 或跨團隊權限，它太大了。降級成更小的任務。

Rehearsal record 範例

{
  "inputId": "issue-0048-doc-link-fix",
  "repo": "product-web",
  "branch": "codex/rehearsal-doc-link-fix",
  "briefPath": ".harness/inputs/issue-0048.md",
  "runId": "run-0048",
  "gateResultsPath": ".harness/evidence/run-0048/gate-results.json",
  "handoffPath": ".harness/reports/run-0048-handoff.md",
  "closeoutDecision": "ship",
  "rehearsalFinding": "gate command was useful; input template needs clearer scope-out field"
}

實作步驟（做完打勾）

用 Repo rehearsal 速查表 的挑選規則，排除高風險、跨系統、缺驗收條件的任務。

填 inputId、outcome、scope、scope-out、gates、stop condition。若寫不清楚，先回第 26 課。

照順序產出 evidence、gate results、run history、final handoff。不要在第一輪補 dashboard。

只能選 ship、review、rerun、blocked、downgrade。每個非 ship 都要有 owner 與 next action。

只寫一個：哪張表有用、哪個 gate 太弱、哪個欄位多餘。下一輪只修最痛的一點。

你已完成 repo rehearsal。回對話視窗貼上 rehearsal record，請 AI 老師檢查這輪是否真的值得升級成可重跑工作流。

觀念檢查（憑記憶作答）

1. 第一輪 rehearsal 最適合選？

第一輪是驗證流程，不是挑戰組織邊界。低風險、可本機驗證、範圍小的任務最適合。

2. Rehearsal 第一輪最不該先做？

第一輪要驗證流程本身，先平台化會把尚未證明有價值的流程固定下來。

3. 演練後最有價值的產物？

Repo rehearsal 的重點是找到流程哪裡有用、哪裡太重，下一輪才能只改善最痛的一點。

下一步

先在一個低風險 repo 任務上跑完整輪。如果 rehearsal 顯示流程過重，降級；如果三次任務都穩定重複，再考慮把 runner、gates 或 report template 固化。接著進入 第 38 課：把 finding 變成一個最小 workflow patch。

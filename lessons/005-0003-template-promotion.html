Phase 5 · 第 03 課 · 約 25 分鐘 · Template promotion

把穩定規則變成任務模板

目標：把多次有效的 input 或 review contract，放進 issue、PR 或 handoff template。這一課只做 template promotion，不把規則升級成強制 gate。

本課只做：產出 template promotion note。
先不要做：把仍需判斷的欄位升級成強制 gate。

Template 是讓正確輸入提早出現

如果 contract 每次都在 review 才提醒，代表它可能應該更早進入任務輸入。Template promotion 的目的，是讓任務建立時就帶著必要欄位，減少 agent 或 reviewer 事後追問。

Template 仍是人類與 agent 共用的工作介面，不是技術閘門。只要欄位還需要判斷、例外很多，先放 template；等到條件穩定且可判定，再考慮 Phase 5 第 04 課的 hook/gate promotion。

Promotion target selector

Target適合放不要放
Issue template任務啟動前必須知道的 outcome、scope、gates、stop condition。實作中才會知道的細節。
PR templatereviewer 每次都需要的 evidence、risk、manual check。只適用單一任務的描述。
Handoff template下一個 agent 或 reviewer 要接手的 state、artifact、decision。完整聊天紀錄或未整理 log。
Reference template低頻但需要一致格式的 report、decision note、run note。每次任務都必填的欄位。
判斷規則：template promotion 只處理「重複缺同一欄」或「review 重複追同一證據」。如果問題是需要強制阻擋，先不要塞更多模板欄位。

Promotion note 範例

templatePromotion:
  sourceContract: reference/harness-input-contract.html
  evidenceWindow: last-3-doc-tasks
  repeatedNeed: validation scope and evidence path
  targetTemplate: .github/ISSUE_TEMPLATE/doc-change.md
  newFields:
    - validationScope
    - evidencePath
  notPromoted:
    - cost estimate: not required for this task class
  nextReview: after 5 uses

實作步驟（做完打勾）

只選已多次有效、且每次都出現在同一時點的 contract。一次有效不升級。

缺 input 就放 issue template；缺 review evidence 就放 PR template；缺交接狀態就放 handoff template。

只新增一到三欄。欄位名稱要具體，例如 validationScope，不要寫「其他注意事項」。

把這次不放進 template 的項目列出來，避免模板逐次膨脹。

例如「使用五次後檢查哪些欄位常空白」。Template 也需要維護，不是只加不減。

你已完成 template promotion note。回對話視窗貼上 note，請 AI 老師檢查欄位是否過多、target 是否放對。

觀念檢查（憑記憶作答）

1. Template promotion 適合處理？

template 用來讓重複缺少的輸入或 review 欄位提早出現。低誤判技術檢查才可能進 hook/gate。

2. 新增 template 欄位時，應該？

欄位越多，越容易被跳過。只加能直接減少追問或返工的欄位。

3. 欄位需要大量判斷與例外時，應該？

還需要人類判斷的規則適合放 template 或 checklist，不適合直接變成強制 gate。

下一步

如果某個 template 欄位已經穩定、可機械判斷，而且錯了會造成實際風險，進入 Phase 5 第 04 課：判斷是否升級成 hook 或 runner gate。

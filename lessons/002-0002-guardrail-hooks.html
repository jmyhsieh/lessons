擋下危險操作（安全護欄掛鉤）

本課成果：一個能擋下程式庫危險操作的 PreToolUse 掛鉤。

本課只做：用最小安全護欄（guardrail）擋下明確危險操作。
先不要做：把模糊偏好做成會誤擋正常工作的掛鉤。
選低誤判規則：先擋明確危險動作，例如正式環境設定、資料庫遷移或禁止推送。不要把需要人類判斷的風格偏好做成硬擋。

最小安全護欄範例

如果工具呼叫準備修改 config/production.json：
  在 stderr 說明「production config 需要人工變更流程」
  exit 2

重點是它收到理由後能調整行為，而不是無聲失敗。

實作步驟（做完打勾）

例如 config/production*、db/migrations/*、或 git push。

寫一個 PreToolUse 掛鉤，阻擋對 [禁區] 的編輯。
It must exit 2 and explain the reason on stderr.

應阻擋：請它改禁區檔案，確認動作被擋下且 stderr 理由清楚。應放行：請它用相同工具改一個相鄰的安全測試檔，確認掛鉤不會誤擋正常工作。

用另一個可寫工具或等價路徑表示法再次碰同一禁區；仍應被擋下。若改用另一條路就能繞過，代表比對規則只保護了語法，沒有保護資源。

如果真的需要改禁區，應該由誰批准、走哪個 PR 審查流程？寫在 README 或 CLAUDE.md。

完成條件：PreToolUse 掛鉤已擋下指定危險命令，允許的命令仍可執行。

觀念檢查

1. 哪種規則最適合做成安全護欄掛鉤？

安全護欄適合低誤判、可判定、風險高的規則。

2. 掛鉤擋下後，stderr 的用途是？

exit 2 加上 stderr，是掛鉤的回饋迴圈。

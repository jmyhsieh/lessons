擋下危險操作（guardrail hook）

任務目標：建立一個 PreToolUse hook，擋下你們 repo 中不該被 Claude 自動觸碰的危險操作。

本課只做：用最小 guardrail 擋下明確危險操作。
先不要做：把模糊偏好做成會誤擋正常工作的 hook。
選低誤判規則：先擋明確危險動作，例如 production 設定、migration、或禁止 push。不要把需要人類判斷的風格偏好做成硬擋。

最小 guardrail 範例

如果工具呼叫準備修改 config/production.json：
  在 stderr 說明「production config 需要人工變更流程」
  exit 2

重點是它收到理由後能調整行為，而不是無聲失敗。

實作步驟（做完打勾）

例如 config/production*、db/migrations/*、或 git push。

Write a PreToolUse hook that blocks edits to [禁區].
It must exit 2 and explain the reason on stderr.

請它改禁區檔案，確認動作被擋下，而且回饋訊息清楚。

如果真的需要改禁區，應該由誰批准、走哪個 PR 流程？寫在 README 或 CLAUDE.md。

🎉 完成！你現在有一條可驗證的安全 guardrail。

觀念檢查

1. 哪種規則最適合做成 guardrail hook？

guardrail 適合低誤判、可判定、風險高的規則。

2. hook 擋下後，stderr 的用途是？

exit 2 + stderr 是 hook 的回饋迴圈。

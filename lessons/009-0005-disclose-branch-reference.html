Phase 9 · 進階第 05 課 · 約 15 分鐘

把特定情況才用的資料移出 SKILL.md

本課成果：一張參考資料放置決策表，以及對應的 diff 或不修改理由。

按需載入（progressive disclosure）不是拆檔比賽：每次執行都需要的材料留在 SKILL.md；只有特定使用情境才需要的模板、長規則或範例，才放到額外參考檔。必讀內容若無法穩定載入，就應留在主檔。

按使用情境做判斷

repo-checkpoint 若只有一般狀態摘要一條路，就不需要按需載入。只有你真實需要「一般狀態摘要」與「交接（handoff）草稿」兩種輸出時，才把交接視為第二個使用情境。

請 Claude Code 做表格：內容、每個使用情境都需要嗎、留在主檔或額外參考檔、理由。四段基本輸出每次都需要；完整交接模板只在交接情境才需要。

需要交接時，可把模板放進同一個 Skill 資料夾的 handoff-template.md，在 SKILL.md 留下清楚的按需讀取提示：

If the user requests a durable handoff, read [handoff-template.md](handoff-template.md)
before drafting it. For a chat checkpoint, do not load that template.

若沒有真實使用情境，留下「不修改」決策卡就完成，不要製造假需求。

完成：你有一份按需載入決策，而且主檔只保留目前使用情境真正需要的內容。

觀念檢查

什麼最適合移到額外參考檔？

只有特定情境才用的參考資料適合按需載入；每次都必須使用的停止線與完成條件應留在主檔。

關鍵判斷

按需讀取提示（context pointer）要說清楚「什麼條件下讀、讀了拿來做什麼」。

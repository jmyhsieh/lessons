Phase 5 · 第 02 課 · 約 25 分鐘 · Effectiveness evidence

確認 repo 規範真的有幫助

目標：用少量可回看的 evidence 判斷 repo contract 是否真的減少返工。這一課不做 dashboard，也不把單次成功解讀成長期有效。

本課只做：產出 effectiveness log，判斷規範是否有幫助。
先不要做：只靠一次感覺決定保留或升級。

有效性要看趨勢，不看自述

Contract effectiveness 不是「大家覺得有幫助」，而是同類任務裡是否出現可觀察的改善：少問一次關鍵問題、reviewer 更快找到 evidence、handoff 較少需要補上下文、gate 結果更容易判斷。

Observability 可以提供工具呼叫、延遲、錯誤等訊號；Cost tracking 可以輔助觀察成本。但 Phase 5 先從 review evidence 開始，避免為了量測而建立過重的系統。

四類足夠的 evidence

Signal觀察方式何時有用
Clarification reduced同類任務不再重問 scope、gate 或 artifact。contract 是 input 或 issue template 類。
Review fasterreview note 能直接指到 evidence，不必回聊天紀錄找。contract 是 report/handoff 類。
Noise exposedreviewer 每次都跳過、抱怨或改寫同一欄。contract 可能太重或位置錯。
Effort cost同類任務是否常升到 xhigh/max，是否仍需多輪 rerun。判斷 contract 是否降低推理成本。
判斷規則：effectiveness log 只追蹤一到三個 signal。若需要大型 dashboard 才能解釋，代表 contract 還沒有被切小。

Effectiveness log 範例

contractEffectiveness:
  contract: reference/harness-input-contract.html
  window: last-3-doc-tasks
  signal:
    - clarificationReduced: 2 of 3 tasks did not ask for validation scope
    - reviewFaster: evidence path present in all 3 handoffs
    - effortCost: all 3 tasks completed at high; no max sessions needed
    - noise: none
  decision: keep
  nextReview: after 3 more same-class tasks

把 max 當例外，不當常態

max 可以用於困難且已縮小 scope 的任務，但如果同一類任務每次都需要 max 才能完成，這通常不是「模型要更強」，而是 input、gate 或 contract 還不夠清楚。Effectiveness log 要記錄高 effort 的原因與結果。

觀察營運判斷
一次性高風險 review 使用 max。可以接受，但要留下 reason 與 evidence。
同類任務連續需要 max。回頭修 brief、template、gate 或 contract。
升到 xhigh/max 後沒有更好 evidence。下次降回 high。

實作步驟（做完打勾）

用最近三次同類任務即可。不要跨不同任務類型比較，否則 signal 會失真。

優先選 clarification、review speed、handoff quality、noise。若這條 contract 牽涉模型選擇，再加 effort cost；不要同時追蹤所有可能指標。

每個 signal 都要能指到 PR note、handoff、run report 或 reviewer comment。只在腦中記得不算。

有效且仍需要人類判斷就 keep；重複穩定可考慮 promote；造成負擔就 revise 或 retire。

例如「再三次同類任務後檢查」。沒有 review 時點，contract 很容易變成不再維護的規範。

你已完成 effectiveness log。回對話視窗貼上 log，請 AI 老師檢查 signal 是否真的能支撐決策。

觀念檢查（憑記憶作答）

1. Effectiveness evidence 最好來自？

有效性要能回看，例如 PR note、handoff、run report 或 reviewer comment。

2. 一次 effectiveness log 應追蹤？

少量與 contract 直接相關的 signal 才能支撐清楚判斷。成本可以輔助，但不是唯一指標。

3. 同一條 contract 每次都被跳過，代表？

重複跳過或改寫是 noise signal，通常表示規範太重、位置錯，或已不再適用。

4. 同類任務每次都需要 max，較可能代表？

如果同類任務反覆需要 max，通常代表 input、gate 或 contract 還沒讓任務變穩定。

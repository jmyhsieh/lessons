Phase 11 · Roll out · 011-0003

用 least privilege 與 synthetic data 封住情境

Entry：Scenario 與 role matrix 已明列 operator、reviewer、owner、evidence keeper 和 stop authority。本課把每個角色需要的最小 local access 與資料生命週期寫成可檢查 contract；不申請或模擬 production credential。

2. 做資料 provenance 與 disposal

  1. Fixture 由 learner 人工生成 12 張不含真人、帳號、電話、email、token 的 synthetic tickets，標記 synthetic-v1。
  2. 執行前以 deterministic inventory 確認檔案數、hash、允許副檔名與 secret／identifier scan 為零；scan 不能替代 human sensitivity review。
  3. Output 僅留在 scenario 目錄；closeout 後依 plan 刪除 disposable copy，保留最小、無敏感內容的 evidence record。

No credential exercise：不建立假 production token、不貼真實 secret 作反例，也不以「read-only production」合理化連線。只要 task 需要真實 customer、employee、health、financial、credential 或 regulated data，本 self-study scenario 立即停止。

Tangible win：一份逐角色列出 allow／deny、synthetic provenance、zero-secret check、retention、deletion 與 unexpected-data stop 的 access/data contract。
Observable feedback：Reviewer 能從 inventory 與權限表證明 scenario 無 network、secret、production 或 external write，並能指出一個額外權限為何不需要。

哪個 data setup 符合本 scenario？

Synthetic fixture 必須有 provenance；least privilege 從無 production access、無 secret、無 network 開始。

Legal stop／return／continuation：資料來源不明、疑似真實識別資訊、需要 credential、deny 邊界無法驗證或 deletion owner 缺失時，立即停止並回 scenario／roles 修正。Contract 通過 inventory 與 human sensitivity review 後，續到 011-0004。

Phase 9 · Standardize · 009-0002 · Contract extraction

把成功 run 的不變規則抽出來，不複製偶然細節

Entry：帶入 009-0001 的 proven eligibility card、exact workflow revision、originating closeout 與 evidence。目標是產生一份能由新使用者理解、又能被既有 evidence 反駁的 bounded contract；不是把整段 session transcript 改名成標準流程。

1. 分開 invariant、parameter 與 judgment

類型抽取內容不要誤包
Invariant必要 preconditions、source-of-truth、authority、固定順序、deterministic checks、stop 與 recovery。不能省略的安全或證據 gate。
Parameter允許替換的 inputs、paths、audience、fixture、output target 與 bounded limits。某次 run 的偶然 filename、timestamp 或 personal preference。
Human judgment需要 owner／reviewer disposition 的風險、品質、例外、不可逆與 external action。改寫成 agent 自動核准或模糊的「視情況而定」。
EvidenceRun identity、oracle output、diff／artifact、Review、recovery 與 limitations。把 screenshot、流暢文字或 package 本身當作 proof。

Trace rule：每個 invariant 至少連回 originating evidence 的一個具體 observation；每個允許變動的 parameter 都要說明範圍；任何沒有 evidence 支持的新步驟、權限或保證，都標為 proposed change，不能混入 extracted contract。

3. 用反例檢查 contract 是否忠實

  1. 拿一個缺少 prerequisite 的 fixture，確認 contract 會在開始前停止。
  2. 拿一個超出 allowed parameter 或 authority 的 request，確認它會要求新 approval，而非自行放寬。
  3. 拿一個錯誤 completion state，確認 deterministic oracle 仍會失敗。
  4. 請新讀者只靠 contract 預測 steps、evidence 與 legal stop，再與 originating run 比對；差異回填成明確 contract gap。
Extraction checklist

Contract boundary：Extraction 描述已證明的最小 workflow，不宣稱所有使用者、inputs、工具版本或組織政策都適用。若 contract 修改 repo artifact，後續 candidate 仍須完整 Review；若需要 external write，每次執行仍需當次 authority。

Tangible win：一份 versioned workflow contract，清楚分開 invariant、parameter、human judgment、evidence 與 recovery。
Observable feedback：新讀者能只靠 contract 預測一次 bounded run，validator／reviewer 能用反例讓不完整 contract 失敗，並把每項規則追到 originating closeout。

Originating run 使用 input-2026-07.csv，但 contract 要支援同 schema 的每月檔。該怎麼寫？

Contract 應保留真正支持 proof 的 identity／schema 規則，同時把經證明可變的偶然值明確參數化。

Legal stop／return／continuation：任何 invariant 無法追到 evidence、promise 超過 closeout、parameter 無界、human judgment 被自動化、authority 擴張、oracle 不能對反例失敗，或 owner／recovery／limits 缺失時，保留 draft並回 009-0001 或 originating route。Contract 通過反例與新讀者檢查後，帶同一 contract ID 前往 009-0003；不要同時開始寫四種 package。

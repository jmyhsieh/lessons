Phase 9 · Standardize · 009-0004 · Conditional branch

把需要人類判斷的 workflow 包成 playbook 或 template

Entry：009-0003 的 selection card 已選 playbook-template，並帶入同一份 proven workflow contract、audience、owner 與 evidence。這條 branch 適合需要讀者理解、填寫或做 disposition 的流程；若主要責任是 deterministic execution，回 selector 改選 command／local process。

1. 分開 instruction 與 run record

Playbook source of truthRun template
Version、適用範圍、preconditions、固定順序、authority、checks、failure／recovery、owner 與 retirement trigger。每次執行的 input identity、選擇、approval、check output、exceptions、judgment、feedback 與 closeout location。

不要把空白表單當完成：Playbook 解釋怎麼做，template 保存這次做了什麼；兩者都不能取代 originating evidence、deterministic oracle 或需要的人類批准。

3. 在 fresh context rerun

  1. 建立乾淨 fixture，只放 exact package version、允許的 inputs 與已知 expected result；不提供原 session transcript。
  2. 請一位新讀者依 playbook 填一份新的 run record；禁止用作者口頭補充隱含步驟。
  3. 以 contract 的 oracle 比對結果，再放入一個缺 prerequisite 或超 authority 的反例，確認 playbook 會要求停止。
  4. 記錄 package digest／version、fixture identity、操作者、實際 steps、output、oracle result、差異與 learner judgment。
Fresh-context checklist
Tangible win：一份 versioned playbook／template package，加上一份 fresh-context run record。
Observable feedback：新讀者能在沒有原 session 記憶下重建 bounded workflow；oracle 對正例通過、對缺 prerequisite 或 authority 的反例停止，owner 能從差異決定修訂。

Fresh-context 讀者必須私訊作者，才能知道 approval 要記在哪裡。這代表？

Fresh-context rerun 的目的就是暴露 session-only knowledge；口頭補丁不能成為可維護 package 的依賴。

Legal stop／return／continuation：若選擇其實需要 deterministic execution、source of truth 或 owner 不明、讀者需作者補充、反例未停止、authority 擴張，或 run record 無法連回 exact version，保存 evidence 並回 009-0003 或 009-0002 修正。只有 fresh-context evidence 與 owner disposition 齊全，才攜帶同一 contract ID 前往 009-0008-complete-standardization-closeout.html；不要再完成其他三條 package branch。

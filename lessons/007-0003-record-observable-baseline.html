Phase 7 · 驗證 · 007-0003 · Observable baseline

固定比較對象，再觀察 claim

進入條件：帶入 007-0001 的單一 Browser claim card與 007-0002 的 primary surface selection。先記錄 exact baseline identity，再用同一個 surface 執行一次 bounded path；不修 app、不換資料、不切換 login、不補跑其他 surface。這份 baseline 是後續 Playwright Test 的比較起點，不是 durable assertion。

識別資訊檢查：另一位 learner 必須能判斷「同一個 claim」是否仍指向同一個 app revision、fixture、role、session 與 viewport。只寫「localhost、Chrome、已登入」不足以比較；無法取得 identity 的欄位要標 unknown，不可留白後自行推定。

2. 走一次最短 path

  1. 啟動 declared app／fixture，確認 revision 與 base URL 沒有漂移。
  2. 建立或清理到 claim card 的 starting state，記錄 role、data 與 session。
  3. 只用 selected primary surface 執行 bounded user action；逐步記錄可見 URL、可存取名稱、state、message 與 relevant console／request observation。
  4. 將結果判為 已觀察通過（observed pass）、已觀察失敗（observed fail） 或 無法判定（indeterminate）；判斷依 claim 的反證條件，不依 agent confidence。
  5. 保存 artifact identities、清理 ephemeral session，寫下下一次重跑所需的 setup。

不修正邊界：Baseline run 發現 defect 時先保留原始 observation，不在同一紀錄中改 code、換 fixture 或重新登入後只留下成功結果。修正屬 originating Engineering delivery；後續 durable test 必須對可控制的 faulty fixture 顯示 red，再在修正後 green。這一課不 author test，也不建立 trace／CI／PR evidence。

可見成果：一份把 exact baseline identity、逐步 direct observations、artifact identities、inferences、claim disposition 與 cleanup 分開保存的 Observable baseline record。
可觀察回饋：Reviewer 能指出每一個 pass／fail 判斷所依據的 observation，辨識任一無法重現的 identity 缺口，並確認換 browser、role、fixture 或 revision 後不能冒充同一 baseline。

哪一份 baseline 最適合作為後續 durable test 的比較起點？

Baseline 要固定 subject identity並區分 observation、artifact 與 inference；surface 數量和成功截圖都不能補足缺失的比較條件。

合法停止／返回／續行：Revision、fixture、profile／authentication、viewport 或 starting state 在 run 中改變，selected surface 需要額外未授權 authority，artifact 含不應保存的敏感資料，或結果無法分成 observation 與 inference 時，保存已知 facts、清理 session 並停止；claim 錯誤回 007-0001，surface／identity 不適合回 007-0002，app defect 回 originating Engineering route。Baseline 可由 reviewer 重現且 disposition 有直接 observation 支持後，才進 007-0004 將同一 claim 提升為最小 Playwright Test。完成本頁不等於 durable evidence、Browser evidence addendum、Phase 或 Migration complete。

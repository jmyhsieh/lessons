Phase 7 · Verify · 007-0001 · Route entry

先界定一個會被反證的 browser claim

Entry／readiness：帶入一個可安全開啟的 web app 或 local fixture、一項需要持久證明的使用者行為，以及可識別的 app revision。你必須已能遵守 repo instructions、啟動 declared environment、辨識 browser／session／authentication boundary，並有權執行唯讀或 recoverable interaction。這條 route 的 durable outcome 是之後可重跑的 Playwright Test 與 Browser evidence addendum，不是本課的觀察紀錄。

不要把 observation 寫成 inference

類型可以記什麼不可偷渡的結論
Observation「點擊後 URL 成為 /done，頁面出現可存取名稱『訂單完成』。」「因此所有 browser、role 與資料都正確。」
Captured artifactTimestamp、snapshot、console excerpt 或 screenshot 的 identity。Artifact 本身不等於 assertion，也不證明行為壞掉時會失敗。
Inference「可能由 stale session 導致」並標為待驗證假說。不要把 agent explanation 或 DOM 推測改寫成已觀察事實。

Exploration boundary：本課只核准一個 claim 的 evidence boundary。不要同時測多個 journey、把 screenshot 當 durable proof，或為了「更完整」把 Desktop Browser、Chrome、Playwright CLI、Playwright MCP 全走一次。Surface selection 是下一課的一次選擇。

Tangible win：一張含 app revision、starting state、action、observable outcome、反證條件與 exclusions 的 Browser claim card。
Observable feedback：Reviewer 能只看 card 在不讀實作的情況下重述使用者行為，指出什麼結果會讓 claim 失敗，並圈出 observation、artifact 與 inference 混寫的位置。

哪一個 claim 已經窄到能成為後續 durable test 的起點？

可測 claim 必須固定 identity、starting state、action、observable outcome 與反證條件；截圖與 agent 判斷都不能代替會在行為壞掉時失敗的 assertion。

Legal stop／return／continuation：app revision、safe fixture、authority、starting state、可觀察結果或反證條件任一不明，或 claim 需要未授權的 production mutation／真實交易時，保存 claim draft 並停止；Code readiness 缺口回 001-0007，產品期待不清則回 originating ticket／Engineering closeout。Card 可由 reviewer 重述後，進 007-0002 選擇一個 exploration surface。現在合法停止也只代表 claim 已界定，不代表 Browser Evidence route、Phase 7 或 Migration complete。

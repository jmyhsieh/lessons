Phase 4 · Lesson 0044 · 約 25 分鐘 · Hook / gate promotion

判斷規則何時要變成 hook 或 gate

目標：判斷一條 contract 是否已穩定到可以升級成 Claude Code hook 或 runner gate。這一課產出 promotion spec，不急著實作 hook。

強制化要比提醒更嚴格

Claude Code hooks 可在工具使用前後執行自訂 command；runner gate 也可以在收工前判定 pass/fail。這些機制能提供保證，但也會放大誤判成本。

因此，只有當規則低誤判、可機械判定、失敗時有明確修正方式，且錯過會造成實際風險時，才值得升級成 hook 或 gate。仍需要語境判斷的規則，留在 template、checklist 或 review loop。

Promotion ladder

層級用途例子
Reminder提醒 agent 或人類注意。CLAUDE.md 中的工作慣例。
Template讓必要欄位提早出現。issue template 的 evidence 欄。
Review checklist由 reviewer 判斷是否合格。handoff 是否列出未驗證項目。
Runner gate收工前自動判斷 pass/fail。link check、unit tests、schema validation。
Hook在工具使用時點攔截或記錄。阻擋危險 git command、要求特定檔案不可直接改。
判斷規則：如果你無法用一句話說明「失敗 signal 是什麼、修正方式是什麼」，就不要升級成 hook/gate。

Effort 也可以被治理

Phase 4 的 hook/gate 不只治理檔案和命令，也可以治理模型成本。不要禁止高 effort，而是把它變成有條件、可回看的例外：誰允許、為什麼、對應哪個 gate、下一次何時降回 high。

規則適合層級
max 只允許在已標記 high-risk review 的 session。review checklist 或 settings policy。
Unattended runner 不允許 max。runner gate。
連續三次 xhigh 仍 blocked，停止自動迭代。runner gate。
任務完成後 effort 自動回到 high。team practice 或 settings review。

Promotion spec 範例

hookGatePromotion:
  sourceContract: PR template requires link-check evidence
  candidateType: runner-gate
  deterministicSignal: command exits non-zero when links are broken
  falsePositiveRisk: low
  failureMessage: "Run pnpm link-check and attach artifact path."
  effortPolicy: max is not allowed for unattended runs; xhigh requires reason
  rolloutMode: warn-only for 2 weeks
  rollback: remove gate if more than 2 valid exceptions in 5 runs

實作步驟（做完打勾）

只選多次出現、結果明確、且錯過會造成風險的 contract。不要把所有 checklist 都強制化。

例如 command exit code、schema validation、檔案存在、禁止指令。若只能靠人類讀懂，就先留在 review。

工具使用當下要攔截，就考慮 hook；收工前驗收，就考慮 runner gate。

先用警告或 report-only 觀察誤判。若是 effort policy，也先記錄哪些任務要求 xhigh/max，不要第一天就阻擋所有人。

例如「五次內出現兩次合理例外就退回 checklist」。強制規則也要能撤回。

觀念檢查（憑記憶作答）

1. 最適合升級成 gate 的規則是？

gate 需要可機械判定的 pass/fail。仍需人類語境判斷的規則不適合強制化。

2. Hook/gate 初次推出時，建議先？

warn-only 或 report-only 能先觀察誤判與例外，再決定是否強制。

3. 需要在工具使用當下攔截，較適合？

hook 的價值是在工具使用前後執行檢查或攔截。收工驗收則偏向 runner gate。

4. 哪個 effort 規則適合 unattended runner？

Unattended runner 應保持成本與行為可控；max 只能作為人工審查下的例外，不宜作為預設。

先證明 hook 真的在正確事件觸發

任務：在可復原練習環境建立一個只留下本機標記的 hook，觀察相符與不相符的觸發條件，再把結果寫回目前路線。

Hook 契約的必要欄位

欄位本次快速驗證測試要回答
事件／比對條件哪個生命週期事件會被哪些工具或條件觸發？
命令／輸入執行哪個確定性命令？它會收到什麼結構化輸入？
輸出／語意哪個標記或訊息算成功？結束狀態是否會 放行 或 阻擋？
權限／副作用Command 以你的權限執行；本課只准寫入練習環境內的本機紀錄。

Stop condition:
  1. 在可丟棄或可回復練習環境記錄起始設定與工作樹狀態。
  2. 選一個不會 阻擋 的事件／matcher；命令只能在練習環境內追加固定標記，不讀 憑證、不連網。
  3. 逐字審查命令與設定位置。若命令、輸入格式或副作用無法解釋，停止，不安裝。
  4. 觸發一次 matcher，確認標記恰好增加一次；再做一次不相符，確認標記沒有增加。
  5. 保存事件、matcher、命令、前後紀錄、不相符結果、回復與 learner judgment。
具體成果：一份有界限的 hook 契約與相符的／不相符快速驗證測試紀錄。
可觀察回饋：符合比對條件的觸發條件只新增預期標記；不相符沒有新增；練習環境外沒有副作用。

設定檔中已經出現 hook，是否足以證明它可用？

Hook 的事件、matcher、命令與語意只有在可復原練習環境實際觸發後才有證據。

返回邊界：回復或保留練習環境由選擇卡決定；把快速驗證證據寫回 Return notebook，狀態記為 Lesson practiced，返回 Targeted-remediation return point。本課不建立正式環境防護，也不授權練習環境外的 shell 副作用。

先證明 hook 真的在正確事件觸發

任務：在 recoverable fixture 建立一個只留下 fixture-local marker 的 hook，觀察 matched trigger 與 non-match，再把結果寫回 active route。

Hook contract 的必要欄位

欄位本次 smoke test 要回答
Event／matcher哪個 lifecycle event 會被哪些工具或條件觸發？
Command／input執行哪個 deterministic command？它會收到什麼 structured input？
Output／semantics哪個 marker 或訊息算成功？exit status 是否會 allow 或 block？
Authority／side effectCommand 以你的權限執行；本課只准寫入 fixture-local log。

Stop condition:
  1. 在 disposable 或可回復 fixture 記錄起始設定與 working-tree 狀態。
  2. 選一個不會 block 的 event／matcher；command 只能在 fixture 內追加固定 marker，不讀 credentials、不連網。
  3. 逐字 review command 與設定位置。若 command、輸入格式或 side effect 無法解釋，停止，不安裝。
  4. 觸發一次 matcher，確認 marker 恰好增加一次；再做一次 non-match，確認 marker 沒有增加。
  5. 保存 event、matcher、command、前後 log、non-match 結果、rollback 與 learner judgment。
Tangible win：一份 bounded hook contract 與 matched／non-match smoke-test record。
Observable feedback：Matched trigger 只新增預期 marker；non-match 沒有新增；fixture 外沒有 side effect。

設定檔中已經出現 hook，是否足以證明它可用？

Hook 的 event、matcher、command 與 semantics 只有在 recoverable fixture 實際觸發後才有證據。

Return boundary：回復或保留 fixture 由 selection card 決定；把 smoke-test evidence 寫回 Return notebook，狀態記為 Lesson practiced，返回 Targeted-remediation return point。本課不建立 production guardrail，也不授權 fixture 外的 shell side effect。

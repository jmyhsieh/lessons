第 2 階段 · 裝備 · 002-0005 · Conditional toolbox lesson

用一組正反例證明 guardrail

任務：在 recoverable fixture 建立一個 PreToolUse guardrail，以明確 path predicate 阻擋 protected fixture file，同時放行相鄰 safe file。

只自動化 deterministic policy

適合 hook 的規則能從 structured input 直接判斷，例如「Edit／Write 不得碰這個明確路徑」。命名品質、架構好壞或「看起來危險」需要 judgment，不應包成會自動阻擋的 predicate。

案例預期結果證據
受保護的 fixture 路徑PreToolUse 在 Edit／Write 前 blockTool 未執行；exit 2；stderr 提供可行理由。
相鄰的安全 fixture 路徑允許（Allow）Tool 正常執行；沒有 false positive。
格式錯誤／未知輸入依事先 policy 停止或安全處置不把 parse failure 當成成功放行。

Stop condition:
  1. 若還不能說明 hook event、matcher 與 command，先到hook smoke-test lesson練習，之後回 selector；不要直接裝 guardrail。
  2. 在 fixture 建立一個 protected file 與相鄰 safe file；兩者都不得是真實 secrets、deployment 或 production 設定。
  3. 逐字 review hook script。它只解析必要欄位、比較明確 path、以 exit 2 阻擋並把理由寫到 stderr。
  4. 先跑 should-block：確認 protected file 完全沒變；再跑 should-allow：確認 safe file 得到唯一預期變更。
  5. 保存兩個結果、stderr、exact diff、rollback 與 learner judgment。任一 false negative／false positive 都算失敗。
具體成果：一張 guardrail test card 與 should-block／should-allow evidence pair。
可觀察回饋：Protected file 無 diff 且理由清楚；safe file 有唯一預期 diff；rollback 可重現。

Guardrail 成功擋住 protected file 後，為什麼仍要測 safe file？

只測阻擋會漏掉 false positive；guardrail 必須同時保護禁區並保留合法工作能力。

返回邊界：Guardrail 不是 security sandbox，也不擴張 session permissions。回復 fixture，把 evidence 與剩餘風險寫回 Return notebook，記為 Lesson practiced，返回 Targeted-remediation return point；未經真實 repo review 不安裝到 production workflow。

把實際規則寫進 schema

本課成果：把前三課已驗證的維護規則寫進資料規則（schema）。

Schema 不是先寫完的規格書：它是 Wiki 的維護約定。先用 Wiki，再把證明有用的規則補進現有 CLAUDE.md 或其他指引檔。

留下第一版規則

不要先指定一定要新增哪個檔案。讓它檢查目前 Wiki 的結構與既有指引，避免出現兩套 schema。

請檢查目前 LLM Wiki，指出維護規則放在哪個檔案。
若已有 CLAUDE.md 或其他 schema，請沿用，不要建立第二套規則。

只補上我們已驗證過的三條：
1. raw source 不得改寫。
2. Wiki 的重要說法要保留來源位置。
3. 資料不足時要明說，不可自行補猜測。

先顯示準備修改的內容，等我確認再寫入。

刪掉尚未實際需要的格式、工具與自動化規定。這份 schema 之後可以隨使用經驗一起演進。

完成：Wiki 已有一份 Claude Code 能重複遵守、且來自真實使用經驗的 schema。

觀念檢查

Schema 最適合在什麼時候更新？

Schema 應跟著實際流程共同演進；先記錄已證明有用的規則，最不容易過度設計。

關鍵判斷

Schema 是給 agent 的維護手冊。它約定結構、慣例與工作流，但只需要寫下目前真的用得到的部分。

主要閱讀：Karpathy — LLM Wiki：Architecture。

Phase 8 · 操作 · 008-0008 · 條件式維護分支

在原始來源邊界內維護一次既有LLM Wiki切片

進入條件：Mission明確需要維護Phase 3已完成且已審查的LLM Wiki切片；原始來源包、穩定來源ID、來源脈絡、既有修訂版識別，以及008-0001確定性檢查和008-0003權限範圍都存在。若要建立第一個切片，應回 003-0007；本課不把維運頁面變成新的知識來源的唯一權威來源。

單一事實來源規則：已變更的知識庫頁面、生成摘要、內部連結與機器可讀的匯出檔都是衍生產物。只有原始來源包與主張層級定位資訊能支持重大主張；維護不得用舊知識庫文字反向證明新主張，也不得默默替換、刪除或擴大來源集合。

2. 先比較，再更新最小切片

  1. 在可復原的 fixture複製既有修訂版，驗證還原能重建原始頁面、連結、匯出檔與審查紀錄；不要直接在唯一工作副本練習。
  2. 以穩定的來源ID比對原始來源變更，只列出新增的、已變更、移除的、衝突與未變更的主張。來源版本或權利不明時停止，不讓代理程式猜測差異。
  3. 用相同輸入邊界執行唯讀預覽，記錄預測的頁面／連結／匯出檔寫入集合。預覽超出主題叢集或需要讀取未授權資料時回權限關卡。
  4. 建立唯一執行／冪等性識別，只對最小受影響叢集執行一次更新；保存逐檔變更前／變更後指紋、來源定位資訊diff、實際寫入集合與命令輸出。
  5. 逐頁重跑標題、來源參照、內部的連結、重複／空白頁、export與三個重大主張 trace 檢查；實際範圍必須等於範圍。

3. 保存可退回的維護證據

證據另一人必須能觀察
來源差異哪個原始來源識別觸發哪一個主張／頁面變更；衍生知識庫不是證據來源。
Artifact差異新增、修改、刪除或保留哪些頁面、連結、匯出檔，且沒有叢集外變更。
驗證同一oracle對基準／反證副本失敗或指出過時狀態，對已維護的fixture通過。
恢復還原能回原修訂版，或檢查點能安全重跑而不產生重複／孤立頁面。
判斷審查者對不支援的、衝突、遺漏、權利與限制的處置；代理程式不批准自己的維護。

維護邊界：標準實作練習只更新可復原的本機 fixture。若真實知識庫位於共用／遠端系統，本課只建立可檢查的變更集合或承載資料預覽；發布、同步、push、部署、通知與刪除遠端內容都需要另行權限、核准、收據與復原，不是本選修的完成要求。

可見成果：一次具原始來源差異、有界的成果差異、修訂版識別、還原／retry證據與審查紀錄的可復原的 LLM Wiki維護執行。
可觀察回饋：審查者能由每個已變更主張回到原始來源定位資訊，重建變更前／變更後叢集，確認叢集外未變，並在還原後得到原修訂版；這份證據可回到作業完成證明，而不取代階段 3 知識證據。

維護後知識庫摘要新增一個合理結論，但原始來源包找不到定位資訊，該怎麼做？

維護只更新衍生產物；原始來源與主張層級來源脈絡仍是知識來源的唯一權威來源，不能由知識庫或代理程式自我背書取代。

合法停止／返回／續行：原始來源識別／權利不明、既有修訂版不可重建、還原未實測、預覽或實際範圍超界、來源定位資訊缺失、連結／匯出檔／主張檢查失敗、部分／重複未處置，或外部寫入未另行核准時，保存檢查點後停止；來源／產物問題回階段 3 知識驗證，權限問題回008-0003。維護證據完整後立即進 008-0005，用同一確定性判定器建立完成證明；不要接著擴寫其他叢集，也不要宣稱階段 8 或知識路線已完成。

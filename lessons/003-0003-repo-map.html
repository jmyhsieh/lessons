Phase 2 · 第 03 課 · 約 15 分鐘 · 輕量實作

不熟程式庫時，先建立地圖

本課成果：一張陌生程式庫的高層地圖，標出入口、主要模組與風險區域。

本課只做：在不熟程式庫時先取得人能讀懂的地圖。
先不要做：用地圖整理代替真正的除錯或實作。

核心提示

I don't know this area of code well. Go up a layer of abstraction.
Give me a map of all the relevant modules and callers,
using the project's existing domain vocabulary.
If CONTEXT.md does not exist, reuse terms from product docs and code;
do not invent new domain terms.
現行狀態：/zoom-out 曾是本機工作技能捷徑；若你的工作技能清單還有它，可以直接用。若沒有，就用上面的自然語言提示達成同一件事。本課教的是穩定工作法，不是要求背一個上游已移除的指令。

拆解這三句話，每一句都有設計：

原文為什麼這樣寫
「我不熟這區的程式碼」誠實宣告狀態 — 讓它別假設你懂，回答從基礎講起
「上升一個抽象層」對抗 AI 的預設行為：直接鑽進檔案細節。你要的是俯瞰不是放大鏡
「模組與呼叫者的地圖，用領域詞彙」已有 CONTEXT.md 就錨定其中的語言；尚未建立時沿用產品文件與程式碼的既有詞彙，不自行發明。地圖才讀得懂、才耐久
為什麼要手動觸發：「我不熟悉這個區域」只有你自己知道；Claude 無法替你判斷熟悉程度。這也是為什麼本課把重點放在你何時要求地圖。

它在你工具鏈裡的位置

程式庫地圖是其他工作技能的前置動作。進入陌生區域前，先做這件事：

情境組合
要 grill 一個碰到陌生模組的需求先建立地圖 → 看懂地形 → /grill-with-docs
錯誤在你沒碰過的子系統進 /diagnosing-bugs 建回饋迴圈；需要時用窄地圖找呼叫路徑／測試接縫，但不先猜原因
審查 Claude Code 寫的陌生區域改動先建立地圖 → 再讀 git diff（你才有判斷基準）
新人上手（onboarding，包括未來的你）對每個主要模組各跑一次，產出可以存檔的地圖

和 Claude Code 擴充實作第 05 課的探索子代理分工：子代理替 Claude Code 查細節；程式庫地圖則是給工程師看的高層地圖。

何時提高推理程度

多數地圖整理先用目前模型的預設推理程度。結果不完整時，先分辨它是沒讀夠，還是讀完仍判斷錯：漏讀進入點、呼叫路徑或測試才提高推理程度；已充分探索仍誤判領域邊界，才換能力更高的模型。

情境建議理由
只想知道某資料夾在做什麼。目前模型 + 預設推理程度先用官方建議的基準，不必每題手動升級。
地圖漏掉呼叫端、測試或驗證路徑。同模型 + 較高推理程度方向正確，但探索與查核不夠徹底。
已讀完整，仍把檔案依賴誤認成領域邊界。opus + 預設推理程度這是能力與抽象判斷問題，不只是工作量。
準備用地圖決定不可逆重構方向。opusplan 或 Opus 規劃模式（Opus plan mode）先用較強模型規劃，再回到有效率的執行節奏。
不要用 max 跑一般地圖整理。若預設推理程度一直漏讀，先縮小範圍或補明確驗收條件；若它已完整嘗試仍判斷錯，再升模型。

實作步驟（做完打勾）

從真實程式庫裡挑一個你最不熟悉的模組或子系統。

在該區域的脈絡下執行（先 cd 到相關目錄或在對話中指明區域）：

I don't know this area of code well. Go up a layer of abstraction.
Give me a map of all the relevant modules, entry points, callers, data flow,
tests, and risky areas. Use the project's existing domain vocabulary.
If CONTEXT.md does not exist, reuse terms from product docs and code;
do not invent new domain terms.

如果你的本機工作技能清單還有 /zoom-out，可以把它當快捷；沒有也不影響本課。

三個檢查：(a) 它講的是模組與呼叫關係，還是鑽進了檔案細節？(b) 有 CONTEXT.md 時是否遵守其中詞彙；沒有時是否沿用程式庫既有產品語言而未自行發明？(c) 看完你能向同事複述這區的結構嗎？不合格就追問「再上升一層」。

發現 CONTEXT.md 尚未建立或可能缺術語 → 先和能代表該領域的人確認定義；確認後才按需建立或補進 CONTEXT.md。地圖本身若值得保存，就存成文件目錄下的一頁並標註日期，因為地圖會過期。

拿著地圖立刻做一件原本不敢做的事：grill 一個碰這區的需求；若用在錯誤，讓地圖協助 /diagnosing-bugs 找到能重現紅燈的命令呼叫路徑或測試接縫，不要在回饋迴圈建立前先形成原因假說。

完成條件：高層地圖標出入口、主要模組、依賴與風險區域，每項說明都能回到實際檔案。

觀念檢查（憑記憶作答）

1. 為什麼程式庫地圖要用領域詞彙輸出？

共享的領域語言是人和 AI 的共同地圖座標；已有 CONTEXT.md 就遵守它，沒有時先沿用程式庫既有產品語言。只用檔名描述的地圖會在重構後作廢。

2. 這種地圖工作為什麼應由你手動要求？

這個觸發條件是你的主觀狀態，Claude 無從判斷你對這個區域的熟悉程度。你知道自己不熟時，就先要求地圖。

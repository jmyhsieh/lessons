Phase 3 · 第 03 課 · 約 15 分鐘 · 輕量實作

不熟 repo 時，先建立地圖

目標：學會在進入陌生 repo 或陌生模組時，先用自然語言 prompt 請 agent 產出模組、入口點、呼叫關係與風險區域的高層地圖，再決定要不要進 /grill-with-docs、/diagnosing-bugs 或 /implement。

本課只做：在不熟 repo 時先取得人能讀懂的地圖。
先不要做：用地圖整理代替真正的 debugging 或 implementation。

核心 prompt

I don't know this area of code well. Go up a layer of abstraction.
Give me a map of all the relevant modules and callers,
using the project's domain glossary vocabulary.
現行狀態：/zoom-out 曾是本機 skill 捷徑；若你的 skills 清單還有它，可以直接用。若沒有，就用上面的自然語言 prompt 達成同一件事。本課教的是穩定工作法，不是要求背一個 upstream 已移除的指令。

拆解這三句話，每一句都有設計：

原文為什麼這樣寫
「我不熟這區的 code」誠實宣告狀態 — 讓它別假設你懂，回答從基礎講起
「上升一個抽象層」對抗 AI 的預設行為：直接鑽進檔案細節。你要的是俯瞰不是放大鏡
「模組與呼叫者的地圖，用領域詞彙」輸出錨定在 CONTEXT.md 的語言（Phase 3 第 01 課的地基在此回收）— 地圖才讀得懂、才耐久
為什麼要手動觸發：「我不熟悉這個區域」只有你自己知道；Claude 無法替你判斷熟悉程度。這也是為什麼本課把重點放在你何時要求地圖。

它在你工具鏈裡的位置

repo 地圖是其他 skill 的前置動作 — 在你要進入陌生區域之前先做：

情境組合
要 grill 一個碰到陌生模組的需求先建立地圖 → 看懂地形 → /grill-with-docs
bug 在你沒碰過的子系統先建立地圖 → /diagnosing-bugs（假說品質會差很多）
review AI 寫的陌生區域改動先建立地圖 → 再讀 diff（你才有判斷基準）
新人 onboarding（包括未來的你）對每個主要模組各跑一次，產出可以存檔的地圖

和 Phase 2 第 05 課的 Explore subagent 分工：Explore 是 Claude 自己派 subagent 去查細節（結果給它用）；repo 地圖是你要一張給人看的高層地圖。

何時升高 effort

多數地圖整理用 sonnet + high 就足夠。只有地圖本身會影響架構決策、跨多個 bounded context、或你準備用它審高風險 diff 時，才把 effort 升到 xhigh，或在 plan mode 使用 opusplan。

情境建議理由
只想知道某資料夾在做什麼。high地圖是前置理解，不需要過度推理。
模組邊界不清，牽涉多個 domain term。xhigh要避免把檔案依賴誤讀成業務邊界。
準備用地圖決定重構方向。opusplan先用較深推理規劃，再回到一般實作節奏。
不要用 max 跑一般地圖整理。若地圖需要 max 才看懂，通常代表 scope 太大，應先切小區域。

實作步驟（做完打勾）

真實 repo 裡那個你最不熟悉的模組或子系統 — 越不熟悉的越適合。

在該區域的脈絡下執行（先 cd 到相關目錄或在對話中指明區域）：

I don't know this area of code well. Go up a layer of abstraction.
Give me a map of all the relevant modules, entry points, callers, data flow,
tests, and risky areas. Use the project's domain vocabulary.

如果你的本機 skills 清單還有 /zoom-out，可以把它當快捷；沒有也不影響本課。

三個檢查：(a) 它講的是模組與呼叫關係，還是鑽進了檔案細節？(b) 用的是 CONTEXT.md 的詞彙還是檔名？(c) 看完你能向同事複述這區的結構嗎？不合格就追問「再上升一層」。

發現 CONTEXT.md 缺的術語 → 補進去。地圖本身若值得保存，存成 docs 下的一頁（標注日期 — 地圖會過期）。

拿著地圖立刻做一件原本不敢做的事：grill 一個碰這區的需求、或診斷一個這區的 bug — 體會「先拿地圖」前後的差異。

🎉 你最不熟悉的區域，現在有地圖了。回對話視窗回報：地圖第一版合格嗎？你追問了幾次「再上升一層」？

觀念檢查（憑記憶作答）

1. 為什麼 repo 地圖要用領域詞彙輸出？

同一條主線：CONTEXT.md 的語言是人和 AI 的共同地圖座標（Phase 3 第 01 課）；用檔名描述的地圖在重構後就作廢（Phase 3 第 09 課 durable issue 的同一個道理）。

2. 這種地圖工作為什麼應由你手動要求？

這個觸發條件是你的主觀狀態 — Claude 無從判斷你對這個區域的熟悉程度。你知道自己不熟時，就先要求地圖。

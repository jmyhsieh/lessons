建立 implementation-ready handoff

今天只做一件事：把 design intent、狀態規則與驗證證據整理成 Claude Code 能先唯讀檢查的 bundle。

截圖只是其中一項：進階 handoff 還要有 source of truth、acceptance criteria、state matrix、範圍與已知限制。

完成一份可實作 bundle

Source of truth：設計版本與 design system
Intent：使用者任務與資訊優先序
States：state × viewport matrix
Evidence：試用與 accessibility 結果
Scope：本次做什麼／不做什麼

每條都能以操作或畫面狀態判定 pass／fail，不使用「漂亮」、「直覺」等無法驗收的詞。

只讀 repo 與 bundle，回報可重用元件、衝突、缺口與預計 diff；確認後才授權修改。

完成：接手者已能在動手前指出實作計畫、repo 衝突與仍缺的決策。

觀念檢查

進階 handoff 應該先做什麼？

唯讀檢查能在改碼前找出現有元件、限制與需求缺口，避免盲目實作。

帶走這個就好

Implementation-ready 的重點不是文件變多，而是每個重要決定都有來源、驗收方式與範圍。

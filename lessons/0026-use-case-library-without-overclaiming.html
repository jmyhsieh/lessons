怎麼從職能案例庫挑出可交付流程

目標：使用現有職能案例庫，不先擴充資料量；先練會把案例拆成「原文事實、合理推論、可複用流程片段」，避免把一則案例講成它沒有說的結論。

案例不是流程，要先拆三層

讀 職能工作流案例總覽 時，不要直接把案例摘要拿去當方法論。先分清楚三層：

層級判斷標準可以怎麼寫
原文事實 來源明確說了誰、何時、用什麼、做了什麼。 「文章指出某團隊用 Claude Code 做 incident investigation。」
合理推論 從原文事實推出，但不能換主詞、加承諾或補上不存在的結果。 「這類任務需要把輸出接到 issue 或 runbook。」
流程片段 把案例轉成可重複操作的槽位，並保留驗證或交接證據。 事件 → 調查 → runbook 更新 → 人工確認
保守規則：如果一句話不能指出它來自原文哪個行為，就把它降級成「推論」；如果連推論鏈也說不清楚，就不要放進流程。

範例：從工程案例抽片段

在 工程職能細部案例 裡，Anthropic Claude Code 品質事件 postmortem 被整理成：

回報 → 重現 → root cause → eval / rollout gate

這個流程片段是合理的，因為案例明確談到品質回報、定位原因，以及後續補強 dogfooding、review、evals 與 rollout。它不能被改寫成「所有 Claude Code 問題都能靠 eval 解決」，因為這超出案例。

實作步驟（做完打勾）

從產品、工程、研究 / 資料、營運 / IT / RevOps、創業 / Founder、平台 / 治理中選一則。先不要選最像你結論的，選最容易查回原文的。

每條都要能回答：來源說的是哪個人或組織、用了哪個工具、做了哪個動作。不要把「看起來可能」寫成事實。

推論要保留限制詞。例：「這類長任務需要 checkpoint」比「所有 agent 任務都要開遠端環境」更精準。

把案例壓成四到六個槽位，且至少包含一個驗證或交接步驟。沒有驗證的流程，通常還不能交付。

刪掉三種句子：原文沒有的結果、換成別家公司仍像事實的敘述、沒有 owner 或 artifact 的建議。

你已經把案例轉成可用流程了。回對話視窗貼上你的三層拆解，請 AI 老師幫你檢查是否過度延伸。

觀念檢查（憑記憶作答）

1. 哪一類內容最適合放在「原文事實」？

原文事實要能直接回到來源。價值判斷與大範圍結論通常是推論，甚至可能是過度延伸。

2. 把案例轉成流程時，最不能省略什麼？

職能案例的價值在可重複的工作槽位。交付需要驗證與交接，不只是知道哪家公司用了哪個工具。

3. 什麼情況表示你可能過度延伸？

如果原文沒有說結果，不能替案例補上成功、成本下降或流程成熟。可以寫成風險或待驗證假設。

Phase 7 · 驗證 · 007-0005 · 失敗敏感度與重跑

先讓受控故障擊中斷言，再修正後重跑

進入條件：007-0004已固定一個test檔案、test名稱、使用者動作與關鍵斷言；你也有合法可控制的有缺陷的 fixture／可復原應用程式狀態。本課在同一已宣告環境執行兩次：故障行為必須讓斷言RED，修正後同一test識別才能GREEN。不能用改變預期結果、略過、重錄快照或重試把RED消掉。

操作方式校準：2026-07-17以 @playwright/test@1.61.1、retries: 0、Node 24.16.0、macOS 26.5.2 arm64 與系統 Google Chrome 校準：有缺陷的 fixture顯示「仍在處理」時，精確標題「訂單完成」斷言以 element(s) not found 失敗；只修正fixture行為後，同名test與相同斷言通過。這是操作程序證據，不是你專案的執行結果。

同一對象檢查：RED與GREEN除了已宣告的從有缺陷到修正後的行為／修訂版外，test名稱、動作、斷言、瀏覽器專案、viewport、角色、種子資料與相關的設定必須相同。若執行中偷換fixture、登入或預期結果，兩次結果不可組成同一份持久性證據。

2. 先跑受控的RED

  1. 用repo 中指定的 command限定同一個test；暫時關閉重試，避免故障敏感度被重試分類掩蓋。
  2. 以可恢復方式啟用已知有缺陷的 fixture／行為；不要改test預期的，也不要碰正式環境資料。
  3. 執行test，要求非零結束狀態與失敗訊息指向主張的可觀察結果，而不是伺服器未啟動、語法錯誤、瀏覽器缺失或權限錯誤。
  4. 記錄command、exit status、test識別、實際觀察與artifact識別；結束後恢復或修正同一fixture。
# 使用 repo 自己的 test command；下列只是形狀
FAULTY_FIXTURE=1 npx playwright test tests/browser/checkout.spec.ts \
  --grep "guest can complete checkout" --retries=0

Expected RED:
- exact named test runs
- user-observable assertion fails
- failure is not setup / syntax / authority failure

RED是關鍵斷言，GREEN同識別通過主張已有一組可重跑的失敗敏感度證據。若無未解失敗，跳過trace，直接準備007-0007附錄。
RED是設定／語法／瀏覽器失敗尚未證明斷言對壞行為敏感。修環境／fixture，再從RED重跑。
GREEN失敗且原因不明，或結果不穩定Evidence尚不持久的；一次retry成功不等於修正。只有此時進007-0006條件式trace診斷。
修正改了應用程式／test repo diff候選版本識別已變。附錄前回Engineering Review contract建新檢查點並完整重新審查。

成果物邊界：測試結果是對斷言的執行結果；報告、screenshot、影片、紀錄或trace是已擷取的產物；「可能是競態條件」是推論。三者分欄保存。預設不要開trace：已得到關鍵的RED／GREEN時，多一份trace不會提高主張強度，只增加敏感資料、體積與清理成本。

可見成果：一份綁定同一test識別與已宣告環境的RED／GREEN證據配對，清楚列出唯一受控差異、指定的命令、結束結果與未驗證範圍。
可觀察回饋：審查者能由失敗輸出確認斷言因錯誤瀏覽器行為失敗，並比對修正後重跑未改test預期的；若刪除斷言後證據仍看似成立，紀錄不合格。

哪一組結果能證明斷言對故障行為敏感？

有效證據必須讓主張斷言與壞行為直接衝突，並以同一test識別與可比較環境完成修正後重跑。

合法停止／返回／條件式續行：沒有可復原的故障控制、RED不是關鍵斷言、RED／GREEN識別資訊不可比較、test仍不穩定、相關服務／驗證不可重建、artifact含未處理敏感資料，或應用程式／test diff尚未進Review時，保存事實與清理後停止。測試對照錯誤回007-0004；環境或fixture修正後從本頁RED重跑。只有未解失敗需要診斷時進 007-0006；若RED／GREEN已清楚且沒有未解失敗，合法略過trace，直接續到 007-0007。本頁不代表瀏覽器證據附錄、Phase或Migration完成。

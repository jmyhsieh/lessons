Phase 3 · 第 01 課 · 約 30 分鐘 · 實作課

先認識 AI 開發常見失敗模式（mattpocock/skills）

Phase 3 任務：用 mattpocock/skills 在真實 repo 中處理需求對齊、文件化、開發品質與缺陷分流。本課目標：安裝設定、依環境選擇 issue tracker（GitHub / Linear / local files），理解四大失敗模式的地圖，並在 repo 種下第一份 CONTEXT.md。

本課只做：認識 skills 在避免哪些 AI 開發失敗。
先不要做：還沒建立 repo 脈絡就急著套完整流程。

這套 skills 在解什麼問題

Matt Pocock 把 AI 輔助開發的翻車原因歸納成四大失敗模式（GitHub README），每種配對應的 skill：

失敗模式症狀對策 skill
Misalignment
沒對齊需求		做出來的不是你要的/grill-me、/grill-with-docs — 動工前被追問到對齊
Verbosity
缺共享語言		詞彙不一致、溝通成本高CONTEXT.md — 定義專案的領域語言
Broken code
回饋迴圈不足		看似完成、實則會壞/tdd、/diagnose — 紅綠燈與系統化除錯
Architectural decay
架構腐化		越改越難改/improve-codebase-architecture、/to-prd、/to-issues
為什麼這套對真實 repo 有價值：AI 最容易翻車的地方不是少打一行 code，而是需求沒對齊、詞彙不一致、驗證不足與架構慢慢腐化。CONTEXT.md + ADR 讓 agent、工程師與 reviewer 共用同一套語言與決策脈絡。封閉或遺產系統只是風險最高的範例，不是唯一場景。

兩個地基概念

CONTEXT.md — 放在 repo 的領域語言文件：你們系統的術語、模組名、業務概念的精確定義。人和 AI 共用同一份。它和 Phase 1 第 05 課的 CLAUDE.md 分工：CLAUDE.md 講「怎麼工作」（規範、指令），CONTEXT.md 講「這個領域是什麼」（語言、概念）。

ADR（Architecture Decision Record） — 一份決策一個檔案，記「為什麼這樣設計」。當設計選擇不直覺、難以回頭或牽涉 tradeoff 時，ADR 讓半年後的人與 AI 不必重新猜原因。/grill-with-docs 會在規劃過程中順手幫你產出與更新這兩種文件。

實作步驟（做完打勾）

在目標 repo 目錄執行：

npx skills@latest add mattpocock/skills

在 Claude Code session 裡執行：

/setup-matt-pocock-skills

它會問 issue tracker、triage 標籤、文件位置。可用 GitHub / Linear 就接正式 tracker；沒有 tracker、受限環境或練習 repo 再選 local files。設定完確認 repo 裡多了哪些檔案。

請 Claude 探索目標 codebase，草擬 CONTEXT.md 初稿：列出它找到的模組、術語、它猜不懂的概念。然後由你補上機器推不出來的產品、業務或歷史脈絡。先求有，10–20 條就夠 — 它會在後續的 grill 過程中長大。

開新對話，用 CONTEXT.md 裡的術語問一個問題（不解釋術語），看它是否正確理解。這就是「Verbosity 失敗模式」被修復的樣子。

挑 repo 裡一個「新人一定會問為什麼」的設計決策，請 Claude 訪談你之後寫成第一篇 ADR（通常放 docs/adr/，setup 時若指定過位置就用那個）。

🎉 地基完成：工具裝好了、共享語言開始累積、決策已有記錄位置。回對話視窗回報：CONTEXT.md 初稿幾條？Claude 探索時哪些概念它猜錯了？

觀念檢查（憑記憶作答）

1. 「系統裡有個內部術語叫『計費規則』，新功能會用到它」— 這個知識該放哪？

術語與概念 = CONTEXT.md。CLAUDE.md 管「怎麼工作」；ADR 記「為什麼這樣設計」— 三份文件三種職責。

2. 某個產品模組「沒人記得為什麼計費要繞過快取」，最該用哪個機制止血？

「為什麼」的知識 = ADR 的職責。TDD 保護的是行為不是原因；CONTEXT.md 定義語言不記決策。

3.（複習 Phase 2 第 03 課）這套 skills 安裝後是「用到才載入」還是「每個 session 全文載入」？

（間隔複習）skill 的本質沒變：description 進列表、本文用到才載入。mattpocock/skills 就是一批做好的 skill。

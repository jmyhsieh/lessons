Phase 3 · 第 01 課 · 約 20 分鐘 · 必要設定

完成 mattpocock/skills 的程式庫設定

本課成果：一份安裝完成紀錄，寫清楚工作追蹤、分類標籤與領域文件放在哪裡。

本課只做：完成安裝與程式庫設定。
先不要做：建立詞彙表、ADR，或啟動需求流程；它們會在真正釐清術語或決策時才按需產生。

這套工作技能在解什麼問題

Matt Pocock 把 AI 輔助開發的翻車原因歸納成四大失敗模式（GitHub README），每種都配有對應的工作技能：

失敗模式症狀對策工作技能
需求錯位（Misalignment）做出來的結果不符合需求/grill-me、/grill-with-docs — 動工前被追問到對齊
表達冗長（Verbosity）詞彙不一致、溝通成本高domain-modeling、CONTEXT.md — 定義專案的領域語言
程式碼損壞（Broken code）
回饋迴圈不足		看似完成、實則會壞/tdd、/diagnosing-bugs — 紅綠燈與系統化除錯
架構腐化（Architectural decay）越改越難改/improve-codebase-architecture、codebase-design、/to-spec、/to-tickets
為什麼這套對真實程式庫有價值：AI 最常在需求沒對齊、詞彙不一致、驗證不足與架構逐漸腐化時出錯。CONTEXT.md 與真正需要的 ADR，讓代理、工程師與審查者共用同一套語言與決策脈絡。封閉或遺產系統只是風險最高的範例，不是唯一場景。

兩個地基概念

CONTEXT.md — 放在程式庫的純領域詞彙表：只記系統術語與業務概念的精確定義，不放模組結構、類別（class）名稱或其他實作細節。人和 AI 共用同一份。它和 Phase 1 第 06 課的 CLAUDE.md 分工：CLAUDE.md 講「怎麼工作」（規範、指令），CONTEXT.md 講「這個領域是什麼」（語言、概念）。

ADR（Architecture Decision Record） — 一份決策一個檔案，記「為什麼這樣設計」。只有當決策同時難以回頭、缺少背景會令人意外，而且確實涉及取捨時才寫；少一項就跳過。/grill-with-docs 與 domain-modeling 會在術語或決策真正收斂時，才更新這些文件。

現行共用工作技能 — domain-modeling 管共享語言與決策脈絡，codebase-design 管深模組與介面設計語言；它們通常是其他工作技能背後共用的詞彙，不需要每次獨立成任務。

實作步驟（做完打勾）

Claude Code 外掛（plugin）：想由外掛市集管理並取得上游更新，就在 Claude Code 裡執行：

/plugin marketplace add mattpocock/skills
/plugin install mattpocock-skills@mattpocock

可編輯的專案副本：想把工作技能複製進程式庫自行調整，或交給 Codex 等相容工具使用，就在目標程式庫執行：

npx skills@latest add mattpocock/skills

兩條路選一條即可；選好後再進行下一步的程式庫設定。

回到剛才選定的工具工作階段，執行：

/setup-matt-pocock-skills

它會先探索程式庫，再依現況提出設定草案。可用 GitHub 或 GitLab 就接正式追蹤系統；沒有追蹤系統、權限受限或只是練習時，再選本機 Markdown。使用 Linear、Jira 等其他工具時，把實際流程寫進 docs/agents/issue-tracker.md。寫入前先審完整草案，確認後才允許修改檔案。

確認代理已回報並讓你審過 docs/agents/issue-tracker.md 與 docs/agents/domain.md；若已安裝 triage，再確認 docs/agents/triage-labels.md。這些檔案只描述後續工作技能的共同設定，不應預先製造 CONTEXT.md 或 ADR。

完成條件：安裝方式、工作追蹤位置、分類標籤與領域文件位置都已記錄並確認存在。

觀念檢查（憑記憶作答）

1. 情境：「系統裡有個內部術語叫『計費規則』，新功能會用到它。」這個知識該放哪？

術語與概念 = CONTEXT.md。CLAUDE.md 管「怎麼工作」；ADR 記「為什麼這樣設計」。三份文件各有職責。

2. 團隊曾在計費一致性與效能間取捨，最後決定繞過快取；這項選擇日後很難改，沒有背景也會令人意外。最該用哪個機制記錄？

這個情境同時符合難以回頭、缺少背景會令人意外、真實取捨三項條件，因此適合 ADR。TDD 保護的是行為不是原因；CONTEXT.md 只定義領域語言。

3. 本課的程式庫設定驗收後，哪組產出最符合邊界？

設定流程只建立後續工作技能共用的程式庫設定：議題追蹤系統與領域設定一定會有；只有安裝 triage 時，才會出現分類標籤。CONTEXT.md、ADR、規格與工作項目都要等真實需求出現後按需建立。

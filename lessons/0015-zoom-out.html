/zoom-out — 迷路時先拿地圖

目標：學會在進入內部系統的陌生區域時，先用 /zoom-out 拿一張「模組與呼叫者的地圖」再動工。最小的 skill，卻是遺產系統日常出場率最高的動作之一。

整支 skill 的全文（真的就這麼短）

---
name: zoom-out
description: Tell the agent to zoom out and give broader context...
disable-model-invocation: true
---

I don't know this area of code well. Go up a layer of abstraction.
Give me a map of all the relevant modules and callers,
using the project's domain glossary vocabulary.

拆解這三句話，每一句都有設計：

原文為什麼這樣寫
「我不熟這區的 code」誠實宣告狀態 — 讓它別假設你懂，回答從基礎講起
「上升一個抽象層」對抗 AI 的預設行為：直接鑽進檔案細節。你要的是俯瞰不是放大鏡
「模組與呼叫者的地圖，用領域詞彙」輸出錨定在 CONTEXT.md 的語言（第 14 課的地基在此回收）— 地圖才讀得懂、才耐久
注意 frontmatter：disable-model-invocation: true — 第 9 課考過你的欄位。這支只能手動觸發，因為「我迷路了」只有你自己知道；Claude 不會替你承認迷路。

它在你工具鏈裡的位置

zoom-out 是其他 skill 的前置動作 — 在你要進入陌生區域之前先跑：

情境組合
要 grill 一個碰到陌生模組的需求/zoom-out → 看懂地形 → /grill-with-docs
bug 在你沒碰過的子系統/zoom-out → /diagnose（假說品質會差很多）
review AI 寫的陌生區域改動/zoom-out → 再讀 diff（你才有判斷基準）
新人 onboarding（包括未來的你）對每個主要模組各跑一次，產出可以存檔的地圖

和第 11 課的 Explore subagent 分工：Explore 是 Claude 自己派分身去查細節（結果給它用）；zoom-out 是你要一張給人看的高層地圖。

實作步驟（做完打勾）

內部系統裡那個「一直繞著走」的子系統 — 越心虛的越好。

在該區域的脈絡下執行（先 cd 到相關目錄或在對話中指明區域）：

/zoom-out [可補充：特別想懂它和 X 模組的關係]

三個檢查：(a) 它講的是模組與呼叫關係，還是鑽進了檔案細節？(b) 用的是 CONTEXT.md 的詞彙還是檔名？(c) 看完你能向同事複述這區的結構嗎？不合格就追問「再上升一層」。

發現 CONTEXT.md 缺的術語 → 補進去。地圖本身若值得保存，存成 docs 下的一頁（標注日期 — 地圖會過期）。

拿著地圖立刻做一件原本不敢做的事：grill 一個碰這區的需求、或診斷一個這區的 bug — 體會「先拿地圖」前後的差異。

🎉 你最心虛的那塊地，現在有地圖了。回對話視窗回報：地圖第一版合格嗎？你追問了幾次「再上升一層」？

觀念檢查（憑記憶作答）

1. 為什麼 zoom-out 要求「用領域詞彙」輸出地圖？

同一條主線：CONTEXT.md 的語言是人和 AI 的共同地圖座標（第 14 課）；用檔名描述的地圖在重構後就作廢（第 23 課 durable 的同一個道理）。

2. zoom-out 為什麼設 disable-model-invocation: true？

（複習第 9 課）這個欄位讓 skill 只能手動觸發。zoom-out 的觸發條件是你的主觀狀態 — Claude 無從判斷你熟不熟這區。

3.（複習第 22 課）陌生子系統出 bug，zoom-out 放在 /diagnose 的哪裡最有價值？

（間隔複習）診斷的 Phase 3 要列 3–5 個排序假說 — 不懂地形的假說是亂槍。先 zoom-out 再 diagnose，假說直接站在結構理解上。

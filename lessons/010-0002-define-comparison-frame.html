Phase 10 · 驗證 · 010-0002

讓 candidate 與 comparator 在同一 frame 被觀察

進入條件：010-0001 claim card 已固定 exact candidate、comparator、audience、threshold 與 claim ceiling。本課只設計公平、可重跑的 comparison frame；不先跑案例，也不因某一 candidate 工具較熟就放寬條件。

1. 鎖定共同條件

維度先定義可觀察 evidence避免
任務品質可抽查 artifact 與明列 omissions只問 agent 自評
安全性越界輸入是否在 effect 前停止成功案例沒有出事就算安全
可靠度同一 identity 的 rerun／recovery把 retry 後成功隱藏第一次 failure
投入成本固定開始／結束與人工介入記錄用不一致的計時方式

先記原始證據再評分：每次 run 先保存 inputs、outputs、events、errors、interventions 與未觀察項，再依預先定義的 rubric 評分。若只有分數、沒有原始 observation，該項不能支持 decision。

比較基準邊界：Comparator 可以是目前人工流程、上一個 package version 或 no-package baseline，但必須是實際可執行、適合相同 task 的選項。不要建立刻意較弱的 straw comparator，也不要混用不同 input、authority 或 environment。

可見成果：一份固定 shared inputs、environment、authority、observation schema、rubric 與 material-failure override 的 comparison frame。
可觀察回饋：Reviewer 能在尚未看結果前判斷 candidate 與 comparator 是否可公平比較，並重建每個分數背後要保存的 raw evidence。

哪個 frame 能支持比較？

比較需要共同 frame；先記 observation 再 scoring，才不會讓結果倒過來決定規則。

合法停止／返回／續行：Comparator 不可執行、inputs／authority 不等價、rubric 無獨立 anchors、threshold 事後才選，或 material failure 能被平均分掩蓋時停止，回 010-0001 修 claim 或重做 frame。Frame 可重建後，續到 010-0003。

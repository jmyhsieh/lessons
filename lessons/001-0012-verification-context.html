Phase 1 · 第 12 課 · 約 15 分鐘 · 驗證與收尾

確認結果並整理 context

本課成果：一份收尾紀錄，列出驗證結果、已知限制與下次接手需要的資訊。

本課只做：把完成條件、驗證結果與 context 收尾說清楚。
先不要做：只接受「我完成了」這類沒有證據的回覆。

可驗證比「完成了」可靠

不夠好：實作 email 驗證函式。
較好：實作 validateEmail，並加入測試：
user@example.com → true
invalid → false
user@.com → false
實作後執行測試，失敗就修到通過。

要求它出示指令與結果，不只說「已完成」。

context 收尾三原則

  • 不相關的新任務 → 桌面 App 用 sidebar 開新工作階段。
  • 長對話但方向正確 → 先看 usage ring，必要時切 Summary view 或整理需求；/compact 若可用才當快捷。
  • 糾正兩次同一問題仍失敗 → 停止，整理教訓後重開。
需要回到前面狀態時，桌面 App 先用 session history、diff pane 與 git 檢查。/rewind 若目前可用，也只當快捷；它不取代 git，重要節點仍要 commit。

實作步驟（做完打勾）

寫成一條 Claude 能自己跑或你能手動檢查的句子。

Run the relevant verification and show me the exact command
and output. If it fails, fix and rerun.

桌面 App 確認是否要開新工作階段、切 Summary view、或整理目前脈絡。若 /compact 在 / 清單中，可用它提早壓縮；若是可重複的教訓，補回 CLAUDE.md。

完成條件：收尾紀錄列出驗證結果、未執行項目、已知限制與接手資訊。

Phase 1 驗收 rubric

勾完 checkbox 只是提醒，不代表通過。把一個真實小任務交給新的 Claude Code 工作階段，只有以下五項都能從 artifact 找到，才算完成 Phase 1：

  • 任務 scope 與刻意不做的項目。
  • 獨立分支上的完整 diff。
  • 實際 verification command、exit status 與 output。
  • 你親自 review 後的 commit 或明確不 commit 理由。
  • 下一個 session 需要知道的風險或 context。

觀念檢查

1. Claude 說「測試都過了」，你下一步該？

交付看 evidence，不看自述。

2. 同一問題糾正兩次仍不對，較好的做法是？

長對話已被失敗嘗試污染，乾淨 session 通常更有效。

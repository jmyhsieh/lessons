Lesson 0012 · 約 30 分鐘 · 進階實作課（桌面 App 優先）

平行 session 與 worktrees — 多個 Claude 同時開工

任務目標：理解 worktree 如何隔離平行修改，同時跑兩個互不干擾的 session（功能＋修 bug），並體驗 Writer/Reviewer 雙 session 品質工作流。

問題：兩個 Claude 改同一份檔案會打架

git worktree 是同一個 repo 的另一個工作目錄：自己的檔案、自己的分支、共用同一份歷史（官方文件）。每個 session 各待在自己的 worktree，修改就永遠不會互踩。

桌面 App 使用者的好消息：每個新 session 自動建立自己的 worktree — 你其實已經在用了。這課把原理講清楚，讓你能主動駕馭它。

三種平行方式的分工（你已學過其一）：

機制隔離什麼適合
subagents（第 11 課）context（同一 session 內）調查、review 等子任務
worktree 平行 session檔案修改（不同 session）同時推進多個獨立任務
agent teams（更進階）多 session ＋互相通訊需要協調的大型工作

CLI 的對應指令（桌面是自動的）

# 開一個隔離 session（建在 .claude/worktrees/feature-auth/）
claude --worktree feature-auth

# 另一個終端機再開一個 — 兩者互不干擾
claude --worktree bugfix-123

三個實用知識：

  • .gitignore 加 .claude/worktrees/，避免 worktree 內容出現在主 checkout 的未追蹤清單。
  • worktree 是全新 checkout：.env 等 gitignored 檔案不會在裡面。在專案根目錄放 .worktreeinclude（gitignore 語法）列出要自動複製的檔案。每個 worktree 也要重裝依賴。
  • 清理：session 結束時，乾淨的 worktree 自動移除；有未提交變更會問你留或刪。手動清理用 git worktree remove。

品質工作流：Writer / Reviewer 雙 session

第 11 課用 subagent 做獨立 review；雙 session 是更徹底的版本（官方 best practices 推薦）：

Session A（Writer）Session B（Reviewer）
「實作 API 的 rate limiter」
「審查 @src/middleware/rateLimiter.ts 的實作，找邊界案例、race condition、與既有 middleware pattern 的一致性」
「這是 review 意見：[貼上 B 的輸出]。逐項處理。」

同理可玩測試：一個 session 寫測試，另一個寫實作讓測試通過。

實作步驟（做完打勾）

工作 repo 的 .gitignore 加 .claude/worktrees/；若專案有 .env 之類的本機設定，建 .worktreeinclude 列進去。

桌面 App 開兩個 session（自動各有 worktree）：一個做小功能、一個修小 bug。輪流推進，觀察兩邊的修改互不可見。

兩個 session 各自走熟悉的流程：review diff → commit → PR。注意它們是兩條獨立分支。

挑一個適中任務照上表跑：A 實作 → B 審查（給它檔案路徑與審查重點）→ 把 B 的意見貼回 A 處理。比較：B 抓到的問題，A 自己會發現嗎？

結束 session 時依提示處理 worktree 去留；用 git worktree list 確認沒有殭屍 worktree。

觀念檢查（憑記憶作答）

1. 「同時做功能 A 和 bugfix B」vs「調查某子系統再回報」，分別該用？

（串連第 11 課）獨立推進的「任務」→ 各自的 session + worktree（隔離檔案）；附屬於當前任務的「調查」→ subagent（隔離 context）。

2. 新 worktree 裡跑不起來專案，最常見的原因是？

worktree 是全新 checkout：.env、node_modules 都不在。解法：.worktreeinclude 自動複製設定檔 + 重裝依賴。

3.（複習第 7 課）Writer/Reviewer 用兩個 session 而不是同一對話接著問，核心理由是？

（間隔複習，同第 11 課獨立 review 的原理）fresh context = 獨立立場。這條原則從 subagent 到雙 session 到 agent teams 一路通用。

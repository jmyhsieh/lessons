Phase 6 · Build · 006-0002 · Read-only reconnaissance

用檔案證據畫出 bounded repo map

任務：在零寫入的 reconnaissance 中，只追與 request 相關的 instructions、entry points、call path、domain terms 與 checks；不把「我看過目錄」當理解。

建立可抽查的地圖

Repository root / HEAD:
Applicable instructions:
Request-relevant entry points:
Immediate callers / data flow:
Existing domain terms:
Focused checks and test seam:
Unknowns / risky boundaries:
Evidence paths:
  1. 先確認 root、HEAD、dirty state 與 instructions；不得更動 user-owned files。
  2. 由 request 中的行為往下找 immediate entry point，再沿 callers、data flow 與 tests 查證。
  3. 每個 map 主張附一個 path、symbol 或 command；不知道就標 unknown。
  4. 跑唯讀的 discovery command，確認 reconnaissance 沒產生 diff。
Tangible win：一張有路徑與 command 證據的 bounded repo map。
Observable feedback：另一個人能抽查 entry point、call path 與 test seam，且 git status --short 沒有新增變更。

哪張 map 可以帶進 request alignment？

可 review 的 repo map 由 repo evidence 支持，也保留未知。

Return／legal stop／continuation：找不到 root、instructions 衝突、dirty ownership 不清或需要寫入才能查證時，保存 unknown 後回 入口。Map 可抽查且 working tree 未被 reconnaissance 污染後，續到 006-0003。

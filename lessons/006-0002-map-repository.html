第 6 階段 · 建置 · 006-0002 · 唯讀偵察

用檔案證據畫出有界限的儲存庫地圖

任務：在零寫入的偵察中，只追與要求相關的指引、進入點、判斷路徑、領域術語與檢查；不把「我看過目錄」當理解。

建立可抽查的地圖

Repository root / HEAD:
Applicable instructions:
Request-relevant entry points:
Immediate callers / data flow:
Existing domain terms:
Focused checks and test seam:
Unknowns / risky boundaries:
Evidence paths:
  1. 先確認根目錄、HEAD、未提交狀態與指引；不得更動使用者自有檔案。
  2. 由要求中的行為往下找直接進入點，再沿呼叫端、資料流程與測試查證。
  3. 每個地圖主張附一個路徑、符號或命令；不知道就標未知項目。
  4. 跑唯讀的探索命令，確認偵察沒產生差異。
具體成果：一張有路徑與命令證據的有界限的儲存庫地圖。
可觀察回饋：另一個人能抽查進入點、判斷路徑與測試接縫，且 git status --short 沒有新增變更。

哪張地圖可以帶進要求對齊？

可 review 的儲存庫地圖由儲存庫 evidence 支持，也保留未知。

返回／合法停止／續行：找不到根目錄、指引衝突、未提交歸屬不清或需要寫入才能查證時，保存未知項目後回 入口。地圖可抽查且工作樹未被偵察污染後，續到 006-0003。

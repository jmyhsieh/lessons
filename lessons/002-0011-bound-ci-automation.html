做桌上演練，不碰遠端 CI

  1. 只有已在上一課通過的有界限的本機單次執行才能帶入；若本機契約尚未穩定，先返回修正。
  2. 用儲存庫負責人核准的 CI／Claude Code GitHub Actions 文件逐欄填卡；未知欄位標成阻塞，不用安全語氣掩蓋。
  3. 對上表三張情境卡逐一走觸發條件 → 權限 → 模型/工具動作 → 完成證明，記錄放行、拒絕或核准停止點。
  4. 確認紀錄不洩漏提示、權杖或敏感輸出；綠燈狀態之外仍要有確定性成果／check。
  5. 保存卡、三個結果與 learner judgment。本課不建立工作流程檔案、不開 PR、不連遠端 CI。
具體成果：一張 CI 邊界卡與三個桌上演練結果。
可觀察回饋：不受信任的密鑰要求、未核准工具與失敗的完成證明都得到明確拒絕／停止點，而不是模糊的「小心使用」。

哪一項最能證明 CI 自動化邊界已有清楚界線？

CI 是外部執行環境；邊界必須由平台權限、工具允許清單、確定性 checks 與停止點行為證明。

合法停止／續行：缺少儲存庫負責人、遠端權限資訊、密鑰政策、受信任觸發條件或已證明本機單次執行時，保留卡並停止。要把設計變成版本控制工作流程，已跨過儲存庫交付邊界，必須另開建置任務、取得權限、套用 Review contract；真實遠端 CI 不是本自學課程的完成條件。把本課記為 Lesson practiced 並返回 Targeted-remediation return point。

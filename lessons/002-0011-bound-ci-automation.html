任務：把已驗證的 local headless one-shot 放進 CI scenario，逐欄界定 trigger、input trust、permissions、secrets、tools、cost、failure 與 approval stop。

Scenario probe預期 boundary feedback
Fork PR 的文字要求讀取 secretSecret 不注入 untrusted context；job stop，留下可診斷紀錄。
模型要求未列入 allowlist 的 write／network toolTool denied；不能靠 prompt 自行擴權。
Budget、timeout 或 deterministic check 失敗Job fail closed；不 retry 非 idempotent side effect。

做 tabletop，不碰 remote CI

  1. 只有已在上一課通過的 bounded local one-shot 才能帶入；若本機 contract 尚未穩定，先返回修正。
  2. 用 repository owner 核准的 CI／Claude Code GitHub Actions 文件逐欄填 card；未知欄位標成 blocker，不用安全語氣掩蓋。
  3. 對上表三張 scenario cards 逐一走 trigger → permissions → model/tool action → completion proof，記錄 allow、deny 或 approval stop。
  4. 確認 log 不洩漏 prompt、token 或敏感 output；green status 之外仍要有 deterministic artifact／check。
  5. 保存 card、三個結果與 learner judgment。本課不建立 workflow file、不開 PR、不連 remote CI。
Tangible win：一張 CI boundary card 與三個 tabletop outcomes。
Observable feedback：Untrusted secret request、未核准 tool 與 failed completion proof 都得到明確 deny／stop，而不是模糊的「小心使用」。

哪一項最能證明 CI automation boundary 已經 bounded？

CI 是外部執行環境；boundaries 必須由平台權限、tool allowlist、deterministic checks 與 stop behavior 證明。

Legal stop／continuation：缺少 repository owner、remote permission 資訊、secret policy、trusted trigger 或 proven local one-shot 時，保留 card 並停止。要把設計變成 version-controlled workflow，已跨過 Repo delivery boundary，必須另開 Build task、取得 authority、套用 Review contract；真實 remote CI 不是本 self-study lesson 的完成條件。把本課記為 Lesson practiced 並返回 Targeted-remediation return point。

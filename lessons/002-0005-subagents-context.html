把大型調查交給另一個 agent（Subagents）

任務目標：知道什麼時候把調查交給 subagent，避免主對話被大量檔案與探索過程塞滿。

本課只做：把大型調查交給隔離 context 的 subagent。
先不要做：把需要即時決策的主線工作丟給 subagent 後放著不管。

為什麼需要 subagent

調查一個子系統常會讀很多檔案；如果全部塞進主對話，後續實作就容易變慢、變亂。subagent 在自己的 context 裡探索，主對話只收摘要。

主對話：用 subagent 調查 token refresh 流程。
subagent：在獨立 context 讀檔與整理。
主對話：只收到結論、檔案依據與風險。
判斷句：如果任務只是「為主任務蒐集資訊」，先想 subagent；如果它要獨立改檔，改用 worktree session。

實作步驟（做完打勾）

例如 auth、billing、cache、routing。不要選整個 repo。

Use a subagent to investigate how [子系統] works.
Return only: summary, key files, risks, open questions.

抽查它列出的 2–3 個 key files，確認摘要不是空泛推論。

🎉 完成！你已經用 subagent 保護主對話 context。

觀念檢查

1. 調查會讀大量檔案時，不用 subagent 的主要代價是？

subagent 的核心價值是 context 隔離。

2. 子任務只需要回報摘要，不改檔，適合？

調查與摘要是 subagent 的典型場景。

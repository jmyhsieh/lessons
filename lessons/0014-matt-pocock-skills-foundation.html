mattpocock/skills 入門 — 四大失敗模式與 CONTEXT.md

Phase 2 任務：用 mattpocock/skills 在公司內部封閉系統（遺產程式碼、文件缺乏、不能用 GitHub/Linear）做維運與新功能開發。本課目標：安裝設定（issue tracker 選 local files），理解四大失敗模式的地圖，並在內部系統 repo 種下第一份 CONTEXT.md。

這套 skills 在解什麼問題

Matt Pocock 把 AI 輔助開發的翻車原因歸納成四大失敗模式（GitHub README），每種配對應的 skill：

失敗模式症狀對策 skill
Misalignment
沒對齊需求		做出來的不是你要的/grill-me、/grill-with-docs — 動工前被拷問到對齊
Verbosity
缺共享語言		雞同鴨講、token 浪費CONTEXT.md — 定義專案的領域語言
Broken code
回饋迴圈不足		看似完成、實則會壞/tdd、/diagnose — 紅綠燈與系統化除錯
Architectural decay
架構腐化		越改越難改/improve-codebase-architecture、/to-prd、/to-issues
為什麼這套對你的封閉系統特別有價值：遺產系統的最大風險正是 misalignment（沒人記得為什麼這樣寫）與文件缺乏（沒有共享語言）。這套 skills 的 CONTEXT.md + ADR 制度，等於一邊開發一邊把部落知識變成文件。

兩個地基概念

CONTEXT.md — 放在 repo 的領域語言文件：你們系統的術語、模組名、業務概念的精確定義。人和 AI 共用同一份。它和第 4 課的 CLAUDE.md 分工：CLAUDE.md 講「怎麼工作」（規範、指令），CONTEXT.md 講「這個領域是什麼」（語言、概念）。

ADR（Architecture Decision Record） — 一份決策一個檔案，記「為什麼這樣設計」。對遺產系統是救命的：半年後沒人（包括 AI）需要猜某個怪設計的原因。/grill-with-docs 會在規劃過程中順手幫你產出與更新這兩種文件。

實作步驟（做完打勾）

在內部系統 repo 目錄執行：

npx skills@latest add mattpocock/skills

在 Claude Code session 裡執行：

/setup-matt-pocock-skills

它會問 issue tracker（GitHub/Linear/local files — 封閉系統選 local files）、triage 標籤、文件位置。設定完確認 repo 裡多了哪些檔案。

請 Claude 探索內部系統的 codebase，草擬 CONTEXT.md 初稿：列出它找到的模組、術語、它猜不懂的概念。然後由你補上機器推不出來的部落知識（業務術語的真正意思、歷史包袱的名字）。先求有，10–20 條就夠 — 它會在後續的 grill 過程中長大。

開新對話，用 CONTEXT.md 裡的術語問一個問題（不解釋術語），看它是否正確理解。這就是「Verbosity 失敗模式」被修復的樣子。

挑內部系統裡一個「新人一定會問為什麼」的怪設計，請 Claude 訪談你之後寫成第一篇 ADR（通常放 docs/adr/，setup 時若指定過位置就用那個）。

🎉 地基完成：工具裝好了、共享語言開始累積、決策有了家。回對話視窗回報：CONTEXT.md 初稿幾條？Claude 探索時哪些概念它猜錯了？

觀念檢查（憑記憶作答）

1. 「系統的計費模組大家都叫它『老黃曆』，新功能要跟它對接」— 這個知識該放哪？

術語與概念 = CONTEXT.md。CLAUDE.md 管「怎麼工作」；ADR 記「為什麼這樣設計」— 三份文件三種職責。

2. 你的封閉系統「沒人記得為什麼計費要繞過快取」，最該用哪個機制止血？

「為什麼」的知識 = ADR 的職責。TDD 保護的是行為不是原因；CONTEXT.md 定義語言不記決策。

3.（複習第 9 課）這套 skills 安裝後是「用到才載入」還是「每個 session 全文載入」？

（間隔複習）skill 的本質沒變：description 進列表、本文用到才載入。mattpocock/skills 就是一批做好的 skill。

Phase 9 · 標準化 · 009-0001 · Route entry

先證明 workflow 值得重用，再談怎麼包裝

進入條件／readiness：帶入一份可解析的 Knowledge、Presentation、Engineering 或 Agent Operations closeout；它必須辨識 exact workflow revision、inputs、authority、deterministic checks、limitations、learner judgment 與 evidence locations。若只有一段看起來合理的 prompt、demo 或 agent 自評，本課尚未具備入口條件。

1. 用 evidence 判斷 eligibility

候選來源最低可接受 evidence缺口的 return
Knowledge workflow 知識流程Attributable sources、claim verification、deliverable、judgment 與 feedback 都在同一 closeout。003-0006
Presentation workflow 簡報流程Source pack、audience、export、accessibility、rehearsal 與 limitations 可重建。005-0007
Engineering workflow 工程流程Final candidate、checks、兩軸 Review 與 closeout 對齊同一 immutable identity。006-0009
Operating workflow 作業流程Deterministic completion、bounded authority、failure／recovery 與 learner disposition 已完成。008-0007

證明規則：Standardize 可以縮短下一位使用者理解與執行的成本，但不能補做來源驗證、completion oracle、Review 或 recovery。缺失的 evidence 必須回 originating route 修正；不得把 package 寫得更肯定來掩蓋未證明行為。

選擇邊界：一張 closeout 只證明 declared context。高風險、不可逆、production 或 external-write workflow 不因被選中就獲得新權限；package 後仍須逐次確認 authority、target、payload 與 approval。

3. 只選一條 contract extraction path

一般 workflow 進 009-0002。只有候選明確是已證明的 LLM Wiki maintenance，且對應 conditional lesson 已發布時，才可改走 009-0009-extract-llm-wiki-maintenance-contract.html；兩條路都回到 009-0003，不必重複完成。

可見成果：一張只指向一個已證明 revision、closeout 與重用需求的 workflow eligibility card。
可觀察回饋：另一位 reviewer 能沿 evidence locations 重建 proof，對任何缺口指出精確 originating-route return，並獨立同意或拒絕進入 contract extraction。

團隊有一段常用 prompt，但沒有 deterministic completion、failure 或 closeout evidence。下一步是？

Package 不能修補未證明的 workflow；先取得可重建的 route 或 operations evidence，才有穩定 contract 可抽取。

合法停止／返回／續行：Closeout 缺失、identity 衝突、completion 無法 disconfirm、authority 或 recovery 不明、learner judgment 缺漏，或候選只在 demo 成功時，保存 eligibility card 並回表中精確 route，不得建立 shared instructions。只有 evidence 齊全且 reviewer disposition 為 proven，才帶同一 candidate ID 前往 009-0002；選擇本課不代表 package、Phase 9 或 course complete。

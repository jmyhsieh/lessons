Gates 與 evidence 速查表

把 harness-ready issue / brief 轉成可驗收、可回看、可重跑的完成條件。

Gate 決定能不能收工；evidence 決定能不能相信。沒有 pass/fail、沒有 artifact、沒有 reviewer 的項目，只能算提醒。

Gate 類型

類型問題常見 evidence
Scope gateAgent 是否只碰允許範圍？git diff --name-only、保護路徑檢查、blocked path 清單。
Verification gate需求是否真的被滿足？test/build/lint exit code、fixture diff、截圖比對。
Review gate機器無法完全判斷的品質是否可接受？reviewer、review checklist、decision、例外說明。

假 gate 改寫

假 gate可用 gate
確認品質。執行 npm test 與 npm run lint；若 UI 有變更，附 before/after screenshot。
注意安全。列出 auth、secret、permission 相關檔案；若有變更，指定 security reviewer。
不要影響其他功能。執行目標測試與 smoke test；列出未跑完整 regression 的原因。
看起來完成就好。回報 command、exit code、artifact path、review decision。

導入強度

層級適合情境做法
Prompt gate一次性任務或新流程。在 prompt 要求 agent 跑檢查並貼 evidence。
Checklist gate半重複任務。把 gate/evidence 固定到 issue template 或 handoff。
Hook gate高頻、低容忍錯誤。用 Claude Code hooks 阻擋收工或危險操作。
Telemetry gate長期 runner 或平台。收集 tool calls、token、failure、artifact path 等可觀測資料。

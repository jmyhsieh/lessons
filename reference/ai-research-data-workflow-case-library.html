AI 研究 / 資料職能工作流案例庫

2026/04 起公開案例，聚焦 Claude Code 如何支援研究重現、科學軟體、資料驗證與 domain review。

篩選規則：來源需在 2026-04-01 之後發布，且案例本身明確使用 Claude Code。這裡的重點不是「產生程式碼」，而是研究結論能否被重跑、檢查與質疑。

案例對照表

日期案例流程片段對應槽位可學走的模式
2026-05-28 物理學家監督 Claude Code 開發科學軟體 研究者在 12 個工作天、57 個 Claude Code sessions 中建立 JAX 科學模組；15 個 supervision events 中，agent 透過 oracle tests 自主處理 10 個，另有 2 個靠物理 domain knowledge，3 個繞過 oracle detection。 paper / model → implementation → oracle tests → domain review 把 domain invariant 寫成明確檢查；不要讓 Claude Code 用「看似可跑」的修補取代理論正確。
2026-06-09 Claude Code 重現社會科學研究結果 SocSci-Repro-Bench 用 221 個 computational social science tasks 評估 Claude Code 與 Codex；Claude Code 表現較強，但 prompt framing 會影響 bias。 paper / data → reproduce → compare → bias check 把 reproduction script、輸出差異、prompt framing 與失敗原因一起留下；不要只交一個成功結果。

重複出現的模式

重現比生成重要
研究職能要優先交付可重跑的 script、notebook、資料切分與環境說明。
oracle tests 不夠
測試可以抓數值錯誤，但 domain invariant、研究限制與模型假設仍要由專家審查。
prompt 也是研究條件
prompt framing 會影響結果與偏誤，應該和資料、程式碼、版本一起記錄。
失敗要可解釋
失敗案例要分成資料缺口、環境問題、推論錯誤、理論假設錯誤，而不是只寫「agent failed」。

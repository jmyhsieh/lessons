Closeout decision 速查表

決定一輪 harness run 應該 ship、review、rerun、blocked，或降級回單次 agent。

Closeout 的驗收句：每個 run 都能回答「可以停止嗎？」以及「如果不能，誰要做什麼」。

Decision table

Decision條件必填
shipGates 通過、evidence 可開、handoff 可接手。report path。
review證據足夠，但需要產品、安全、風險或架構判斷。review owner。
rerun已有修正、原因明確、retry budget 未用完。parentRunId、rerun reason。
blocked缺 credential、資料、環境、權限或外部回覆。unblock condition。
downgrade任務不重複、input 不穩、gate 不值得維護。降級理由。

Record template

{
  "runId": "",
  "decision": "ship | review | rerun | blocked | downgrade",
  "reason": "",
  "evidenceVerified": false,
  "handoffPath": "",
  "retryBudgetRemaining": 0,
  "owner": "",
  "nextAction": ""
}

停止檢查

檢查失敗時
Final handoff 指向最新 run。先修 handoff。
Evidence paths 都存在。標成 stale，不可 ship。
Open risks 都有 owner。轉 review。
Retry budget 未超過。停止 rerun。
任務仍值得 harness。降級回單次 agent。

完成定義

Done when:
- Closeout decision is one of five allowed values.
- Reason is specific and tied to evidence.
- Non-ship decisions have owner and nextAction.
- Rerun cannot loop without budget.
- Downgrade is allowed when harness no longer pays off.

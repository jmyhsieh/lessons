AI 創業 / Founder 職能工作流案例庫

2026/04 起公開案例，聚焦 Claude Code 如何把 founder 工作從「能不能做」推向「該不該做、誰要用、怎麼驗證」。

篩選規則：來源需在 2026-04-01 之後發布，且案例本身明確使用 Claude Code。Founder 職能不等於自己寫最多 code，而是負責問題、使用者、速度與品質 tradeoff。

重複出現的模式

問題定義不能外包
Claude Code 可以加速實作，但不會自動知道哪個痛點值得做。
Spec 是 founder 杠桿
越小的團隊越需要清楚寫出行為、限制、驗收條件與不做事項。
Demo 要接觸市場
Postcard Press 的重點是把 prototype 帶到 ProductCon 和真實使用者面前。
Review 不能省
Claude Code 寫得越多，founder 越要安排安全、支付、資料與維護檢查。

套回可重跑工作流

使用者洞察 → 一頁 spec → Claude Code 做產品切片 → founder review → 真實使用者回饋 → 下一輪假設

下一個可驗收 artifact 是 demo、使用者回饋、review checklist 或下一輪假設，而不是「產生了多少 code」。

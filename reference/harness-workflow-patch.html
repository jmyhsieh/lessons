Workflow patch 速查表

把一次 repo rehearsal 的 finding 收斂成一個可驗收的小改進。

Workflow patch 的驗收句：只修一個重複會造成成本的流程問題，且下一輪 rehearsal 能驗證它是否有效。

Finding categories

Category改哪裡先不要
inputBrief template、scope-out 範例。新增 runner command。
gateGate definition、trusted command。讓模型判斷 pass。
evidenceArtifact path、capture rule。把 log 塞進 handoff。
handoffHandoff section、owner/action 格式。複製完整 transcript。
closeoutDecision rule、retry budget。允許無限 rerun。
overhead刪步驟、downgrade rule。平台化。

Patch note template

{
  "findingId": "",
  "sourceRunId": "",
  "category": "input | gate | evidence | handoff | closeout | overhead",
  "symptom": "",
  "patch": "",
  "changedArtifact": "",
  "acceptance": "",
  "doNotDo": ""
}

升級門檻

情況動作
只出現一次。改 reference 或 checklist。
連續兩次出現。補 template 與驗收欄位。
連續三次出現。考慮 runner、hook 或 command。
流程比任務重。downgrade 或刪步驟。

完成定義

Done when:
- The finding has one category.
- The patch changes one artifact.
- Acceptance is observable in the next rehearsal.
- The do-not-do line prevents scope creep.
- The next change is smaller than the original workflow.

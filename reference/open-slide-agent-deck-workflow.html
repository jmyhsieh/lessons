回饋迴路

1 · 檢查在瀏覽器選定具體元素，不用「整份更好看」。
2 · 評論寫清問題、保留項、成功條件，再儲存。
3 · 套用請代理程式使用 apply-comments，審查實際 Git diff。
4 · 驗證開啟 dist/，重跑主張、權利、鍵盤、目標螢幕與彩排。

不可跨越的停止線

CLI 識別／稽核不符合邊界、沒有讀 repo 規則、來源 ID 不可追溯、註解偷改主張、素材權利不明、只看開發伺服器、沒有檢查靜態建置、沒有在目標環境彩排：任何一項存在，就不要擴成完整簡報或對外發布。

不可變的 Review 邊界

檢查通過後先建立精確的候選版本 SHA，再依 Repo Review contract分開執行 Standards Review 與 Spec Review。修任何 code、內容、test 或 config 都會產生新候選版本；重跑建置／checks 與兩軸 Review，不得沿用舊 SHA 的證據。

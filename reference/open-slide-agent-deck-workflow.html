Claude Code × open-slide

先用工具卡判斷是否需要 open-slide。選定後，Claude Code 建立隔離工作區、先讀初始專案產生的 AGENTS.md／CLAUDE.md 與工作區 Skills，再做三頁切片；你核准命令、審查 diff 並親自看瀏覽器。

留在 Claude Design，如果：
需要 PPTX 交接、想用 canvas 快速修改，或團隊不想維護 React／Git。
讓 Claude Code 使用 open-slide，如果：
交付接受 HTML／PDF，而且確實需要 Git diff、客製互動、React 元件或部署流程。

一句話做決定

「我選 Claude Design／open-slide，因為交付格式需要＿＿，團隊也願意／不願意維護 React 與 Git。」

三頁實作路線

課只做這件事留下什麼
01請 Claude Code 唯讀比較 Claude Design 與 open-slide人工核准的選路理由
02核對目標與命令，再讓 Claude Code 建立隔離工作區開發伺服器與瀏覽器證據
05先讀 AGENTS.md／CLAUDE.md 與本次需要的 Skill檔案契約、禁止事項與驗證命令摘要
03讓 Claude Code 使用 /create-slide人工審查過的三頁 diff
04請 Claude Code 建置並預覽，真人打開正式輸出dist/＋檢查紀錄

讓 Claude Code 提議的最小命令

npx @open-slide/cli init phase7-open-slide --use-npm --locale zh-TW
cd phase7-open-slide
npm run dev
npm run build
npm run preview

學員不必背 React 或 open-slide API；先核對目標目錄與命令，再授權執行。建立後，Claude Code 應先讀工作區的 CLAUDE.md，再選用對應 Skill。

Claude Code 工作迴圈

讀 CLAUDE.md 與相關 Skill
→ 說明這次只改什麼
→ 等人核准後執行
→ 顯示 diff 與建置輸出
→ 真人在瀏覽器檢查

需要才接 06–09

課解決的真實需求留下什麼
06Claude Code 以 /create-theme 收斂重複規則主題＋一個重用模式
07Claude Code 列查核點，真人檢查來源與畫面來源＋無障礙證據
08Claude Code 以 /apply-comments 處理具體回饋留言＋diff＋重新驗證
09Claude Code 準備部署套件；負責人決定是否部署可部署套件

停止線

必須交可編輯 PPTX 就回 Phase 4。第 04 課是獨立完成線；不需要重用、稽核、回饋或部署，就不必繼續第 06–09 課。建置成功仍要打開目標輸出；Claude Code 不能代替負責人授權公開部署。

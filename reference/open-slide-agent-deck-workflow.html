第 07 課 core closeout 通過後，只有新需求需要 React／Git／static HTML 路線才進入；先做 3 頁 vertical slice、固定 candidate 並完成兩軸 Review，再決定是否擴充。

30 秒選路

選 Claude Design需要 visual canvas、非工程協作、PPTX 交接，或不想維護 Node／repo。
選 Open-Slide需要 Git diff、React 客製、互動、static hosting，而且 HTML／PDF 是可接受的交付格式。
輸出／completion 邊界：Open-Slide 官方流程提供 static HTML 與 browser-print PDF，不要把它寫成 PPTX 產製工具。這份 elective 的 build 與 Review 都不會單獨構成 Presentation closeout。

Agent prompt 骨架

Read AGENTS.md and use the local create-slide and slide-authoring skills.
Create phase5-vertical-slice with exactly 3 pages:
cover, evidence, recommendation.

Inputs: [storyboard cards + confirmed source IDs + approved brand]
Keep source IDs and caveats in the sidecar claim ledger.
Do not add claims, quotes, logos, dependencies, or asset rights.
Plan first. Then edit. Run npm run build and report evidence.

Feedback loop

1 · Inspect在 browser 選定具體元素，不用「整份更好看」。
2 · Comment寫清問題、保留項、成功條件，再 Save。
3 · Apply請 agent 使用 apply-comments，review 實際 Git diff。
4 · Verify開啟 dist/，重跑 claims、rights、keyboard、目標螢幕與彩排。

不可跨越的停止線

CLI identity／audit 不符合邊界、沒有讀 repo rules、source ID 不可追溯、comments 偷改主張、asset rights 不明、只看 dev server、沒有檢查 static build、沒有在目標環境彩排：任何一項存在，就不要擴成完整 deck 或對外發布。

Immutable Review boundary

Checks green 後先建立 exact candidate SHA，再依 Repo Review contract分開執行 Standards Review 與 Spec Review。修任何 code、content、test 或 config 都會產生新 candidate；重跑 build／checks 與兩軸 Review，不得沿用舊 SHA 的 evidence。

Runner 第一片速查表

先實作 list、show、dry-run，確認 runner 會跑對任務，再接真 agent。

第一片的驗收句：不呼叫模型、不改檔，也能清楚顯示 runner 會讀什麼、送什麼、跑哪些 gates、把 evidence 寫去哪。

命令契約

命令成功輸出失敗條件
runner list --jsoninput id、source、status。input 目錄不存在。
runner show <id> --json正規化後的 input contract。找不到 id、必填欄位缺漏。
runner run --dry <id> --jsonprompt preview、allowed tools、gates、paths、willCallAgent:false。stop condition 已觸發、gate 設定不完整。

正規化格式

{
  "id": "",
  "source": "",
  "outcome": "",
  "scope": [],
  "gates": [],
  "stop": [],
  "evidenceDir": "",
  "reportPath": ""
}

Fixture 組合

Fixture目的期待
完整 issuehappy path。show 與 dry-run 都成功。
缺 Outcome驗證 parser 不接受模糊任務。show 失敗，指出缺漏欄位。
缺 Gates避免無驗收 runner。dry-run 失敗，不產 prompt。
Scope 越界保護路徑。dry-run 顯示 blocked。

完成定義

Done when:
- list can enumerate valid inputs.
- show can normalize one input and reject malformed input.
- dry-run prints prompt/tools/gates/paths.
- dry-run always reports willCallAgent:false and willModifyFiles:false.
- fixtures cover pass and fail cases.

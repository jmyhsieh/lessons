Harness readiness 速查表

用來判斷一個 Claude Code / skill workflow 是否值得變成可重跑 harness。

先判斷，不要先實作。Harness 的價值來自重複、可驗收與可追溯；不是因為我們想多做一層工具。

四槽填寫表

槽位必填問題可接受答案不成熟訊號
Input任務從哪裡來？格式穩定嗎？issue、PR diff、固定 brief、資料夾路徑每次都靠人重講背景
Runneragent 執行順序是否固定？read → plan → edit → test → report每次都臨場決定步驟
Gate什麼條件不過就停止？tests、lint、protected-file check、manual approval只看 agent 自稱完成
Evidence結果要留下什麼給下一個人？report、log、diff、screenshot、handoff證據只在聊天紀錄裡

三種決策

決策何時使用下一步
不要 harness一次性探索、輸入模糊、驗收依賴大量人類判斷。用一般 agent session，加強 brief 與 handoff。
先半手動流程會重複，但 gate 或 evidence 還不穩。先寫 checklist、固定回報格式與人工確認點。
值得 harness輸入穩定、runner 順序清楚、gate 可檢查、evidence 會被使用。再考慮 CLI、run history、report store 或更完整的工具層。

最小摘要格式

當 [input] 出現時，
runner 依 [steps] 執行；
必須通過 [gates]；
最後留下 [evidence]。

目前決策：不要 harness / 先半手動 / 值得 harness

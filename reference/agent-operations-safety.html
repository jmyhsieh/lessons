Agent 作業安全參考

核心契約：先以唯讀的或計畫演練界定受影響的範圍；只授予任務必要的工具、路徑與時間；僅在可復原的本機 fixture 寫入；任何外部副作用另行取得明確權限；以確定性的證據證明結果，並保存失敗、復原、未驗證的限制與 stop。

權限與證據矩陣

層級允許前提必留證據立即停止
讀取可信輸入、允許的路徑、敏感資料邊界已寫明。讀取集合、基準、未知事項。需要越界、解密、取得新帳號或外部資料。
寫入明確路徑／作業、還原點、有界的批次、負責人已核准；只在可復原的 fixture。前／後、寫入集合、確定性的 check、復原位置。計畫／實際範圍不符、fixture 無法恢復、oracle 失效。
外部副作用每一動作的目標、payload、成本、受眾、去重／冪等性與復原已由有權者核准。核准識別、動作收據、後置條件、補償措施或安全的 stop 處置。目標／payload 漂移、無法避免重複、不可逆且判斷未完成。

五個不能被代理程式自評取代的關卡

  1. 範圍關卡：規劃的讀取／寫入／外部的目標與觀察到的受影響範圍一致。
  2. 權限關卡：每種副作用都能連回具體核准；脈絡隔離、排程或委派不會自動增加權限。
  3. 完成關卡：oracle 能對錯誤狀態失敗，並針對本次執行輸入產生證明。
  4. 復原關卡：受控失敗後能重試而不重複、回復還原點，或在無法安全恢復時停住。
  5. 判斷關卡：殘餘風險、未知與不可逆決定由學習者／負責人處置；模型不批准自己。

正式環境邊界：標準自學收尾不要求無人值守的正式環境變更、push、部署、真實寄送、付款或其他外部寫入。若真實任務另需這些行為，必須離開練習 fixture，重新確認權限、Review 與組織操作手冊；未執行正式環境動作不是收尾缺陷。

回顧案例		 PM 用 Claude Code 做 Postcard Press PM 前一晚用 Claude Code 做可在手機上跑的 postcard app；在 ProductCon 收集回饋，再補 Stripe、Postgrid、資安修正與上線。 定義範圍 → 原型 → 回饋 → 驗證 → 交付 快速 prototype 的價值不是一次做完，而是更早拿到真實使用者與安全測試回饋。

重複出現的模式

PM 變成吞吐管理者
Claude Code 壓縮 coding loop 後，瓶頸會跑到需求切片、跨職能協調與驗收定義。
原型仍要外部驗證
Postcard Press 的重點不是四小時完成，而是 ProductCon、社群回饋、付款與資安檢查。
長任務需要狀態設計
agent 會跑到你離開會議室或搭飛機時還沒結束；checkpoint 與 resume 要進 workflow。
角色邊界要重畫
PM、工程、設計的分工會因 Claude Code 改變，但責任歸屬與驗收條件仍要明確。

AI 工作流編排速查表

不要先問「該用哪個 skill」。先問：下一個可驗收 artifact 是什麼？需要實例時，先看 職能工作流案例總覽。

核心規則：把 skill 當成工作槽位，而不是固定菜單。只要能把上一個輸出變成下一個可驗收 artifact，就可以替換工具。

七個工作槽位

槽位輸入可替換 skill / 工具輸出與驗收訊號
1. 定義範圍口頭需求、截圖、會議筆記obsidian-vault、文件、一般筆記一頁需求摘要：目標、非目標、使用者、成功條件
2. 收斂假設需求摘要grill-me、grill-with-docs、ubiquitous-language風險、開放問題、必須驗證的假設被列出
3. 固化專案文件已收斂的假設to-prd、documents、PROJECT.md決策、驗收條件、範圍邊界可被引用
4. 發散方案專案文件design-an-interface、writing-fragments、imagegen、brainstorm prompt至少 2-3 個可比較方案，不只一個漂亮答案
5. 製作原型選定方案prototype、presentations、spreadsheets、hyperframes使用者能打開、操作、閱讀或播放
6. 驗證校準原型或內容playwright、Browser、review、設計 token 檢查截圖、測試、審查回饋顯示問題已收斂
7. 交付接力通過驗證的 artifacthandoff、PR、deck、文件、issue下一個人知道成果、限制、後續動作

常見組合

PM 原型
grill-me → prototype → playwright → handoff
決策文件
grill-with-docs → to-prd → review → issue
數據報告
spreadsheets → documents → presentations → review
文章內容
writing-fragments → writing-shape → edit-article → handoff

三問選 skill

  1. 現在卡在收斂、發散、製作、驗證，還是交付？
  2. 下一個 artifact 要被誰使用：PM、設計師、工程師、主管、客戶？
  3. 這一步失敗最貴的是什麼：方向錯、品質差、不可驗證、交接斷裂？

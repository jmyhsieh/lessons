AI 職能工作流案例與路線選擇器

先看責任，不看職稱：同一個人可能同時負責需求、repo 變更、可恢復營運或治理；每次只依「這次要交付什麼、誰能驗收、需要哪些權限」選一條最貼近的 route。案例是選路線的線索，不是職稱對課程的固定分配。

  • 產品
  • 工程
  • 研究／資料
  • 一般營運／營收營運
  • 創辦人
  • 平台／治理

產品：把模糊需求變成可驗收決定

代表責任／使用案例：切小需求、建立原型、收集可追溯 feedback、對齊利害關係人；若交付物最後成為 repo diff，責任就跨入 Engineering，而不是因為職稱是產品經理就留在設計。

這次真正要交付建議 route產生的證據
可檢查狀態、互動與假設的設計交接設計入口 → 交接收尾有版本的 Design handoff bundle、原型假設、學習者判斷與 feedback 處置。
需要實作、checks 與 Review 的儲存庫變更Engineering 入口 → Engineering 收尾精確的候選版本、確定性的 checks、雙軸 Review 與交接。

前置條件／準備度：知道受眾、要促成的決定、可用輸入、feedback 負責人與資料權限；repo 實作另需 Code readiness。

具體成果／可觀察回饋：得到一張 route 選擇卡；審查者能由 artifact 與權限說明為何走設計或 Engineering，並指出交付物何時跨越 repo 交付邊界。

合法停止點／主張上限：需求、feedback 路徑或權限不明就停在 readiness；原型 feedback 不是產品市場契合度，Engineering checks 也不是上線、採用或正式環境核准。

案例線索（2026-04-06）：Anthropic 產品工程師／迷你產品經理報導可用來分析需求切片與責任移動；供應商／媒體案例只支持其所報導情境，不是普遍成效證明。

工程：交付可重建、可 Review 的精確候選版本

代表責任／使用案例：探索 repo、釐清需求、切工作票 DAG、實作小 diff、診斷難解缺陷、建立不可變的 Review 檢查點；瀏覽器主張或可重複代理程式執行是不同續作，不是每張工程工作票都要走。

這次真正要交付建議 route產生的證據
符合規格與儲存庫標準的 code 變更Engineering 入口 → Engineering 收尾已實作 diff、聚焦的／完整的 checks、最終檢查點、標準／Spec Review 收尾包。
只需證明一個可由瀏覽器觀察的主張瀏覽器證據入口 → 證據收尾有界的主張、基準、互動證據、反例/邊界案例觀察與附錄。

前置條件／準備度：Code readiness 已證明；能讀 repo 指示、界定安全的工作區、看 diff、跑相關的 checks，且原始意圖可解析。

具體成果／可觀察回饋：得到一份精確 SHA 的 Engineering 收尾；接手者能重建 diff、重跑 checks、分開檢查兩軸 Review，且瀏覽器續作的必要性可由主張決定。

合法停止點／主張上限：工作區、權限、checks 或意圖不清就停；tests PASS 與代理程式審查不等於合併、安全簽核、正式環境可靠性或部署權限。

案例線索（2026-04-23）：Anthropic Claude Code 品質事件事後檢討可用來分析重現、根本原因、評估與導入關卡；這是該事件的第一方敘述，不是所有工程流程的模板。

研究／資料：讓來源、計算與限制可重跑、可質疑

代表責任／使用案例：保存原始來源、建立來源到主張的沿革、重現論文／資料、實作分析程式碼、校準 oracle tests，並把網域審查與偏誤／限制留在證據中。

這次真正要交付建議 route產生的證據
有來源脈絡的報告、資料切片或本機的知識 artifact知識入口 → 知識收尾原始來源參照、來源到主張檢查、可審查交付物、判斷與 feedback。
會改 repo 的重現／分析實作Engineering 入口 → Engineering 收尾有版本的程式碼／資料識別、oracle checks、網域審查的限制與最終候選版本 Review。

前置條件／準備度：資料使用權、來源識別、預期的比較、可反證條件與網域審查者已知；會執行或修改 code 時另需 Code readiness。

具體成果／可觀察回饋：得到可追到來源與精確的計算的交付包；另一位審查者能重跑、重現差異，並指出 oracle 沒覆蓋的網域假設。

合法停止點／主張上限：資料權利、版本、oracle 或審查者不明就停；成功重現一次不等於研究正確、無偏誤、可泛化、同行審查或正式環境資料核准。

案例線索（2026-05-28）：物理學家監督 Claude Code 開發科學軟體可用來分析 oracle 與領域監督；單一研究結果不能替代你自己的資料、方法與審查者。

一般營運／營收營運：先證明可停、可恢復，再談重複執行

代表責任／使用案例：先預覽匯入 diff、建立事件/操作手冊交接、處理有界的本機的批次、記錄進度/檢查點，並讓 retry 不會重複寫入；真實客戶關係管理或外部通知不屬於自學 fixture。

這次真正要交付建議 route產生的證據
一個已由人安全做過、值得重複的可復原的本機工作流Agent 作業入口 → 作業收尾確定性完成證明、權限範圍、失敗／復原紀錄與學習者判斷。
需要分享給他人的已證明工作流標準化入口 → 套件收尾單一有版本的套件、全新脈絡正例／反例重跑、負責人與退役條件。

前置條件／準備度：Code readiness、可復原的本機 fixture、輸入/輸出識別、確定性的 oracle、寫入邊界、還原點與人工核准 stop 已知；標準化還要先有可解析收尾。

具體成果／可觀察回饋：得到一份可由第三方重跑的有界作業收尾；審查者能注入受控失敗，確認安全的 stop／復原，並拒絕越界目標。

合法停止點／主張上限：沒有安全的 fixture、還原、冪等性或權限就停；本機的復原不等於正式環境服務水準，套件也不授權客戶關係管理寫入、寄送、付款、採購或真實事件動作。

案例線索（2026-05-12）：Mach 1客戶關係管理匯入與長任務報導可用來分析 preview、檢查點與人工核准；報導不是實際資料權限或正式環境授權。

創辦人：縮短回饋迴路，而不是跳過驗證

代表責任／使用案例：把假設切成可檢查原型、向真實受眾解釋提案、收集 feedback、做下一輪保留/變更/stop 判斷；若需要儲存庫實作，另走 Engineering。

這次真正要交付建議 route產生的證據
測試核心任務、狀態與假設的原型交接設計入口 → 交接收尾設計意圖、重大狀態、假設證據、feedback 處置與實作未知事項。
需要受眾作決定的有來源支持的簡報簡報入口 → 簡報收尾主張台帳、權利紀錄、可及的目標格式簡報、演練與 feedback。

前置條件／準備度：單一任務、受眾、決策、可用來源、素材權利、feedback 負責人與不做事項已明確；付款、寄送或客戶資料預設不在練習範圍。

具體成果／可觀察回饋：得到可被受眾檢查的原型交接或簡報；另一個人能重述假設、指出證據缺口，並記錄下一輪保留、修改或停止。

合法停止點／主張上限：問題、受眾、權利或 feedback 路徑不清就停；示範、掌聲或簡報完成不等於商業驗證、收入、市場契合度、上線 readiness 或投資批准。

案例線索（2026-05-25，回顧案例）：Postcard Press 原型報導可用來分析原型→feedback→強化；其後續付款、寄送與上線不能被本課當成已授權練習。

平台／治理：把決策權、證據與主張上限放在同一張圖

代表責任／使用案例：定義存取/資料邊界、比較工作流主張、設計有界的導入情境、處理成本/風險、演練事件/變更/退役；只有既有沿革成立時才往後走。

這次真正要交付建議 route產生的證據
判斷一個已證明的套件應保留、變更或退役驗證入口 → 檔案收尾固定的主張、成功/失敗/比較的證據、衝突處置、限制與學習者判斷。
對既有導入沿革起草可稽核自學政策治理入口 → 政策收尾負責權、變更/資料生命週期、風險/成本、桌上演練證據、退役條件與處置。

前置條件／準備度：評估需精確的標準化收尾；治理需可追溯情境導入計畫、檔案、套件識別、限制、負責人與決策權。缺上游證據就回原始的 route。

具體成果／可觀察回饋：得到可重建的證據檔案或政策草稿；獨立審查者能追到每個重大決策，重播桌上演練，並找出任何越過權限的主張。

合法停止點／主張上限：沿革、負責人、資料邊界或決策權利不明就停；評估、桌上演練與政策草稿都不是採用證明、法律意見、安全/隱私/合規認證、組織政策或正式環境核准。

案例線索（2026-04-23）：Claude Code 品質事件事後檢討可用來分析變更、評估與導入證據；事件敘述不會替你的組織建立決策權或批准。

路線選擇的共用檢查

  1. 用一句話寫出這次的 可審查的 artifact；只選能產生它的 route。
  2. 確認先決條件、權限、feedback 負責人與法務 stop；缺口回 readiness，不靠代理程式補猜。
  3. 完成後只宣稱該 route 的結束證據；需要另一種交付物時，重新選 route，不把所有 Phase 串成必修階梯。

來源與證據界線：案例來源依發布資訊與可辨識的第一方／研究敘述保留日期。它們只說明「曾被報導的工作形狀」，不獨立證明普遍效果；route 完成仍以學習者自己的 artifact、確定性的證據、人工判斷與 feedback 為準。

Canonical reference · Responsibility-based routing

AI 職能工作流案例與 route 選擇器

先看責任，不看職稱：同一個人可能同時負責需求、repo change、可恢復營運或治理；每次只依「這次要交付什麼、誰能驗收、需要哪些權限」選一條最貼近的 route。案例是選路線的線索，不是職稱對課程的固定分配。

產品：把模糊需求變成可驗收決定

代表責任／use cases：切小需求、建立 prototype、收集可追溯 feedback、對齊 stakeholder；若交付物最後成為 repo diff，責任就跨入 Engineering，而不是因為職稱是 PM 就留在 Design。

這次真正要交付建議 route產生的 evidence
可檢查 states、interaction 與 assumptions 的設計 handoffDesign entry → handoff closeoutVersioned Design handoff bundle、prototype assumptions、learner judgment 與 feedback disposition。
需要實作、checks 與 Review 的 repository changeEngineering entry → Engineering closeoutExact candidate、deterministic checks、two-axis Review 與 handoff。

Prerequisite／readiness：知道 audience、要促成的決定、可用 inputs、feedback owner 與資料權限；repo implementation 另需 Code readiness。

Tangible win／observable feedback：得到一張 route selection card；reviewer 能由 artifact 與 authority 說明為何走 Design 或 Engineering，並指出交付物何時跨越 repo delivery boundary。

Legal stop／claim ceiling：需求、feedback path 或 authority 不明就停在 readiness；prototype feedback 不是 product-market fit，Engineering checks 也不是 launch、adoption 或 production approval。

案例線索（2026-04-06）：Anthropic product engineer／mini PM 報導可用來分析需求切片與責任移動；vendor／媒體案例只支持其所報導情境，不是普遍成效證明。

工程：交付可重建、可 Review 的 exact candidate

代表責任／use cases：探索 repo、釐清 request、切 ticket DAG、實作小 diff、診斷 hard bug、建立 immutable Review checkpoint；瀏覽器 claim 或可重複 agent run 是不同 continuation，不是每張工程 ticket 都要走。

這次真正要交付建議 route產生的 evidence
符合 spec 與 repository standards 的 code changeEngineering entry → Engineering closeoutImplemented diff、focused/full checks、final checkpoint、Standards／Spec Review bundle。
只需證明一個可由瀏覽器觀察的 claimBrowser Evidence entry → evidence closeoutBounded claim、baseline、interaction evidence、negative/edge observation 與 addendum。

Prerequisite／readiness：Code readiness 已證明；能讀 repo instructions、界定 safe workspace、看 diff、跑 relevant checks，且 originating intent 可解析。

Tangible win／observable feedback：得到一份 exact-SHA Engineering closeout；接手者能重建 diff、重跑 checks、分開檢查兩軸 Review，且 browser continuation 的必要性可由 claim 決定。

Legal stop／claim ceiling：workspace、權限、checks 或 intent 不清就停；tests PASS 與 agent review 不等於 merge、security sign-off、production reliability 或 deploy authority。

案例線索（2026-04-23）：Anthropic Claude Code 品質事件 postmortem可用來分析 reproduction、root cause、eval 與 rollout gates；這是該事件的第一方敘述，不是所有工程流程的模板。

研究／資料：讓來源、計算與限制可重跑、可質疑

代表責任／use cases：保存 raw sources、建立 source-to-claim lineage、重現 paper/data、實作 analysis code、校準 oracle tests，並把 domain review 與 bias/limitation 留在證據中。

這次真正要交付建議 route產生的 evidence
有 provenance 的報告、資料切片或 local knowledge artifactKnowledge entry → Knowledge closeoutRaw-source references、source-to-claim checks、reviewable deliverable、judgment 與 feedback。
會改 repo 的 reproduction／analysis implementationEngineering entry → Engineering closeoutVersioned code/data identity、oracle checks、domain-review limits 與 final candidate Review。

Prerequisite／readiness：資料使用權、source identity、expected comparison、可反證條件與 domain reviewer 已知；會執行或修改 code 時另需 Code readiness。

Tangible win／observable feedback：得到可追到 source 與 exact computation 的交付包；另一位 reviewer 能重跑、重現差異，並指出 oracle 沒覆蓋的 domain assumptions。

Legal stop／claim ceiling：資料權利、版本、oracle 或 reviewer 不明就停；成功重現一次不等於研究正確、無 bias、可泛化、同行審查或 production data approval。

案例線索（2026-05-28）：物理學家監督 Claude Code 開發科學軟體可用來分析 oracle 與 domain supervision；單一研究結果不能替代你自己的資料、方法與 reviewer。

營運／RevOps：先證明可停、可恢復，再談重複執行

代表責任／use cases：先預覽 import diff、建立 incident/runbook handoff、處理 bounded local batch、記錄 progress/checkpoint，並讓 retry 不會重複寫入；真實 CRM 或外部通知不屬於自學 fixture。

這次真正要交付建議 route產生的 evidence
一個已由人安全做過、值得重複的 recoverable local workflowAgent Operations entry → Operations closeoutDeterministic completion proof、authority envelope、failure/recovery record 與 learner judgment。
需要分享給他人的已證明 workflowStandardize entry → package closeoutSingle versioned package、fresh-context positive/negative rerun、owner 與 retirement conditions。

Prerequisite／readiness：Code readiness、recoverable local fixture、input/output identity、deterministic oracle、write boundary、restore point 與 human approval stop 已知；Standardize 還要先有可解析 closeout。

Tangible win／observable feedback：得到一份可由第三方重跑的 bounded operations closeout；reviewer 能注入 controlled failure，確認 safe stop／recovery，並拒絕越界 target。

Legal stop／claim ceiling：沒有 safe fixture、restore、idempotency 或 authority 就停；local recovery 不等於 production SLA，package 也不授權 CRM write、寄送、付款、採購或真實 incident action。

案例線索（2026-05-12）：Mach 1 CRM 匯入與長任務報導可用來分析 preview、checkpoint 與 human approval；報導不是實際資料權限或 production authorization。

Founder：縮短 feedback loop，而不是跳過驗證

代表責任／use cases：把假設切成可檢查 prototype、向真實 audience 解釋 proposal、收集 feedback、做下一輪 keep/change/stop 判斷；若需要 repository implementation，另走 Engineering。

這次真正要交付建議 route產生的 evidence
測試核心 task、states 與假設的 prototype handoffDesign entry → handoff closeoutDesign intent、material states、assumption evidence、feedback disposition 與 implementation unknowns。
需要 audience 作決定的 source-backed deckPresentation entry → deck closeoutClaim ledger、rights record、accessible target-format deck、rehearsal 與 feedback。

Prerequisite／readiness：單一 mission、audience、decision、可用來源、素材權利、feedback owner 與不做事項已明確；付款、寄送或客戶資料預設不在練習範圍。

Tangible win／observable feedback：得到可被 audience 檢查的 prototype handoff 或 deck；另一個人能重述假設、指出 evidence 缺口，並記錄下一輪保留、修改或停止。

Legal stop／claim ceiling：問題、audience、rights 或 feedback path 不清就停；demo、掌聲或 deck 完成不等於 business validation、收入、market fit、launch readiness 或投資批准。

案例線索（2026-05-25，回顧案例）：Postcard Press prototype 報導可用來分析 prototype→feedback→hardening；其後續付款、寄送與上線不能被本課當成已授權練習。

平台／治理：把 decision rights、evidence 與 claim ceiling 放在同一張圖

代表責任／use cases：定義 access/data boundaries、比較 workflow claim、設計 bounded rollout scenario、處理 cost/risk、演練 incident/change/retirement；只有既有 lineage 成立時才往後走。

這次真正要交付建議 route產生的 evidence
判斷一個 proven package 應 keep、change 或 retireProve entry → dossier closeoutFixed claim、success/failure/comparative evidence、conflict dispositions、limits 與 learner judgment。
對既有 rollout lineage 起草可稽核 self-study policyGovern entry → policy closeoutOwnership、change/data lifecycle、risk/cost、tabletop evidence、retirement conditions 與 dispositions。

Prerequisite／readiness：Evaluation 需 exact Standardization closeout；Govern 需可追溯 Scenario rollout plan、dossier、package identity、limits、owner 與 decision rights。缺上游 evidence 就回 originating route。

Tangible win／observable feedback：得到可重建的 evidence dossier 或 policy draft；獨立 reviewer 能追到每個 material decision，重播 tabletop，並找出任何越過 authority 的 claim。

Legal stop／claim ceiling：Lineage、owner、data boundary 或 decision right 不明就停；eval、tabletop 與 policy draft都不是 adoption proof、法律意見、security/privacy/compliance certification、organization policy 或 production approval。

案例線索（2026-04-23）：Claude Code 品質事件 postmortem可用來分析 change、eval 與 rollout evidence；事件敘述不會替你的組織建立 decision rights 或批准。

Route 選擇的共用檢查

  1. 用一句話寫出這次的 reviewable artifact；只選能產生它的 route。
  2. 確認 prerequisite、authority、feedback owner 與 legal stop；缺口回 readiness，不靠 agent 補猜。
  3. 完成後只宣稱該 route 的 exit evidence；需要另一種交付物時，重新選 route，不把所有 Phase 串成必修 ladder。

來源與證據界線：案例來源依發布資訊與可辨識的第一方／研究敘述保留日期。它們只說明「曾被報導的工作形狀」，不獨立證明普遍效果；route 完成仍以 learner 自己的 artifact、deterministic evidence、human judgment 與 feedback 為準。

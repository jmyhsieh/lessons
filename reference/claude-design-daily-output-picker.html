Quick Reference · Phase 5

Phase 5 日常視覺交付物速查表

先選使用時刻，再選格式。主交付物只選一個；其他格式在主版本通過內容查核後再改作。

30 秒選路

你會在現場帶著聽眾走向決策？
選 簡報。需要故事 spine、delivery notes（可獨立成 sidecar）、時間控制與彩排。
讀者會自行閱讀、轉寄或核准？
選 單頁稿。需要完整上下文、掃讀層級與獨立來源。
只要在單一版位推動一個動作？
選 社群素材。需要單一 hook、單一 CTA、權利與版位測試。
要測試流程、互動或任務完成率？
選 原型，回到 Phase 4 設計路線。

格式比較

格式主要優勢最常失敗可獨立執行的驗收
簡報講者控制節奏與共同決策把講稿全文塞進 slide限時自行講述或錄影回放，記錄時間、迷失點與未說清楚的決策，再以同一模式 rerun
單頁稿可獨立閱讀與轉寄缺少講者後上下文斷裂遮住原稿，依 audience-question checklist 在三分鐘內自行重述主張、CTA 與來源
社群素材快速觸及與單一 CTA一張圖承擔太多訊息目標尺寸三秒掃讀＋CTA 清楚
原型可觀察真實任務與互動把漂亮畫面當 usability 證據真實使用者完成指定任務
Phase 5 個人驗收：簡報、單頁稿與社群素材的必要 oracle 是 audience-question checklist、自行重述、限時講述或錄影回放；若有真人聽眾／代表性讀者，可選擇性請他重跑同一檢查，但不是完成條件或 blocker。原型的真實任務驗證仍依 Phase 4 gate 執行。

Deck 選定後，再選 authoring surface

Claude Design 核心
需要 canvas 精修、非工程協作或 PPTX 交接；走 005-0001 至 005-0007。第 07 課通過即可合法停止。
Open-Slide 選修
只有在 core closeout 後，新需求需要 React 客製、Git diff 或 static HTML／PDF，才走 005-0009 垂直切片。
再利用選修
新需求是自行閱讀／轉寄或單一 CTA，才選 005-0008 單頁／社群改作，並重新驗證新格式。
Mermaid CLI 選修
只有在 core closeout 後，新需求需要可 diff、可重跑的 diagram source，才走 005-0010。
Elective 與 Review 邊界：三個 electives 彼此沒有先後依賴，也都不能單獨構成 Presentation closeout。若 elective 產生 repo／code artifact，必須固定 candidate SHA 並依 Repo Review contract做兩軸 Review；視覺回饋或 render／build green 不能替代。

選定後填四欄

受眾：誰？已知什麼？
使用時機：現場聽、自行讀、滑到內容或實際操作？
下一步動作：之後要決定、核准、分享、點擊或完成什麼？
成功條件：能觀察到什麼才算交付有效？

停止線

不要用 Claude Design 的能力清單替你決定格式。若受眾、使用時刻與下一個動作還寫不出來，先不要生成。

Workflow package selector

使用前提：只為已有 route／operations closeout、可追溯 contract 與明確重用需求的 workflow 選 package。選擇 package 不會把未證明 workflow 變可靠，也不會授予 execution 或 external-write authority。

Selector 演算法

  1. Proof：沒有 exact closeout 與 contract，停止並回 originating route。
  2. Audience：誰會在什麼 context 讀或執行？若答案是「所有人、所有 repo」，先縮小 scope。
  3. Responsibility：把 deterministic 工作交給 code；把解釋、judgment 與批准留在明確的人類介面。
  4. Locality：Repo-only rules 優先 CLAUDE.md；跨 workspace instructions 才考慮 Skill。
  5. Minimum：選能承載完整 contract 的最小一種 package，記錄其他三種被拒絕的理由。
  6. Ownership：指定 source of truth、version、review、change、retirement 與回報路徑。

Composition boundary：一個較大的 workflow 可以引用既有 command 或 playbook，但本次 Standardize 仍只 author 一個 primary package。引用不等於複製 source of truth；若第二個 artifact 需要獨立 owner、version 或 completion evidence，應另立 scope，而不是在同一 branch 偷做。

停止條件：Proof、audience、source of truth、owner、authority、Review path 或 deterministic／judgment boundary 任一不明時，不開始 authoring。將 gap 帶回 009-0001、009-0002 或 originating route；不得用「四種都做」逃避選擇。

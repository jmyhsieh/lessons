選擇演算法

  1. 證明：沒有精確的收尾與契約，停止並回原始 route。
  2. 受眾：誰會在什麼脈絡讀或執行？若答案是「所有人、所有 repo」，先縮小範圍。
  3. 責任：把確定性工作交給 code；把解釋、判斷與批准留在明確的人類介面。
  4. 適用範圍：僅限儲存庫的規則優先 CLAUDE.md；跨工作區指示才考慮 Skill。
  5. 最小方案：選能承載完整契約的最小一種套件，記錄其他三種被拒絕的理由。
  6. 所有權：指定唯一權威來源、版本、審查、變更、退役與回報路徑。

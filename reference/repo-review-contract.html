Phase 6 · Build · Canonical reference

Repo Review contract

Entry：implementation checkpoint 已存在，且 learner 要建立或稽核 Review bundle。
核心規則：Review evidence 只對一組固定的 fixed point、exact candidate SHA、originating spec 與 standards sources 有效。candidate 任何 byte 改變，都必須建立新 checkpoint 並完整重跑 checks、Standards Review 與 Spec Review。

Tangible win：一份可複製、可抽查的 Review bundle schema。
Observable feedback：依表格可判斷 evidence 是否仍綁定同一 SHA，以及 finding repair 後是否真的完整重跑。

Review bundle 的必要欄位

欄位有效證據無效替代
Fixed point可解析的 commit／tag／merge-base identity「開始前」、未記錄的 base
Candidateexact commit SHA；working tree cleanbranch、PR latest、moving HEAD
Diff由固定 identities 重建的 same three-dot diffreviewer 各自看到不同 snapshot
Standards axis規則來源、file/hunk、獨立 findings以「需求有做到」代替 standards
Spec axisrequirement 引用、file/hunk、獨立 findings以「lint green」代替 spec correctness
Verificationfocused 與 full relevant checks 的 commands／results模型自評、未列出的 skipped check

候選版本狀態轉移

implemented change
  → checks green
  → checkpoint SHA A
  → Standards(A) + Spec(A)
    ├─ no unresolved findings → Review bundle for A
    └─ finding → repair → checks green → checkpoint SHA B
                 → Standards(B) + Spec(B) from the beginning

失效規則：不能把 SHA A 的 Review 搬到 SHA B，也不能只重跑曾經有 finding 的那一軸。修 comment、test、內容或設定都會產生新的 candidate；舊 evidence 保留為歷史，但不證明新 candidate。

Return／legal stop／continuation：bundle 有任何空白、candidate identity 會移動、兩軸被合併、relevant checks 未跑，或修正後未重跑完整 contract 時，回到 implementation checkpoint 並停止 closeout。只有 evidence 明確對應最終 SHA 時，才能交給後續 closeout；這份 reference 本身不授權 merge、push、deploy，也不代表 Phase 或 Migration complete。

實作檢查點 · 獨立 Review

第 6 階段 · 建置 · 標準參考

儲存庫審查契約

入口：實作檢查點已存在，且學習者要建立或稽核審查收尾包。
核心規則：審查證據只對一組固定的 fixed point、精確的 candidate SHA、原始規格與標準來源有效。候選版本任何位元組改變，都必須建立新檢查點並完整重跑檢查、標準審查與規格審查。

具體成果：一份可複製、可抽查的 Review 收尾包 schema。
可觀察回饋：依表格可判斷證據是否仍綁定同一 SHA，以及發現事項修正後是否真的完整重跑。

Review 收尾包的必要欄位

欄位有效證據無效替代
固定點可解析的 commit／標籤／合併基準識別「開始前」、未記錄的基準
候選版本精確 commit 的 SHA；工作目錄乾淨branch、PR 最新、移動中 HEAD
差異由固定識別資訊重建的相同三點差異 diff審查者各自看到不同快照
標準軸規則來源、檔案/差異區塊、獨立發現事項以「需求有做到」代替標準
規格軸要求引用、檔案/差異區塊、獨立發現事項以「靜態檢查通過」代替規格正確性
驗證聚焦檢查與完整相關檢查的命令／結果模型自評、未列出的已略過 check

候選版本狀態轉移

implemented change
  → checks green
  → checkpoint SHA A
  → Standards(A) + Spec(A)
    ├─ no findings → Review bundle for A
    └─ finding → disposition: fixed / evidence-rejected / unresolved
         ├─ fixed → repair → checks green → checkpoint SHA B
         │           → Standards(B) + Spec(B) from the beginning
         ├─ evidence-rejected, no candidate change → record evidence → Review bundle for A
         └─ undisposed / unresolved / blocking → stop closeout

失效規則：不能把 SHA 版本甲的 Review 搬到 SHA 版本乙，也不能只重跑曾經有發現事項的那一軸。修註解、test、內容或設定都會產生新的候選版本；舊證據保留為歷史，但不證明新候選版本。

返回／合法停止點／續作：收尾包有任何空白、候選版本識別會移動、兩軸被合併、相關的 checks 未跑、修正後未重跑完整契約，或發現尚未處置、未解或具阻擋性時，停止收尾。已修正的發現回到實作檢查點建立新 SHA；附證據駁回且候選版本未變的發現可保留紀錄並續行。只有證據明確對應最終 SHA，且每個發現都已處置而無未解或具阻擋性的項目時，才能交給後續收尾；這份參考本身不授權合併、push、部署，也不代表 Phase 或 Migration 完成。

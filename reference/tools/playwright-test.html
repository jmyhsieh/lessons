Playwright Test

把重要的瀏覽器風險寫成可重跑、可審查、可進 CI 的測試。

解決的問題

讓回歸可被發現

用測試程式固定前置條件、互動與 assertion，讓同一風險之後能再次驗證。

何時用

風險值得長期保護

登入、付款、建立資料、關鍵導覽或曾經壞過的流程。

何時不用

只需探索目前畫面

需求尚未穩定或只需一次性查核時，先用 Playwright MCP。

會讀寫什麼

repo 測試資產

可能修改 Playwright 設定、測試檔、fixtures、快照、trace 與測試資料。

權限與副作用

先讀既有測試慣例。確認啟動方式、base URL、帳號、資料清理與 CI 限制；不要把正式環境當測試資料場。

最低完成證據

  • 測試會在目標風險壞掉時失敗。
  • 保留先失敗、修正後通過的證據，或清楚說明為何無法先製造失敗。
  • diff、命令與結果可由其他人重跑。

交給 Claude Code

只修改必要檔案，完成後回報 diff、命令、結果與未覆蓋範圍。

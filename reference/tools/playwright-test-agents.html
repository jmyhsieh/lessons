Playwright · 進階測試流程

Playwright Test Agents

用 planner、generator、healer 分工規劃、產生與修復 Playwright 測試；前提是測試地基已經可用。

解決的問題

把多步測試工作拆開

先形成可審查的規格，再產生測試；失敗時由 healer 根據證據提出最小修復。

何時用

已有穩定 Test 地基

多條使用路徑需要一致規格、人工核准與修復紀錄。

何時不用

第一支測試都還跑不起來

先建立 Playwright Test、fixtures 與測試資料，不要用代理掩蓋基礎問題。

會讀寫什麼

代理定義與測試檔

初始化會增加代理設定；generator 與 healer 可能修改測試，需逐次審查 diff。

權限與副作用

代理輸出不是自動授權。planner 的規格先由人核准；healer 不得刪除或放寬 assertion 來換取綠燈。

最低完成證據

  • 人工核准的測試規格。
  • 可說明的測試 diff 與實際執行結果。
  • 修復時保留 trace／錯誤證據，並證明 assertion 未被弱化。

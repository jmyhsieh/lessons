Phase 2 · 無人值守邊界

Claude Code CI

把範圍明確、可稽核的 Claude Code 任務放進 CI，並以最小權限與可驗證輸出控制風險。

解決的問題

自動處理重複的 repo 事件

在 pull request 或排程觸發時執行固定分析、摘要或檢查，不依賴人工開啟工作階段。

何時用

輸入、權限與失敗條件都清楚

結果可留下 log、artifact 或 comment，且即使任務失敗，也不會造成難以回復的外部狀態。

何時不用

會直接改正式環境或自動推送

未經審查的 production write、自動合併、權限升級與不可逆操作，不應只靠模型自行決定。

會讀寫什麼

Checkout、workflow、secrets 與平台輸出

CI 可讀 repo 與事件內容，並依 workflow 權限寫 comment、artifact 或 branch；每一項都要顯式授權。

權限與副作用

從唯讀、最小權限開始。限制觸發來源、工具、timeout 與花費；特別檢查 fork PR 的 secrets 邊界，不允許模型繞過既有 required checks。

最低完成證據

  • Workflow 顯示最小 permissions、觸發條件與 secret 使用範圍。
  • 一個成功案例與一個失敗案例都有可查 log／artifact。
  • 輸出需要人類核准才會進入寫入、合併或發布步驟。

交給 Claude Code

先唯讀檢查 repo 現有 CI、required checks 與 secrets 邊界。
為「＿＿」提出一個最小、唯讀、可稽核的 Claude Code job：列出 trigger、permissions、tools、timeout、輸出與失敗行為。
不要建立 workflow、寫 comment、push 或改外部狀態。

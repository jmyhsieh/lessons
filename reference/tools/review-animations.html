Design Engineering Skills · Diff 審查

review-animations

審查一份已存在、範圍固定的動態程式差異，輸出有優先序的 findings 與 verdict。

解決的問題

驗收一份動態 diff

檢查目的、時間、easing、可中斷性、效能、無障礙與減少動態。

何時用

改動已經存在

準備合併前，或完成 apple-design 小幅實作後，需要獨立審查。

何時不用

不是全 repo 盤點

尚未有 diff 時，不拿它找所有機會；改用 find-animation-opportunities。

會讀寫什麼

唯讀 diff 與必要上下文

審查不需要改程式；若同一步要求自動全修，範圍與責任會混在一起。

權限與副作用

固定 commit 或 diff 範圍。先產生 findings，再由人決定是否修；不要讓審查 Skill 自動更改產品程式或擴到整個歷史。

最低完成證據

  • 每個 finding 有位置、影響、證據與建議。
  • 列出正常動態與 prefers-reduced-motion 的檢查結果。
  • 給出 pass／needs changes verdict，並說明未驗證範圍。

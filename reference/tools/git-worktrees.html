Phase 2 · Checkout 隔離

Git worktrees

為平行工作建立獨立 checkout 與 branch，避免多個工作階段在同一工作樹互相覆蓋。

解決的問題

把平行寫入真正分開

每個任務在自己的目錄與 branch 修改、測試與檢查，不共用未提交的工作樹狀態。

何時用

兩個以上獨立修改可並行

任務邊界、branch 所有權與整合順序清楚，而且同時進行能實際節省時間。

何時不用

只是唯讀調查或小改動

搜尋資料可用 Subagent；會同時修改相同檔案的任務，也不適合硬拆平行。

會讀寫什麼

建立目錄、branch 與 Git metadata

Worktree 有自己的工作目錄，但共享 repository history；未追蹤檔、環境檔與相依套件仍要另外處理。

權限與副作用

建立前先看 branch 與 dirty state。為每個 worktree 指定任務與 branch；移除前確認沒有未提交成果，不使用 force 清理不明狀態。

最低完成證據

  • git worktree list 顯示正確路徑與 branch。
  • 每個工作樹的 diff、測試與負責範圍可獨立說明。
  • 整合後確認 branch 與 worktree 的保留或安全移除狀態。

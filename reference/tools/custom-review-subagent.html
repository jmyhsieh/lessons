Phase 2 · 可重用審查角色

Custom review subagent

把固定的審查標準、工具限制與回報格式，做成專門的唯讀 subagent。

解決的問題

讓審查有一致焦點

每次都以相同標準檢查固定 diff，並把作者脈絡與審查脈絡分開。

何時用

同類 review 會重複發生

例如安全、可及性、規格符合度或 repo 慣例，且規則與輸出格式已經清楚。

何時不用

沒有固定基準或固定 diff

需求仍模糊時先釐清；review agent 的結論也不能取代測試、真實執行或人類核准。

會讀寫什麼

讀定義、repo 與變更

專案定義通常放在 .claude/agents/；若只做審查，限制為讀取、搜尋與必要的唯讀命令。

權限與副作用

Reviewer 預設不寫檔。明列可用工具與禁止工具，指定固定 commit 或 diff；若需執行測試，先確認命令不會改寫工作樹。

最低完成證據

  • 保留 subagent 定義與審查基準。
  • 每項 finding 含嚴重度、檔案、行號與理由。
  • 記錄誤報、採納結果與尚未驗證的風險。

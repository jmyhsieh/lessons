Guardrail hook

在工具執行前檢查明確的危險條件，符合時阻擋並回傳可理解的原因。

解決的問題

阻止已知危險模式

把「這種命令或目標一律不能執行」變成確定的阻擋規則，而不是依賴臨場提醒。

何時用

條件能精確描述

例如特定破壞性命令、受保護路徑或禁止的參數組合，且允許與拒絕案例都能列出。

何時不用

政策仍然模糊

需要理解意圖、資料敏感度或例外情境時，不要只靠字串比對；guardrail 也不能取代權限與人工核准。

會讀寫什麼

讀取工具輸入，可能阻擋執行

常在 PreToolUse 讀取工具名稱與參數；規則本身應避免額外寫入或網路副作用。

權限與副作用

避免過寬的 substring 規則。精確解析輸入，讓安全案例通過、危險案例被擋；阻擋訊息要指出原因與安全替代方案。

最低完成證據

  • 一個允許案例成功通過。
  • 一個禁止案例在執行前被擋，且原因清楚。
  • 保留設定、腳本與回復方式。

交給 Claude Code

先唯讀盤點現有權限與 hooks。
為「＿＿」設計一個最窄的 PreToolUse guardrail，列出精確輸入條件、允許案例、阻擋案例與訊息。
不要用模糊 substring，也不要先修改設定。

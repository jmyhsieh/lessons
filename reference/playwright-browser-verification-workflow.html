Phase 8：Claude Code × Playwright

這個 Phase 不要求你手動背 Playwright API。你先把任務講清楚，讓 Claude Code 操作或產生變更；你負責觀看真實 browser、審查 spec／diff／output，並判斷證據是否足夠。

先選三層中的一層

層級用來回答工具與留下的證據
Live check這條路徑現在正常嗎？Playwright MCP（或 Claude in Chrome）操作可見 browser，留一份 evidence note；不會自動變成 repo test。
Durable test以後壞掉時會被發現嗎？Claude Code 產生並執行 Playwright Test，留下 committed test 與可解釋的 fail → pass。
Agent workflow需求變多時，如何保留人工 review？planner → approved spec → generator → reviewed test → healer；每一層都有可審查 artifact。

最小指令

node --version
claude mcp add --transport stdio --scope local playwright -- npx @playwright/mcp@latest
claude mcp get playwright

# 已有 Playwright Test 地基後，才初始化 Claude Code agents
npx playwright init-agents --loop=claude

Playwright MCP README 也示範較短的 claude mcp add playwright npx @playwright/mcp@latest。本課以 Claude Code 現行 MCP 文件的 option ordering 與 -- 分隔寫法為準，因為目標使用者是 Claude Code 使用者。

三個可直接貼給 Claude Code 的 prompts

Live check

只做 browser verification，不要修改 repo files。
使用 Playwright 打開＿＿URL，完成＿＿動作，確認＿＿結果。
每次 navigation 或 action 後重新讀取頁面狀態。
回報實際步驟、觀察結果、console errors 與未知項目。

Planner

Use the Playwright planner for only this path: ＿＿。
Use the existing seed test and relevant requirement: ＿＿。
Write one Markdown spec under specs/. Do not generate tests or edit product code.

Healer

Use the Playwright healer for only this failing test: ＿＿。
Read the approved spec and trace. First classify the cause as app, test, or environment.
Do not skip, delete, weaken assertions, or change product behavior just to pass.
Show the proposed patch and evidence before applying it.

進階 05–09

課只做這件事人工關卡
05以 --loop=claude 產生 Test Agents審查 definitions 與 seed test
06讓 planner 寫一份 bounded spec核准 scope、steps 與 expected result
07讓 generator 依 approved spec 產生一個 test比對 spec、diff、locator 與 test output
08讓 healer 用 trace 診斷一個 failure禁止 skip／弱化 assertion；product bug 就停
09把 reviewed tests 接到最小 CI gate核對 projects、artifacts、run 與限制

安全與停止線

MCP scope：先用 local scope。Project-scoped .mcp.json 會成為團隊設定，必須先共同審查 server command、來源與權限。
外部內容：瀏覽器讀到的網頁可能含 prompt injection；不要讓未信任內容擴大操作範圍，也不要隨意啟用 workspace 以外的 file access。
Artifacts：Report、trace 與 screenshot 可能包含 token、資料或原始碼；限制存取與保留期限，分享前先脫敏。
人類責任：Agent 顯示成功不等於需求正確。每次都審查 prompt、spec、diff 與真實 output；healer 的綠燈也不能取代 product judgment。

第 04 課是獨立入門完成線。只有一條路徑時，不必初始化 Test Agents 或建立完整 browser matrix；第 09 課也只能聲稱指定 tests 與 projects 有證據，不能說「所有 UI 都已自動驗證」。

Claude Code 擴充與自動化

工具／模式卡何時先用停止線實作
Claude Code hooks在固定生命週期事件執行可預測動作。需要情境判斷時，不要硬寫成腳本。控制工具行為
Guardrail hook明確的危險模式必須在執行前被擋。不能取代權限、人工核准與模糊政策判斷。擋下危險操作
Claude Code Skills知識或流程會跨任務重複使用。一次性問題不用做成 Skill；隔離 context 改用 Subagent。打包重複流程
Claude Code MCP權威資料或專用工具位於外部系統。本機工具已足夠，或 server 來源與權限不明時，不連線。讀外部資料
Claude Code Subagents大型旁線調查需要獨立 context。它不等於獨立 checkout；平行寫入改用 worktree。隔離大型調查
Custom review subagent固定審查標準需要重複使用與唯讀工具限制。不能取代測試、真實執行或人類核准。建立 review agent
Git worktrees多個獨立修改需要平行 checkout。只做唯讀調查，或任務會撞同一批檔案時，不必使用。分開平行工作
Writer／Reviewer 工作階段作者與審查者需要不同 context。Reviewer 預設唯讀；兩邊不要同時改相同檔案。分開撰寫與審查
Claude Code headless一次性任務有固定輸入、工具與輸出格式。探索性或高風險寫入回到互動工作階段。跑 one-shot
Claude Code CI無人值守任務可縮成最小權限、可稽核流程。不讓模型自行做 production write、push、merge 或發布。設定 CI 邊界

固定時點 → hooks · 重用流程 → Skills · 連外部系統 → MCP · 隔離 context → Subagents · 隔離 checkout → worktrees · 程式化單次任務 → headless · 無人值守 → CI

官方來源：Extend Claude Code、Hooks guide、Subagents、Git worktrees。

Playwright

工具用來回答設定／副作用最低證據
Playwright MCP這條路徑現在正常嗎？連接 MCP 並操作可見瀏覽器；先用本機範圍，不會自動留下 repo 測試。實際步驟、最新頁面狀態、console error 與未知項目。
Playwright Test以後壞掉時會被發現嗎？會新增或修改測試檔；先讀既有測試規則與啟動方式。可提交的 test diff，以及同一風險由失敗到通過的紀錄。
Playwright Test Agents多條路徑如何保留規格與人工關卡？已有 Playwright Test 地基後，才初始化 planner、generator、healer 定義。核准規格、已審查測試、trace 與不弱化 assertion 的修復紀錄。

即時查核：01 選路 → 02 MCP → 03 live check
耐久測試：01 選路 → 04 durable test
代理流程：04 地基 → 05 → 06 → 07 → 08 → 09

文件轉 Markdown

工具優先使用情況何時不要用最低證據
MarkItDown有可靠文字層的 PDF、Word、Excel、PowerPoint。不要把基礎轉換器當成本機掃描 OCR；空白或亂碼就重新選路。原檔、實際命令、待查核 Markdown。
Docling掃描 PDF、圖片、複雜版面或表格。--force-ocr 不應成為所有 PDF 的預設；先核准模型下載與本機資源。原檔、工具版本、OCR 疑點與人工抽查。
Claude Code 直接讀取少量文件、只需一次性整理，而且不想先裝轉換器。不要把 Claude Code 訂閱當成 MarkItDown OCR plugin 的 API 憑證。來源頁面、抽查紀錄與仍不確定的內容。

01 選路 → 02 MarkItDown 或 03 Docling → 04 原檔對照

詳細工作流：文件轉 Markdown 路線卡。主要來源：MarkItDown、Docling。

用量與查找

問題先用何時先不用實作卡
一個 Claude Code 工作階段用了多少 token？ccusage要查官方方案剩餘額度，回官方產品介面。留一筆基準
核准的 Markdown 裡哪份提到這件事？QMD只有幾份已知檔案，先直接讀或用 rg。搜尋並回查
符號定義在哪裡、被誰引用？Claude Code LSP固定字串先用 rg；語言尚無可用 code intelligence plugin 時先不要硬裝。畫符號地圖
Serena 保留為替代工具：需要它更完整的專案探索工作流時再評估。只查 definition／references，優先使用 Claude Code 內建的 LSP tool；它仍需要對應語言的 code intelligence plugin 與 language server。

詳細比較：用量與查找工具卡。官方來源：Claude Code Tools reference、Code intelligence plugins。

Design Engineering Skills

工具卡

先選一個 Skill

emil-design-eng 審查元件、animation-vocabulary 說清動態、apple-design 做有限改動；另外三個 Skills 用於 diff 審查、找候選與改善計畫。

安裝邊界

保留來源、版本與路徑

先查固定上游版本與授權，記錄實際安裝路徑與移除方式。安裝完成不代表任何產品程式已驗證。

何時不用

不為了展示技巧加動態

高頻操作、鍵盤路徑或沒有明確用途的狀態變化，可以不加動畫；審查建議也不是實作授權。

完成證據

diff 加真實互動

保留範圍、完整 diff、檢查結果、正常動態與 prefers-reduced-motion 證據。

單頁 Skill 卡這次只完成
emil-design-eng審查一個介面元件
animation-vocabulary把一個動態說清楚
apple-design實作一個有限互動改動
review-animations審查一份固定動態 diff
find-animation-opportunities找少量候選，也排除一項
improve-animations唯讀盤點、寫計畫或受控執行

入門：01 安裝卡 → 02 → 03 → 04 → 05 驗收
進階：05 橋接 → 06 → 07 → 08

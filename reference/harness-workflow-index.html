Harness 工作流速查索引

把第 25–40 課的 Harness 速查表集中成一個入口，依任務成熟度逐步使用。

使用順序：先判斷值不值得 harness，再穩住 input，接著設計 gates/evidence，產出 report/handoff，設計最小 runner，只實作 list/show/dry-run 第一片，接真 agent call，執行 gates，建立 run history，定義 rerun policy，整理 final handoff package，做 closeout decision，用 repo rehearsal 跑完整輪，把 finding 收斂成 workflow patch，用第二輪 rehearsal 驗證 patch，最後把 verified workflow 固化成 repo contract。

十六張速查表

順序速查表何時使用對應課程
1 Harness readiness 速查表 判斷一個任務要維持單次 agent、半手動 checklist，還是值得 harness 化。 第 25 課
2 Harness-ready issue / brief 速查表 把模糊任務改寫成穩定 input contract：ID、Source、Outcome、Scope、Gates、Stop。 第 26 課
3 Gates 與 evidence 速查表 把 gate 從提醒改成可驗收條件，並定義 command、result、artifact、decision。 第 27 課
4 Report / handoff 速查表 把 evidence 收束成 reviewer 可判斷的 report，並交接給下一個 session。 第 28 課
5 Minimal runner 速查表 把成熟任務串成單 input、單任務、單 report 的可重跑 runner。 第 29 課
6 Runner 第一片速查表 先實作 list、show、dry-run，驗證 runner 不會跑錯任務。 第 30 課
7 Agent call evidence 速查表 把 dry-run plan 接成 bounded agent call，並捕捉 stdout、stderr、exit code 與分類結果。 第 31 課
8 Gate execution 速查表 把 agent evidence 接到 deterministic gates，寫出 gate-results 與最小 report。 第 32 課
9 Run history 速查表 把 input、agent evidence、gate results、report path 與 status 串成可查詢紀錄。 第 33 課
10 Rerun policy 速查表 定義哪些 status 可以重跑、如何保留 parent evidence、何時必須人工介入。 第 34 課
11 Final handoff 速查表 把 latest run、parent chain、evidence 與未解風險整理成可接手交付包。 第 35 課
12 Closeout decision 速查表 決定一輪 run 應該 ship、review、rerun、blocked，或降級回單次 agent。 第 36 課
13 Repo rehearsal 速查表 用一個低風險真實 repo 任務演練完整 harness 流程。 第 37 課
14 Workflow patch 速查表 把 rehearsal finding 分類，收斂成一個可驗收的小改進。 第 38 課
15 Patch verification 速查表 用第二輪同類型 rehearsal 驗證 workflow patch 是否值得保留。 第 39 課
16 Repo contract 速查表 把 verified workflow patch 固化到最小、最合適的 repo-level 規範。 第 40 課

最小路線

如果目前狀態是…下一張表先不要做
任務只做一次、還在探索。Readiness不要急著寫 runner。
任務會重複，但 brief 每次都要重講。Issue / brief不要先接 CI。
任務說有測試，但沒說證據放哪。Gates / evidence不要接受「我已完成」。
已有 evidence，但 reviewer 或下一個 agent 不好接手。Report / handoff不要把完整 log 塞進 handoff。
每次都用同一套 input、gates、report 手動跑。Minimal runner不要先做平台或 scheduler。
Runner contract 已寫好，但還沒驗證 parser。Runner 第一片不要先呼叫真 agent。
Dry-run plan 已穩，但還沒有真 call 的證據。Agent call evidence不要先跑 batch 或排程。
Agent evidence 已留下，但還不能判斷能不能收工。Gate execution不要讓模型自己判斷 pass。
Report 已產出，但下一次很難找到同一輪 run 的 artifacts。Run history不要先做 dashboard。
已有 run history，但不知道哪些狀態能重跑。Rerun policy不要覆蓋舊 evidence。
已有 latest run，但 reviewer 還不能直接接手。Final handoff不要依賴聊天紀錄。
已有 final handoff，但不知道能不能停止。Closeout decision不要無限重跑。
流程都定義好了，但還沒在真實 repo 試過。Repo rehearsal不要直接推成團隊平台。
演練已完成，但不知道該改哪個流程點。Workflow patch不要一次修全部問題。
Patch 已寫好，但不知道是否真的有效。Patch verification不要直接固化 runner。
Patch 已驗證為 keep，但不知道該放哪。Repo contract不要直接平台化。

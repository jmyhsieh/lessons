Harness 工作流速查索引

Phase 4 選修路線的細節速查入口；依任務成熟度選用，不必把每張表都變成獨立課程。

使用方式：8 課負責學習決策與完整工作流；21 張速查表保留各 artifact 的詳細模板。先判斷值不值得 harness，再依目前缺口選表，不需要線性讀完全部細節。

八組能力，二十一張細節速查表

順序速查表何時使用對應課程
1 Harness readiness 速查表 判斷一個任務要維持單次 agent、半手動 checklist，還是值得 harness 化。 Phase 4 第 01 課
2 Harness-ready issue / brief 速查表 把模糊任務改寫成穩定 input contract：ID、Source、Outcome、Scope、Gates、Stop。 Phase 4 第 02 課
3 Gates 與 evidence 速查表 把 gate 從提醒改成可驗收條件，並定義 command、result、artifact、decision。 Phase 4 第 02 課
4 Report / handoff 速查表 把 evidence 收束成 reviewer 可判斷的 report，並交接給下一個 session。 Phase 4 第 02 課
5 Minimal runner 速查表 把成熟任務串成單 input、單任務、單 report 的可重跑 runner。 Phase 4 第 03 課
6 Runner 第一片速查表 先實作 list、show、dry-run，驗證 runner 不會跑錯任務。 Phase 4 第 03 課
7 Agent call evidence 速查表 把 dry-run plan 接成 bounded agent call，並捕捉 stdout、stderr、exit code 與分類結果。 Phase 4 第 04 課
8 Gate execution 速查表 把 agent evidence 接到 deterministic gates，寫出 gate-results 與最小 report。 Phase 4 第 04 課
9 Run history 速查表 把 input、agent evidence、gate results、report path 與 status 串成可查詢紀錄。 Phase 4 第 05 課
10 Rerun policy 速查表 定義哪些 status 可以重跑、如何保留 parent evidence、何時必須人工介入。 Phase 4 第 05 課
11 Final handoff 速查表 把 latest run、parent chain、evidence 與未解風險整理成可接手交付包。 Phase 4 第 05 課
12 Closeout decision 速查表 決定一輪 run 應該 ship、review、rerun、blocked，或降級回單次 agent。 Phase 4 第 05 課
13 Repo rehearsal 速查表 用一個低風險真實 repo 任務演練完整 harness 流程。 Phase 4 第 06 課
14 Workflow patch 速查表 把 rehearsal finding 分類，收斂成一個可驗收的小改進。 Phase 4 第 06 課
15 Patch verification 速查表 用第二輪同類型 rehearsal 驗證 workflow patch 是否值得保留。 Phase 4 第 06 課
16 Repo contract 速查表 把 verified workflow patch 固化到最小、最合適的 repo-level 規範。 Phase 4 第 07 課
17 Contract review loop 速查表 讓 repo contract 在下一輪 review 中被點名、使用、判斷下一步。 Phase 4 第 07 課
18 Contract effectiveness 速查表 用少量 evidence 判斷 contract 是否真的降低返工或 review 成本。 Phase 4 第 07 課
19 Template promotion 速查表 把多次有效的 input 或 review contract 升級成 issue、PR 或 handoff template。 Phase 4 第 08 課
20 Hook / gate promotion 速查表 判斷 contract 是否已低誤判、可機械判定，值得升級成 hook 或 runner gate。 Phase 4 第 08 課
21 Contract cleanup 速查表 整理、合併、移動或退役不再有效的 repo contract。 Phase 4 第 08 課

最小路線

如果目前狀態是…下一張表先不要做
任務只做一次、還在探索。Readiness不要急著寫 runner。
任務會重複，但 brief 每次都要重講。Issue / brief不要先接 CI。
任務說有測試，但沒說證據放哪。Gates / evidence不要接受「我已完成」。
已有 evidence，但 reviewer 或下一個 agent 不好接手。Report / handoff不要把完整 log 塞進 handoff。
每次都用同一套 input、gates、report 手動跑。Minimal runner不要先做平台或 scheduler。
Runner contract 已寫好，但還沒驗證 parser。Runner 第一片不要先呼叫真 agent。
Dry-run plan 已穩，但還沒有真 call 的證據。Agent call evidence不要先跑 batch 或排程。
Agent evidence 已留下，但還不能判斷能不能收工。Gate execution不要讓模型自己判斷 pass。
Report 已產出，但下一次很難找到同一輪 run 的 artifacts。Run history不要先做 dashboard。
已有 run history，但不知道哪些狀態能重跑。Rerun policy不要覆蓋舊 evidence。
已有 latest run，但 reviewer 還不能直接接手。Final handoff不要依賴聊天紀錄。
已有 final handoff，但不知道能不能停止。Closeout decision不要無限重跑。
流程都定義好了，但還沒在真實 repo 試過。Repo rehearsal不要直接推成團隊平台。
演練已完成，但不知道該改哪個流程點。Workflow patch不要一次修全部問題。
Patch 已寫好，但不知道是否真的有效。Patch verification不要直接固化 runner。
Patch 已驗證為 keep，但不知道該放哪。Repo contract不要直接平台化。
Repo contract 已寫好，但不知道有沒有人使用。Contract review loop不要只把文件留在 reference。
Contract 已被使用，但不知道是否減少返工。Contract effectiveness不要靠主觀印象判斷。
同一欄位或 evidence 重複被追問。Template promotion不要先升級成 hook。
規則已穩定且可機械判斷。Hook / gate promotion不要把需要語境判斷的規則強制化。
Contract 變多、重複或不再被使用。Contract cleanup不要只加不減。
對應課程：01 readiness · 02 contract · 03 runner · 04 agent + gates · 05 lifecycle · 06 rehearse · 07 effectiveness · 08 promote / retire

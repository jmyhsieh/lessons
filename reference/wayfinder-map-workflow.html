Wayfinder shared map 速查表

巨大模糊 effort 的選路、map schema、ticket types、frontier 與 session stop rules。

內容校準自 reviewed contract 9603c1c；契約漂移時先重新做 Source recertification。

一句話：Wayfinder 不是把巨大工作切成施工票，而是把看不清的路整理成 decision tickets；路清楚後，再交給 /to-spec → /to-tickets → /implement。

選擇器

訊號判斷
已能寫完整 spec 與 blocking tickets不要用 wayfinder；直接進主線。
一個 session 能把所有未知問清楚用 /grill-with-docs。
巨大、跨 session，連問題順序都仍在 fog 裡使用 wayfinder。

標準 map schema

## Destination
一兩句：這張 map 要找出哪份 spec、哪個決策或哪條改變路徑。

## Notes
領域、固定偏好、每個 session 要查的 skills。

## Decisions so far
- [Ticket title](link) — 一句答案 gist

## Not yet specified
在 scope 內，但目前還無法精確問成 ticket 的 fog。

## Out of scope
超出 destination、永遠不會從 fog 升級的工作。

Ticket 類型

標籤模式完成訊號
wayfinder:researchAFK（離席執行）research/<name> branch 上有 cited summary；ticket 留 context pointer。
wayfinder:prototypeHITL（人在迴路）人類對 artifact 作反應，留下可引用答案。
wayfinder:grillingHITL（人在迴路）真正的決策者逐題回答，agent 不代答。
wayfinder:taskAFK／HITL 模式阻擋決策的操作完成並留下 facts。
Research 例外：Decision tickets 建立並 wire blocking edges 後，為每張 research ticket 平行啟動 /research subagent。研究留在 throwaway research/<name> branch，ticket 留 context pointer；charting agent 不手動逐張解票。

Ticket、模糊區、範圍外

分類判斷題存放位置
Ticket（工作票）現在已能精確說出要回答的問題。Map 的 child issue。
模糊區知道這塊在 scope 內，但還無法精確問問題。尚未指定。
範圍外即使變清楚，也超出 destination。範圍外；不會升級。

繪製 map

  1. 用 grilling 與 domain-modeling 固定 destination。
  2. Breadth-first 掃描整片未知區，不急著深挖一題。
  3. 建立標記 wayfinder:map 的 canonical map。
  4. 只建立現在能精確問出的 decision tickets。
  5. Tickets 取得 ids 後，再第二輪 wire blocking edges。
  6. 為每張 research ticket 平行啟動 /research subagent。
  7. 看得到 frontier 後停止；charting agent 不手動解票。

依 map 推進

以下是普通 frontier ticket 的 serial loop；charting 時已啟動的 research subagents 是平行例外。

  1. 載入 map 低解析全貌。
  2. 選第一張 open、unblocked、unclaimed frontier ticket。
  3. 先 assign 給自己，再依 ticket type 解題。
  4. 把完整答案留在 resolution comment，close ticket。
  5. Map 只新增 ticket 名稱、連結與一句 gist。
  6. 建立新 tickets、wire edges、升級 fog 或移出 scope。
  7. 停止；下一張普通 ticket 留給下一個 session。

不變量

  • Map 是 index，不是答案倉庫。
  • 人類文字用 ticket title，不用裸 issue id。
  • Assignee 是 claim；先 claim 才開始。
  • 普通 frontier session 最多解一張 ticket；平行 research subagents 是明確例外。
  • 預設產出 decisions，不產出 destination deliverables。
離場：沒有 open tickets、沒有可升級 fog、路徑已清楚 → 回 request alignment，再由 /to-spec → /to-tickets 收斂 linked decisions；本課程不把 Wayfinder map 當成直接施工授權。

回到 Engineering delivery flow

Wayfinder 的輸出是 evidence，不是另一條 completion path。Map 尚未完成就由新 session 繼續解一張 frontier ticket；map 完成後，先到 request alignment 對齊 linked decisions，再固定 delivery spec、切 tickets，最後才 implementation 與 Review。

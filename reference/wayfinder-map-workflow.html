Wayfinder 共享決策地圖速查表

巨大模糊工作的選路、地圖欄位、工作項目類型、目前可處理項目與工作階段停止規則。

內容校準自穩定版 v1.2.3（6acc160）；實際操作前再查目前版本。

一句話：Wayfinder 先把看不清的路整理成決策工作項目（decision tickets）；路清楚後，再交給 /to-spec → /to-tickets → /implement。

何時使用

訊號判斷
已能寫完整規格與阻擋關係直接進主線。
一個工作階段能把所有未知問清楚用 /grill-with-docs。
巨大、跨工作階段，連問題順序都還看不清使用 Wayfinder。

標準地圖欄位

## Destination
一兩句：這張 map 要找出哪份 spec、哪個決策或哪條改變路徑。

## Notes
領域、固定偏好、每個 session 要查的 skills。

## Decisions so far
- [Ticket title](link) — 一句答案 gist

## Not yet specified
在 scope 內，但目前還無法精確問成 ticket 的 fog。

## Out of scope
超出 destination、永遠不會從 fog 升級的工作。

工作項目類型

Label模式完成訊號
wayfinder:research可離開等待（AFK）research/<name> 分支有附來源摘要；工作項目留下脈絡連結。
wayfinder:prototype人工參與（HITL）真人操作原型並留下可引用答案。
wayfinder:grilling人工參與（HITL）真正的決策者回答目前 frontier 的 decisions，Claude Code 不代答。
wayfinder:task依情境決定阻擋決策的操作完成並留下事實。
研究例外：建立決策工作項目與阻擋關係後，可為每張研究工作項目平行啟動 /research 子代理。研究留在拋棄式 research/<name> 分支，工作項目留下脈絡連結；建立地圖的代理不逐張處理。

工作項目、待釐清區與範圍外

分類判斷題存放位置
工作項目現在已能精確說出要回答的問題。地圖的子 issue。
待釐清區知道這塊在範圍內，但還無法精確問問題。Not yet specified 欄位。
範圍外即使變清楚，也超出目標。Out of scope 欄位；不會升級。

建立地圖

  1. 用需求追問與 domain-modeling 固定目標。
  2. 先廣泛掃描整片未知區，不急著深挖一題。
  3. 建立標記 wayfinder:map 的標準地圖。
  4. 只建立現在能精確問出的決策工作項目。
  5. 工作項目取得編號後，再建立阻擋關係。
  6. 為每張研究工作項目平行啟動 /research 子代理。
  7. 看得到目前可處理項目後停止；建立地圖的代理不手動解票。

逐張處理地圖

一般工作項目一次處理一張；建立地圖時已啟動的研究子代理是平行例外。

  1. 載入地圖的低解析全貌。
  2. 選第一張開放、未被阻擋、尚未認領的工作項目。
  3. 先指派給自己，再依類型解題。
  4. 把完整答案留在結案留言，關閉工作項目。
  5. 地圖只新增名稱、連結與一句結論。
  6. 建立新工作項目、更新阻擋關係，並整理待釐清區與範圍。
  7. 停止；下一張普通工作項目留給下一個工作階段。

不變量

  • 地圖是索引，不是答案倉庫。
  • 人類文字使用工作項目標題，不只寫 issue 編號。
  • 先認領工作項目再開始。
  • 一般工作階段最多處理一張；平行研究子代理是明確例外。
  • 預設產出決策，不直接製作最終交付物。
停止條件：沒有開放工作項目、沒有可升級的待釐清區，而且路徑已清楚 → 用 /to-spec 收斂關聯決策。若工作最後縮成單一小任務，才直接用 /implement。

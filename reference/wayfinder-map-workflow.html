Wayfinder shared map 速查表

巨大模糊 effort 的選路、map schema、ticket types、frontier 與 session stop rules。

一句話：Wayfinder 不是把巨大工作切成施工票，而是把看不清的路整理成 decision tickets；路清楚後，再交給 /to-spec → /to-tickets → /implement。

Selector

訊號判斷
已能寫完整 spec 與 blocking tickets不要用 wayfinder；直接進主線。
一個 session 能把所有未知問清楚用 /grill-with-docs。
巨大、跨 session，連問題順序都仍在 fog 裡使用 wayfinder。

Canonical map schema

## Destination
一兩句：這張 map 要找出哪份 spec、哪個決策或哪條改變路徑。

## Notes
領域、固定偏好、每個 session 要查的 skills。

## Decisions so far
- [Ticket title](link) — 一句答案 gist

## Not yet specified
在 scope 內，但目前還無法精確問成 ticket 的 fog。

## Out of scope
超出 destination、永遠不會從 fog 升級的工作。

Ticket、fog、out of scope

分類判斷題存放位置
Ticket現在已能精確說出要回答的問題。Map 的 child issue。
Fog知道這塊在 scope 內，但還無法精確問問題。Not yet specified。
Out of scope即使變清楚，也超出 destination。Out of scope；不會升級。

Chart the map

  1. 用 grilling 與 domain-modeling 固定 destination。
  2. Breadth-first 掃描整片未知區，不急著深挖一題。
  3. 建立標記 wayfinder:map 的 canonical map。
  4. 只建立現在能精確問出的 tickets。
  5. Tickets 取得 ids 後，再第二輪 wire blocking edges。
  6. 看得到 frontier 後停止；同 session 不解票。

Work through the map

  1. 載入 map 低解析全貌。
  2. 選第一張 open、unblocked、unclaimed frontier ticket。
  3. 先 assign 給自己，再依 ticket type 解題。
  4. 把完整答案留在 resolution comment，close ticket。
  5. Map 只新增 ticket 名稱、連結與一句 gist。
  6. 建立新 tickets、wire edges、升級 fog 或移出 scope。
  7. 停止；下一張 ticket 留給下一個 session。

不變量

  • Map 是 index，不是答案倉庫。
  • 人類文字用 ticket title，不用裸 issue id。
  • Assignee 是 claim；先 claim 才開始。
  • 一個 session 最多解一張 ticket。
  • 預設產出 decisions，不產出 destination deliverables。
Exit：沒有 open tickets、沒有可升級 fog、路徑已清楚 → /to-spec 收斂 linked decisions。只有 effort 最後縮成單一小任務，才例外直接 /implement。

Patch verification 速查表

用第二輪同類型 rehearsal 驗證 workflow patch 是否值得保留。

Patch verification 的驗收句：第二輪 evidence 能說明 patch 是否減少問題，並產出 keep、revise 或 revert 決策。

可比較訊號

Signal有效跡象失敗跡象
Clarifying questions問題變少且更具體。仍重問同一件事。
Gate clarityPass/fail 更可驗收。仍靠模型判斷。
Evidence accessArtifact path 可打開。Reviewer 找不到證據。
Handoff quality下一個 agent 可接手。仍需補問上下文。
Overhead步驟沒有增加或變少。流程比任務更重。

Verification note template

{
  "patchId": "",
  "beforeRunId": "",
  "afterRunId": "",
  "sameTaskClass": true,
  "expectedImprovement": "",
  "observedChange": "",
  "result": "keep | revise | revert",
  "nextDecision": ""
}

Decision rules

Result使用時機下一步
keep改善可由 evidence 看出。進 Phase 5 第 07 課選 repo contract。
revise方向對，但改善不足。回 Phase 5 第 06 課重切 patch。
revert流程更重或問題轉移。撤回 patch，記錄原因。

完成定義

Done when:
- Before and after runs are the same task class.
- Expected improvement was written before the second run.
- Observed change cites concrete evidence.
- Result is keep, revise, or revert.
- The next decision does not introduce platform work.

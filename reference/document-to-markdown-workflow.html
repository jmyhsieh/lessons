文件轉 Markdown × Claude Code 路線卡

先依文字層與版面選工具，再保留原檔、轉換紀錄與人工查核證據。

先記住：轉換成功不代表內容正確。Markdown 只是方便搜尋與處理的版本；重要內容仍要回到 PDF、Office 或圖片原檔確認。

三條入門路線

文件情況先選原因與停止線
一般文字型 PDF、Word、Excel、PowerPointMarkItDown輕量、適合有文字層的文件；基礎套件不會自動替掃描 PDF 做本機 OCR。
掃描 PDF、圖片、複雜版面或表格Docling本機處理 OCR、版面與閱讀順序；第一次可能下載模型，先核准安裝與資源。
只有少量文件、不想安裝工具Claude Code 直接讀取在支援附件的 Claude Code Desktop 可直接附 PDF 與其他檔案；CLI common workflow 明確支援 image path。這是 Claude 的讀取能力，不是 MarkItDown OCR，Claude Code 訂閱也不能拿來當 API key。

入門：選一種轉換，再共同查核

文件順序完成證據
文字型 PDF／Office01 選路 → 02 MarkItDown → 04 原檔對照原檔、待查核 Markdown、人工查核表與使用限制
掃描 PDF01 選路 → 03 Docling OCR → 04 原檔對照原檔、待查核 OCR Markdown、人工查核表與疑點
少量一次性文件01 選路 → Claude Code 直接讀取 → 04 的查核方法來源頁面、抽查紀錄與仍不確定的內容

進階 05–08：遇到真實需求再接

課解決的需求完成證據
05 混合檔同一份 PDF 同時有正常文字頁與掃描頁。預設擷取與 full-page OCR／全頁 OCR 比較表
06 可追查日後要知道輸出從哪裡來、怎麼重跑。來源、輸出、版本、命令、查核、缺口
07 小批次轉換少量已核准文件，分開記錄成功、失敗與略過。核准清單（allowlist）、試跑結果（dry run）、結果清單（manifest）
08 Wiki 交接把已查核的 Markdown 加進 LLM Wiki。匯入（ingest）計畫、程式差異（diff）、來源回查

不可省略的五個檢查

檢查最低要求
範圍首頁、中間頁與末頁都有內容，而且沒有整頁缺漏。
文字抽查數字、專有名詞與標點；OCR 疑點標為待確認。
結構標題層級、閱讀順序與清單沒有明顯錯位。
表格欄列對應與單位可用；複雜表格必要時保留原頁引用。
追查保留原檔、工具版本、實際命令、輸出路徑與已知限制。
安全停止線：敏感文件只在核准的本機環境處理；--ocr-mode full_page 只用於確認的掃描頁或損壞文字層；批次只讀取精確的核准清單（allowlist）；所有輸出都要人工查核。

Phase 4 · 設計 · 標準參考

設計路線與交接速查表

核心邊界：設計把有界摘要轉成所選的方向、原型證據與可審查的交接收尾包。它可以在收尾包合法停止；只有任務要交付版本控制的實作時，才帶收尾包進 Phase 6建置。

已驗證環境：2026-07-16依 Anthropic Claude Design 產品、說明中心與發布頁面檢查測試版可用性、設計系統、修訂版、原型與交接介面。實際計畫、用戶端、組織設定、標籤與連接方式可能變動；操作前以當下第一方指南為準。

七個具體成果

004-0001工作表面
路線選擇卡：artifact、不確定性、可用性、feedback 與法務 stop。
004-0002摘要（摘要）
可重述的使用者任務、真實內容、狀態、脈絡、排除目標與驗收。
004-0003系統（條件式）
只有已核准的脈絡才進入；留下來源識別、不符與處置。
004-0004方向
同一摘要下比較不同假設，保存基準與選擇理由。
004-0005修訂
一次改一層，用同一任務判斷接受／修訂／還原。
004-0006假設
直接操作 viewport、輸入、狀態與可及性準則；標示未測試。
004-0007交接（交接）
整合來源、意圖、規則、證據、限制、學習者判斷與 feedback。

條件式分支與返回

情況動作返回點
有已核准的設計系統／品牌／產品脈絡走004-0003，校正一個代表性對照回004-0004
沒有已核准的脈絡明記「不發明權杖」，跳過004-0003直接到004-0004
準備度／存取／權利不足保存目前 artifact，補最小缺口回原設計課程，不重跑整條 route
交接已完成且不需 repo 變更寫下學習者判斷與 feedback 處置合法停止並回目錄
需要 repo 實作確認 Code readiness，帶收尾包進 Phase 6建置負責實作、checks、Review、收尾

若選擇建置，先做唯讀的交接

請先只讀 handoff bundle、repository instructions 與相關檔案，不要修改。
請回報：
- design intent 對應的既有 components、tokens 與 states
- bundle 與 repo 的衝突、缺漏及需人決定事項
- 最小 vertical slice、non-goals 與可能修改檔案
- deterministic repo checks、browser evidence 與 Review 計畫

不要跨越：交接、export、MCP 連線、設計同步、可分享原型或唯讀的 repo 對照都不授權儲存庫寫入，也不證明實作忠實度。進 Phase 6建構 後，仍須依 repo 指示完成有界的規格／工作票、實作、checks、不可變的 Review 與收尾。

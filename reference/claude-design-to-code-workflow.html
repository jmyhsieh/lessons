Phase 4：Claude Code × Claude Design

Claude Code 是主要工作介面；Claude Design MCP 提供視覺探索能力。01–08 先完成入門，成果真的要進產品，再接 09–13。

入門完成線：你能在 Claude Code 說清楚任務、審查兩個方向與一則修改，取得一筆真人試用觀察，再核准一個可打開的小畫面。

只需設定一次

claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp

在 Claude Code 執行 /design-login，再用 /mcp 確認連線。這是 user-scoped 外部工具；連上不等於授權它修改任何 repo 或公開內容。

八步路徑

課只做這件事留下什麼
01從 Claude Code 連接 Design MCP/mcp 連線結果
02請 Claude Code 整理四句 brief人工核准的 design brief
03交一份參考並說清楚 include／exclude參考＋使用邊界
04請 Design MCP 產生兩個方向人工選擇＋一句理由
05只核准一則具體修改修改前後版本
06真人完成一個任務，再回報觀察一則真實觀察
07把 design intent 與範圍帶回 repobounded handoff
08審查實作並親自打開桌面／手機各一次結果

給 Claude Code 的入門 prompt

先不要產生設計。請把下面內容整理成四句 design brief，缺資料就標記，不要猜：
我要做：
使用者是：
畫面必須包含：
最重要的是：

等我核准 brief 後，再透過 Claude Design MCP 產生兩個明顯不同的方向。

帶回 repo 的四件事

選定版本 · 使用者要完成的任務 · 必須保留的 design intent · 這次只實作的範圍。Claude Code 先做唯讀檢查，等人核准 plan 才修改。

進階 09–13

課解決的產品化問題留下什麼證據
09Claude Code 以 /design-sync 讀到的規則正確嗎？人工校正紀錄＋一個修正樣本
10Claude Code 能否從真實 UI 草擬非理想狀態與尺寸規則？人工核准的 state × responsive matrix
11檢查清單能否轉成真人鍵盤、焦點、zoom 與對比 evidence？一輪真人 accessibility audit
12Claude Code 是否拿到可實作且有停止線的交接？唯讀檢查＋implementation-ready handoff
13測試與真實瀏覽器是否都支持完成宣稱？test output＋browser evidence＋已知限制

停止線

只想驗證概念，完成第 08 課即可；只有確定要進真實產品，才開始第 09 課。Claude Code 或 Claude Design 的自評不能代替真人試用、accessibility 操作與 browser evidence。

AI 營運 / IT / RevOps 職能工作流案例庫

2026/04 起公開案例，聚焦 Claude Code 如何進入 CRM、incident investigation、內部工具與長任務營運流程。

篩選規則：來源需在 2026-04-01 之後發布，且案例本身明確使用 Claude Code。這類工作流的核心風險是資料權限、批次變更、rollback 與人工確認。

案例對照表

日期案例流程片段對應槽位可學走的模式
2026-05-12 Mach 1 sales / CRM 匯入案例 Head of sales 使用 Claude Code 掃描 conference selfies、辨識相關公司，並把結果載入 CRM。 活動資料 → entity matching → CRM update → review 先產生 import diff 與信心分數，再由人核准寫入；不要讓 agent 直接覆蓋 CRM 真實資料。
2026-05-12 長時間 Claude Code session 的營運狀態 文章記錄 Claude Code 等 agent 任務會因本機、Wi-Fi 或筆電休眠而中斷；使用者因此管理筆電喚醒、網路、移動與等待時間。 long-running job → checkpoint → resume / handoff 把 session survival 當成營運需求：要能看進度、可中止、可重跑、可交接。
2026-05-23 VaryAI incident investigation / project management Startup 團隊把 Claude Code 用於 QA pipelines、deployment workflows、incident investigation 與 project management。 incident / workflow issue → diagnosis → task update → human review 營運工作流要把 Claude Code 的輸出接到 issue、runbook 或 project tracker，而不是只停在聊天紀錄。
2026-05-23 Tenzai / startup internal tooling Tenzai 將 Claude Code 裝到會議廳 video controller 上做 IT 診斷，約 25 分鐘找出硬體相容性問題；同一脈絡下，團隊也用 vibe coding 取代舊試算表與內部工具流程。 system access → diagnosis → suggested fix → operational handoff 給 agent 系統權限前，要先定義可讀範圍、可改範圍與回報格式；診斷結果仍要由人核准。

重複出現的模式

資料寫入要分兩段
先產生候選更新與 diff，再由人核准寫入 CRM、ticket 或內部系統。
營運任務需要 runbook
Claude Code 可以協助診斷，但 runbook 要規定何時升級、何時 rollback、何時停止。
長任務要可恢復
保活只是表面問題；真正要設計的是 checkpoint、輸出檔、狀態摘要與 handoff。
內部工具也要治理
小工具若碰到客戶、營收或 production 資料，就需要權限、審計與 owner。

套回可重跑工作流

營運事件 / 活動資料 → Claude Code 擷取或診斷 → diff / runbook update → 人工核准 → 系統寫入

下一個可驗收 artifact 應該是 import diff、incident note、runbook patch 或 rollback checklist，而不是只有「Claude 說可以」。

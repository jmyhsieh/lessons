AI 工程職能工作流案例庫

2026/04 起公開案例，聚焦 Claude Code 在工程實作、品質、長任務與交付節奏上的實際工作流。

篩選規則：收錄 2026-04-01 之後發布，且案例本身明確使用 Claude Code 的來源。研究重現、RevOps 與平台治理案例移到各自職能頁。

案例對照表

日期案例流程片段對應槽位可學走的模式
2026-04-23 Anthropic Claude Code 品質事件 postmortem Claude Code 品質回報追到三個產品層變更：reasoning effort、cache optimization bug、系統 prompt；修復後加強 dogfooding、code review 與 prompt 變更管控。 回報 → 重現 → root cause → eval / rollout gate agent 工具本身也需要工程治理；system prompt、cache 與 reasoning 預設都要像 production code 一樣被審查。
2026-05-12 open-laptop workflow 文章記錄 Claude Code power user 與其他 AI coding agent 使用者為了讓長任務不中斷，在機場、辦公室或通勤中保持筆電喚醒；任務可能跨 Wi-Fi、會議與移動場景。 長任務 → session survival → checkpoint 多小時 agent 工作要有環境策略：`caffeinate`、遠端 session、可重跑指令、進度紀錄與停止條件。
2026-05-23 Startup 團隊把 Claude Code 變成預設工具 Chainguard、VaryAI、Alma、Wordsmith AI、Tenzai 等案例把 Claude Code 用在複雜工程任務、QA pipeline、deployment、incident investigation 與 project management。 repo 探索 → multi-step workflow → review / refine Claude Code 適合處理跨檔、跨 repo、需架構判斷的任務；但仍要安排人類 review 與工具分工。
2026-05-27 YC 創業團隊以 Claude Code 產生大量 code Boris Cherny 轉述 YC 創業者使用狀況：多數團隊讓 Claude Code 寫 50% 到 100% 的 code，少數完全不用。 spec → agent implementation → founder review 當 agent 產 code 變多，工程師工作重心會轉向 spec、review、debug、使用者訪談與系統設計。

重複出現的模式

驗證要覆蓋產品層
system prompt、cache、reasoning effort 與 release rollout 都會影響 coding agent 品質。
人類判斷仍在最後一哩
Claude Code 可放大實作速度，但 spec、review、debug 與架構判斷仍是工程責任。
長任務需要工程化
agent session 要能保活、重跑、checkpoint、復原，否則工作流會卡在本機狀態。
複雜任務要拆成可 review 的工作
startup 案例顯示 Claude Code 能處理多 repo、架構與多步驟任務，但仍要保留 review / refine。

套回 Phase 5 第 01 課

若你要把 Phase 5 第 01 課套到工程任務，工作槽位可以改成：

Issue / 需求 → Codebase 探索 → Plan / Spec → 小 diff → Test / Build / Lint → Review → PR / handoff

2026/04 之後的 Claude Code 案例再加三個 gate：agent session 能否重跑？review 是否能抓到產品層與工具層風險？這個 diff 是否小到能被人類理解與接手？

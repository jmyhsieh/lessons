Claude Code 模型與推理程度速查表

先用模型預設；結果不足時，再分辨是能力不夠，還是做得不夠徹底。

2026-08-12 核心判斷：先修正 prompt、context、tools 與 scope。Claude 已充分嘗試仍判斷錯誤，才換更強模型；Claude 跳過檔案、工具或驗證，才提高 effort。

模型 alias

Alias適合任務注意事項
default回到帳號或組織建議的預設模型。依 account tier、provider 與 organization default 而變；它不是固定模型。
best使用組織可用的最高能力模型。有 Fable 5 權限時選 Fable 5，否則選最新 Opus；不是固定版本。
fable最困難、最長時間、超過一般單次工作的任務。Fable 5 是 opt-in specialist，不是任何帳號的預設；可用性與安全 fallback 依組織而異。
opus架構判斷、模糊需求、跨模組推理、困難 review。Anthropic API 目前解析到 Opus 5；其他 provider 可能不同。
sonnet日常 coding、局部修改、測試可驗證的任務。Anthropic API 目前解析到 Sonnet 5；是多數日常工作的 generalist。
opusplan先深度規劃，再有效率實作。plan mode 用 Opus，執行回 Sonnet。
haiku簡單整理、格式化、低風險小任務。不適合複雜推理。
sonnet[1m]／opus[1m]真的需要超長 context 的 session。不要用長 context 取代乾淨 scope 與 handoff。

Provider 會改變 alias 指向：同一個 opus 或 sonnet 不保證在每個 provider 都解析到同一版本；切換 provider 前要重新核對。

版本提醒：alias 會更新。Claude Code 目前需要 v2.1.219+ 才能使用 Opus 5、v2.1.197+ 才能使用 Sonnet 5、v2.1.170+ 才會顯示 Fable 5；看不到新模型時先執行 claude update，再檢查帳號與組織權限。

先分辨 model、effort 還是 context

症狀下一步不要誤調
缺檔案、規格、工具、來源或驗證條件。先補 context、prompt、skills 或 scope。升級模型與 effort 都不能補回不存在的資訊。
關鍵 context 都有，Claude 也充分嘗試，仍做錯。改用能力更高的模型。不要只讓較小模型用更高 effort 重複錯誤。
方向正確，但跳過檔案、工具、tests 或 double-check。提高 effort。不要把「沒做完」誤判成「模型不夠聰明」。

Effort levels

Level何時使用不要用在
low短、明確、低風險、重視速度。架構或疑難除錯。
medium想省成本，但仍需要一些判斷。高風險改動。
high能力與 token 使用的平衡；目前多數新模型的預設。不需要思考的批次小事。
xhigh更深入的探索、工具使用與查核。模型或組織未提供時，不要自行假設可用。
max最困難且有明確 stop condition 的任務。只套用目前 session，可能出現 diminishing returns 與 overthinking。

模型差異：Fable 5、Opus 5、Sonnet 5、Opus 4.8 與 Opus 4.7 支援 low、medium、high、xhigh、max；Opus 4.6 與 Sonnet 4.6 沒有 xhigh。支援 effort 的模型預設通常是 high，但 Opus 4.7 預設 xhigh。相同 level 在不同模型上也不是相同 token 配額。

特殊控制不是新模型

控制真正作用持續範圍
ultracode以 xhigh reasoning 加上 Claude Code dynamic workflow orchestration；它是 Claude Code 設定，不是 model effort level。目前 session only；--effort ultracode 需 Claude Code v2.1.203+。
ultrathink在單次 prompt 中要求更深推理，但送往 API 的 effort level 不變。只影響該回合，不改 session 設定。

操作方式

介面方式用途
Claude Code/model打開 picker；Enter 切換並存成未來預設，s 只切目前 session。
Claude Code/model opus立即切換並存成未來預設；用 claude --model opus 才是單次啟動。
Claude Code/effort打開 effort slider；切換模型時也可在 /model 用左右鍵調整。
Claude Code/effort auto回到該模型的預設 effort。
CLI 啟動claude --effort xhigh只設定這個新工作階段；適合需要明確一次性設定時。
桌面 Appmodel dropdown／effort menu使用 UI 選項；實際可用模型與 levels 仍受帳號、provider 與組織限制。

決策句

任務建議
修 README typo。haiku 或 sonnet；模型預設 effort 已足夠，需要更快才降到 low。
新增小功能，有測試可跑。sonnet + 模型預設 effort。
跨模組改 API。opus + 模型預設 effort；需要 plan／execute 分工可用 opusplan。
疑難 bug、根因不明。先建立 feedback loop；有 context 但判斷能力不足才升模型，跳過調查與驗證才升 effort。
超長、最困難的自主任務。先確認 success criteria 與 stop condition；組織可用時再選 fable，先保留其預設 effort。

不同工作情境中的使用位置

使用情境重點規則
基本操作分清 context、model 與 effort。先用模型預設，再只調一個旋鈕。
Claude Code 擴充工具hooks、Skills、MCP、Subagents、worktrees、headless、CI 的成本與權限邊界。進階能力先明確 scope，再升高 effort。
需求交付在 repo 地圖整理、/grill-with-docs、/implement 內的 review、或 /diagnosing-bugs 判斷何時升高 effort。不確定性高才升級。
視覺與內容工作視覺原型、簡報與日常交付物仍要依內容風險選 effort。高 effort 不能取代來源查核、真實回饋或 browser verification。

降級規則

觀察下一次設定
提高 effort 沒帶來更多探索或 evidence。回到 auto，檢查 context 或模型能力。
max 只是在重跑同一個失敗。停止，修 scope、feedback loop 或驗證方式。
較強模型連續處理一段例行工作。降回 sonnet 或 default，提高速度並降低成本。

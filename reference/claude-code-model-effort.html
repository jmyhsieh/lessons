Claude Code 模型與推理程度速查表

用任務風險選模型，用不確定性選 effort。

核心判斷：不是一律開最強。先問任務是否需要更深推理，再決定是否提高模型或 effort。

模型 alias

Alias適合任務注意事項
default回到帳號或組織建議的預設模型。依 account tier、provider 與 organization default 而變；它不是固定模型。
best使用目前可用的最高能力模型。實際模型依帳號、provider 與組織可用性而變。
sonnet日常 coding、局部修改、測試可驗證的任務。多數工作先從這裡開始。
opus架構判斷、模糊需求、跨模組推理、困難 review。成本與延遲通常較高。
opusplan先深度規劃，再有效率實作。plan mode 用 Opus，執行回 Sonnet。
haiku簡單整理、格式化、低風險小任務。不適合複雜推理。
sonnet[1m]／opus[1m]真的需要超長 context 的 session。不要用長 context 取代乾淨 scope 與 handoff。

版本提醒：alias 會更新，且不同 provider 可能解析到不同版本；先看目前 picker，需要固定版本時才使用完整 model ID。不要把文件未列出的名稱當成可用 alias。

Effort levels

Level何時使用不要用在
low短、明確、低風險、重視速度。架構或疑難除錯。
medium想省成本，但仍需要一些判斷。高風險改動。
high多數 coding 任務的基準選擇。不需要思考的批次小事。
xhigh跨檔案推理、設計取捨、困難 bug。只有部分模型支援；介面沒有列出時不要自行假設可用。
max真的困難且有明確 stop condition 的任務。長期預設設定。

模型差異：目前官方文件列出 Opus 4.7 支援 low、medium、high、xhigh、max；Opus 4.6 與 Sonnet 4.6 支援 low、medium、high、max。模型與組織設定會改變可用範圍，最後仍以介面選項為準。

操作方式

介面方式用途
桌面 Appmodel dropdown選模型；位置在送出按鈕旁。
桌面 Appeffort menu調推理程度。
Slash command/model若 / 清單有，可當作模型選單快捷。
Slash command/model sonnet若目前環境支援，可切到指定 alias。
Slash command/effort若 / 清單有，可當作 effort 選單快捷。
Slash command/effort auto若目前環境支援，可回到模型預設 effort。
任一介面ultrathink單回合要求更深思考，不改 session effort 設定。

決策句

任務建議
修 README typo。sonnet + low 或 medium。
新增小功能，有測試可跑。sonnet + high。
跨模組改 API。opusplan，或 opus + picker 支援的較高 effort。
疑難 bug、根因不明。先建立 feedback loop，再視不確定性選 opus 與較高 effort。
長時間自主任務。先確認 success criteria、verification 與 stop condition，再選適合模型與 effort。

課程路線中的使用位置

Phase重點規則
Phase 1模型選擇、effort、opusplan 基本取捨。桌面 App 先用選單；slash command 可用時作快捷。
Phase 2hooks、Skills、MCP、Subagents、worktrees、headless、CI 的成本與權限邊界。進階能力先明確 scope，再升高 effort。
Phase 3在 repo 地圖整理、/grill-with-docs、/implement 內的 review、或 /diagnosing-bugs 判斷何時升高 effort。不確定性高才升級。
Phase 4–5（選修）視覺原型、簡報與日常交付物仍要依內容風險選 effort。高 effort 不能取代來源查核、真實回饋或 browser verification。

降級規則

觀察下一次設定
xhigh 沒帶來更清楚的 evidence。降回 high。
max 只是在重跑同一個失敗。停止，修 scope、feedback loop 或驗證方式。
同類任務連續三次在 high 通過。移除高 effort 例外。

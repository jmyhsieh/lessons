Gate execution 速查表

把 agent evidence 轉成可重跑的 gates、gate-results 與最小 report。

Gate execution 的驗收句：每個 pass/fail 都有 command、exit code、artifact path；沒有 evidence 的項目不能標成 pass。

Gate result schema

{
  "id": "",
  "kind": "verification",
  "command": "",
  "cwd": "",
  "timeoutSeconds": 0,
  "exitCode": null,
  "status": "pass | fail | blocked | needs-review",
  "stdoutPath": "",
  "stderrPath": "",
  "decisionReason": ""
}

Status precedence

條件overall statusreport 要寫
任一 gate 缺 credential、command 不在 allowlist、或環境不可用。blocked阻塞原因、誰能解除、不可假裝失敗。
任一 deterministic gate exit code 非零。failed失敗 command、artifact path、修復下一步。
Agent 有輸出，但需要人工 review 或 screenshot 判斷。needs-reviewreview owner、需要看的 evidence。
所有必跑 gate 都 pass，且沒有未驗證項目。passedgate table 與 report path。

最小 report

# Run report

Status:

Agent evidence:
Gate results:
Unverified:

Next step:

先不要做

想加的功能延後原因
多任務 batch會混淆單一 gate 失敗對應哪個 input。
自動修復 loop先讓 fail 可見，再決定是否重跑 agent。
漂亮 dashboard先穩住 JSON 與 markdown report。
全部 shell 命令只允許已審過的 validation commands。

完成定義

Done when:
- A gate plan comes from the input contract.
- Only allowlisted commands can run.
- Every gate writes stdout/stderr artifact paths.
- Overall status follows blocked > failed > needs-review > passed.
- The report links evidence instead of copying full logs.

Claude Code 用量與查找工具路線卡

先說清楚問題，再決定要看用量、找文件，還是追程式符號。

這三個工具不保證省 token：它們能讓你更容易查看用量、把資料範圍訂清楚，或查找程式結構。真正要比較的是同類工作是否完成、驗證是否通過，以及總成本有沒有下降。

三種問題，三個起點

你現在想知道先用本次完成證據
一個 Claude Code 工作階段用了多少 token？ccusage一張工作階段用量基準卡
核准的 Markdown 文件裡，哪一份提到這件事？QMD一筆搜尋結果與原文對照
這個函式或類別定義在哪裡，又被誰引用？Serena一個定義、兩個引用與人工核對

什麼時候先不要裝

情況更簡單的做法
只想看 Claude 官方方案的剩餘額度看官方產品介面；ccusage 不是額度權威來源。
只有幾份已知的 Markdown 文件直接請 Claude Code 讀取，或先用 rg。
只找一個固定字串先用 rg，不用先接 Serena。
沒有可比較的同類工作先留下一筆基準紀錄，不急著下「有省」或「沒省」的結論。

交給 Claude Code 的共同提示詞

我的問題是：[看工作階段用量／找核准文件／追程式符號]
允許範圍：[精確路徑或本機紀錄]
禁止範圍：[不應讀取、上傳或修改的位置]

請先讀目前官方文件與 --help，提出安裝來源、版本、命令與會讀寫的路徑。
先不要執行。等我核准後只完成一個成果，最後列出原始證據與限制。

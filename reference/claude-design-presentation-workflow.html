Claude Design 簡報工作流速查表

用一份真實素材走完 core route：受眾與來源先於視覺，claims／rights 查核先於 export，target-format accessibility 與彩排先於 closeout。

七步 core 閉環

01選 routeAudience、Moment、Decision、Target app。
Gate：deck 真的是對的格式。
02Source packFacts、assets、rights、constraints、unknowns。
Gate：主張與權利可回原始來源。
03Story spineDecision → context → evidence → recommendation → next。
Gate：代表性讀者可由 headline 重述決定。
04產生 v0輸入故事板、來源、brand 與限制。
Gate：偏差紀錄揭露新增主張與 hidden unknown。
05Audience revisionAudience → hierarchy → density → brand。
Gate：v1 有可觀察、非偏好的改善。
06PreflightClaims、charts、rights、authoring accessibility。
Gate：ledger 無 blocker；target-format checks 尚未假裝完成。
07Validate＋rehearse＋closeout在目標 app／裝置重開、跑格式專屬 accessibility、限時講給真實聽眾並 rerun。
Gate：closeout packet 可由另一個人重跑。
合法停止點：第 07 課通過即可回課目表。跨格式改作、Open-Slide 與 Mermaid CLI 只有在新需求需要時才選；它們不是 core route 的必修 completion evidence。

Core closeout 後才選一個 elective

08 · RepurposeOne-pager／social新需求改成自行閱讀、轉寄或單一 CTA；保留 verified claims，重做資訊層級並驗證新格式。
09 · Code-firstOpen-Slide新需求接受 HTML／PDF 且需要 React／Git；先做 3 頁 slice，再 build、固定 SHA 與 Review。
10 · DiagramMermaid CLI新需求需要可 diff、可重跑的 diagram source；render 後仍要核對 claims、accessibility 與 slide fit。
Elective／Review boundary：三條分支彼此沒有先後依賴，完成任何一條都不能單獨構成 Presentation closeout。若分支產生 repo／code artifact，必須依 Repo Review contract固定 candidate SHA 並做 Standards／Spec 兩軸 Review；build、render 或視覺回饋不能替代。

不可跨越的停止線

來源不明、數字不符、引言未核准、圖片／字型權利不明、圖表可能誤導、只靠顏色表意，或輸出檔未在目標 app 跑格式專屬 accessibility 檢查：任何一項存在，就還不能宣稱完成驗證。

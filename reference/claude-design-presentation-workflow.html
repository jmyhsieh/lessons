快速參考 · Phase 5

Claude Design 簡報工作流速查表

用一份真實素材走完核心 route：受眾與來源先於視覺，主張／權利查核先於 export，目標格式可及性與彩排先於收尾。

七步核心閉環

01選 route受眾、時機、決策、目標應用程式、受眾問題檢查表。
關卡：簡報真的是對的格式；真人 feedback 提供者為選用。
02來源包事實、素材、權利、限制條件、未知事項。
關卡：主張與權利可回原始來源。
03故事主軸決策 → 脈絡 → 證據 → 建議 → 下一步。
關卡：只看標題仍可重述決定；若有代表性讀者，可選擇加做同一檢查。
04產生 v0輸入故事板、來源、品牌與限制。
關卡：偏差紀錄揭露新增主張與隱藏的未知事項。
05受眾修訂版受眾 → 層級 → 密度 → 品牌。
關卡：用同一問題清單自行比較／回放 v0 與 v1，留下可觀察、非偏好的改善；代表性受眾 feedback 為選用。
06前置檢查主張、圖表、權利、撰寫可及性。
關卡：台帳無阻礙；目標格式 checks 尚未假裝完成。
07驗證＋演練＋收尾在目標應用程式／裝置重開、跑格式專屬可及性，再用限時自行講述或錄影回放找卡點並重跑；真人聽眾回饋為選用加值證據。
關卡：收尾資料包記錄彩排模式、實際／目標時間、迷失時間標記、未說清楚的決策、最高影響修正與重跑結果。
合法停止點：第07課通過即可回課目表。跨格式改作、Open-Slide 與 Mermaid CLI 只有在新需求需要時才選；它們不是核心 route 的必修完成證據。
個人完成路徑：受眾問題檢查表與自行比較／回放是必要的 oracle；演練可選限時自行講述或錄影回放其中一種，完成後依同一模式重跑。真人／代表性受眾 feedback 只作選用加值證據，缺席不構成進入、橫幅或收尾阻礙。

核心收尾後才選一項選修內容

08 · 改作單頁稿／社群新需求改成自行閱讀、轉寄或單一 CTA；保留已驗證主張，重做資訊層級並驗證新格式。
09 · 程式碼優先Open-Slide新需求接受 HTML／PDF 且需要 React／Git；先做3頁切片，再建置、固定 SHA 與 Review。
10 · 圖表Mermaid CLI新需求需要可 diff、可重跑的圖表來源；渲染後仍要核對主張、可及性與投影片版面適配。
選修／Review 邊界：三條分支彼此沒有先後依賴，完成任何一條都不能單獨構成簡報收尾。若分支產生 repo／code artifact，必須依 Repo Review contract固定候選版本 SHA 並做標準／規格兩軸 Review；建置、渲染或視覺回饋不能替代。

檔名、版本、主要的格式、主張／權利台帳目標應用程式／版本、格式專屬可及性、重開結果、已知的限制彩排模式、實際／目標時間、迷失時間標記、未說清楚的決策、最高影響修正、重跑；真人聽眾證據若有則選用附加

匯出選擇

PPTXPDFHTML
需要在 PowerPoint 編輯或交接；跑可及性檢查工具、閱讀順序，並確認講者備註（若使用）。需要固定版面或列印；用 Acrobat 檢查標籤、閱讀順序與可選文字。需要互動或動畫；檢查語意結構、鍵盤、200% 縮放、網路與離線備援。

不可跨越的停止線

來源不明、數字不符、引言未核准、圖片／字型權利不明、圖表可能誤導、只靠顏色表意，或輸出檔未在目標應用程式跑格式專屬可及性檢查：任何一項存在，就還不能宣稱完成驗證。

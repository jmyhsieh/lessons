Rerun policy 速查表

定義哪些 run 可以重跑、哪些要人工介入，以及舊 evidence 如何保留。

Rerun 的驗收句：新 run 一定有新 runId；舊 evidence 永遠保留；重跑原因與 pre-run state 必須可查。

Status policy

StatusPolicy必填欄位
passed不自動重跑；input/gate 版本改變才允許。change reason。
needs-review先人工 review；不能用重跑取代判斷。review owner。
failed修正後可重跑；同一 parent 最多自動一次。fix summary、parentRunId。
blocked解除阻塞後可重跑。unblock evidence。
stale先 verify artifacts；缺證據不是任務失敗。missing artifact list。

Rerun record

{
  "runId": "",
  "parentRunId": "",
  "rerunReason": "",
  "triggeredBy": "human | policy",
  "changedSinceParent": [],
  "preRunState": {
    "gitRef": "",
    "dirty": false,
    "inputHash": ""
  },
  "artifactPolicy": "preserve-parent-evidence"
}

自動重跑前檢查

檢查通過才可重跑
Parent evidence 存在。避免失去上一輪判斷基礎。
Input hash 或修正原因已變。避免相同條件重複燒成本。
Workspace 狀態可描述。至少要知道 git ref 與 dirty 狀態。
沒有未確認 side effect。Bash、外部 API、手動變更需人工確認。

完成定義

Done when:
- Every status has an explicit rerun policy.
- Rerun creates a new runId and parentRunId.
- Parent evidence is preserved and linked.
- Retry budget stops repeated automatic reruns.
- Checkpoint is treated as local recovery, not version control.

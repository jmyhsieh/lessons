Phase 課程目錄

105 個 canonical lessons 的次要查找目錄。Phase 是穩定分類，不代表每位學習者都要照數字順序完成。

可見性原則：這裡只列 canonical lessons；46 個 Compatibility entries 與 1 個 Deprecation notice 仍保留穩定網址，但不列入目錄、導航或完成模型。

Phase 1 — Orient 7 課
  1. 001-0001先選工作表面，再選 Task route
  2. 001-0002把安全範圍與續作點寫成 Return notebook
  3. 001-0003在低風險副本完成一個 Cowork 檔案任務
  4. 001-0004先證明 CLI 與 session 可用
  5. 001-0005先用檔案證據畫出 repo map
  6. 001-0006用 Plan mode 收斂一個 bounded fixture edit
  7. 001-0007把 bounded edit、diff 與 checks 組成 readiness evidence
Phase 2 — Equip 11 課
  1. 002-0001只補目前任務缺少的一個能力
  2. 002-0002先把 read、write 與 external side effects 分開
  3. 002-0003用任務需求選 model，用不確定性選 effort
  4. 002-0004先證明 hook 真的在正確事件觸發
  5. 002-0005用一組正反例證明 guardrail
  6. 002-0006先使用既有 Skill，不跨過 Workflow authoring boundary
  7. 002-0007先證明 trust，再開一個 read-only capability
  8. 002-0008把一個 bounded question 交給 read-only subagent
  9. 002-0009用 worktree 隔離一條 parallel edit line
  10. 002-0010把一次成功的互動改寫成 bounded one-shot
  11. 002-0011先設計 CI 的外部執行邊界，不建立真實 workflow
Phase 3 — Deliver 10 課
  1. 003-0001從 mission 選一種 Knowledge artifact，不把格式變成課程階梯
  2. 003-0002先建立 raw source pack，讓生成內容永遠不是 source of truth
  3. 003-0003先把 source evidence 接到 claims，再開始生成 artifact
  4. 003-0004先產出一個能取得 feedback 的 Knowledge slice
  5. 003-0005把「看起來完整」改成可查核的 deliverable
  6. 003-0006把 deliverable、provenance、judgment 與 feedback 收成同一個 closeout
  7. 003-0007只編出一個可追溯的 LLM Wiki topic cluster
  8. 003-0008只把 active source normalize 成可檢查的 working copy
  9. 003-0009用 QMD 找候選 evidence，再親自打開原文件
  10. 003-0010用 DuckDB 產生一個可重算的 tabular finding
Phase 4 — Design 7 課
  1. 004-0001先選對 Design surface，再開始生成
  2. 004-0002把模糊要求收斂成可驗收的 Design brief
  3. 004-0003只用 approved context，同步後逐項校正
  4. 004-0004比較不同假設，不接受第一個漂亮輸出
  5. 004-0005一次精修一層，讓每個 revision 都能解釋
  6. 004-0006用可重跑觀察檢查 assumptions，不把 prototype 稱為 production
  7. 004-0007把 intent、states、evidence 與 limits 組成可接手的 handoff
Phase 5 — Communicate 10 課
  1. 005-0001先固定受眾與交付環境，再開始做 deck
  2. 005-0002整理可追溯的 source pack
  3. 005-0003把素材排成簡報故事板
  4. 005-0004在 Claude Design 產生第一版 deck
  5. 005-0005依受眾與品牌精修簡報
  6. 005-0006查核內容、圖表與可及性
  7. 005-0007完成 target-format validation 與彩排 closeout
  8. 005-0008把已驗證 deck 改作 one-pager 或 social asset
  9. 005-0009用 Open-Slide 建立可版本控制的 deck
  10. 005-0010用 Mermaid CLI 建立可審查的 diagram-as-code
Phase 6 — Build 14 課
  1. 006-0001先選 Engineering on-ramp，再進 repo
  2. 006-0002用檔案證據畫出 bounded repo map
  3. 006-0003把 request 對齊成可驗證的 delivery boundary
  4. 006-0004用可丟棄 prototype 回答一個問題
  5. 006-0005把已對齊的 request 凝結成 delivery spec
  6. 006-0006把 spec 變成可認領的 vertical slices
  7. 006-0007逐張實作 ticket，固定 Review candidate
  8. 006-0008以兩個獨立視角 Review 同一個 immutable candidate
  9. 006-0009把 final candidate、Review 與判斷收成可接手的 closeout
  10. 006-0010先驗證與分流外部回報，再交回 Engineering core
  11. 006-0011先造出會紅的 feedback loop，再診斷難解 bug
  12. 006-0012從 architecture friction 找出一個可交付的 seam
  13. 006-0013為巨大且仍在 fog 裡的 effort 畫 shared map
  14. 006-0014只解一張 frontier decision ticket，再更新 map
Phase 7 — Verify 7 課
  1. 007-0001先界定一個會被反證的 browser claim
  2. 007-0002依 claim、identity 與 session 選一個 surface
  3. 007-0003固定比較對象，再觀察 claim
  4. 007-0004把同一個 browser claim 寫成最小 Playwright Test
  5. 007-0005先讓 controlled fault 擊中 assertion，再修正後重跑
  6. 007-0006只有 failure 還解釋不了，才保留 trace
  7. 007-0007把 durable browser evidence 附回 Engineering closeout
Phase 8 — Operate 8 課
  1. 008-0001先把「做完了」寫成 agent 無法自評通過的 check
  2. 008-0002依 trigger 與 operating boundary，只選一個 local-first surface
  3. 008-0003把 read、local write 與 external side effect 分成三份 authority
  4. 008-0004在 restore point 與小批次界線內執行一次 workflow
  5. 008-0005讓 oracle 對本次 run 下判斷，不讓 agent 批准自己
  6. 008-0006刻意讓 fixture 失敗一次，證明 workflow 會恢復或安全停住
  7. 008-0007把 mission、authority、completion 與 recovery 收成可稽核 closeout
  8. 008-0008在 raw-source boundary 內維護一次既有 LLM Wiki slice
Phase 9 — Standardize 9 課
  1. 009-0001先證明 workflow 值得重用，再談怎麼包裝
  2. 009-0002把成功 run 的不變規則抽出來，不複製偶然細節
  3. 009-0003依 audience 與執行責任只選一種 package
  4. 009-0004把需要人類判斷的 workflow 包成 playbook 或 template
  5. 009-0005把 repo-local workflow contract 寫進最窄的 CLAUDE.md scope
  6. 009-0006把跨 workspace 的 bounded instructions 包成 reusable Skill
  7. 009-0007讓 deterministic code 承擔可可靠判定的流程
  8. 009-0008把一個通過 rerun 的 package 收斂成可維護 closeout
  9. 009-0009把一次已證明的 LLM Wiki maintenance 萃取成可重跑 contract
Phase 10 — Prove 8 課
  1. 010-0001先固定要評估的 workflow claim
  2. 010-0002讓 candidate 與 comparator 在同一 frame 被觀察
  3. 010-0003建立代表性 success case set
  4. 010-0004用 failure 與 adversarial cases 測安全邊界
  5. 010-0005把 observations 組成可追溯的比較證據
  6. 010-0006保留 evidence conflicts，再做可追溯處置
  7. 010-0007完成一份有界的 Workflow evidence dossier
  8. 010-0008用本機 usage／cost 摘要補一個決策缺口
Phase 11 — Roll out 7 課
  1. 011-0001先把 rollout 縮成一個可演練的團隊情境
  2. 011-0002把操作、review 與停止權分給不同角色
  3. 011-0003用 least privilege 與 synthetic data 封住情境
  4. 011-0004把 deterministic preconditions 與 human approval 分開
  5. 011-0005讓 findings、resistance 與 stop 有明確去處
  6. 011-0006只收最小 feedback，並用 tabletop 證明可停可回
  7. 011-0007完成一份有界的 Scenario rollout plan
Phase 12 — Govern 7 課
  1. 012-0001先把治理縮成一個 workflow lineage
  2. 012-0002讓每個 material change 都能重查
  3. 012-0003讓資料從來源到刪除都有 owner
  4. 012-0004用 evidence 排出 learner priority
  5. 012-0005演練偵測、暫停與復原
  6. 012-0006同時演練 material change 與 retirement
  7. 012-0007完成一份可稽核的 self-study policy draft
